# 三实例共享会话配置说明

适用部署：三台服务器各运行相同的 FastAPI 和 Agent，使用同一个 GoldenDB 应用库。会话模式需要三个节点统一切换，不能把节点本地 JSONL 当成共享存储。

## 当前交付状态

**本次只交付代码、表结构定义及说明，不执行建表 SQL、数据库迁移或生产切换。** 提交迁移文件不等于已经建表，数据库模式也不会因为更新代码自动开启。

| 项目 | 已准备内容 | 现有环境状态 |
| --- | --- | --- |
| 共享会话表 | 四张表的定义与 `0006_agent_shared_sessions` 增量迁移 | 未在实际应用库执行本次建表迁移 |
| 会话存储 | JSONL 与数据库两种模式；数据库模式已做隔离验证 | 当前本机仍使用本地 JSONL，未启用数据库会话 |
| 三节点共享 | 共享历史、改名、删除、写租约、停止信号与流式重连接线 | 尚未在三台服务器及真实 GoldenDB 上联调 |
| 旧历史迁移 | 明确切换检查、备份与回退边界 | 未提供导入工具，未导入现有历史 |

共享应用库与共享 Agent 会话是两件事。现在后端使用同一个应用库，不会让各节点本地 JSONL 自动共享；只有完成建表、旧历史迁移并统一启用数据库模式后，Agent 才会读写同一份会话。启用后由程序维护会话数据，不需要管理员逐条维护。

## 会话运行方式

- 数据库模式通过 Pi 的公共 `Storage` 接口保存原生消息、分支、用量及操作检查点。Pi 继续负责业务工具循环、上下文、压缩和操作恢复，不另建执行框架。
- 会话目录、名称、运行标记以及删除墓碑都在应用库。相同账号在不同节点看到同一份记录；其他账号查询或删除统一返回不存在。
- 单个会话由一个启动实例持有写租约，其他实例可以读取。租约使用数据库时间，45 秒有效、每 5 秒续期。节点失联后可由其他节点接管；所有后续写入校验租约代次，旧节点不能恢复写入。
- 删除与本节点提问接纳共用入口锁，数据库事务再核对活动操作和租约后写墓碑。运行中的会话返回冲突，不允许删除后继续写回；多个不同会话可并发删除。已删除记录重复删除返回 404，前端按已移除处理；数据库故障不会伪装成 404。
- 停止操作按明确的 `operation_id` 或 `request_id` 写入共享信箱。202 表示请求已接收，持有租约的节点读取后执行；轮询间隔为 5 秒，实际响应还受当前事务、队列和故障恢复耗时影响，失联接管需等待租约过期。不能把 202 解读为执行已经停止。
- 原提问连接断开后，执行仍继续，已校验的页面事件顺序入库。其他节点通过同一 SSE 接口重放本轮事件并重新核验权限。共享事件只保留最近接纳轮次，正式历史来自原生会话；观察期间发生新一轮提问时提示重新打开。
- 已失联节点的未完成操作由后续认证访问重新授权恢复。恢复过程中可能先显示历史快照、最后显示结果，不能承诺故障接管时每一段临时文本都连续重放。

Agent 无需互相访问端口。每台 Agent 需要访问应用库和其配置的 FastAPI；模型和业务数据访问路径延续原有设置。

## 应用库与配置

新增四张表：`agent_sessions`、`agent_session_records`、`agent_session_events`、`agent_session_cancellations`。使用 InnoDB 事务及区分大小写的 UTF-8 排序规则；数据库连接池每个 Agent 最多 5 个连接，不跨模型调用持有数据库事务。

| 表 | 保存内容 |
| --- | --- |
| `agent_sessions` | 账号归属、名称、创建时间、活动操作、删除标记及写租约代次 |
| `agent_session_records` | Pi 原生消息、应用值、分支与执行检查点 |
| `agent_session_events` | 最近接纳轮次的页面流式事件及重放序号 |
| `agent_session_cancellations` | 按操作或请求投递的停止信号 |

通过现有 GoldenDB Alembic 入口执行 `0006_agent_shared_sessions`，沿用原有变更许可和目标数据库校验。先完成测试库演练和现场审批，再执行生产迁移；服务运行账号不自行建表。参见现有 [行内UAT部署交接与打包说明](行内UAT部署交接与打包说明.md) 的数据库及配置保留流程。

本机默认仍为 `jsonl`，不改变现有开发历史。启用共享模式时，三个节点配置：

```dotenv
AGENT_SESSION_STORAGE=database
AGENT_DEPLOYMENT_REPLICAS=3
AGENT_SESSION_DATABASE_URL=ENC[SM4:v1:由现有加密方式生成的密文]
```

连接串采用 `mysql://用户:密码@主机:端口/应用库`，也接受现有 `mysql+pymysql://` 格式，账号和密码中的特殊字符必须进行 URL 编码。密钥仍使用现有 SM4 主密钥配置，不填写到源码或示例中。

启用 Nacos 时，前两项放在 `sznsznws_agent_runtime.json`，连接串放在 `sznsznws_agent_security.json`。这些是启动配置，三个节点应使用相同版本和配置后重启。声明多副本但保留 JSONL 会被拒绝；数据库不可用或表缺失也会拒绝启动，不回退本地文件。

**现有 JSONL 和旧 JSON 会话历史不会自动导入。** 数据库模式检测到原状态目录仍有这两类会话历史时会拒绝启动，防止切换后历史悄悄消失。本次未提供、未执行旧历史离线导入；已有环境切换前必须单独完成历史导入及核对，并为数据库模式使用新的本机状态目录。不要通过清空旧目录绕过检查，原目录需保留备份。

## 后续启用顺序（本次不执行）

1. 核对三节点版本、应用库权限、数据库连接容量与配置来源，保留应用库及各节点历史目录备份。
2. 单独准备旧 JSONL/JSON 导入工具，在隔离环境验证账号归属、名称、消息、工具结果引用及未完成操作的迁移和核对方法；不能直接把多份文件拼接为共享历史。
3. 在测试 GoldenDB 演练增量迁移、并发及回退，完成现场审批后，才在目标应用库执行建表迁移。
4. 停止旧会话写入，按已验证方案导入并核对历史，保留原文件备份；准备数据库模式的新本机状态目录。
5. 三个节点统一启用 `database`、同一应用库及约定配置，再启动服务。不能混用本地模式与数据库模式承接同一批历史。
6. 经过真实负载均衡验证跨节点读取、改名、批量删除、重复请求、停止、断线重连及节点失联；同时检查账号与机构权限、实际取数次数和最终回答。

上述步骤完成前，保持当前本地模式。本说明中的配置片段用于后续实施，不代表已执行切换。

## 兼容与回退

本次没有修改正式指标、机构和期间解析、查询 SQL、业务计算或数据权限规则。新增 SQL 仅用于 Agent 自身的会话持久化。默认单机 JSONL 模式仍沿用原生文件仓库，并保留批量删除的目录互斥修复。

回退到 JSONL 必须先停掉全部数据库模式 Agent，再按确认的历史导出/备份方案恢复单写部署。数据库模式运行期间的新会话不会自动回写旧 JSONL，直接改开关会使两份历史分离。保留新增表即可，不需要为了程序回退立即执行降级删除数据。

## 除会话外仍需处理的事项

| 场景 | 当前代码依据与影响 | 后续处理 |
| --- | --- | --- |
| 管理员维护业务知识、查询方案 | `BusinessKnowledgeStore` 仍使用本地 JSON 与进程锁；不同节点可能读到不同内容 | 独立迁入共享存储并采用数据库版本冲突控制，不用共享盘加本机锁代替 |
| 模型、提示词与技能配置 | 模型配置支持配置中心，但未使用配置中心时仍写本地文件；技能自定义正文也保存在节点本地文件，保存后供本节点后续轮次使用 | 统一配置来源、版本与发布流程，核对各节点实际生效值；不能仅以配置已保存认定全节点已刷新 |
| 测评任务与记录 | `EvaluationStore` 仍使用本机文件、任务协调仍在本机 | 独立迁移记录与任务队列；本次不承诺测评跨节点恢复 |
| 高并发问数 | 模型信号量和部分连接池是进程内限制，三节点总并发会增加 | 根据模型额度、GoldenDB 和业务库容量核定集群总并发，必要时增加共享排队/限流 |
| 指标与机构目录变更 | 正式目录来自数据库，指标缓存已有计数和更新时间失效依据 | 做跨节点变更后读取回归；不能把所有目录缓存一概判为永久不同步 |
| 登录和机构权限 | 后端已逐次读取账号启用状态、机构、角色和 `session_version`；JWT 密钥等配置必须一致 | 验证各节点认证结果一致；数字农商变更到应用库的同步时差仍是此前暂缓的独立问题 |
| 故障切换与流式代理 | 应用层重连具备共享会话依据，仍受代理缓冲、空闲超时和节点健康摘除影响 | 在真实负载均衡环境验证断网、重连、节点重启及滚动升级，不能只依赖会话粘滞 |

既有业务查询任务已经使用数据库行锁和幂等键。本次保留这些保护，不能仅因为部署了三节点就认定所有业务取数都会重复执行；需要在现场验证中同时核对实际 SQL 次数、任务键及最终回答。

## 验证边界

本地使用隔离 MySQL 8.4 实例验证公共存储契约及多个独立宿主，并包含独立 Node 进程互斥测试。模型和认证服务使用隔离桩，验证的是并发、持久化、HTTP/SSE 和故障保护，不代表真实业务答案或性能验收。

本次没有连接或修改生产数据库，也没有在三台生产服务器上部署。GoldenDB 的现场驱动/DDL 兼容、隔离级别、真实负载均衡、旧历史导入、业务知识与测评共享仍需完成相应验证或改造，不能据本次会话修复宣布整个系统已满足三实例投产要求。

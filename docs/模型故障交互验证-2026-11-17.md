# 模型故障交互验证

日期：2026-11-17。范围：共享模型限流、超时、服务不可用和流式中断时的反馈与恢复操作。未修改实际模型配置，未增加自动重试循环。

## 根因与改动

- 原有首响应时限、流式空闲时限、取消和部分结果交付已有实现，但多种模型错误在展示投影中合并成同一句提示。现在统一分类限流、额度、授权、超时、服务不可用和连接中断，实时终态与历史读取使用相同的安全说明，不展示网关原始正文。
- SDK 已发出真实重试事件，但页面未展示退避与重试阶段。现在将这些事件接到已有执行过程，展示实际重试次数、等待时间和结果，不推测排队人数或完成进度。
- 失败结束时，前端曾将未结束步骤一律标成完成；停止后又可能留下“正在重试”的旧说明。现在只收尾仍运行的步骤，标明中断并清除失效的动态说明，保留查询条件及已完成步骤。
- 超过 30 秒显示“本轮用时较长，可以继续等待，也可以停止后稍后再试。”，保留实际计时和停止入口；有真实重试说明时优先展示该说明。
- 末轮可重试错误提供“重新提问”：只回填原题并聚焦输入框，用户发送后才发起新请求。已有草稿不被覆盖；额度、模型授权或权限变化等错误不鼓励直接反复重试。
- 保持现有聊天布局、执行过程默认展开和指标、机构、数据日期。正式结果沿用原有核验与保留机制，未完成的模型片段不当作成功业务答案。

## 重复运行故障演练

使用项目支持的 Node 版本和现有依赖，在 `agent-service` 执行：

```sh
node --import tsx scripts/model-fault-fixture.ts --fault-fixture \
  --backend-port=8011 --first-timeout-ms=35000 \
  --idle-timeout-ms=3000 --retry-delay-ms=5000
```

`--backend-port` 必须与当前本地页面使用的真实后端一致，本次为 8011。测试 Agent 为 `127.0.0.1:18020`，故障端点为 `127.0.0.1:18321`。脚本显式启用才会运行，只监听回环地址，为每次启动创建独立临时会话目录，不读取 `.env` 或真实模型密钥。

另开终端，在 `frontend-vue` 启动独立测试页面：

```sh
VITE_BACKEND_NEXT_BASE_URL=http://127.0.0.1:8011 \
VITE_AGENT_SERVICE_BASE_URL=http://127.0.0.1:18020 \
npm run dev -- --host 127.0.0.1 --port 5176 --strictPort
```

打开 `http://127.0.0.1:5176`，使用现有本地账号认证。不要将正常前端或内网运行配置指向故障端点。

默认场景是限流，可在本机切换下一次模型请求的场景：

```sh
curl http://127.0.0.1:18321/__fault/scenario \
  -H 'X-Model-Fault-Fixture: 1' -H 'Content-Type: application/json' \
  -d '{"scenario":"rate-limit"}'
```

| 场景 | 模拟行为 |
| --- | --- |
| `rate-limit` | HTTP 429，包含 QPM 限流错误 |
| `unavailable` | HTTP 503 |
| `first-timeout` | 不返回首响应 |
| `idle-timeout` | 返回明确标注的故障片段后停止输出 |
| `disconnect` | 直接断开连接 |
| `truncated` | 流未完成就结束 |

`GET http://127.0.0.1:18321/__fault/state` 可查看场景、请求数和连接释放情况，不包含问题正文或凭证。运行中的请求保持原场景；切换只作用于下一次模型请求。演练结束后在两个测试服务终端按 Ctrl+C，正常业务服务无需修改或回切配置。

## 当前边界

- 共享模型的容量、排队和内网网络问题仍需现场定位；本次改善等待、失败和恢复操作。
- 外层重试仍使用原配置退避时间，尚未按网关 `Retry-After` 动态调整，不叠加第二层重试。内网实际网关若使用特殊状态码或错误结构，需采集脱敏响应后再核对分类。
- 重试活动沿现有实时进度协议展示，刷新后保留错误类别和重新提问入口，不新增重试时间线的历史持久化。
- 内网发布需配套更新 Agent 与前端；本轮未执行内网部署或 Git 提交、推送。

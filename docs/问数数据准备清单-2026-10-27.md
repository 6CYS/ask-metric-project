# Ask Metric 问数数据准备清单

日期：2026-10-27。用途：明确为了得到正确、自然、有依据的问数和分析，需要向数据/业务负责人梳理哪些资料，以及放在哪里维护。

本清单与[菜单及按钮清单](平台功能清单-菜单与操作-2026-10-27.md)配套。这里的资料项不是要求新建同样数量的数据库表，也不要求把资料全部放进提示词。可以用现有数据目录、受控视图、接口或一份分表签的资料包交付。

本轮依据当前代码、配置及既有讨论整理，未重新查询数据库、调用模型或逐行复核原 Excel。**代码已支持、配置已登记、实际有值、业务口径已确认，是四种不同状态。** 当前数据范围和最新日期仍须用真实来源核对，不能引用旧截图当本次数据盘点结果。

## 1. 先从想问的问题反推需要什么

| 想问的问题 | 必需数据/资料 | 可以回答到哪一步 | 不能仅凭这些推断什么 |
| --- | --- | --- | --- |
| 紫金的存款余额有多少 | 正式机构与别名、存款余额正式编号/口径/单位、该机构实际有效日期和值 | 在明确统计日给出余额 | 没有历史就不能附带增长结论 |
| 我行存款情况如何 | 账号所属机构/权限、总量与主要分项、实际日期、可比数据、分项口径 | 概况、变化、已核实结构 | 不等于所有业务维度都已覆盖 |
| 同比环比呢 | 对应的正式比较指标及定义，或同口径当前值与真实基期值 | 增减额、增幅；比例指标可按口径说明百分点变化 | “较上月”不能自行当作“上个月发生额” |
| 近几个月走势怎样 | 按该指标更新频率提供的多个真实观测点、缺数说明、版本/单位一致性 | 展示实际时间序列 | 多个比较基期不能拼成连续趋势；缺期不能补零 |
| 个人和对公谁拖下来的 | 两期总量和分项，分项是否互斥完整、分母/合计口径、源批次 | 已核准范围内的变化分解和贡献 | 分项下降本身不证明业务原因 |
| 哪些机构拖下来的 | 两期各机构同一指标、有效机构汇总关系、完整成员与总量、调整项 | 机构变化排名；满足对账条件后计算贡献 | 截取几家负增长机构不等于解释全行净变化 |
| 定期存款是哪个期限变化大 | 各期限正式编码、原始单位、期限边界和分类依据、同日/两期事实 | 期限结构、变化；关系批准后可进一步分解 | “一年及以下”等标签不足以证明四项覆盖全部定期存款 |
| 紫金最近贷款质量如何 | 不良余额/不良率等已批准观察指标及定义、可比历史、分母；如做评价另需适用阈值/目标 | 描述规模、比例与变化，解释本行口径 | 没有阈值和适用依据不能断言“风险可控”；总贷款不一定是不良率分母 |
| 哪些客户转出资金 | 经授权客户/账户标识、账户余额或交易流水、机构/产品归属、交易方向与类型、冲正/内部划转规则 | 有账户余额时定位余额下降；有相应流水时核实资金转出 | 余额下降不必然是对外转出，更不证明客户流失或其动机 |
| 主要是什么原因、为什么 | 上述分解事实，加经确认的业务事件、客户/产品/渠道明细或其他原因证据 | 解释有证据的变化构成；区分已证实、可能原因和待核查 | 通用知识、历史案例和相关变化不能直接作为本期原因 |
| 帮我画结构图/趋势图 | 与答案一致的正式结果；结构分母/组成关系，或真实时间点序列 | 图文表使用同一来源和单位 | 分类重叠、不同分母的比例不能硬凑成饼图 |

**提升效果的顺序：先让指标和机构对得上，再让数值、日期、单位与比较口径正确，然后补关系和业务证据。** 模型已有一般语言和业务常识；本行事实、特殊叫法、口径和数据边界需要提供。

## 2. 必须整理的基础资料

### D01 正式指标字典：让“问的概念”落到正确指标

每个首批指标需要这些信息，不只交一列指标名：

| 信息 | 应确认的内容 | 维护位置 |
| --- | --- | --- |
| 唯一身份 | 正式指标编码、正式名、源指标编码与派生口径的对应关系 | 正式指标源；应用指标目录 |
| 业务含义 | 定义、包含/排除项、统计对象、币种范围；余额/日均/期间发生额/累计值的区别 | 指标说明与口径；结构化语义补充 |
| 数值单位 | 原始数值究竟为元、万元、亿元等；允许的展示换算与精度 | 正式目录及取数映射；不是只写在知识正文 |
| 比例与变动 | 原值是 0—1 比值还是百分数；增减额、增幅、百分点分别是哪项 | 指标定义、比例编码和正式比较关系 |
| 时间性质 | 日/月/季/年频率，时点/期间/年内累计，实际业务日期的含义 | 正式口径与语义配置 |
| 同义与歧义 | 行内简称、旧名、常用说法；同词对应多个指标时的区别 | 指标同义词；必要的澄清依据 |
| 管理信息 | 权威来源、责任人、正式版本、生效/停用、修改理由 | 上游指标平台；本地补充和发布记录 |

当前“指标术语”可维护编号、名称、单位、同义词、说明和口径；没有完整的责任人/业务发布版本页面。新增一个目录条目只让系统认识该指标，不会自动产生事实数值。

不需要枚举每句自然语言。重点记录“本行使用的叫法和一般含义不同”以及确实容易混淆的概念。

### D02 机构与权限资料：让“紫金、我行、下辖机构”有明确范围

- 正式机构编码、标准名、简称/别名，哪些名称有歧义。
- 法人/分行/支行等真实层级、上级编码、有效起止日期，撤并或更名记录。
- 全行/全省汇总对应什么对象；是否已有汇总行；哪些成员纳入、哪些排除；不能把汇总行与子机构再相加。
- 账号归属机构、可查询范围及生效时间；支持“我行”默认范围，不能由模型猜权限。
- 做历史比较时采用当时组织范围还是重述后的可比范围，需要业务明确。

维护：机构源和身份系统为准；“机构别名”维护别名。现有页面没有父机构/层级编辑，不应靠手工别名代替组织关系或授权。

### D03 指标事实和历史：让答案真正有数

每笔事实至少能够确定：**哪个正式指标、哪个机构、哪个业务日期/期间、哪个取值口径、数值和原始单位、来源版本/批次**。如果还区分币种、产品、客户类别等，应说明这些是否已经汇总，或纳入该记录粒度。

需要数据方确认：

- 数据唯一键和重复记录处理；同机构同指标同日多批次时选哪一版。
- 业务统计日、ETL 日期、指标定义生效日分开；不能用入库日期代替业务日期。
- 最早/最晚日期、更新频率、实际有值的机构和期间；目录存在不代表事实齐全。
- NULL、空串、非数值、缺行、确实为零分别是什么意思。
- 迟到数据、补录、冲正与重述规则；已经生成的报告保留原结果还是重新计算。
- 历史数据的单位、口径、组织范围发生变化时，给出可比标识或转换依据。

交付可为受控只读表/视图/API，附字段字典和覆盖统计，不必先复制全量历史到另一套库。

### D04 比较口径与基期：让同比环比算得对

| 需要确认 | 具体问题 |
| --- | --- |
| 正式比较指标 | “较上月/较同期/较年初”分别是增减额还是增幅，绑定哪个基础指标，按哪个基期生成 |
| 比较日期 | 上月同日、上月末、上一个有效日是哪一种；闰年、月末、节假日怎么对齐 |
| 计算路径 | 优先使用已确认的正式比较事实；若允许由基础值计算，必须取得真实、同口径的两期来源 |
| 特殊分母 | 基期为零、负数、缺失怎样处理；不能无条件输出增长率 |
| 比例指标 | 占比变化的百分点与相对增幅分开，不直接套金额比较模板 |
| 跨期变更 | 指标定义、组织范围、币种、汇率、分类或源版本改变时是否仍可比 |

两期可比值足以支持一次差额比较；稳定展示月度趋势需要多个真实月度点。若希望同时看近一年月度走势和同比，建议提供覆盖所需当前期与对应上年基期的历史，具体跨度按问题确定，不机械规定所有指标必须交全量日数据。

季度的时点指标通常需要目标时点及相应比较期；期间发生额需要完整期间或正式期间汇总。不能把季度内任意一天的值称为完整季度表现。

### D05 组成关系和可比集合：让结构和贡献有依据

每组关系要写清：父指标、子指标/成员集合、关系类型、适用机构和期间、同一单位/币种/口径、是否互斥、是否完整、残差/调整项如何处理、审核依据和责任人。

关系类型要分开：

- **组成关系：** 分项能够组成总量，才可能做占比和变化分解。
- **包含或交叉关系：** 一项包含另一项或分类有交叉，不能直接求和。
- **相关观察指标：** 可以一起分析，但不能相加、自动当作贡献。
- **机构汇总关系：** 完整下级集合与父级汇总的对应规则，和指标父子关系分别维护。

对变化贡献，先核对两期总量和分项是否平衡，再给分项增减及对净变化的贡献。净变化为零、负数、分项对冲或贡献超过 100% 时，应按已确认方法解释；残差不能硬分配给某个机构。只有部分数据时，可以说明已查机构的变化，不能称完整贡献。

当前 `analysis-semantics.json` 关系为空，`business-topics.json` 中有试点组成规则且仍需审核；现有 `structure` 主要是占比，不等于跨机构两期贡献已经实现。**资料准备好以后，还要按平台计划接通关系发现和执行。**

## 3. 按业务目标补充的增强资料

### D06 贷款质量、目标与对标依据

先提供本行批准使用的观察指标集合及定义，例如当前主题已有不良余额、不良率等映射。核实其分母、机构/币种/分类口径，不把名称类似的总贷款自动当分母。

如果要回答“好不好、是否达标、风险是否偏高”，还需要有出处的目标/阈值/对标集合、适用机构、期间、版本和批准人。没有这些仍可描述事实和趋势，不必补造评价。

逾期、迁徙、核销、回收等额外维度仅在业务希望深入、且有对应正式数据和口径时接入。不要凭行业常识假定本库已经具备。

### D07 客户、产品和交易明细

只在需要相应问题时准备，走授权的最小范围：

| 要分析什么 | 所需明细 | 额外规则 |
| --- | --- | --- |
| 哪些客户余额下降 | 稳定客户/账户标识、两期余额、机构归属、产品/币种、日期 | 客户多账户聚合、账户关闭/迁移、归属变更、脱敏展示 |
| 资金向哪里转出 | 交易日期、金额/币种、方向、交易类型、授权的对手方类别或去向、账户关联 | 内部划转、冲正/撤销、现金、到期续存与重复流水排除口径 |
| 哪些产品/渠道变化 | 正式维度编码/字典、机构和时间关联、对应粒度事实 | 产品归类版本、跨维度重复、总分对账 |
| 利息成本为何变化 | 付息/利率/期限或合同等实际证据，按批准粒度接入 | 实际成本与估算分开；不能从活定期比例直接断言成本增减 |

当前三表指标模式不足以自动回答这些细节。拿到明细也不意味着现有指标查询合同能直接使用；需要相应数据集映射、权限和最小计算支持。首期可以先完成聚合指标问数，不要求先上传客户姓名、证件号或完整流水到模型。

### D08 业务知识、事件与案例

适合维护到“业务知识”的内容：本行特有业务用语、解释指标时的注意事项、已批准的分析方法、适用的制度/流程、核实过的历史案例和业务事件。

每条至少说清**讲什么、适用于什么、依据是什么、谁确认**。资料有时效再补生效/失效与版本，不要求所有方法性短文填同样多字段。现有页面只维护标题/正文/启用，额外治理资料可先留在受控资料包或既有知识系统，不能假称当前都有字段。

应分开存放：

- 指标的单位、定义、取值口径：指标目录/正式语义。
- 实际金额、比例、流水、当期业务事件证据：事实来源；事件可附资料，但不能替代事实核验。
- 怎么分析、何时可以采用某种解释：业务知识/方法。
- 回答语言、风格和工具约束：实际生效的提示词/代码配置。
- 某次历史案例：知识参考，不能当作本次机构下降的原因。

### D09 质量、覆盖与数据变更记录

每个首批数据集或指标组提供：更新计划、最近成功业务期/批次、缺失机构/日期、非数值/重复/冲突、单位未确认项、停用项、版本变化和问题负责人。查询时必须区分无数据、未查询成功、无权限和部分可用。

原始资料与目录同步的权威关系也要明确：当前源同步会设置指标启用，尚需确定本地停用是否可覆盖、源退役如何生效。不要通过反复人工改目录维持不一致状态。

### D10 真实问题和核准答案依据

这也是支持好效果的重要资料，不是给每句话写提示词。

收集业务人员原话和连续追问，标注：业务目标、应查机构/指标/期间、允许的默认值、正式来源/核准数值或复核查询、合理缺数说明、禁止得出的结论、适用图表、复核人和版本。

覆盖：明确问题、省略追问、切换指标、追加/替换机构、不同日期、缺数、同义词歧义和超能力问题。不要只收已经优化过的问法；标准答案按事实和条件评估，不要求每句措辞一样。

| 正式语义扩展 | 定义了频率、数量性质、比例编码、批准状态和关系结构 | 当前空配置不等于已审核全量关系；试点映射不等于完成正式发布 |
| 旧实测与截图 | 可作为待复现样例和历史记录 | 不能当作当前数据库覆盖、最新日期或全量准确率证明 |

对 Excel 的处理：逐项列“业务项→正式编码/取值口径→原始单位/比例编码→实际机构/日期覆盖→关系类型→已确认/待确认”，而不是把整张 Excel 塞进知识正文。对公非银、保证金、市场份额、期限类尤其要确认分类范围和分母；配置中的“总账非税/1104/手工导入”目前是来源标签，不是完整血缘证据。

当前三表接入的字段约定可直接交给数据方核对，**以实际环境配置和字段字典为准**：

| 来源 | 代码已有映射约定 | 必须确认 |
| --- | --- | --- |
| 指标事实 | `indcr_no`、`orig_indcr_no`、`indcr_nm`、`org_no`、`data_dt`、`indcvl`、`indcvl_incrrng`、`etl_date`、`btch_seq_no` | 正式编码/基础编码/取值口径关系；业务日与加载日；数值原始单位；批次选取。`indcvl_incrrng` 不能只凭名称认定为期间发生额 |
| 指标配置源 | `indcr_no`、`indcr_nm`、`eff_dt`、`indcr_ver_no`、`btch_seq_no` | 哪个版本在目标日期生效；名称是否混含比较口径；单位与完整定义从哪里提供 |
| 机构源 | `org_no`、`org_chn_nm`、`corpt_no`、`org_hier_code` 及配置的上级/快照字段 | 编码与账号映射、法人/支行范围、正式层级和历史有效期 |

另一种 MySQL 合同使用 `metric_values` 的机构、指标、日期、数值和来源批次等字段。支持不同合同不等于当前环境同时具备全部数据；提供方应确认实际采用哪一种，不按文档默认表名直接认定现场。

## 5. 给数据提供方的具体交付清单

建议第一包聚焦存款和贷款质量、目标用户有权限的机构。资料可以是一份工作簿加只读数据入口；下列名称是交付物建议，不是已创建文件。

| 交付物 | 应包含的内容 | 负责人 | 收到后怎么验 |
| --- | --- | --- | --- |
| ① 指标字典与口径 | D01 字段，特别是原始单位、比例编码、存量/流量、比较定义及权威来源 | 指标/业务负责人 | 正式编码唯一；同义词可解释；关键语义无未标注歧义 |
| ② 机构及账号范围 | D02 正式名/别名/层级/汇总成员/有效期，测试账号允许范围 | 主数据/身份负责人 | “紫金/我行/下辖”映射可复核；无母子重复计数 |
| ③ 事实来源与覆盖 | 只读表/视图/API、字段字典、唯一键/批次规则、实际机构与日期覆盖 | 数据负责人 | 代表指标能核准来源；缺失与零分开；原始单位一致 |
| ④ 历史与比较说明 | 当前和所需基期事实或正式比较事实；日期对齐、变更可比规则 | 业务/数据负责人 | 两期条件一致，正式增减/增幅可核对；无法比较时明确原因 |
| ⑤ 组成关系与对账 | 总分/机构成员清单、互斥完整性、调整项、分母和确认依据 | 业务/数据负责人 | 同期总分对账；重复/缺项可识别，残差可解释 |
| ⑥ 业务资料与核准样例 | 本行特有知识、有效制度/阈值、真实问题及来源答案、复核人 | 业务专家 | 问题落到真实数据；案例/阈值适用，不把常识当事实 |
| ⑦ 问题与更新清单 | 未知单位、冲突编码、缺数、发布/停用、刷新频率、责任人 | 数据/运营负责人 | 每个未知项可跟踪；更新后可重新验证 |

客户明细/交易流水是第二包，仅在确认要做客户或资金去向分析后提供；先确定权限、最小字段与产品支持范围。

可以直接发给同事的说明：

> 请先按存款及贷款质量主题提供正式指标字典（含原始单位、比例编码、统计口径和比较定义）、机构及汇总范围、指标事实的只读入口/字段字典/批次规则与实际日期覆盖，以及已确认的总分关系。请单列四个定期期限指标原始单位、含/不含协定共用编码、缺数和口径冲突。再配一组业务原话与可以复核的标准条件/结果来源。先不要求全量客户流水，也不要为了凑齐资料补估算值；不清楚的请标待确认及责任人。

## 6. 补到哪里，以及怎样推进

| 资料 | 当前维护入口/方式 | 还需补的能力 |
| --- | --- | --- |
| 指标名称、单位、同义词、说明和口径 | 指标术语页面；正式目录同步 | 单位/来源审核、同步覆盖规则、版本责任；不能用“新增指标”替代取数数据 |
| 机构标准名与别名 | 机构别名页面；正式机构/身份同步 | 层级可见、历史汇总范围和授权权威；不直接手改层级扩大权限 |
| 原始事实与历史 | 既有查询库/受控数据服务 | 数据覆盖、批次可比和实际质量；现有数据集页保存并不完成接入 |
| 比例编码、频率、数量性质、正式关系 | 现有语义/主题配置及上游批准资料 | 管理和发布方式、关系发现与执行，保持与正式指标一致 |
| 本行业务方法、解释和案例 | 业务知识页面/既有知识系统 | 出处/适用范围和检索验证，不无限扩充提示词 |
| 客户、产品、渠道、流水 | 对应授权明细来源 | 新数据集映射、粒度、权限与受控计算，当前未全具备 |
| 核准问题及答案依据 | 受控验收样例和现有测试资产 | 版本对照、反馈复测；事实依据可更新，旧验证记录保留版本 |

推进顺序：

1. **查得准：** D01–D04、D09、D10 先完成首批指标；用单值、比较、缺数和追问核对。
2. **分析得清：** 批准 D05，补足结构/贡献的计算接线；先能对账，再做归因表达和图表。
3. **解释得深：** 根据实际业务目标补 D06–D08 和明细能力，不要求第一批就覆盖客户原因。

每次验收同时核对“资料已确认”和“程序已经消费并执行”。不因为数据已经交付就宣布问数能力完成，也不因模型给出流畅回答就认定数据正确。

# SSE 正文连续展示优化

**目标：** 减少正文因完整格式被过度缓存而成段出现，以及预览转正式回答时的页面跳动。

**范围：** 沿用现有 SSE、报告预览和 Vue 展示链路。当前真实利润会话的 584 次正文增量仅形成 6 个中途候选边界；加粗和括号触发整段等待是已复现原因。预览往返耗时和浏览器更新已通过临时采样测量，结果见下文。

## 约束

- 保留来源权限、归属、引用替换、单位及计算校验，最终报告独立校验。
- 不添加词语白名单、泛化语义审核、模拟打字或人为延迟。
- 保留执行过程的现有展开偏好、查询与回答内容、桌面布局。
- 测试桩仅限隔离自动化检查；联调使用现有真实数据、模型和正式链路。
- Git 操作遵循用户授权，仅纳入本次 SSE 改动；保留已有配置及其他无关改动。

## 任务 1：正文边界

- [x] 先证明已闭合加粗、括号和引号后的完整句子会被旧实现阻塞。
- [x] 用格式状态区分闭合与未闭合结构，删除遇到格式字符就停止句子交付的粗粒度限制。
- [x] 保留未闭合引用、代码、链接保护；表格、围栏及同级列表项沿用块边界。
- [x] 验证分片、转义、嵌套格式、正文改写、取消、重试、晚到预览和最终交付。
- [x] 重放真实会话，对比候选边界并确认最终文本一致。

## 任务 2：正文展示连续性

文件：`frontend-vue/src/components/chat/BackendNextChatPanel.vue`、`ChatResultContent.vue`、`ChatProvisionalAnswer.vue`、`frontend-vue/src/lib/answerStreamPresentation.ts` 及对应现有规格测试；以实际最小修改为准。

- [x] 检查预览与正式正文的组件切换及滚动时机，补最小行为回归。

- [x] 不在本轮引入全文 Markdown 增量解析器或无关长历史、图表重构。

## 任务 3：测量与验证

- [x] 以临时诊断脚本记录边界形成、预览完成、SSE 到达，避免增加常驻审核或监控系统。

- [x] 检查最终 diff，说明删除的限制、保留的保护、实测改善及未验证项。

## 校验精简决策

先量化当前预览成本。只有实测及调用链证明存在明显重复工作时，再在同一操作和模型尝试内精简已核验正文处理；来源或权限失效不能被缓存掩盖。不因来源 ID 相同就跳过实时权限与元数据检查。


## 实施与验证结果（2026-11-04）

- 删除遇到任意格式字符后整段等待的限制；新增纯格式句界扫描。闭合强调、括号、引号、行内代码和行内链接后的完整句子可及时进入原有预览核验。未闭合结构仍等待，表格、围栏、列表与复杂 HTML/引用式链接保留块边界。
- 预览、普通终态与正式报告复用同一个正文组件及 Markdown 节点；删除无调用方的旧预览组件。同次调用的重复正文保留原消息对象，不再请求无效滚动。没有更改默认展开偏好或加入人为延迟。
- 权限、来源、引用替换、单位、计算及最终报告校验均沿用原链路。第一轮 16 次预览往返为 68–137 毫秒，中位数 80.5 毫秒；这不是纯校验 CPU 时间。该样本没有证据表明移除校验能解决数十秒首段等待，因此本轮未削减这些保护。

### 同一真实历史会话重放

584 次正文增量重建的 1120 字符原文与存储正文严格一致。修改前后候选交付点由 6 个变为 16 个，最大单次新增原文由 361 字符降为 225 字符，等待结束才释放的尾部由 116 字符降为 0。最终文本一致。这些数值为预览核验前的候选边界和带引用原文长度，不能换算为真实 SSE 事件数、可见字数或耗时收益。

### 真实模型与桌面联调

使用现有业务数据和配置的模型，单独建立本地验证会话；未替换业务数据或注入成功结果。

- 第一轮“紫金最近的利润情况如何？”实际收到 16 次正文 SSE 更新，间隔 75–898 毫秒；SSE 处理到对应 DOM 更新为 10–23 毫秒。预览至正式回答保持同一 Markdown 节点，正文输出期间未采样到超过 50 毫秒的主线程任务。
- 同一会话长追问收到 17 次更新，间隔 189–2749 毫秒，同样保持正文节点身份，正文期间未采样到超过 50 毫秒的主线程任务。向上阅读后，内容高度由 1508 增至 3410 像素，滚动位置仍为 0，终态没有抢回底部。
- 第三轮在真实生成中点击停止，页面进入“已停止生成”；刷新恢复了既有回答与停止状态，输入框可继续输入，无残留停止按钮。
- 清理全部临时前后端采样代码后，构建产物与已验证的干净版本一致；只重启本地 Agent，健康接口返回 `{"status":"ok"}`，桌面页面恢复正常。验证截图和逐次计时保存在 git 忽略的 `.runtime/local/sse-cadence-20261104/`。

第一轮首段仍等待约 29.6 秒，总计约 37.4 秒，其中第二次模型调用首 token 等待约 22.1 秒。长追问还出现了原有跨指标计算拒绝与多轮尝试，属于本轮未调整的业务执行链路。独立模型调用存在输出和耗时波动，不能把本次与历史会话的总耗时差异归因于分段修改；这次不宣称首段响应、业务归因或全部卡顿已经解决。

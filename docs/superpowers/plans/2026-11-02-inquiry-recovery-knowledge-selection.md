# 有效纠错与知识关联指标选择

## 范围

先修正 inquiry 执行流程的无进展判定，再将已维护的知识关联接到取数前的正式指标选择。沿用现有查询、权限、目录引用与执行预算，不扩展归因计算，不修改并行工作的 SSE 或管理页面。

## 已核对的断点

- `inquiryStalled` 对非计算工具只比较工具和错误类别，没有比较执行条件。不同查询条件的失败可能被合并，随后关闭调查工具。计算已有独立输入标识，需保持兼容。
- 知识已在每轮首次模型调用前检索，但搜索结果和 Agent 接收类型没有保留 `metric_codes`，因而关联无法用于预先选择正式指标。
- 真实配置已有“经营质量”知识关联不良率与拨备覆盖率，可用于实测；不新增测试业务知识。

## 实施顺序

1. 建立当前无进展误判回归，比较真正影响执行的条件；忽略说明文案和集合顺序，保留空参数重复、权限和总预算停止。
2. 知识搜索保留关联编码，同次请求通过现有正式目录解析有限候选。复用签名绑定与引用恢复；让模型自行选择，缺少关联时沿用原目录搜索。
3. 验证预查询引用可用、恢复稳定、权限、无链接兼容与纠错边界。检查最终 diff 与类型、相关 lint 和测试。
4. 用独立本地服务、现有业务数据和真实模型对比知识选择与无关联查询，检查机构、指标、期间、事实及正文，记录检索数、模型轮数和耗时。重放真实回执补充验证失败恢复；不能将受控重放写成真实模型自然触发。

## 验收边界

隔离服务只隔离 Agent 会话，不伪造业务结果。真实测试若遭登录替换、服务不可用等干扰，单独记录，不纳入性能比较。不以单次耗时保证整体性能，也不以单元测试代替业务效果验收。

## 实际实现

- 纠错判断仍在现有 `inquiryStalled` 内完成。失败产生处通过可选 `correction_fields` 声明相关字段；运行时比较这些执行条件，忽略目的、标题、未知字段和集合顺序。引用错误按正式绑定比较，换别名、编造其他引用或只改日期不能算作修正。未增加重试次数或新的恢复框架。
- 查询与日期覆盖共用失败目录快照，保留部分引用纠正的身份。权限终态、原有调查和交付总预算不变；失败快照不作为成功事实。
- 知识搜索保留 `metric_codes`，同一次后端请求通过既有目录加载和签名逻辑提供 `linked_catalog`。每次最多返回 3 条知识、30 个关联正式候选；无关联时不读取指标目录，超出部分或不适用候选仍走现有检索。
- 自动前置资料与显式知识工具共用绑定逻辑；自动候选使用正式编码引用，恢复在途工具前重新绑定。模型选择所需子集，不自动把所有关联指标发往查询。
- 同步分析技能、工具描述和系统说明，取消旧技能中无条件先 `metric_search` 的约定。没有新增固定模型调用、问句正则或完整归因计算。

## 提交后独立评审与修正（2026-11-02）

按指标管理前端、后端关系与知识、Agent 恢复三个范围独立评审，发现并修正以下缺口：

- 引用错误原先统一按正式指标集合比较，丢失重复次数，逐项去除重复引用仍可能被误判。区分引用未解析和正式指标重复两个已有校验阶段；重复阶段保留身份次数，别名互换仍归一为同一指标。未知引用阶段继续忽略额外别名，防止编造进展。
- 新目标逐项补齐必填条件时，统一错误码掩盖了实际推进。目标校验回执通过已有 `validation_stage` 表达尚未满足的结构条件；已有主题、日期的改写不能改变同一格式错误。
- 已接纳目标重绑定失败时，模型填写的指标、机构、日期会被宿主覆盖，但此前仍参与无进展比较。此阶段改按实际选中的目标引用比较，省略和显式引用同一目标视为一致；切换正式目标仍可继续。
- 指标关系写入发布目录，在标准只读部署下保存返回 503，且升级可能覆盖维护结果。沿用现有配置外置方式增加 `ANALYSIS_SEMANTICS_PATH`，管理、目录发现、知识候选与分析复核共用此路径；首次迁移旧文件，后续保留。升级与旧版本回退边界已同步部署说明。

修复未增加重试次数、模型调用、问句匹配规则或新的恢复框架；权限、正式来源、配置版本签名与执行总预算保持原有保护。前端评审未发现需要修改的明确缺陷，本次未再改页面。

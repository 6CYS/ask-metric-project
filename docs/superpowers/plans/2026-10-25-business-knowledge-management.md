# 业务知识维护实施计划

**目标：** 管理员能维护业务知识，并通过现有主题知识工具向模型提供当前启用的资料。

**范围依据：** 已讨论并确认的轻量知识菜单；参考 MFWS 的维护、启停与知识消费方式，指标口径仍由指标目录负责。

**实现：** 沿用 Vue 管理列表、FastAPI 管理权限和现有 JSON 数据；不新增依赖、数据库表或检索平台。现有部署使用单个后端工作进程，文件写入在进程内串行化，并校验修订号、原子替换。部署配置保存在版本目录外。

## 交付与约束

- 菜单“业务知识”：搜索、新增、编辑、启停；复用 Ask Metric 的管理列表、表单、弹窗和样式。
- 表单只维护标题、正文和启停状态。适用范围与限制直接写入正文；既有来源、日期、使用边界等元信息兼容保留，编辑时不抹除。
- 当前知识量少，现有知识工具统一读取启用条目，由模型结合正文判断适用性；指标目录仍按业务主题读取。暂不增加分类维护或检索系统。
- 管理接口仅系统管理员可访问；运行接口沿用登录校验，仅返回启用条目。旧条目缺少 `enabled` 时视为启用。
- 文件修订冲突返回 409，页面保留编辑内容并提示重新读取，不静默覆盖别人的改动。
- 本轮知识读取保留；模型上下文中的旧知识回执标记过期，持久历史及页面记录不改写。知识不能代替正式口径、查询结果或因果证据。
- 保留工作区既有改动；不提交、不推送，不改无关问数、报告或图表逻辑。

## 接口约定

管理路径：`/api/v1/catalog/business-knowledge`。

- `GET`：`{items, revision}`。
- `POST`：新增，`PUT /{id}`：编辑；页面请求只含 `title/text/enabled/revision`。新增条目不默认归入贷款或存款。
- `PATCH /{id}/enabled`：`{enabled, revision}`，只改变启停状态。
- 写响应：`{item, revision}`。条目保留原有字段，并返回 `updated_at`（旧项可为空）。
- 标题 1–200 字，正文 1–8000 字。存储层继续校验既有元信息，兼容旧文件及已存在的资料。

## 重点检查

- 普通用户不能绕过菜单直接写管理接口。
- 启停不能覆盖正文，旧页面保存不能覆盖并发修改。
- 文件损坏或写入失败不返回成功，不破坏已有文件。
- 停用知识不再从运行接口返回，旧工具正文不作为当前知识继续注入。
- URL 与正文按不可信资料处理，页面不执行输入 HTML；知识内容不作为工具指令。

# 问数报告多图与随文展示实施计划

> 执行：按 executing-plans 与 test-driven-development 实施；当前用户已确认修复，直接执行，不提交或推送。

**目标：** 移除单图、仅最后一次选图及全部图表固定文末的限制，让完整分析按章节展示多张真实数据图。

**架构：** 复用既有取数、来源鉴权、图表可比性校验和 ECharts 组件。最终回答支持 `charts` 集合并兼容旧 `chart`；图表附加段落位置，来自后端已核验正文及证据映射，不让模型提交图值或重新查询。无位置的旧报告继续文末展示。

**技术：** 现有 TypeScript、Vue、markdown-it、Vitest，不新增依赖。

**依据：** 本聊天已确认的三项根因及修复方向；后续反馈要求改善固定横条样式并补充分组柱图。范围是现有报告链路，不扩展为新报告系统或专项 Skill。

## 约束与接口

- 保留当前工作区的其他改动，在原位置集成；不更改认证、查询、数据库、模型配置或业务数据。
- `buildReportChart` 返回所有合法候选；同图必须满足已有机构、指标、日期、单位、基期与来源规则。
- `inquiryCharts(messages)` 返回本轮所有去重的成功选图回执；最终 `charts` 显式给出时优先使用，旧 `chart` 为兼容入口。
- 每图可携带 `placement: { after_paragraph: number; section_index?: number }`。段落从最终正文按空行切分、非空段落从 1 计数；缺省 section 表示 summary，否则对应 sections 的零基下标。
- 自动图优先覆盖不同章节，默认最多 4 张；显式图集最多 12 项，资源有界。单值不凑图，纯文字要求继续有效。
- 前端利用既有 Markdown 解析器将插入点移到完整顶层块尾，避免截断表格、列表和代码块；失效位置回文末，不丢正文和其他有效图。
- 图表使用同批已鉴权事实；单张选图失败不拒绝合法正文及其他图。权限失败仍停止。

## 回归重点

- 多次选图保留不同图，重复选择去重，旧轮图不泄漏。
- 正文恢复后重新绑定最终证据，不沿用失效草稿图或位置。
- 一张图不合法时保留其他图及正文，数值仍与正式来源一致。
- Markdown 表格、空行列表、代码围栏不被插图拆断。
- 旧消息、流式最终切换及历史重放保持可读，正文不重复。

## 四、回归场景池

以下来自既有讨论，作为可选验收样例，不表示每题当前仍有缺陷，也不是需要新增的路由规则。每批只选择受影响类别及必要变体；预期数值和可用日期以当前正式来源核准。

| 类别 | 样例 | 核验重点 |
| --- | --- | --- |
| 精准查值 | 2026年8月27日紫金农商行的个人存款余额当日数是多少 | 条件准确，避免无必要的调查和正文重写；短路径复用统一底层能力 |
| 省略追问 | 我行活期存款情况 → 江南的呢 | 指标继承、机构替换、实际日期 |
| 追加对比 | 江阴近期的利润情况 → 对比紫金如何 | 两家对比对象保留，期间和单位可比 |
| 缺数与排名 | 2026年4月末各家农商行信贷客户数量前3名 | 缺数说明依据准确，不把其他日期冒充指定期，不伪造排名 |
| 期间与质量分析 | 紫金今年三季度的贷款质量如何 | 所需期间与实际覆盖明确，不能把单日缺数扩大为整季缺数 |
| 原因追问 | 贷款质量回答 → 是什么原因导致的 | 按已有证据继续调查，缺证据时说明边界，不反复空转 |
| 分机构结果 | 2026年8月各分行各项存款余额对比，请按机构列出 | 授权范围、机构类型、完整性和实际统计日 |
| 自然回答与配图 | 我行存款情况如何 → 帮我绘制饼图 | 分类互斥和分母正确，结果复用，数字不重复，内部资料不泄漏 |

另用隔离测试覆盖错引用、撤权、原始单位未知、负数、小额、无基期、服务超时及并发恢复；隔离结果不能冒充真实业务验收。

## 五、实施顺序与暂缓事项

建议顺序为 **T01 → T02 → T03—T07 按调用依赖分批收敛 → T08 汇总验收**。回归与性能记录从 T01 开始，每批改动都验证；已经确认的正确性缺陷优先于纯格式整理，不等待全仓规则清零后才处理。

每批交付说明：解决哪类根因、删除或合并了什么、保留哪些保护、实际验证范围和未解决事项。既有数据结构变化要有兼容与回退安排；不为回退长期保留两套业务主流程。提交和推送按用户明确授权范围执行。

以下内容暂不进入本轮开发：

- 新业务菜单、报告平台、多数据源等功能扩展。
- 为了架构“显得规范”而替换 Pi，或叠加另一套编排框架。
- 默认引入 Jieba、BM25、重排序或长期记忆库。出现已证实的检索或跨会话记忆需求后，先检查已有能力，明确替换位置，再评估收益、维护与运行成本。
- 任意扩大归因结论。指标口径与业务知识分别维护；子指标关系、可加总性、期限单位和数据覆盖仍需正式依据，代码重构不能补造缺失数据。

# Pi 语义任务反馈与引用契约

这是版本 2 的待实现工具反馈，定义业务工具回执的 `details`，不替代 Pi 原生 `AgentToolResult` 包装和证据正文。公开请求、内部规范化结果与工具反馈构成同一个闭环；实现时必须一起接入。反馈形状见 [feedback.schema.json](feedback.schema.json)，合成状态样例见 [feedback-examples.json](feedback-examples.json)。内部状态仍以 [任务状态与执行](state-and-execution.md) 为准。

## 固定反馈与下一步

反馈固定为 `protocol_version`、`status`、`state`、`issues`、`continuation`。`state` 只投影已保存的可信条件、待解释提案和任务完成状态，内部编译参数及许可不交模型重填。`conditions` 中没有待确认值；未决表达放在 `pending`，不能因为它能显示在页面上就当作已确认条件。

| 状态 | 含义及接续边界 |
| --- | --- |
| `invalid_input` | 原始参数形状不合法，保留原用户消息；尚未绑定任务时 `task_status=unbound`，不编造任务或条件已保存的回执 |
| `needs_interpretation` | 已保存提案，但当前证据仍有冲突或目标对账缺口；由同一 Pi 修订或查证，不能先执行已完整的半份目标 |
| `needs_user` | 只有用户能决定的实质选择；停止工具循环，只询问当前缺口，其他已确认条件保留 |
| `prepared` | 仅准备并保存条件，不消费取数或计算许可；准备动作结束不代表原查询目标完成 |
| `ready` | 当前执行组已校验且许可已持久化，宿主仍须消费时复核；模型不能用这一状态自行填写执行参数 |
| `executing`、`unknown` | 已在途或结果暂时不明；按原命令关联等待或回查，不换幂等键重发 |
| `succeeded` | 本步骤已有正式成功回执；任务可能仍为 `active/partial`，Pi 可继续分析而非立即收尾 |
| `reused` | 已通过当前权限复核并读取原成功快照，没有新的取数 |
| `unsupported`、`denied`、`conflict`、`failed` | 分别表示能力边界、权限拒绝、状态冲突及运行失败；保留目标和已有证据，禁止自动改目标来制造成功 |

`continuation` 指明当前由 Pi、用户、宿主或无人接续及其动作。它不建立第二条执行循环：Pi 动作仍在原生工具循环中，宿主动作仍走已有自动接续入口和许可门禁。需要用户时是 `user/ask_user`；许可就绪时是 `host/execute_permitted_step`；结果未知时是 `host/reconcile_execution`。已确定无进展或预算耗尽时可 `none/stop`，不能为生成停止文案再依赖一次模型成功响应。

任务证据齐备仍需完成答案交付：`succeeded/completed/full` 默认接续 `pi/answer`，缺少可直接使用的结果正文时先读取正式结果。只有正式答案已经持久化交付，才能以 `none/stop` 结束成功回合。宿主自动执行的回执正文可以携带同一正式执行的证据；状态 `full` 本身既不是答案正文，也不是已交付标记。

Schema 不证明状态转换合法。实际生成反馈前必须核验：存在 `task_ref` 才能引用保存的任务；所有 `target_ref` 属于该任务；`full` 或 `partial_accepted` 必须有对应完成依据；`ready` 必须对应已保存未失效许可；失败或澄清不能被投影成完整成功。形状错误不能回传“条件已保存”，除非确有可恢复的已绑定草稿。

## 内部规范化结果

每项语义操作的内部 `NormResult` 固定包含 `field`、`status`、原始提案引用、所用来源、影响对象及可解释问题；只有 `resolved` 可以带可信规范值。状态区分 `resolved`、`needs_interpretation`、`needs_confirmation`、`invalid_calendar`、`unsupported_expression`、`conflict`、`unavailable`。它不是另一套模型必填参数。

Pi 解释操作角色、目标绑定、时间与取数含义；宿主对目录实体、已保存来源、明确硬约束与能力兼容做确定性核验，并用同一业务日期和日历算法计算边界。不能直接将任意业务字符串作为 SQL、正式指标代码、计算表达式或已确认口径。目录缺口返回候选和缺口；含义冲突反馈给同一 Pi；确有多个影响结果的合法选择时才交用户决定。解析器暂不支持合法表达，不得报作用户提供了不存在的日期。

规范化以字段和目标为单位产生，任务原子保存其中的有效值与未决提案。执行许可则以当前执行组为单位判定，不能因部分字段 `resolved` 就执行。目标覆盖对账还必须包含原始消息和可信历史形成的义务，而非仅遍历模型提交的 targets。

## 引用签发与生命周期

`task_ref`、`target_ref` 是宿主签发的不透明定位引用，映射记录保存在同一原生 Session。它们不是授权令牌，也不嵌入模型需要维护的版本、代码、权限或许可信息。只有已实际保存的任务及目标才能取得引用；工具回执与 `business_context_read` 返回可用引用及自然语言描述，Pi 只能复制和选择。

admission 保存本轮的当前任务候选身份；首次业务绑定在事务中确定本 operation 的任务身份，新建任务也在该事务固定绑定并保留来源。随后按这个绑定区分当前续接与历史导入，不能按稍后变化的页面焦点或 `completed` 状态临时换分支。参数纠错不能改掉已绑定任务；用户新回合明确换目标时才重新建立绑定。

- `task_ref` 绑定 Session 内的任务身份；`target_ref` 绑定该任务中的目标身份、语义修订和条件快照。宿主登记并验证配对，不能只检查字符串格式。
- 继续当前任务时，引用须匹配当前目标修订；修订已变化则返回 `REFERENCE_REVISION_CONFLICT`，由 Pi 重新读上下文，不能静默套用旧快照或覆盖新值。`current` 同样需要唯一当前目标及最新状态。
- 历史任务条件作为不可变来源导入新任务；读取历史索引本身不改变焦点，不修改旧目标或重发旧查询。引用保存原始快照来源，但执行门禁还需核对来源操作的最新在途或未知状态，不能用旧 READY 绕过它。
- 引用不因模型压缩或进程重启自动失效；从 Session 映射恢复，不依赖进程内缓存。没有任意的分钟级有效期。会话按既有保留策略清理、记录损坏或来源被显式撤销后引用失效，返回 `REFERENCE_UNAVAILABLE`，不得回退到最近目标。
- 跨 Session、错误配对和未签发引用返回 `REFERENCE_INVALID`；当前权限变化返回 `PERMISSION_DENIED`。这些错误均不扩大范围、不改变焦点、不发起新取数。

新协议 `business_context_read` 的投影只包含版本 2 的任务、目标、条件、未决项及上述引用。旧 Frame、Delta 或 fixed 参数的读取与执行保留在旧 operation 的协议绑定内；历史导入只投影业务条件和来源，不能把旧工具 Schema 再交给新 Pi 选择。

## 对账反馈例

原句要求“查询合成指标甲和合成指标乙”，Pi 只提交甲时，宿主在原始义务对账中仍保留乙。反馈为 `needs_interpretation`，乙列为未决义务，`continuation=pi/revise_proposal`，未获部分执行授权前零取数。不得因为返回的甲目标字段全部有效，就将 `completion` 设为 `full`。

宿主不能形式证明任意自然语言的全部含义。确定性硬约束对账用于阻止可识别的漏项和越界；其余语义理解仍由 Pi 完成，质量以独立完整任务验收衡量。任务台账和 Schema 都不能自证已达到 95% 的正确率。

# 统一语义入口与经营分析衔接

基础问数、多轮状态和经营分析共用 `resolve_business_turn` 版本 2 入口。基础查询沿用 `target.query`，继承和修改使用 `source + operations`；经营分析使用 `intent=analyze` 与 `target.analysis`，不恢复旧版 `capabilityHint/baseReference/fieldChanges` 模型参数。

## 分析计划

```json
{
  "protocol_version": 2,
  "intent": "analyze",
  "targets": [{
    "source": {"kind": "new"},
    "operations": [{"action": "set", "field": "organizations", "value": "用户原文机构名"}],
    "analysis": {
      "kind": "business_overview",
      "plan": {
        "topic": "loan",
        "goal": "overview",
        "sections": ["scale", "growth", "structure", "quality"],
        "comparisons": ["mom", "yoy", "ytd"]
      }
    }
  }]
}
```

单一存款或贷款主题使用 `business_overview`。跨主题或没有专项配置的经营问题，先用 `analysis_catalog` 发现正式指标，再提交 `kind=business_analysis`，计划含 `objective/scope_notice/requirements/steps`，指标引用来自本轮正式目录回执。每个子问题关联执行步骤或具体缺口。

`business_topic_read` 同时加载本主题第一页正式分析目录，将编码、短引用与签名登记到和 `analysis_catalog` 相同的回合引用表；后续目录追加引用，不从头编号。原生回执保存引用映射供恢复。加载失败时保留专项主题能力并提示补查通用目录，不能猜短引用或把元数据加载失败当成无业务数据。

分析目标的 `operations` 只表达机构、日期、目标的变化；没有变化可省略空数组。不能混填 `query`，不能直接提交内部 `_analysis` 字段。后者仅为宿主编译计划时使用。
`analysis` 目标可带 `query: null` 表示未选择查询分支，公开Schema明确允许，校验通过后归一为空缺字段；非空查询条件、字符串 `"null"` 和只有空query的请求仍被拒绝，不从空值补造业务条件。

新问题用 `source.kind=new`；继续或补查用 `current` 或签发的 `reference`。分析未给日期时使用查询库实际覆盖中的最新记录，未给机构时采用已认证用户所属机构，并在结果中说明。基础查数的缺项处理保持原协议，不由分析默认策略代替。
原文已识别明确机构但模型省略对应范围变化时，服务端要求模型补正；不能只在 `scope_notice` 写机构名称后实际查询账号默认机构。
“我行／本行／我们行／我们银行”由认证账号的所属机构解析，并再次核对目录和权限；不进入普通模糊机构推荐。账号没有可用的所属机构时，明确询问具体机构，不能猜选某家银行或扩大到全省。
模型提供规范机构名时，分析适配复用语义入口的原文身份绑定。内部正式编码必须完整匹配本轮绑定的机构集合，随后再次执行目录和权限复核；不将规范名称或编码误判为“未出现在原文”，也不接受替换、缩小或重复的机构集合。
明确延续分析却误选 `source=new` 时，在创建新焦点之前要求模型修正为 `source=current`，保留原来源。完成的分析跨轮派生新计划版本，存款、贷款主题变化不会误用上一轮已完成步骤。

### 基础查询未匹配后的恢复

`semantic-task/queryRecovery.ts` 接管尚未执行的指标零命中，以及普通取值的相关正式指标多候选。先完成其他参数修正，再返回 `query_recovery`，由宿主引导 `analysis_catalog` 检索业务核心词，随后重提同一目标。可以修复原查询，或使用目录签发引用提交小范围 `business_analysis` 计划；不将单值问题扩成整套经营概览。仅准备条件的 `prepare` 沿用原流程，不能由恢复路径转为执行型分析。

模型提交了未能绑定用户原意的指标别名，导致 `FIELD_REQUIRED(metrics)` 时，同样按保留的原问题发现目录；用户没有提出指标、明确清空指标等场景仍沿用原缺项处理，不擅自补指标。“最近／近期／近来”等无界取数要求在基础日期通道被拒绝时，可与指标恢复一起转入分析；账本保存 `latest_snapshot` 策略，服务端查询真实覆盖后决定各指标的观测日期，模型不能猜日期。此时允许保留 `latest_in_range` 的最新记录意图；明确日期、有界期间、排名和比较总体仍不得降级或扩大范围。

失败正文由 `semantic-task/feedback.ts` 投影已核验范围、受控障碍与可继续操作，不再只显示“没能完成这次查询”。已有正式成功回执的公开结果可以保留；权限失效时优先阻断数据展示，内部连接信息和原始异常不进入正文。分析中途失败仍使用既有重新鉴权后的部分结果交付链。该调整只需重启 Agent，无数据库迁移或前端接口变更，不改变失败状态本身。

例如“上月末紫金各项存款信息”，目录返回余额、较年初增量、增幅及已发布排名等可独立查询的候选时，将完整清单放入 `metric_alternatives`，不按页面的四条展示上限截断。候选须有正式编码、为原指标相关名称或来自信息/情况等概览目标，单组上限十二项；基础身份选择、不同日历及明确只要一种口径仍保留原澄清。目录已签发全部引用后，程序在模型的小范围计划中补齐遗漏的 `observe` 读取和对应子问题；同一未执行单目标的普通重提也可编译为完整候选的并列分析，不反复依赖模型重填清单。原始模型调用保留在原生消息，生成的分析计划经过现有范围、目录、许可与权限校验；未发现的候选必须先取得引用，不猜编码或公式。缺数逐项说明，不混算口径。有效计划签发时旧指标单选题置为 `superseded`；模型自选不作为用户确认入账，真实用户点击仍走原确认流程，机构和范围问题照常保留。

恢复预算和首次范围保存在原生回合账本，每轮最多两次恢复；单次发现阶段最多两次目录调用，成功检索后立即重新规划。重提、重新创建 store 或重启不能重置预算。正常精确查询不增加目录发现或模型调用。比较基期没有依据时，分别标注正式比较指标或只询问缺少的基期，不能把“净增”自动等同于环比或较年初。
目录已声明多个正式差额基期时，恢复计划不能只选一个代表未指定基期的“净增”，需并列读取并标注。只使用已有比较关系，不按名称推导公式。“上月末／上月底”由确定性自然日算法解析为上个月最后一天，原文事实抽取和分析入口同步保留单日语义。

升级分析时，从可信账本补齐原机构和日期，复用已经核验的精确日历，并在签发执行许可前再次核对范围；不能改用最近有数日来掩盖指定日期无数据。排名操作、比较总体、区间取数方式不允许丢弃后改成普通观察，需修复原 query；读取目录里已发布的排名指标只是普通取值，不等于重算排名。实质身份歧义、权限拒绝、服务错误和已执行的无记录结果保持原有出口；“未匹配指标”不等同于“数据库没有数据”。

该变更需配套更新 Agent 与后端代码，无数据库迁移、领域 JSON 或新模型配置。原生账本新增字段为可选，旧会话仍可读取；回退代码后基础查询和已存结果继续按原流程使用。

## 执行与交付

1. `structuredQuery.ts` 将已校验分析声明编译成内部操作。
2. `planService.ts` 维护完整目标及来源，为语义子任务传递本轮目录引用。
3. `enhancedAnalysis.ts` 复用既有主题、计划、机构、日期校验，生成 Frame，并签发绑定用户、任务版本和条件摘要的执行许可。
4. `execute_business_frame` 消费许可，沿用 `businessOverview.ts` 或 `analysis/tools.ts` 调用后端受治理取数、计算服务。
5. 原生工具回执保存不可变证据；`answerEvidence.ts` 识别语义反馈中嵌套的分析证据。专项/通用报告分别交给 `business_report_present` / `analysis_report_present`，前端继续呈现数据表格与文字报告。

报告工具仅在本轮取得对应成功证据后开放。目录说明不能替代数值证据；模型不能编造指标、公式或业务原因。模型后续失败、重复纠错或调用预算耗尽时，重新鉴权并呈现已有的部分结果，明确未完成分析。独立问候不续跑旧业务。

专项报告正文校验失败时，保留一次模型原地修正机会；仍失败则按自然段保留带有效原子依据的正文，并再次校验合并结果，不能因一个未经核验的计算值而丢弃整篇自然正文。没有可保留正文时，程序直接引用已核验回执中的指标名称、实际日期、现值和比较值生成可见事实，不计算新数字、不补造因果；真实零值与缺失值分开处理，完整表格照常保留。日期与解释限制落在正文末尾，不能只放入默认隐藏的元信息。机构权限、任务归属、不同快照和未知指标等硬错误不得进入文字降级。

与唯一回执展示精确一致的直接数值可以补齐原子引用，正值前的展示正号不构成新的业务数值；反向负号、近似计算、歧义数值仍拒绝。自动关联的引用和模型主动引用一样保存到分段依据。该修复只涉及 Agent，需重启 Agent 生效，无数据库迁移或前端接口变更，已保存的历史报告不会自动重写。

配置错误（如机构层级缺失）归类为服务端故障并停止参数重试，页面提示核对目录同步；不把409一律交给模型改参。集合查询依赖正式机构快照，升级前用`sync-org-catalog --dry-run`核对层级、范围差异及新增编码；目录中有过期或范围外编码时先核实账户绑定和正式来源，保留备份后处理，不能用名称猜层级。

同轮补查的模型Schema限定一次一个目标，并显式要求`inquiry`；通用分析的多主题放在一个计划的子问题和步骤中，服务端拒绝多个通用计划的重复提交。初次查数和跨轮新问题不受补查必填限制。输出被截断的调用不会执行，宿主只允许一次紧凑重发，仍不完整则明确未完成或重新授权交付已有部分事实。流停顿交由既有有界模型重试策略处理，只重试该次未完成生成，不重放此前已执行的工具；权限、额度等不可重试错误仍直接停止。

计划校验列出未覆盖的子问题id、错误答案引用和依赖位置，让模型修正对应位置。相同诊断重复才判无进展；受控计划/Schema诊断发生变化时允许继续，仍受本轮总工具预算限制，不通过删除用户子问题或放松事实约束换取成功。

### 发现驱动的补查与自然正文

首批计划覆盖用户明确提出的目标；`planning_review`、`coverage_review` 和专项的 `followup_candidates` 只是探索建议，不是必须全部查询的清单。用户子问题的事实覆盖由后端报告校验保留，不因取消探索方向门禁而省略用户目标。

泛称“经营”不是正式指标名，目录发现将该泛称展开为利润、不良入口；与模型选择的存贷款等词合并，仍限制为一批四个词，明确指标名称保持原样。这个扩展帮助发现收益与质量，不规定最终报告栏目。`analysis_brief.signals` 根据同机构、同日、同基期真实比较提示分化；分类只有现值时提供待核验疑问及正式 `check_metrics` 入口，不从当前构成推断增长贡献。

未配置专项主题时，可以使用目录的 `base_name/value_basis` 或正式全名精确结尾“较上月/较同期/较年初”提示已取比较量的正负分化；不解析编码，不把增幅、排名当成差额，也不由名称推导公式、会计口径或组成关系。宏观/变化问题仅取得某指标时点值时，若目录已有尚未尝试的同口径比较，可提示“比较方向是否一致”的待核验问题；明确单值取数、已尝试的正式比较或已完成的compare不会因此重复补查。以上是证据线索，不是必须填满的栏目。

同轮已有事实后再次提交分析计划，增加 `plan.inquiry`（通用与专项共用）：

```json
{
  "question": "总量增加是否与部分业务减少并存？",
  "prior_judgment": "总量变化可能不能代表全部类别，尚需核对分类。",
  "basis_refs": ["e1.v2"],
  "expected_change": "查询同期间分类变化，支持或限定总量判断；没有可比数据就保留未解释部分。"
}
```

上述引用仅示意，必须换成此前本轮取得或显式回读并重新鉴权的真实事实、计算原子；专项使用如 `personal.mom.difference` 的原子名。语义受理在执行前校验来源，目录、缺口、未来、未读取的历史或整份回执不充当触发事实。计划只读新增所需证据，仍使用既有轮数预算。取数回执的 `inquiry_review` 列出新增原子和是否新增事实；它不判定业务原因。模型用新证据支持、修正或限定原判断，不能把“查到数据”当作“解释成立”。

回执的 `execution_turn_id` 记录根用户回合，区分同轮补查与历史回读。新追问第一次取数不因回读历史而强制填写补查说明。报告需要结合回读背景时，由Agent把已读取的旧运行标记为 `context_run_refs`；后端逐项重新鉴权，要求保留本轮运行且机构、会话与日期目标一致，不能把全部运行标为历史或引用未选运行。背景只供成文引用，不放宽计算的scope约束；报告覆盖检查针对本轮目标，避免追问被上一轮完整经营目标绑住。

新报告工具只向模型暴露必填 `body`，提交完整自然正文，允许段落、要点和Markdown标题；不要求每个主题单独成章。避免把新旧两套可选入参同时暴露而让模型漏填正文。内部渲染仍兼容历史 `summary + sections`，存档仍保留 `report.summary/sections`，旧客户端和历史报告可阅读；旧格式草案不能再作为新模型工具参数提交。原始多目标可以在正文引用各自事实完成回应；遗漏目标仍被拒绝。业务数字、日期、计算、引用、方向与因果边界沿用原校验。

对明显整表复述（正文引用至少八个事实/计算原子，且占所选可用原子四分之三以上）最多返回一次 `report_editorial_review` 成文提醒，让模型挑选关键发现后改写；不决定业务结论、不规定栏目、不删除事实，也不占用事实纠错次数。明确要求明细等问题不触发，历史报告与普通查询不触发。改写后仍执行原事实校验；这是有边界的启发式提醒，不保证任何问题都能得到深入归因，最坏增加一次模型调用。
金额引用即使数值正确也不能称为增幅或增速；通用和专项报告都检查这类单位语义。该规则与现有正负、日期和引用检查并列，仍不是对全部自然语言含义的形式证明。

数值展示与证据关联分开：`{{ref}}`显示完整数值，`{{ref|cite}}`只关联真实依据，不在正文插入数值。两者使用相同来源、归属与引用有效性检查；`report.body_evidence`保存段落与原子的关联，目标覆盖统计包含两类引用，完整数据仍在表格中。这样不用为证明某子问题已回应而强制正文复述其全部数字。依据引用不能放行未知数值、日期或无依据因果；自然语言语义校验仍有边界。

自由正文按空行分段校验，一次反馈各段错误，减少逐项纠错。达到已有的有限纠错次数后，仅保留整段通过原事实校验的正文，并明确标记部分完成；不删词拼接改变原意，也不将被舍弃段落的引用计算为已完成目标。无有效文字时保留事实与数据缺口，不能伪装为完整分析。

新报告保持展示契约版本 1，增加可选 `presentation.body_mode=narrative`，正文之后展示可展开的完整表格；不强加摘要标题，也不再按运行编号散列轮换布局。来源、默认范围、缺口与权限仍保留。旧报告未带该字段时沿用旧展示，普通基础查数不受此模式影响。升级需配套重启后端和 Agent，并更新前端；不涉及数据库迁移。

缺少正式指标引用或需要由专项转为通用计划时，纠错保留目录工具选择自由；不能强制重复调用 `resolve_business_turn`，否则模型无法获得修正计划所需的依据。

已取得分析证据但模型直接结束文字回答时，宿主通过既有动作纠错回执提醒模型调用报告工具，最多两次；仍未完成才交付已核验的部分结果。参数形状错误提供字段路径和规则，不回显原参数或放松 Schema。

分析执行回执增加 `followup_source`，仅在当前执行编号唯一对应本用户已签发的步骤时返回完整 `reference` 配对。补查复制该来源，多目标不猜 `current`；同一范围的新增取数合在一份分析计划中。从同一来源派生不同目标时分配独立执行编号，避免许可和任务互相覆盖。已全部成功的分析计划重复提交返回完成状态，不再要求执行；普通查数的来源、许可和幂等规则不变。回执字段不替代执行前的归属、版本与权限检查。

## 先核验判断，再组织正文

专项概览与通用分析的取数回执均可携带 `verified_findings`（`verified-findings-v1`）。后端从已授权事实与计算回执生成判断：正式比较方向、不同基期的方向分化，以及明确同组分项、同机构同日同基期且百分数编码已知时的增幅差。固定差值使用原始 Decimal 计算，保留操作类型、缩放规则、输入原子与未舍入值；不从展示值反算。该步骤无额外模型调用或业务查询，最多向模型提供八项判断。

判断也登记为有输入依据的证据原子。通用模型视图用 `e1.j1` 等短引用，原有 `e1.v1` 的编号规则不变；专项沿用原引用。模型先选择有助回答的问题判断，再按需补查和自由成文，可直接插入判断或引用其依据。两条报告链均将判断展开到原始原子，保留段落证据；通用多目标覆盖也使用展开后的依据，不能引用一个主题的判断冒充回答了其他主题。补查允许由有完整依据的判断触发，普通探索提示和缺口仍不能冒充事实。

这是程序能核验的判断集合，不是全部自然语言的形式证明，也不强制报告复述集合。没有专项领域映射时，仍可依据正式目录比较口径或已核验的跨日期计算形成方向判断；没有足够条件的比率、结构贡献、趋势、因果和业务评价不生成。新增计算类型需以受控操作及测试扩展，不能由模型提交任意公式绕过原计算服务。未形成判断时继续交付可核验事实；正文修正耗尽时优先保留已有判断和事实，不只展示失败提示。后续规划、工具预算或模型响应失败时，内部 `analysis_partial_present` 同样重新授权并交付已有判断与可见事实，使用正常报告展示契约；真实未完成状态与内部原因保留在回执，正文末尾说明后续补查的限制，不能只留下提示和折叠表。

回执与报告接口只增加可选字段，历史数据继续可读，普通精确查询不改变，无数据库迁移。更新后重启后端与 Agent；来源、权限、数字、日期及因果校验继续执行。判断计算跟随原回执授权和存储，不能从其他机构、日期或运行中借用。

## 模型接口兼容与升级

`AGENT_MODEL_TOOL_CHOICE_POLICY=native|auto` 默认 `native`，保留宿主对模型生成策略的选择。若网关在 `required` 或指定函数模式下返回接口错误，可显式使用 `auto`。该选项只改变模型请求的 `tool_choice`；工具清单、严格参数校验、执行许可、权限和证据守卫均保留。修改后重启 Agent，配置可直接改回 `native`。

模型地址属于 `siliconflow.cn` / `siliconflow.com` 时，显式使用其[接口文档](https://docs.siliconflow.cn/cn/api-reference/chat-completions/chat-completions)的 `max_tokens` 输出限制字段；其他网关沿用SDK兼容选择。输出上限仍来自既有模型配置，不修改模型、思考开关或证据校验。诊断只记录限制字段和数值，不能记录凭据；本地HTTP桩覆盖两种字段的实际发送行为。

新版后端要求显式配置六项机构目录治理参数，参见 `backend-next/.env.example` 中的 `SIT_ORG_*`。升级现有环境应核对旧环境实际口径后补齐，不能自动扩大机构范围或以默认值掩盖缺失。

新会话使用 `semantic_v2`；旧 `fixed_v1/frame_v1` 会话保留历史只读。用户要继续提问时新建会话，不能把旧 Frame 引用直接作为新版任务引用。无需改写旧会话或业务事实数据。

# Pi 语义业务提案协议

当前版本 2 的运行时输入契约。工具名保留 `resolve_business_turn`，请求版本为 `protocol_version: 2`。Pi 结合上下文判断业务意图和目标范围，宿主绑定原文、目录与可信状态，再编译受治理的执行输入。Pi 继续管理唯一的模型与工具循环；没有前置意图 Agent 或第二套消息历史。具体实现、兼容限制与验证边界见[通用多轮上下文实现](implementation-multiturn-context.md)。

机器可读形状见 [请求 Schema](request.schema.json)，合成示例及设计断言见 [请求示例](request-examples.json)。请求后的状态、规范化结果、接续和引用生命周期统一遵循 [反馈与引用契约](feedback.md)，机器形状见 [反馈 Schema](feedback.schema.json)。内部任务、步骤和执行许可见 [状态与执行设计](state-and-execution.md)，版本隔离见 [迁移与回退设计](migration.md)。

## 请求字段

| 字段 | 含义 |
| --- | --- |
| `protocol_version` | 固定为 `2`，只标识公开输入协议；不替代任务、步骤或存储版本。 |
| `intent` | `query`、`analyze`、`availability`、`calculate`、`reuse`、`prepare` 中的一项真实业务意图。 |
| `targets` | 各自绑定机构、时间、指标和操作的目标组；每组统一为 `source` 与 `operations`。 |
| `context_action` | 可选，`resume`、`defer` 或 `abandon`；由 Pi 明确处理此前保存的目标澄清。缺省不恢复原修改。 |

模型不填写完整内部 TaskRecord、执行步骤图或全字段业务 Frame。目标组的数组位置不承担跨轮身份。身份、版本、原文跨度、数量依据、正式编码、证据绑定、依赖和执行许可由宿主生成；不提供 `mentionIndexes`、`source_text`、`expected_count`、模型自造编码或版本的入口。

## 来源只有三种形状

```json
{"kind": "new"}
{"kind": "current"}
{"kind": "reference", "task_ref": "宿主签发值", "target_ref": "宿主签发值"}
```

`new` 创建本次明确提出的新目标，不继承当前焦点条件。同一请求中的多个新目标组成一次需要整体核验的任务提案，仍分别保留其机构、时间和指标绑定。

`current` 只在当前目标唯一、状态可续接且用户语义确实续接该目标时成立。当前任务包含多个目标时，不能用它任选最近一项或覆盖全部目标。Pi 应读取 `business_context_read`，结合用户语义选择具体引用；原句仍不能唯一定位时请用户澄清。

每轮 `admitted_context` 是宿主在入场时冻结的任务、条件和 Frame 来源；同轮工具调用或其它回合移动焦点，不改变这份基线。宿主不按“追加、换话题、清空”等词改写 Pi 的 `source` 或动作，也不为 `new` 自动补入旧机构、日期。新增指标需要沿用原范围时，Pi 使用 `current/reference` 并提交 `metrics:set`；只改日期或机构时省略未变化指标，保留其正式身份和口径。

`reference` 只接受宿主通过上下文工具或回执签发的引用。Pi 可以复制并选择引用，不能拼接、猜测、改写引用，也不能将“上一笔”等自然语言填进引用槽位。引用是定位值，**不是授权 token**。宿主在同一原生 Session 内保存引用与任务、目标、签发时来源及协议的关联，每次使用仍检查同会话归属、目标属于所引任务、来源可读取性、最新状态和当前权限。

引用随原生 Session 和留存来源保存，不因进程重启或模型上下文压缩而失效，没有任意的分钟级有效期。继续当前目标时，引用须匹配最新修订；不匹配返回 `REFERENCE_REVISION_CONFLICT`，由 Pi 重新读取，不能静默套用旧快照。来源不可用返回 `REFERENCE_UNAVAILABLE`；跨 Session、错误配对和未签发引用返回 `REFERENCE_INVALID`；当前权限变化返回 `PERMISSION_DENIED`。签发、留存、失效和错误含义以 [反馈与引用契约](feedback.md#引用签发与生命周期) 为准。

历史目标作为不可变来源导入派生计划，不能借引用改写旧计划、Frame 或复用旧执行许可。跨用户回合的 `query/prepare` 均派生新计划，待补状态也保留旧计划及原未决条件。新的 `query` 可从原条件派生新 Frame 和新证据；`reuse` 只重显原结果。引用不会冻结旧 READY 状态：源操作已在途或结果未知时，执行门禁必须按最新状态返回受阻或回查原命令，不能回退到当前焦点或最近一笔业务。

显式历史指代的语言理解仍由同一 Pi 完成：读取有描述的历史索引，选择宿主引用，再调用本工具。宿主不另起一个 Agent 来解释历史原句。目标引用只定位来源，不授权改变其业务条件或跳过权限复核。

## 目标澄清与接续

Pi 能结合上下文明确目标时，直接调用 `resolve_business_turn`，可以只选一个目标或选多个目标。只有仍存在会影响答案的多个合理解释时，才调用 `clarify_business_turn`：

```json
{
  "question": "这次日期修改对应哪一项查询？",
  "alternatives": [
    {"task_ref": "宿主签发任务甲", "target_ref": "宿主签发目标甲", "label": "目标甲的已确认条件"},
    {"task_ref": "宿主签发任务乙", "target_ref": "宿主签发目标乙", "label": "目标乙的已确认条件"}
  ]
}
```

备选至少两项，必须是同一 Session 内真实、互不重复的任务与目标配对。该工具只保存原待明确输入、追问与备选，不取数、不修改 Frame；下一轮投影在 `admitted_context.pending_clarification` 中。

`resolve_business_turn.context_action` 由 Pi 根据用户回复明确选择：

| 值 | 待澄清输入的处理 |
| --- | --- |
| `resume` | 选择已保存备选之一的 `reference`，将原待明确修改和本轮补答一起解释、校验。不能用于 `reuse`。 |
| `defer` | 暂缓原修改，本轮可查看结果或处理其它目标，保留待澄清输入。 |
| `abandon` | 放弃原待明确修改，本轮按当前提案处理。 |
| 缺省 | 不自动恢复原修改；引用同一目标也不等于恢复。 |

需要再次澄清时，`clarify_business_turn` 可选 `context_action: resume/abandon`，分别表示接续此前待明确输入再追问，或以当前输入建立新的追问。独立 `new` 目标仅使用本轮条件；同一提案中的新目标也不因其它目标恢复澄清而继承原修改。

旧 Schema 仅供已绑定旧协议的 operation 执行或恢复；同一 operation 不因进程升级临时换用新协议。新的 Pi 请求只接收版本 2 工具定义和对应的历史数据投影，不同时展示旧 Delta、旧字段参数或恢复用联合 Schema。旧历史来源和结果可由宿主受控读取，但不能直接重标为新协议已许可状态。原生历史原件保留，发送投影不另建记忆系统。

## 初始查询与修改统一使用动作

| 动作 | 唯一形状 | 业务含义 |
| --- | --- | --- |
| `set` | `action`、`field`、`value` | 完整替换该槽位；未提供的其它槽位按可信来源继承或保持缺项。 |
| `add` | `action`、`field`、`value` | 向已选集合追加指定成员，保留已确认成员及其正式身份。 |
| `replace` | `action`、`field`、`subject`、`value` | 在已选目标内把指定成员或条件替换为新表达，保留其它成员。 |
| `exclude` | `action`、`field`、`subject` | 从已选集合中明确排除指定对象。 |
| `clear` | `action`、`field` | 清除整个槽位，使其恢复缺项；不表示全范围或无条件执行。 |
| `confirm` | `action`、`field`、`value` | 提议将本轮明确选择或同意作用于已保存的待确认对象。 |

`value` 和 `subject` 一律为业务表达字符串，不另设单值、数组、代码等同操作写法。例如两个机构写为“合成机构甲和合成机构乙”，由宿主绑定实体集合和原文数量依据。允许不改变业务意义的概括，不再要求模型抄写一段必须逐字相等的证明；概括本身也不成为事实或用户授权。

`set` 必须完整替换槽位，不得在字符串中藏入“保留原有并追加”的操作。用户追加合成机构丙时，使用 `add.value: "合成机构丙"`；宿主从可信来源保留已有集合，再绑定新增成员。用户只更换一项或排除一项时，使用 `replace` 或 `exclude`，不能用只剩部分成员的 `set` 伪装完整集合。`add` 只适用于能力支持的集合槽位，不适用于日期、操作等单值槽位；重复成员按正式身份去重，不能据此删除未决或已确认的其它成员。

`replace` 的 `subject` 和 `exclude` 的 `subject` 必须在选定目标中唯一定位；Pi 负责理解替换方向和否定语义，宿主核验真实成员及变更前后身份。目录里存在某对象不能证明用户要求操作它。冲突、同名歧义或没有对应成员时，保留原状态和本轮提案，向同一 Pi 返回可修复问题；不能确定时交用户澄清。

`confirm` 不接受候选索引或模型提供的候选事实。宿主只读取此前保存的候选，核验本轮用户回复或可信点选、候选归属、确认作用域和唯一性；完整原文中的否定与转折仍生效。口头同意不能补造不存在的候选，同轮刚产生的候选不能由模型自我确认。

没有候选或字段已经确认时，`confirm` 返回 `CONFIRMATION_NOT_AVAILABLE`，由 Pi 修正参数，不要求用户重新选择已确定条件。

同一目标的多个操作作为一个业务变更整体核验。不得按数组顺序逐个落地并在中间状态取数；同字段相互覆盖、冲突或无法唯一确定合成结果时，返回明确问题，不采用“最后一个生效”。操作可传递为一组语义提议，但不授权跳过现有字段、能力或权限边界。

## 业务槽位

| `field` | 业务表达 |
| --- | --- |
| `organizations` | 查询对象或机构范围，包括本轮新增与可信继承的组合表达。 |
| `comparison_organizations` | 用户指定的比较机构或范围。 |
| `metrics` | 用户请求的指标或分析过程中有来源的指标选择。 |
| `time` | 原问题的日期、区间、离散日期或相对时间语义。 |
| `selection` | 指定日、区间最新、逐期展示等取数方式表达。 |
| `operation` | 普通取值、排名、比较等操作表达，保留用户明确方向和数量。 |
| `objective` | 用户希望解释、分析或得到的答案目标。 |
| `calculation` | 计算关系及业务对象，事实绑定与精度由宿主生成。 |
| `availability` | 要检查的可用性维度及范围。 |

这些是公开语义槽位，不宣称所有表达或动作组合已经有可执行能力。宿主必须检查意图、槽位、动作和已注册能力的兼容性。无法实现的时间频率、分析操作或计算应保留目标并明确受阻，不能改成已有普通取值能力后宣称完成。模型表达了数字也不意味着获得数量约束豁免；宿主须把真实数量、方向和范围约束绑定到内部契约，不能因为公开输入没有 `expected_count` 而丢掉它们。

## 业务字符串到规范化结果的闭环

业务字符串承载业务对象及含义，不承担隐藏的动作或来源选择。Pi 必须明确提出槽位、集合操作、实体角色、时间含义和用户已表达的取数要求；例如追加用 `add`，替换用 `replace`。Pi 不生成正式目录编码、日期区间算法、证据 ID 或执行参数。用户未说清的日均或时点、年度末或逐日等口径保持未决，不能由模型或宿主默补。

宿主将提案、完整本轮原文、所选目标状态和授权目录送入有确定职责的规范化链。下表以 `NormResult` 概括其职责；当前实现由规范字段、元数据、问题及 `SemanticTransition` 共同保存，不另设同名模型或公开 DSL。规范化链负责目录名称与别名绑定、候选生成、统一日历和时区计算、已有正式身份继承、动作与能力兼容性、来源及权限核验；它不在大段原文上用新增正则猜整笔业务意图，也不另起自然语言规划 Agent。

| 规范化职责的概念名 | 必须表达的结果 |
| --- | --- |
| `field` | 被规范化的业务槽位。 |
| `status` | 当前规范化状态；枚举及含义以 [反馈契约的内部规范化结果](feedback.md#内部规范化结果) 为准。 |
| `proposal_ref` | 宿主保存的原始语义提案引用，不能由模型概括替代原始提案或用户消息。 |
| `source` | 原生用户消息、可信继承、候选选择、目录证据或分析选择来源；同时记录统一业务日期、时区、日历及适用口径等计算基准。 |
| `impact` | 对应目标、动作、被操作成员、新成员及集合影响，不依赖输入数组位置作跨轮身份。 |
| `issues` | 缺项、候选歧义、含义冲突、能力不支持或服务暂不可用等可解释问题，并区分是否需要用户选择。 |

上述信息须可追溯；只有已解析字段可以作为可信规范值参与执行，其中包括已确定的目录正式身份、日期或区间、取数频率及操作。其它状态不得携带看似已确定的执行值，原始业务表达留在提案和未决项中。目标的部分字段已确定也不等于当前执行组已经完整。

只有含义、身份、来源、目标绑定和能力约束全部成立，宿主才从 `NormResult` 编译步骤及签发许可。`NormResult` 是内部可审计结果，不作为新的完整 DSL 交给模型填写。回到 Pi 的反馈只投影理解和决策所需的保存状态、候选、未决项、冲突、有效引用及允许的下一步。

规范化不能唯一确定时，闭环为：**同一 Pi 提议 → 宿主返回 NormResult 的已定与未决部分 → Pi 根据当前证据查目录或修正语义提案 → 仍缺用户选择时按保存状态澄清 → 用户补答进入同一 Session → 宿主重新规范化并只编译满足条件的步骤**。程序可计算统一日期基准，但不能替用户选择滚动五年还是五个完整年度；目录可给候选，但不能替用户选择尚未确认的统计口径。

候选、保存状态、问题与允许下一步统一投影为 [反馈与引用契约](feedback.md) 中的 `protocol_version / status / state / issues / continuation`。本节不引入第二个理解循环，也不以 Schema 校验通过代替 `NormResult` 成立。

## 意图与执行边界

| `intent` | 预期处理 |
| --- | --- |
| `query` | 在目标明确且目录、权限、取数与覆盖契约满足后，编译并执行取数步骤。 |
| `analyze` | 保存分析目标，由同一 Pi 循环选择工具、查证、选择指标并根据结果调整下一步；缺少指标证据不能直接执行取数。 |
| `availability` | 检查指定范围的可查询日期、指标或其它已支持维度。 |
| `calculate` | 从明确的可信结果来源绑定事实和用户常量，核验单位、日期、口径及运算后执行。 |
| `reuse` | 仅重显已成功结果并复核当前权限，`operations` 必须为空，不重新取数。 |
| `prepare` | 仅整理、目录落地与保存条件，不消费取数或计算执行许可。 |

`operations: []` 表示不修改已选目标。它适用于重显结果或沿用完整条件重新查询；新建空目标只能得到缺项状态，不能直接执行。Schema 不因缺少尚待用户补充的业务条件而拒绝整个请求，业务完整性由宿主判断。`prepare` 中的目录核验不是业务取数；目录服务不可用时，保存条件与未决项，不冒充已确认或可执行。

普通、明确、完整的指标请求保留直达路径：Pi 可以直接提出 `query`，宿主按精确目录身份落地并校验；不强制 Pi 先调用目录搜索、分析 Skill 或规划工具。必要的正式目录、权限与覆盖检查不能省略。

只有用户要求分析、解释、选取合适指标，或已有分析任务允许当前证据探索时，Pi 才可为分析自主选择指标。宿主将该来源记录为 `analysis_selected`，并关联原任务目标及目录证据。直接查询中用户明确的指标记录为 `user_explicit`；不能因为设置了 `intent: analyze` 就获得改写既有明确目标或任意扩大范围的授权。来源标签、目录证据和依赖引用均是宿主内部状态，不交模型填。

## 提及与正向目标分开

“把合成指标甲换成合成指标乙”包含两个实体提及。甲是被替换对象，乙是正向查询目标。相反，“查询合成指标甲和合成指标乙”具有两个正向目标。覆盖复核应针对经核验的目标义务和操作角色；不能把所有目录提及直接当成必须查询的指标。

初始 `new` 查询保留原始目录覆盖、日历及目标绑定校验。跨轮修改由宿主从冻结来源和实际字段规范化结果生成内部 `transition`：以旧完整范围为 `before`，保存逐字段动作及规范身份变化，目标执行 `spec` 为 `after`。后端验证旧回执对应 `before`，核对动作链和完整 `after`，复核本轮目录、日历及权限后签发新票；不把替换、排除的旧对象再要求为新的正向查询项。不得把模型未选择的所有实体自动排除，也不得只因为 `exclude` 形状合法就签发可信排除。

`transition` 与只解释历史来源的 `context_sources` 均由宿主生成，不加入 Pi 工具参数。`context_sources` 不能携带动作，也不能获得执行票或使旧查询再次执行。状态变更校验只能证明执行符合已声明动作，不能代替 Pi 对自然语言的正确理解。

多目标以每个 `targets` 元素为绑定边界。机构甲的2024年指标甲，与机构乙的2025年指标乙不能合并为跨机构、跨年份、跨指标组合；同一任务只完成一个目标时，仍须保留剩余义务。对于“分别”“同一期间”“上述机构”等表达，分组与绑定仍由 Pi 理解并由宿主落地核验，Schema 本身不证明绑定正确。

## 连续补充与错误恢复

缺项、未匹配或用户尚未作出的选择属于业务未决状态。泛指标空匹配时保存原表达及其它已知条件，不生成不存在的索引，也不通过默认指标继续执行。上一目标指标为 `missing` 或 `not_found` 时，仍未匹配的补答应保持正常澄清；存在已确认正式身份或真实候选时，未匹配的新表达不能静默覆盖它们。

已确认正式指标身份随目标状态继承。仅补日期、机构或取数频率时，不重新按同名文本检索并替换已确认代码。用户明确更换目标时，旧身份只作为替换来源保留，不自动成为新目标的答案。

模型无本轮或可信来源依据的指标重述，包括目录里存在的其它指标，也不能变成新查询条件。此类错误返回 `needs_interpretation` 供 Pi 修正，不能静默删除动作后宣称成功，也不能把模型造成的歧义转交用户。Pi 在同轮省略该无依据错误字段后恢复冻结基线；用户真实提出的未决新值则继续保留，不能因后续省略而回退旧值。

未获整批准入的错误提案允许 Pi 完整重提并纠正 `source`，宿主重新验证声明来源及全部目标，修复前不执行查询，也不保留多余草案参与执行。已获准或已执行来源不能通过这种重组被覆盖。`new` 误填没有本轮依据的历史机构或日期时，有历史来源则返回 `NEW_TARGET_SOURCE_UNBOUND` 供 Pi 选择真实引用，保持原业务焦点；没有历史来源仍按真实字段缺项处理。

宿主应区分可由当前证据修复的语义冲突、需要 Pi 查证的目录缺口、必须由用户补充的选择，以及真实服务异常。可修复问题回到同一 Pi，并给出保存状态、冲突对象及可用下一步；需要用户的状态停止循环并按保存条件澄清。引用失效或跨任务不匹配返回明确错误，不能自动扩大范围或选取另一来源。

## Schema 以外的必要保证

Schema 只能证明键、类型、动作形状和枚举符合协议。以下仍须业务语义处理、目录落地、服务端控制与验收共同证明：

- 模型的概括是否忠实于完整原句，否定、替换、比较和数量关系是否正确。
- 历史引用是否由宿主签发、属于本会话及所选任务，并能续接最新真实状态。
- 多目标绑定、全任务覆盖、候选确认及已确认身份是否保留。
- 分析选取是否符合用户目标，结果是否足以支撑最终结论。
- 权限、单位、日期、口径、能力支持、执行许可与幂等结果是否满足契约。

实施时必须先对原始请求执行严格 Schema 校验，再进入 Pi 工具 SDK 可能发生的参数类型转换。原始校验应关闭类型转换、默认值填充和未知字段裁剪；`protocol_version: "2"` 必须拒绝，不能被 SDK 转成整数 `2` 后当作协议兼容。业务文本的后续目录落地和语义规范化只发生在形状校验通过后，不能改变这条输入边界。

精准而灵活的语言理解不能由本 JSON Schema 单独实现。同一 Pi 的语义提案、证据反馈、目录落地与可解释恢复仍须以真实模型连续多轮验证；文档和 Schema 不构成业务成功证明。验收按完整任务正确率、关键边界正确率及用户补充负担判断；本次实现说明不代表已经达到 95% 以上。

# 阶段二：统一语义任务候选实现

当前代码已接入候选协议；默认仍为 `fixed_v1`。`AGENT_BUSINESS_PROTOCOL=semantic_v2` 只作用于之后创建的会话。本阶段贯通精确取值、条件准备、跨轮补充/修改/确认、历史条件引用及成功结果重显，复合、比较、排名、覆盖发现及分析计算的执行留到阶段三。阶段四仍需独立语料、基线配对、登录鉴权和浏览器验收。此实现不能证明 95% 以上覆盖率，也不能替代原能力全集上线。

## 实际执行链

用户原始消息由同一 Pi Session 接纳并保存，固定本轮业务日期。Pi 选择工具，提交只有 `protocol_version`、`intent`、`targets` 的语义提议。宿主从同一 Session 绑定来源、保存提案，调用后端目录与日历事实服务，对账原句片段、机构范围和明确数量，将完整条件编译为 Frame，并签发一次执行许可。宿主接续原生工具执行，后端按现有权限与来源绑定校验取数，正式回执再进入同一 Pi 循环生成答案。

这里没有放在 Pi 前面的第二个理解 Agent。原生历史、工具循环、Skill 选择、压缩和回答仍由 Pi 负责；宿主负责事实绑定及执行边界。

| 模块 | 已落地行为 |
| --- | --- |
| `semantic-task/protocol.ts` | 内嵌唯一公开 Schema；原始 JSON 严格校验，拒绝字符串版本、旧字段和内部索引，不接受 SDK 类型转换后的值 |
| `semantic-task/store.ts` | 同一原生 Session 中增量保存任务、目标快照、原始本轮消息、待修修改、业务日期与引用；CAS 更新，历史分页不切焦点 |
| `semantic-task/service.ts` | 六种动作统一解释；原始义务对账；有效字段缓存；失败新条件不悄悄回退；按原句选择候选，分组保留确认进度及每个片段对应的身份 |
| 后端字段事实接口 | 目录身份及权限裁剪；独立机构来源扫描；日历范围与原句对账；区分不支持表达、真实日历无效和正常口径歧义 |
| `semantic-task/tools.ts` | 按任务/目标引用执行或读取；许可绑定用户、operation、修订、Frame 和条件摘要，消费前复核目录权限；未知执行回查原关联 |
| `harnessHost.ts` | 创建时固定会话协议；恢复校验原 operation 协议；同批多个解析提案在任何业务执行前拦截；正常澄清、明确终止及重复失败直接结束 |
| `sessionProjection.ts` | 语义反馈保留任务状态；正式执行结果沿用现有表格投影与证据校验；澄清在历史中可恢复 |
| 聊天组件 | 同轮后续成功回答清除旧失败状态，刷新后保持一致 |

公开工具名称保留 `resolve_business_turn`、`business_context_read`、`execute_business_frame`、`read_business_result`。执行和回读参数只接受宿主签发的任务及目标引用。目录、历史读取、普通回答和 Skill 工具保留，精确完整请求不强制先读 Skill 或搜索目录。

原生 SDK 的参数校验失败会跳过工具后置 Hook。候选入口因此使用内部 JSON 隔离适配器，将形状错误送入同一正式反馈与恢复链；给模型的工具 Schema 仍是严格版本 2，执行入口在任何业务解析之前再次严格检查原始 JSON。这不是接受额外参数方言。

## 从真实模型失败中修正的边界

完整指标名称里的统计口径可能被模型省略，或误放入时间字段。原句中的唯一正式目录片段及候选身份能够一致对账时，宿主补全其身份；原句本身有歧义时保存候选等待确认。不能凭模型正式名称消除用户原句的歧义。

单日范围在日历上只有指定时点的含义，宿主规范为 `exact`。操作描述不再要求命中“普通取值”等固定措辞；当前 `query` 的原值行为由业务意图和完整原句决定，未接入的操作不能降级执行。

日期缺失时，指标片段或模型补造的日期不能成为时间来源；保存机构和指标后直接询问日期，不让模型反复猜今天。时间真正来自用户但尚不支持时仍保留提案并返回可识别的解释问题。

“近 N 年”提供两种常见日历选项：截至本轮业务日期向前滚动 N 年，以及之前 N 个完整年度。选项包含实际起止日期并持久化；跨日确认使用已保存范围。用户也可直接给出明确日期或其它支持的日历表达。没有把“近 N 年”固定解释为某一个范围。

## 配置、兼容与回退

默认配置不切换入口。已有缺少新标记的 Session 使用 `fixed_v1`；已有显式协议的 Session 沿用原协议，即使重启时修改默认配置也不会转换。原 operation 协议与 Session 冲突时停止自动恢复，不换 Schema 重发。

新状态使用 `askmetric.semantic.v2` 命名空间；Frame 与后端任务结构沿用已有契约，本次无数据库迁移。回退新会话默认值到 `fixed_v1`，仍应保留支持两种 Session 的新版运行器，不能让旧二进制恢复新协议 READY 或在途操作。历史新协议会话应保留兼容读取器及原数据副本。

新增直接依赖 `typebox@1.3.7` 用于原始 JSON 严格校验；这是当前锁文件及本地依赖已有的版本，没有升级传递依赖。字段事实接口接受可选 `business_date`、`source_question`，字段业务表达长度与已冻结公开协议的 4000 字边界一致；旧调用方式继续可用。

实际结果及失败样本保存在阶段二验证目录（历史参考材料，未随交付包提供）。合成 SQL、真实模型和当前数据库只读检查分别记录，不能混称为端到端验收。真实库目前验证了目录、日期、来源、planner 和 SQL 执行；样本 SQL 返回零行，尚不能证明有数值结果的完整展示与计算口径正确。

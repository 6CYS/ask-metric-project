# 阶段4：本地全链路、稳定性与切换验收

本阶段由用户确认先验收当前本地全链路、重复稳定性和默认入口切换；95%覆盖率另行验收。Pi继续负责理解、规划、工具选择及结果驱动调整，没有替换Pi或增加另一个理解业务的Agent。

## 验收约束

使用当前项目数据库，业务数据只读；正常创建验收会话、查询和审计记录。真实模型为当前配置的SiliconFlow / DeepSeek-V4-Flash。用户已允许按验收计划发送少量真实机构、指标、日期、数值、单位和摘要；凭据、令牌及无关数据库数据不发送。交付证据保存范围、条数和结果哈希，不导出真实数值。

真实模型配合合成SQL、真实登录页面配合项目数据库、停止操作的可控本地模型桩分别记载，不能互相替代。

## 修复职责

- 日历确认使用已保存候选的唯一业务含义；保留否定及字段归属，不能用指标选择顺带确认日期。单日日期的“当日/当天/这一天”后缀仍由同一日历文法核验。
- 模型简称与原句或可信继承的唯一机构身份对齐。原句已给出的字段被模型遗漏时交给Pi修正，真正缺项仍询问用户。
- 单步规范化产生的派生字段整体复用，修改日期不能丢掉覆盖查询的维度等条件。
- 原始机构、指标和日期义务由整笔任务核验；同一榜单保持完整比较总体，普通取值及计算来源可以分目标。尚未获准的草案可重组，旧提案保留且不能消费许可。
- 内部提案待修时继续同一Pi工具循环。网关忽略工具要求时有限次提醒后明确未完成；不输出内部长篇计划或把修复责任转给用户。
- 浏览器发送前产生request_id；accepted尚未到达时停止也能取消对应请求。停止和接纳共用会话串行边界，原生记录保存取消标记，迟到的接纳不能继续执行。
- 实时及刷新均把用户取消展示为“已停止生成。”；真正模型错误仍显示失败。停止HTTP未确认时不能伪报停止成功。
- 用户主动新建会话立即撤销旧的本地恢复焦点，迟到的历史列表不能把空草稿切回旧会话。

## 切换与回退原则

原计划门槛包括代码回归、类型构建、固定语料对账、重复测试、真实页面、取消竞态及协议回退。用户随后明确要求“直接切换，提供不同场景案例由用户执行测试”，因此先切换当前本地默认入口。此切换不作为自动稳定性验收通过，95%仍单独验收。

默认入口只决定新会话；既有会话继续读取自己的协议。fixed_v1 已随阶段4收尾退役：新会话只使用 semantic_v2，旧 fixed 会话只读保留，配置不再提供 fixed 回退。需要回退程序版本时，不把旧阶段代码接到新任务账本上；先停止在途操作，再重启服务；保留会话及源代码快照。没有业务数据库结构迁移，不整体覆盖用户工作树。

实际计数、失败分类、切换状态及尚未验证项以[本阶段验证目录](../verification/pi-semantic-task-phase4-20261015/)的最终记录为准。开发用例和重复次数均不证明95%实际问法覆盖率。

手工验收见[场景案例](manual-acceptance-phase4.md)。已知自动验收仍有跨机构差额计算的提案重规划失败；刷新时自动回到原会话尚未验收通过。上述问题保留记录，不把本地切换表述为全部问题解决。

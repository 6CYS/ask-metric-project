# Pi 语义任务协议迁移与回退设计

阶段 1 设计草案。迁移必须同时处理工具协议、Session 领域值、Frame、后端执行关联及页面状态；新增设计尚未改变现有会话或运行行为。

切换遵循两个条件：同一原生 operation 只绑定一种业务协议；任何状态升级都保留原始来源和执行关联。新增任务状态可能采用增量存储，但这不代表整个升级无需迁移，也不保证旧程序可以安全恢复新协议的在途 operation。

## 分开管理协议和状态版本

当前浏览器请求与事件使用协议版本 3，固定业务入口使用 `protocol_version: 1`，Frame 领域值使用 `askmetric.business.v1` 命名空间。这三者服务不同边界，不能用一个开关或一个版本号代替。

新模型工具参数固定使用版本 2，只有 `protocol_version`、`intent`、`targets` 三个根字段。目标来源采用 `new`、`current` 或带宿主签发 `task_ref`、`target_ref` 的 `reference`，不再暴露全局 base 或自然语言历史选择器。初始输入和修改都使用 `set`、`add`、`replace`、`exclude`、`clear`、`confirm` 六种 operations，业务值使用字符串；这是一份待校验的语义提议，不直接构成执行许可。

新协议分别声明模型工具参数版本、语义任务状态版本、步骤编译版本、证据回执版本和页面投影版本。除已确认的模型工具版本 2 外，其余版本在实现契约冻结时确定。原生 operation 在创建时绑定完整版本组合，后续模型请求、工具执行、重连与恢复均读取该绑定，不能按进程当前默认设置临时改换 Schema。

旧记录缺少显式绑定时，只能按可识别的既有记录格式映射到旧协议；无法识别时只读展示并停止自动执行。不能因为缺少版本字段就推断它符合新协议。

新工具反馈、内部规范化结果及引用生命周期按[反馈与引用契约](feedback.md)一起切换。反馈 `unbound` 只表示形状错误尚未绑定任务，不迁移为 SemanticTask 状态；原消息已记录也不能被转换成“条件已保存”。已经存在的任务和恢复草稿必须按真实引用、条件及未决提案投影。

## 状态是否可以增量加入

| 对象 | 可以采用增量方式的条件 | 必须迁移或阻断的情况 |
| --- | --- | --- |
| 新任务与步骤领域值 | 在原生 Session 中新增独立命名空间；admission 新增 GoalContract 原文引用及已知义务登记；现有 Frame 与原始消息不变；旧读取器确认会忽略未知值 | 新状态替换旧焦点、历史序号或命令语义，或旧程序不能忽略新值时，需转换或版本隔离 |
| 原文证据引用 | 新值只引用保留的原始用户消息，采用明确的字符跨度规则并保存上下文 | 原文已压缩、缺失、跨度计数不明或无法核验时，不能补造可信引用 |
| 任务与目标引用映射 | 同一 Session 内新增不透明定位映射；仅为实际保存对象签发；重启从 Session 恢复 | 没有映射、跨会话或配对错误时不得仅凭字符串接受；当前目标修订冲突时必须重新读取，不自动套旧快照 |
| Frame 编译快照 | 附加编译来源和版本，旧快照继续由旧编译器解释 | 改变字段含义、目标分组、取数方式或错误语义时，不能原地重标旧 READY 为新 READY |
| 执行许可 | 仅为新协议已重新核验的步骤签发，不重写旧执行身份和命令 | 旧 READY 缺少完整目标、依赖或许可依据时，需重新解析；不能批量补一个已许可标志 |
| 后端任务及结果引用 | 仍可使用现有受治理请求与结果结构，新关联仅保存在 Session | 需要新增后端任务字段、目标分组或持久化回执时，须检查数据库模型并提供增量迁移与回退 |
| 页面任务状态 | 前后端约定可选新字段，旧客户端安全忽略，且新状态不会被旧客户端误报成功 | 状态枚举、澄清操作或事件顺序发生破坏性变化时，需协商页面协议并阻止旧客户端提交 |
| 日志与验证报告 | 增加协议及任务步骤关联，敏感原文仍遵循既有脱敏边界 | 旧报告依赖原字段含义时，需要更新解析器和对照基线，不能混算新旧结果 |

存储能否增量加入，须通过旧版本打开含新领域值的副本验证。若旧版本会改写、删除、误解释新状态或恢复新在途执行，则不能进行原地回退；保留数据副本，并让对应会话继续由兼容的新版本读取或仅只读展示。

## 旧历史和在途运行的处理

| 记录状态 | 切换行为 | 可执行边界 |
| --- | --- | --- |
| 旧协议已完成结果 | 原样保留消息、Frame、后端结果和来源版本；新任务可通过受控引用读取 | 复用前复核当前权限及证据适用范围，不重跑历史查询 |
| 旧协议 READY 或待澄清 Frame | 继续由旧协议处理；用户开始新协议任务时显式导入已知条件与未决项 | 导入后重新校验目标完整性和依赖，重新编译及签发许可 |
| 旧协议 EXECUTING 或结果未知 | 固定旧工具配置和命令关联，由兼容读取器按原关联回查 | 禁止换新 Schema 重发，也不以新幂等键补跑；正式终态前保留在途或未知状态 |
| 新协议已完成任务 | 保留新领域值及其证据；旧程序只能使用已定义的只读兼容投影 | 不能转换成旧 Frame 并继续修改后自动执行 |
| 新协议 READY 或在途任务 | 由兼容新协议的运行器继续处理，或在许可消费前有序停止 | 回退旧运行器前，必须确认无新协议待发送或结果未知的命令 |

历史导入应保存原 Frame、来源操作、协议版本和字段证据的引用；导入动作本身不证明原始任务已经完整。旧记录没有明确目标列表或原文证据时，标记来源能力限制，保留未决状态。不能凭历史助手“完成”文字反推任务义务已经满足，也不能把旧 Frame 已有字段当作原请求义务全集。可取得原始用户消息时重新对账可确定的目录、数量、时间及操作角色；无法确定的部分保持未绑定，由同一 Pi 解释，不能批量标记完成。

新协议的历史条件以不可变来源快照导入新任务，保留原任务与目标修订。宿主仍读取来源操作最新在途或未知状态，再决定能否执行；快照引用不是许可。继续当前任务使用旧 `target_ref` 时，返回 `REFERENCE_REVISION_CONFLICT`，不静默覆盖最新修订。引用不因模型压缩或重启失效，清理、损坏或撤销时按反馈契约返回明确不可用；不存在任意分钟级过期后回退到当前焦点的规则。

升级期间，可允许旧会话继续使用旧协议、新建会话或明确的新任务使用新协议，但同一 operation 的工具集合只能有一种模型输入格式。兼容适配器只在宿主边界确定性运行，模型不同时面对旧 Delta、compact、fixed 和新语义任务四套格式。

## 模块必须一起调整

| 模块 | 必须联动的修改 |
| --- | --- |
| Session 配置与运行恢复 | admission 即登记原始用户消息与可信历史义务；保存 operation 的协议绑定；打开、重连、恢复均使用相同工具配置；不为新任务另建 Agent 会话 |
| 工具 Schema 和参数适配 | 公开输入、NormResult 和固定反馈一起接入；六种动作语义一致；明确拒绝跨版本混用；旧 Schema 只服务已绑定旧协议的 operation |
| 原文与字段解析 | 同一 Pi 解释业务歧义，宿主只做规范化、绑定、校验与编译；接入宿主证据引用、解析错误分型、待修提案保存；确认、数量和否定判断使用相同来源契约 |
| 任务与步骤状态 | 对账 admission 已知义务与 Pi targets；保留漏项、操作角色、依赖、语义版本、恢复草稿与完成判断；有效新值和未决新值均不能在重试中丢失 |
| 历史引用与确认 | 新协议 source 引用与旧协议 current 及显式 Frame 均复核最新操作；多目标通过上下文读取得到明确任务与目标引用，不能默认一个 current 目标；保留来源归属、候选绑定、数量及当前权限控制 |
| Frame 编译和执行 | 绑定编译版本和步骤依赖；引入许可签发及消费；输入改变时失效旧许可和受影响的后继步骤 |
| 后端接口与执行关联 | 分开验证用户显式指标覆盖与分析目录选取来源；复核请求、结果、权限及幂等语义；若需新字段，同步后端模型、迁移、客户端与恢复读取器 |
| Harness 接续与结果交付 | 仍在 Pi 原生循环中选取下一步；步骤成功后检查任务目标，不因最新 Frame 成功自动结束整个任务 |
| 页面投影与前端 | 区分运行结束、任务完成、业务澄清及停止原因；保存状态和最终正文必须对应同一任务修订 |
| Skills 与运行时提示词 | 更新实际加载入口和工具映射；不以文档描述代替新 Schema 或后端校验 |
| 测试和诊断脚本 | 按协议绑定生成输入，保留原始回执，分别统计目标覆盖、执行次数、澄清及基础设施失败 |

这些模块不能只替换提示词或只调整 `fixedTurnArgs` 后就宣称完成统一。字段解析、恢复、执行、历史及前端使用不同状态含义时，必须先解决接口不一致再开放新协议。

## 切换前的实施顺序

整体交付阶段按[改造入口](README.md)执行。以下是阶段内的依赖顺序，不另设一套并行阶段编号。

1. 冻结状态与入口契约。确定目标完整性、来源、版本、许可、错误分类和页面状态；完成旧数据与在途记录清点，记录回退所需版本和配置。
2. 实现新状态与解析路径。新增 admission 目标登记、任务领域值、独立硬约束对账、证据引用和不可执行恢复草稿，验证有效字段保留、未决变化保留、历史最新状态及修复依赖失效。此步骤不允许自动发出新业务查询。
3. 接入编译与执行许可。由已校验步骤生成现有后端契约；验证许可消费、权限变化、幂等重试、断连与崩溃恢复。没有通过许可的旧 Frame 不得借新入口执行。
4. 接入 Pi 接续和页面投影。验证开放分析可逐步形成步骤，明确复合请求不执行半份，任务完成不等于运行结束，旧协议会话继续按其绑定运行。
5. 进行隔离验收与小范围切换。先离线和授权测试环境，再按已授权范围执行真实模型及真实数据源验证；完成新旧协议对照后才扩大默认入口。

进入后续步骤前，需要取得前置步骤的验证证据。设计完成、静态检查、目录桩通过、真实模型通过和真实数据库通过分别记录，不能互相替代。基线与候选使用同一目标、来源和环境，区分共有失败、新增失败及已改善项。

## 允许切换的验收条件

| 边界 | 必须证明的行为 |
| --- | --- |
| 完整目标 | admission 已知义务独立于 Pi targets；“查甲乙”只提交甲时乙仍未决且不执行半份；单目标直接取值保持可达；明确复合目标完整保留绑定 |
| 语言与来源 | 同义、复合确认、带否定和转折的回复不反向确认；日期中的数字不成为候选序号；本轮与历史来源不混淆 |
| 数量和范围 | 用户明确数量与解析集合相符；目录范围、比较总体及权限边界不因参数修复改变 |
| 恢复 | 普通已知条件和未决新值都可恢复；不能改换目标来源、删字段或默认继承绕过本轮待修变化；旧协议仍须保留其已绑定 base |
| 动态步骤 | 开放分析可根据回执调整下一步；已经失败或失效的依赖不会签发执行许可 |
| 引用和空变更 | 多目标 current 歧义不会隐式选目标；reference 不直接获准执行；当前修订冲突不静默覆盖；历史快照导入仍复核最新在途状态；prepare 与 reuse 的空 operations 不会被拒绝或变成取数 |
| 时间及分析来源 | 时间语义由 Pi 解释，日历计算基准由宿主固定；分析目录选取可通过正式来源核验，不被用户原文名称覆盖检查误拒绝 |
| 义务和角色 | 正向、替换、排除及比较角色分别核验；不能把全部提及当正向或未选择项全排除；只有新用户明确变更才能缩减原目标 |
| 在途与幂等 | 显式旧 READY 和 current 对最新在途状态一致；重试和崩溃恢复不生成第二笔不同命令 |
| 完成与展示 | `completed`、等待澄清、任务部分完成和结果未知分别展示；正文与任务及证据版本一致 |
| 旧数据兼容 | 旧完成、待澄清、READY、在途、未知结果及无法识别记录均有验证过的处理路径 |

验收以原始完整用户任务为独立标准，同时检查真实执行次数、目标覆盖及持久化状态，不能只判断自然语言回答是否好看，也不能用 ledger 自己生成义务再证明全部满足。宿主硬约束对账不能证明任意语言含义；大于 95% 的目标必须按独立语料及完整任务标准验证，目录空匹配和未绑定表达不能被统一拒绝后移出分母。上述条件未满足时，新协议可以继续保持隔离验证，不提升为默认可执行入口。

## 回退条件与操作边界

出现目标漏项、错误确认、范围扩大、许可绕过、重复执行、状态丢失或新旧协议混用时，停止接纳新的新协议执行，并保留任务、许可与命令记录。已在途的步骤先按原绑定回查，不立即切换运行器或重复提交。

如果新领域值是增量加入、旧读取器已证明安全忽略且没有新协议在途命令，可以将新建任务默认入口切回旧协议，同时保留新状态只读。回退不删除新领域值，也不把新任务强行降级为旧 Frame。

如果升级改变了旧状态含义、后端持久化结构、许可消费记录或旧程序不能安全读取的新值，则须使用配套兼容读取器、数据转换或备份恢复方案。恢复备份前先对账备份之后的正式执行与结果，避免还原旧幂等登记后再次执行同一请求；历史证据及审计记录不能因回退丢失。

回退完成需要同时确认入口版本、运行器、Session 读取器、后端接口及页面投影匹配。只切环境开关或只回退模型提示词不构成完整回退。

状态和执行不变量见 [语义任务状态与执行设计](state-and-execution.md)，反馈及引用规则见[反馈与引用契约](feedback.md)。

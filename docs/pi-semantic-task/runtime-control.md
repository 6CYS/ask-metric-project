# 智能问数运行控制

运行控制接入现有 Pi 循环和 `SemanticTurn`，复用 `SemanticPlan`、执行许可及分析证据，不另建任务队列或第二套业务账本。简单查询可以直接执行、交付，不要求额外调用模型生成一份规划。

## 阶段与完成条件

`SemanticTurn.runtime` 是可重新计算的控制投影，记录原问题、阶段、当前计划引用及版本、必需目标完成数、未完成目标引用、预算和有限的版本修订记录。业务条件、依赖、权限、执行状态仍以现有任务和计划为准。

| 阶段 | 依据与下一步 |
| --- | --- |
| understand | 尚无工具回执，由模型理解原问题并提出动作 |
| prepare | 读取目录、历史或 Skill；这些读取不能完成查询义务 |
| plan / execute | 已有正式计划及目标；沿用原许可和依赖执行 |
| verify | 已取到数据；分析需提交报告，普通查询可交付正式结果 |
| recover | 按参数、目录或只读服务失败进行有限修复 |
| waiting | 真正需要用户输入，或原执行结果未知、需核对 |
| deliver | 已形成正式公共回答 |
| stopped | 修复耗尽、预算耗尽或操作终止；成功证据继续保留 |

阶段可以跳过，也可以因新证据进入修订和补查。计划变化记录原计划引用、版本及发生时的回执数，不复制或覆盖成功结果。通用分析内部子问题的覆盖仍由 `AnalysisPlan.requirements` 和后端报告校验负责；控制投影中的目标计数指 `SemanticPlan` 的必需步骤。

`execution_complete` 与 `delivery_complete` 分开记录：取得数据不代表报告已经交付；已发出澄清或失败说明也不代表原业务目标已完成。等待确认与未知执行状态不会被目录成功覆盖。

控制状态在模型请求和工具回执边界结算，保存在原生 Session 事务内；后到达的旧观察不能降低已观察的回执数。重开沿用已保存的计划版本和预算，不另起一轮查询。

## 工具与交付边界

回执统一区分准备、执行、交付、失败四种职责。新增工具需补齐正式结果解析和对应测试；不能只因工具执行未抛异常就认为业务完成。

执行前的统一准入会阻止无本轮证据的报告、正式交付后的追加动作、需要用户处理或权限/能力已拒绝后的越界调用，以及未知执行结果的直接重跑。原有解析、机构日期绑定、许可消费和后端鉴权继续生效。

机构清单按成员核对本轮原文，允许模型以逗号、中文逗号或顿号序列化原文中的并列机构，不要求分隔符与原句一致。新目标中多次普通机构 `set` 仅在所有成员都有原文依据且没有集合限定时合并去重；历史来源、结构化范围、排除或替换等动作保持原语义。空成员、未知名称及权限失败不能通过删除成员绕过；正式名称与编码仍由授权目录绑定，其他字段的重复赋值继续拒绝。

正文入口集中于 `runtime/delivery.ts`：

- 接受正式查询快照、语义澄清、普通对话回执及通过校验的报告。
- 目录只证明定义或候选；只有用户明确询问目录/定义时，才用目录说明完成该轮。
- 普通模型文本不能直接充当新协议业务正文。普通查询的历史兼容展示也只复用正式事实。
- 宿主内部 `runtime_finalize_turn` 不接收模型正文，只从真实回执整理结果，不产生额外模型请求。
- 普通对话和报告正文另检查明显的内部通道标记、工具参数和自我编排文字；它是补充检查，不能代替事实和引用校验。
- 受治理的回合不实时播报未经交付检查的模型文本。实时完成和历史回放使用同一正式正文解析规则。

报告仍由模型围绕证据自由成文，保留现有数字、计算、日期、引用和关系校验。未把报告改成固定栏目，也不通过接受未经验证的文字增加分析内容。

正文展示与运行诊断分开：同一快照日期由顶部范围承载，正常报告和事实兜底均去除重复的段首日期；多期数据仍保留各自日期。校验失败、文字降级及补查状态继续记录在回执中，不逐层追加为报告尾注。影响解释的数据时效及业务缺项用简短说明保留，同类缺项合并。该整理不更改数值、事实引用、完成状态或权限校验。

新交付回执携带任务和机构权限来源。刷新、SSE 与后续上下文继续经过现有历史授权；不能因复制出一份正文就绕过原数据权限。旧会话不批量改写，旧协议兼容出口不再放出已识别的内部规划。

## 恢复策略

| 情况 | 处理 |
| --- | --- |
| 通用分析计划漏项、步骤错误、目录引用无效 | 签发结构化恢复任务，定向发现指标并以局部补丁修复；两次修复耗尽才结束，不能提前因相同根因停止 |
| 其他参数或引用错误 | 反馈正式诊断，在原范围内修正；同根因无进展则停止 |
| 基础指标未匹配 | 沿用原有限目录发现流程，保留机构、日期和排序条件；检索后重提 |
| 只读服务暂时失败 | 标明可重试；相同失败和工具总预算继续约束重试 |
| 执行结果未知 | 核对原执行关联，不能按普通网络失败重新发起查询 |
| 权限或能力拒绝 | 保留公开说明，不能换条件或能力绕过 |
| 模型网络超时 | 继续使用 Pi 原有模型重试配置，不再叠加一套重试 |
| 生成被截断 | 截断参数不执行；只允许一次完整紧凑重发 |
| 已取到分析证据，后续失败 | 复用原部分交付工具重新校验并呈现已有证据 |

通用上限集中于 `runtime/recovery.ts`：24 次工具回执、2 次动作纠错、1 次截断修复、2 次阶段提醒；目录发现等领域预算继续由其原模块维护。宿主内部收口和已有部分交付工具可在取数预算耗尽后整理已有结果，不能借此发起新查询。

不把服务失败当成无数据，也不把未知执行状态当成成功。模型理解或上游服务仍可能失败，运行控制负责有界恢复、保留证据、明确失败和稳定交付，不能保证任意问题都有业务答案。

### 分析计划局部恢复

计划校验拒绝后，`analysis_recovery` 返回缺失子问题ID、待修步骤ID、保留步骤ID、计划与目标引用、版本和次数。恢复数据只引用原 `SemanticPlan` 中已保存的提案；`SemanticTurn.analysisRecovery` 保存引用与预算，不复制一份业务计划。

宿主按回执决定目录发现或 `analysis_plan_repair`。该工具仅在恢复阶段向模型公开，接收引用和待修步骤，不接收机构、日期、目标或新子问题。程序合并原正确步骤与补丁，保留原要求和补查依据，再经过完整计划校验、目录绑定、机构权限、日历与执行许可校验。步骤标识冲突、跨目标或过期版本、覆盖正确步骤及未知引用均不能执行；不能删除问题或添加未经确认的缺口以绕过校验。

网关忽略强制工具、模型原样重提整份计划时，宿主切换为目录读取或抽取待修步骤；其他条件不会被采纳。错误补丁最多两次，计数保存在原生事务中，重开不归零；原有24次工具上限继续生效。目录读取失败允许一次有限重读，不能当作无指标。

修复耗尽时，程序保留可独立验证的正确步骤，剔除错误步骤及其依赖后继，重新通过完整校验后执行。原子问题不删除，未执行部分记录为系统规划尚未完成，不能声称数据库无数据。取得的事实直接走原部分交付与重新授权路径，不再请求模型决定如何收口；任务仍标为部分完成。没有可执行步骤时明确系统修复失败，不要求用户重新解释已明确的问题。交付阶段撤权返回正式拒绝回执，不输出数值。

恢复不会把分析结果固定成模板，不会放松事实、数字、引用或报告校验。独立新问题与基础查询不增加修复调用。

## 验证入口

- `specs/runtimeControl.spec.ts`：职责分类、阶段、版本、完成条件、准入及旧正文隔离。
- `specs/semantic-task/analysisRecovery.spec.ts`：四目标三步骤漏项、原范围保护、正确步骤保护、无效补丁与有界恢复。
- `specs/semantic-task/host.spec.ts`：真实 Pi 循环配合本地模型桩，覆盖目录后规划泄露、查询后规划泄露、定义查询、重开恢复和模型调用次数。
- `specs/historyAuthorization.spec.ts`：交付回执独立携带权限来源，刷新和 SSE 撤权关闭。
- 既有截断、超时、参数恢复、报告、基础查询和多轮套件继续回归。

这些测试不请求付费模型，也不修改业务数据。真实模型质量和外部服务可用性需要单独联调，不用本地桩结果代替。

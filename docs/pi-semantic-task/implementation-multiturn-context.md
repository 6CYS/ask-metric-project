# 通用多轮上下文实现

本说明对应当前版本 2 源码中的多轮上下文、目标澄清与状态变更链。代码实现与运行验收分开记录：真实模型连续多轮验证仍在进行，本文件不宣称全部场景已通过，也不据开发用例计算或承诺 95% 以上覆盖率。

## 职责与入口

| 层次 | 职责 |
| --- | --- |
| Pi | 结合原始消息和上下文判断新建、续接、集合动作及作用目标；能明确就执行提案，确有实质歧义再追问；根据正式结果继续规划和回答。 |
| Agent 宿主 | 冻结来源、核验引用、规范目录与日历字段、维护有效和未决状态、生成内部变更账本、编译 Frame 及消费许可。 |
| Backend | 独立核验初始目标覆盖或跨轮状态变更，复核目录、权限及范围，签发正式执行范围回执，受治理执行查询。 |
| Frame | 保存已确认执行输入、来源及结果关联；新条件产生新快照，原快照保持不可变。 |

保留同一 Pi 原生 Session、模型和工具循环。没有前置意图 Agent、关键词路由器或第二套消息历史。运行时提示词和工具定义来自 `agent-service/src/semantic-task/`；修改设计文档不会改变已启动进程。

`resolve_business_turn` 继续使用 `protocol_version: 2`、`intent`、`targets`，目标内为 `source + operations`。可选 `context_action` 只说明已保存目标澄清的处理方式；`transition`、正式编码、签名及许可仍由宿主生成，模型不填写。完整输入见[协议说明](protocol.md)及[请求 Schema](request.schema.json)。

## 一次业务回合的执行链

1. 宿主接纳用户消息，在同一 Session 事务中冻结 `SemanticTurn.context`。`admitted_context` 向 Pi 投影入场计划、确认条件、未决项、Frame 来源及此前待明确输入。
2. Pi 根据原句和上下文选择具体来源、目标范围与字段动作。目标能确定时直接调用 `resolve_business_turn`；没有固定的预搜索或工具顺序。
3. 目标仍有多个合理解释时，Pi 调用 `clarify_business_turn`，宿主只验证备选引用并保存追问。此分支不取数、不编译或修改 Frame。
4. `SemanticPlanService` 按显式来源组织目标；`SemanticTaskService` 规范字段及集合变化，核对本轮或可信继承依据。错误参数交 Pi 修正，真实业务缺项或候选歧义才交用户。
5. 完整新建子步骤可先产生 Frame 编译快照和局部许可，此时整批计划尚未获准，许可不能被消费。`/api/v1/business-context/admit-plan` 随后独立核验整批可执行目标：初始查询核对原始覆盖；跨轮修改核对来源与 before/trace/after。未决、遗漏或错误绑定阻断执行。
6. 整批准入通过后，宿主携新范围回执重放规范结果并编译可执行 Frame，发布对应步骤许可。执行器消费前复核完整计划准入、版本、当前权限、摘要及在途状态，再经现有受治理 Backend 执行并保存正式证据。单独存在 READY 快照或局部许可不能绕过完整计划门禁。
7. 结果返回同一 Pi 循环。Pi 根据完整性、结果差异和待解决目标决定继续规划、等待用户或组织答案；模型运行结束不等于业务目标完成。

## 统一来源语义

| source | 起始状态与边界 |
| --- | --- |
| `new` | 从空条件开始；不会因为历史来源唯一而自动补入机构、日期或指标。 |
| `current` | 仅用于本轮冻结入场目标唯一的续接。多目标时返回需要引用的诊断，让 Pi 选择，不默认全部修改。 |
| `reference` | 选择宿主签发的同 Session 任务与目标配对。Pi 可选择一个或多个具体来源，宿主核验配对、归属、状态与当前权限。 |

宿主不按“追加、替换、清空、换话题”等词重写 `source` 或 `action`。新指标需要沿用原范围时，Pi 选择 `current/reference` 并 `metrics:set`；用户只改机构或日期时不重复填写未变化指标，原正式身份及统计口径继续保留。

`set` 替换整个槽位，`add` 保留原集合并追加，`replace/exclude` 核对被操作成员，`clear` 使字段缺项，`confirm` 只确认已保存候选。动作只在全部校验后执行最终状态，不查询中间集合。多个机构、指标和日期之间的绑定仍分别保留，不能展平成交叉组合。

每次跨用户的 `query/prepare` 都从声明来源派生新计划，待补计划也保持原样。中间草案与需 Pi 修复的错误不切换业务焦点；默认运行上下文只投影当前业务计划，历史工具仍可全量分页读取。实体显示使用当前完整规范名称集合，追加或排除的动作原文不能替代最终集合显示。

首轮尚无有效业务焦点时，错误草案只保留历史地址；默认投影的 `tasks` 为空并标明可读历史，不将全部草案回填为当前条件。旧单目标兼容投影也只显示真实旧焦点。已移除解析器的 `inheritedFields` 参数注入路径；`new` 只从空目标开始，继承只能来自 Pi 声明且经宿主核验的 `current/reference`。保留数据中的旧兼容字段不构成继承依据。

模型填入目录中存在但本轮和可信来源均未支持的指标，也属于参数错误。回执要求 Pi 修正；原始提案保留供追溯，不将该错误变成用户未决选择。Pi 同轮省略这类错误字段后恢复冻结基线；用户真实提出的未决新值则持续保存，不能因省略回退旧值。

未获整批准入时，Pi 可完整重提并纠正 `source`，重新验证后仅保留本轮有效目标参与执行；不能保留错误草案一并取数，也不能覆盖已获准或已执行来源。`new` 无依据复述历史机构或日期时返回 `NEW_TARGET_SOURCE_UNBOUND`，要求 Pi 选择真实来源并保持原焦点。对没有待选候选的 `confirm` 返回 Pi 可修复的 `CONFIRMATION_NOT_AVAILABLE`，不制造用户选择。

## 真歧义的保存与恢复

`clarify_business_turn` 接受一个 `question` 及至少两个不重复的 `alternatives`，每项为真实 `task_ref/target_ref/label`。保存值属于当前 Session，下一轮投影为 `admitted_context.pending_clarification`，无需另建会话或记忆库。

| Pi 的选择 | 行为 |
| --- | --- |
| `resolve.context_action = resume` | 用已保存备选的明确 `reference` 续接原待明确修改，将原句和本轮补答一起核验。 |
| `defer` | 暂缓并保留原修改，本轮可查看原结果或处理其它目标。 |
| `abandon` | 放弃原待明确修改，按当前提案继续。 |
| 缺省 | 不恢复原修改；相同引用本身不会触发恢复。 |

`reuse` 不与 `resume` 合并；暂看原结果使用 `defer`。仍需澄清时，澄清工具可选 `resume` 组合原待明确输入再追问，或用 `abandon` 从本轮输入建立新追问。`new` 目标始终只绑定本轮条件，不被其它目标恢复的原修改污染。

## 内部状态变更与执行许可

宿主的 `SemanticTransition` 使用旧完整查询 `before`，记录实际规范化动作形成的 `changes`，以步骤最终 `spec` 作为 `after`。实体使用正式身份集合，日历和操作使用规范值，不从模型业务文本反推旧条件。

后端先验证旧票对应 **before**，包括 owner、conversation、Session、目录身份和完整范围，再检查动作链、各字段前后状态和最终 after 一致。新增值须有本轮或授权分析来源；当前目录和权限仍重新核验。替换、排除的旧身份在变更账本中解释，不能再次成为必须查询的指标。未能由本轮、来源或变化解释的显式条件仍受阻。

`context_sources` 只解释用户同时提及的旧条件或原结果，不能带 `changes`、不能扩展执行步骤，也不签执行票。每条上下文独立核验来源、目录和当前权限，只有通过的来源能解释本轮义务；失权或无效但本轮未使用的来源不阻断已由实际步骤和合法上下文完整解释的查询，所有未通过来源保留脱敏诊断。若本轮确实依赖被拒来源，整批请求仍拒绝，不借该来源形成执行依据。后端只给真正的 `steps` 签发新范围票。数学与来源校验不能证明 Pi 每次都正确理解自然语言，仍需真实模型验证动作选择与目标范围。

待补目标没有完整 before 时，保留原始义务、已确认子状态及真实候选，条件齐备后再核验。完整来源修改期间出现日期未决，已规范且有依据的指标子状态也继续保存；后续换指标、补日期不能使更早的已替换指标复活。必要字段未明确时不执行半份查询。

Frame 保留：派生执行快照包含 `parentFrameId`、`delta.baseReference` 和变化字段的 `delta.fieldChanges`。Frame 的 delta 表达最终字段变化，完整 `set/add/replace/exclude` 动作和身份前后状态保存在任务 `transition.changes`。旧 Frame、正式结果和引用不因后续问答被改写；来源仍在途或结果未知时回查原命令，不能换键重复取数。

变化字段在最终规范目标中不存在或处于 `missing` 时，Frame delta 明确记录 `clear`；其它变化字段记录最终 `set`。因此可选比较范围被清除时，不会出现字段已删除但 delta 仍写为设置的矛盾。delta 不代替完整集合动作账本。

## 历史读取与显式重显

直接 `read_business_result` 查看旧结果，以及执行工具对已成功目标的重显分支，都重新核验结果访问权限，不触发新 SQL、不重结算旧任务或计划，也不切换当前业务焦点或 Frame 焦点。读取失败只产生本轮失败或拒绝反馈，原计划的成功状态、完成程度、许可和 Frame 继续保留。下一轮 `current` 仍以原当前业务目标为来源。

Pi 明确把历史目标作为本轮业务选择时，先调用 `resolve_business_turn`，使用 `intent: reuse` 和目标内的 `source: reference` 派生新计划。该新计划成为显式焦点，结果读取只结算本轮新计划，旧历史计划保持不变。若此前有待明确修改，查看原结果使用 `context_action: defer`，不恢复或放弃原修改。

## 兼容、升级与回退

本次没有数据库结构迁移。计划、入场快照、待明确输入和状态变更使用既有原生 Session 的增量领域值；不删除或改写既有消息、Frame 和结果。

旧无票 Frame 可使用保留的原始指标覆盖、绑定与排除依据进行兼容复核。该路径只能证明既有指标来源，不具备新票对完整旧范围及 Session 的同等签名保证；不能将旧 READY 或助手“成功”文字重标成新许可。缺少可核验来源的记录保持受阻，重新读取或解析，不从裸 after 补造许可。

Agent 与 Backend 应配套升级：新 Agent 会提交 `transition/context_sources`，旧 Backend 的严格模型可能拒绝这些字段。上线前确认 Backend 支持配套契约、备份原生 Session 和相关配置；等待本地及目标环境的在途请求结束后重启，不能在执行或结果未知时强行切换。文档更新本身不会使进程加载新工具或提示词。

`AGENT_BUSINESS_PROTOCOL=semantic_v2/fixed_v1` 决定新建会话的协议，当前配置缺省为 `semantic_v2`；已有会话继续使用 Session 中保存的协议。回退时调整新会话入口，不批量改写已有会话协议，不删除新 Native 领域值或改造旧 Frame。需要回退运行器版本时，先确认新协议无在途或未知命令，并在原生数据副本验证旧读取器能安全处理新增值；不能安全读取时保留兼容运行器处理原会话。

## 验证与完成边界

验收需分别记录代码检查、合成后端、真实 Python 契约、真实模型、真实数据库和页面验证，不能相互替代。连续多轮应覆盖完成后续问、缺项续补、指标集合变化、多个绑定目标、清空与新建、历史重显、真歧义及恢复、暂缓和放弃、参数纠错、权限变化以及 Frame 来源不变。

真实模型验证还须观察同一意图不同问法和重复运行，核对实际来源、动作、日期、指标身份及查询次数；正常澄清不能算成查询成功，基础设施中断也不能冒充语义失败或通过。最终验证数字和证据由实际报告补充。超过 95% 的验收另用独立实际问法样本，不沿用开发用例计算。

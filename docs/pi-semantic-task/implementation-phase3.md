# 阶段3：贯通现有能力与结果驱动规划

本文保留阶段3实现记录。当前调用链与旧准入删除情况见[问数与多轮上下文实现](implementation-multiturn-context.md)。

阶段3继续使用 `semantic_v2` 候选入口；默认配置仍是 `fixed_v1`。本阶段不新增预测或因果归因，不更换Pi，也没有新增负责理解问题的模型或后台Agent。

## 实际执行链

用户原句 → Pi理解目标、选择工具 → 同一版本2语义提案 → Session任务账本及独立目录/日历事实 → 整批语义预检 → 单步规范条件与内部Frame → 原有查询/排名/覆盖/计算执行器 → 正式结果回执 → 同一Pi检查结果、补充步骤或回答。

Pi决定分析需要什么指标、先做什么、看到结果后是否继续。宿主负责原始义务、来源、机构/日期/指标绑定、候选确认、依赖、许可和正式证据；后端继续检查目录、权限、查询组合、快照归属、精确计算和幂等关联。

## 改动边界

- `semantic-task/planService.ts` 增加任务级编排；原来的单目标 `SemanticTaskService` 继续负责单步规范化。模型仍只有 `protocol_version / intent / targets` 三个根字段，业务值仍是字符串。
- 新任务可含独立绑定的多个目标。普通复合查询必须整批通过预检后才能消费任何子步骤许可。原始片段按机构、指标及日期组合核验，不能仅检查几个集合的并集。
- 离散日期可作为一个查询目标，也可拆成多个步骤；拆分后仍必须覆盖完整原始日期组合。计算中的月份简称仅在可唯一绑定前述明确时点时作为来源指代，不增加整月查询。
- 排名复用现有前后N及对象位次实现。位次中的关注对象和比较总体分别保存；原句明确的完整机构集合可以从独立目录事实恢复，无法确定时保持未决。榜单条数不充当机构数量。
- `availability` 贯通现有指标/日期发现、范围和分页。覆盖结果不作为指标数值或完整类别的证明。
- 计算用普通来源名称及算式表达，宿主绑定正式查询事实。来源可以是唯一objective或唯一日期等aliases；多值来源必须明确聚合。支持现有四则运算、sum/avg/min/max/abs、百分比展示及原句常量。权限、单位、Decimal精度、过期和零分母仍由现有计算后端控制。
- 分析可以根据实际目录或覆盖发现回执中确定的指标身份选择原句之外的指标；近似推荐仍只作探索线索，不要求固定工具顺序。分析支持步骤可分阶段执行；用户明确的指标义务保留在账本中，没有全部取证时不能把任务标记为full。Pi取得第一项结果后可以在原循环中追加步骤。多个成功步骤联合核验离散日期义务，不要求单个步骤同时包含全部日期。
- 未获准的模型拆分可在本轮用完整新提案重组；被替代提案仍留在Session中，不能消费旧许可。已获准、已执行和未知步骤不进入此重组路径，原始完整目标继续独立核验。新建字段误写集合追加等提案错误由Pi修正；真正未决候选仍等待用户选择。
- 模型content、宿主details和页面使用同一份正式语义回执；回执同时包含任务引用、完成状态与实际结果证据。复合结果各自保留身份，实时展示及刷新恢复多个结果表。
- 仅重显一个历史目标不会重查或重显其它目标；历史来源使用签发引用，非当前来源保留原快照。计算依赖的查询目标变化后，旧计算结果不能充当新目标证据。

## 后端与兼容

新增 `POST /api/v1/business-context/inspect-goal` 和 `POST /api/v1/business-context/admit-plan`。后者在整批核对后签发绑定当前身份、会话、启用目录及完整规范查询范围的来源回执。查询执行层重新核验签名、当前目录与权限。模型不填写或接触签名来源参数。

新字段及任务账本保存在原生Session中，未修改业务数据库表结构，没有数据库迁移。原始查询来源校验继续服务旧调用方；精确单目标不增加额外整批准入往返。已有fixed_v1会话保留协议绑定；阶段2的单目标semantic_v2记录可继续读取或按需接续。

部署此候选须同时更新Agent与Backend；仅更新一端会返回可识别失败，不能依赖静默兼容。`jwt_secret`须稳定且各Backend实例一致；轮换后旧来源回执失效，需要重新解析签发。

阶段4再做默认入口切换、真实登录页面验收和发布。回退时先停止候选在途操作；保留Session和阶段3源码/数据快照，不让旧阶段2代码接续阶段3任务账本。默认fixed_v1入口及其会话与候选分开。不得用归档整体覆盖用户工作树。

## 验收边界

[阶段3验证目录](../verification/pi-semantic-task-phase3-20261014/)保存原始失败报告、最终候选报告、只读数据库检查及相对阶段3开始时工作树的源码差异。实现/隔离测试、真实模型配合合成SQL、真实数据库只读检查、真实HTTP身份及浏览器验收分别记载。

对版本2的综合分析能力说明现返回继续规划，预测及因果证明仍保留能力边界。失败回执保留执行器公开原因，不用保存条件代替失败诊断。

本阶段没有证明95%覆盖率。该目标需要独立的实际问法样本、同问题重复测试及基线配对；当前小规模合成验收不能替代这些证据。现有后端容量和不支持组合继续适用，包括逐日排名、超过受控事实容量的计算及不完整数据。未知、缺数、截断及未完成均保留明确状态，不靠缩短问题取得成功。

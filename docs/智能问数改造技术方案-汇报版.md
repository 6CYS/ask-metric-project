# 智能问数改造技术方案（汇报版）

> 详细设计见《[智能分析能力设计说明书-PiHarness](智能分析能力设计说明书-PiHarness.md)》

## 一、结论

在保留现有问数能力的基础上，新增“智能分析”模式：用户只需说出业务目标，系统自动补全条件、自主确定要看的指标、取数并给出分析结论，同时写明系统做了哪些假设，用户可以一键修改。

预计 **约 5 周** 完成三个阶段，第一阶段（约 2.5 周）即可上线“自动补全 + 基础分析”。

---

## 二、现状问题

| 问题         | 表现                            |
| ---------- | ----------------------------- |
| 必须说全条件     | 指标、机构、日期缺任何一项，系统只会反问，不会先查     |
| 只能取数，不能分析  | 一次提问只能查一次数；对比、排名、拆解、“为什么”无法回答 |
| 业务口径写死在程序里 | 例如“没说口径时默认用哪个”，每次调整都要改代码、发版   |

---

## 三、改造目标

1. **说不全也能查**：缺日期、缺口径、指标说得模糊时，系统按规则补全后直接出结果。
2. **能自主分析**：围绕业务目标，自己确定看哪些指标、和什么比，完成对比、排名、结构拆解。
3. **结果可信**：每个数字都有查询依据；系统替用户做的决定全部写明，用户可以改。
4. **不影响现有能力**：条件明确的问题，速度和准确性与现在一致。

---

## 四、方案总览

```
                          用户提问
                             │
                 系统判断：要一个数，还是要分析？
                ┌────────────┴────────────┐
                ▼                         ▼
     ┌──────────────────┐      ┌──────────────────────────┐
     │   精确问数（现有） │      │      智能分析（新增）        │
     │  条件明确 → 直接查 │      │ 补全条件 → 规划指标范围       │
     │                  │      │ → 批量取数 → 对比/拆解计算    │
     │                  │      │ → 给出结论 + 本次分析口径     │
     └──────────────────┘      └─────────────┬────────────┘
                ▲                            │ 遇到必须由用户决定的问题
                └──────── 保底：按现有方式向用户确认 ──────┘
```

**两种模式并存，现有问数作为保底**：新模式处理不了的情况，退回现有的确认方式，系统表现不会比现在差。

## 五、核心设计要点

### 1. 双模式自动切换（意图识别）

由**大模型做意图识别**，不另建分类模型，也不用关键词规则：

- 大模型处理每个问题的第一步，本来就要决定“用哪个工具”。本方案在这一步给它两个入口：“精确取数”和“智能分析”，并写明各自的适用范围：
  - 要一个或几个确定的数 → 精确问数；
  - 要对比、排名、拆解、看趋势、问原因，或只给了业务概念 → 智能分析。
- 大模型结合本轮问题和前几轮对话做判断，判断与理解问题在**同一次调用中完成，不增加等待时间**。
- **选错了也能纠正**：
  - 走了精确问数，但发现用户要的是分析 → 可中途转入智能分析；
  - 走了智能分析，但其实只要一个数 → 照样能查出来，只是多一个步骤。
- 判断准确率纳入验收（目标：取数类 ≥ 95%，分析类 ≥ 90%，以验证阶段的实测为准）。

### 2. 自动补全，并写明假设

缺失或模糊的条件由**服务端按规则补全**（不是让大模型猜）：

| 用户没说清的     | 系统怎么补                      |
| ---------- | -------------------------- |
| 日期         | 取最新有数据的日期                  |
| 机构         | 取用户本人所在机构                  |
| 指标口径       | 按业务规则取默认口径                 |
| 指标名称模糊或有错字 | 取相似度最高且明显领先的指标；分数接近时仍向用户确认 |

回答末尾统一列出“本次分析口径”，用户点一下即可换口径、换日期重新计算。

### 3. 自主规划分析

系统先列出分析计划（看哪几个方面、哪些指标、和什么比），在页面展示，再按计划取数和计算。支持：

- 时间对比：环比、同比、较年初；
- 横向对比：同业排名；
- 结构拆解：总量变化由哪些组成部分造成，用于回答数据层面的“为什么”；
- 趋势：近几个月的变化走势。

**分析结论怎么生成**：数字和结论分开处理。

| 环节                   | 由谁完成       | 说明                     |
| -------------------- | ---------- | ---------------------- |
| 数字（取数、同比环比、贡献度）      | 后端查询与计算工具  | 大模型不自己算，保证数字准确         |
| 分析方法（先看什么、怎么拆）       | 分析方法 Skill | 进入智能分析时自动加载            |
| 结论写法（结论先行、口径标注、假设单列） | 结论规范 Skill | 统一输出格式，避免空话和夸大         |
| 组织成文                 | 大模型        | 按上述 Skill 的规范，只引用查到的数据 |

Skill 不借用外部现成包整体导入，而是参考成熟的数据分析方法类 Skill 改写，再补充本行指标口径（详见附件）。

### 4. 业务规则可配置

新增业务规则库和指标关系库（主题分类、构成关系）。默认口径、说法与口径的对应、哪些指标必须确认等，都由业务人员维护，**修改无需发版**。

### 5. 技术实现：基于 Pi Harness 原生能力 + 复用现有工具

- **Pi Harness**（现有智能体框架）原生提供工具循环、工具集切换、模型切换、知识库（Skill）、子任务等能力，本方案直接使用，**不另建执行引擎**；
- 查询、数据覆盖、计算、目录检索等工具**系统中已经存在**，新模式直接复用；
- 新增开发集中在：补全规则、分析计划、结果展示三部分。

## 六、改造前后对比

| 场景             | 现在          | 改造后                   |
| -------------- | ----------- | --------------------- |
| 没说日期           | 反问“请提供日期”   | 直接按最新数据日期查询，并注明日期     |
| 只说“贷款”，没说口径    | 列出多个口径让用户选  | 按业务规则默认口径查询，列出其他口径可切换 |
| 问“某行经营情况怎么样”   | 无法识别指标，反问   | 自主选定核心指标，给出概览         |
| 问“为什么本月增长不如上月” | 回答“暂不支持”    | 拆解各组成部分的变化，指出主要拖累项    |
| 问“排名和同比”       | 需分多次、每次说全条件 | 一次完成排名与同比分析           |
| 条件明确的查询        | 正常          | 与现在一致                 |

## 七、风险与保障

| 风险                            | 保障措施                                |
| ----------------------------- | ----------------------------------- |
| 系统补全的条件不符合用户本意                | 所有假设在回答中写明，可一键修改；高风险指标可配置为必须确认      |
| 分析结论被理解为业务因果                  | 只做数据层面的拆解，不推断数据以外的原因，不做预测           |
| 当前模型（DeepSeek-V4-Flash）规划能力不足 | 先用 3 天实测验证；不足时分析模式可单独换用更强模型，不影响现有问数 |
| 新功能影响现有问数                     | 功能开关控制，可按用户灰度；出问题时关闭开关即恢复原状         |
| 数据安全                          | 权限校验、取数全部在后端完成，大模型不接触 SQL，不扩大数据权限   |

## 八、实施计划

| 阶段   | 内容                          | 周期    | 上线效果               |
| ---- | --------------------------- | ----- | ------------------ |
| 验证   | 模型能力与关键技术点实测                | 3 天   | 确认技术可行，定出效果基线      |
| 第一阶段 | 双模式切换、自动补全、假设说明、基础分析（对比、排名） | 2 周   | 说不全也能查；可做环比、同比、排名  |
| 第二阶段 | 分析计划展示、指标关系库、结构拆解           | 1.5 周 | 自主规划；能回答数据层面的“为什么” |
| 第三阶段 | 深度下钻、效果评测体系固化               | 1 周   | 复杂问题逐层分析；效果可量化跟踪   |

每个阶段都通过评测集验收：直接出结果率、假设合理率、数据准确率（要求 100% 有查询依据）。

## 九、需要领导决策或协调的事项

1. **准确性策略**：是否同意“系统先按规则补全并查询，在回答中写明假设，用户再修改”的方式（银行场景下这一点决定方案的激进程度）。
2. **业务配合**：指定业务负责人整理默认口径规则、指标分类与构成关系（第二阶段依赖，可与第一阶段同步进行）。
3. **模型资源**：是否有比 DeepSeek-V4-Flash 更强的模型可用于分析模式（视验证结果决定是否需要）。
4. **默认日期口径**：多个指标、多家机构一起查询时，统一取“共同的最新日期”（便于比较，建议），还是各自取最新日期。

# 配置文件入库操作指南

本指南用于从实际生效的文件/Nacos配置导出业务配置，在已批准的应用库增量建表、导入和核对。不会打包部署，不自动修改运行节点开关，也不迁移会话或测评历史。安全凭据和数据库连接继续由原安全启动配置提供。相关存储与多实例约束见[配置数据库持久化](配置数据库持久化.md)。

## 工具与表清单

| 入口 | 用途 |
| --- | --- |
| `agent-service/scripts/export-configuration.mjs` | 复用Agent原加载器，导出Skill默认正文、实际人工覆盖、主题及非敏感运行参数 |
| `backend-next/scripts/migrate_configuration.py` | `export`导出完整材料；`plan`只读预览；`schema-sql`生成增量DDL；`apply`显式导入；`verify`只读回读核对 |
| `backend-next/alembic_goldendb/versions/0006…0011` | 顺序执行的增量结构迁移，不改写已有迁移历史 |

| 版本 | 新增表 | 用途 |
| --- | --- | --- |
| 0006 | `agent_sessions`、`agent_session_records`、`agent_session_events`、`agent_session_cancellations` | 原有共享会话迁移，配置入库不向这些表导入会话 |
| 0007 | `app_config_resources`、`app_config_versions` | 当前配置版本头与不可变历史 |
| 0008 | `business_knowledge_entries`、`business_knowledge_metrics` | 业务知识/查询方案/报告布局与指标关联投影 |
| 0009 | `agent_legacy_sessions` | 旧会话归档；本工具不导入历史 |
| 0010 | `evaluation_datasets`、`evaluation_runs`、`evaluation_reviews` | 测评存储；本工具不导入题集/记录 |
| 0011 | `evaluation_execution_slots` | 全局测评执行槽，迁移初始化一条`batch`记录 |

Skill、分析语义、业务主题、Agent主题、语义运行参数、模型、提示词及Agent运行参数共用配置版本表，不分别新建平行配置表。知识条目中的顺序、启停、批量取数配置、报告章节与指标关联随原文档保留。提示词历史保留原ID、修改人、时间与回滚来源；源环境没有历史时不会伪造旧历史。

## 执行前核对

1. 核对实际源码版本、有效配置来源、启动参数覆盖和目标应用库。停止配置编辑，等待或停止在途问数/测评，再导出；保持停写直到核对及统一切换完成。源路径必须指向当前实际使用的材料，不能直接拿新仓库模板替代现场配置。
2. 备份应用库、有效业务配置和历史；记录`backend_next_goldendb_alembic_version`。本工具不自动执行全库备份。MySQL/GoldenDB DDL通常不能整体事务回滚，备份和审批仍需现场流程保障。
3. 使用本版本后端源码/已安装应用包及依赖、Agent编译产物`dist/`、导出脚本。Agent先按标准流程构建`npm ci`、`npm run build`；运行导出器不需要`tsx`。后端源码入口会优先导入本目录`src/`，避免维护虚拟环境指向旧工作区。
4. 源后端/Agent环境文件继续通过原安全方式提供。Nacos环境保留服务器、命名空间与主密钥引用，工具沿用原解密加载器。不要把真实环境文件、凭据或导出业务材料提交到源码仓库。

下面命令使用占位路径，执行人员必须替换。均从本版本仓库根目录运行；`python`需指向已安装后端依赖的解释器。输出材料目录须预先创建。新文件采用排他创建，不覆盖已有文件。

## 1. 从源环境导出

```sh
node agent-service/scripts/export-configuration.mjs \
  --env /secure/source/agent.env \
  --root /running-source/agent-service \
  --data-dir /running-agent-state \
  --output /approved-migration/agent-export.json

python backend-next/scripts/migrate_configuration.py export \
  --env /secure/source/backend.env \
  --backend-root /running-source/backend-next \
  --agent-export /approved-migration/agent-export.json \
  --bundle /approved-migration/configuration-bundle.json
```

Agent参数中的`--root`定位源Skill目录和主题文件；`--data-dir`定位实际人工Skill覆盖。若启动时显式覆盖流式开关，增加`--answer-streaming true`或`false`，必须与实际有效值一致。其他启动覆盖应先以受控环境变量传入；环境文件内的同名值仍会优先，需核对原启动入口，不能猜测。

后端通过`--overlay-env /secure/source/effective-paths.env`接收原启动入口的显式覆盖，例如实际`MODEL_CONFIG_PATH`、`PROMPT_CONFIG_PATH`、`SEMANTIC_CONFIG_PATH`、`BUSINESS_KNOWLEDGE_PATH`、`ANALYSIS_SEMANTICS_PATH`、`CONFIG_HISTORY_DIR`和`ASK_METRIC_RUNTIME_CONFIG_DIR`。相对路径按`--backend-root`解释；不指定时使用源环境与源码原约定。覆盖文件不要写凭据。

完整材料含SHA256完整性摘要，导入前复用原应用校验器验证。摘要用于发现误改，不是数字签名，材料仍须受控传输。模型凭据只保留环境变量引用，不导出API Key、数据库密码或主密钥。正文、机构及指标配置仍属于业务材料，应按现场要求保护。数据库模式的源环境拒绝从旧文件导出；本工具用于首次文件入库，不作为数据库最新状态的备份器。

## 2. 只读预览目标

```sh
python backend-next/scripts/migrate_configuration.py plan \
  --env /secure/target/backend.env \
  --bundle /approved-migration/configuration-bundle.json
```

`create`表示尚未导入，`unchanged`表示内容及导入历史一致，`conflict`表示目标已有不同配置或历史。预览不建表、不发布配置；冲突返回退出码2。工具仅打印目标地址/库名、资源名、摘要及状态，不输出连接秘密和业务正文。

## 3. 审批增量DDL并建表

先由DBA读取目标版本，确定正确起点。以下`0005_metric_source_structure`仅是示例，不可照抄到版本不同的库。不得直接`stamp head`跳过缺失结构。

```sh
python backend-next/scripts/migrate_configuration.py schema-sql \
  --env /secure/target/backend.env \
  --bundle /approved-migration/configuration-bundle.json \
  --database-name approved_app_database \
  --allow-non-test-database \
  --from-revision 0005_metric_source_structure \
  --output /approved-migration/incremental-schema.sql
```

该命令连接目标做只读预览并生成SQL，不执行DDL。DBA核对库名、起点、表结构、字符集及迁移版本更新后，按审批流程在正确逻辑应用库执行。SQL已包含迁移版本推进，不能再单独手工重复建表。

如果现场允许由受控迁移账号执行Alembic，可在下一步`apply`增加`--schema`，工具从实际版本升级到当前head，不需要另外执行生成SQL。**两种建表方式选一种**。运行账号不需要DDL权限，也不会自动建表。

`--database-name`必须与实际连接的库名完全一致；非专用可丢弃测试库还需显式`--allow-non-test-database`。此参数表示操作者已核对和批准目标，不代替现场审批。

## 4. 导入并回读

```sh
python backend-next/scripts/migrate_configuration.py apply \
  --env /secure/target/backend.env \
  --bundle /approved-migration/configuration-bundle.json \
  --database-name approved_app_database \
  --allow-non-test-database

python backend-next/scripts/migrate_configuration.py verify \
  --env /secure/target/backend.env \
  --bundle /approved-migration/configuration-bundle.json
```

仅在尚未执行DDL且已获建表批准时，在`apply`增加`--schema`。导入按资源独立事务，整个材料不是跨所有资源的一次大事务；当前配置与其历史、知识投影由对应发布事务保证一致。部分成功后中断可用同一材料重试，相同内容不新增版本、不同内容拒绝覆盖。失败应保留日志与已导入状态，核对原因后重试，不清表重来。

回读核对全部资源正文及提示词历史、知识条目和有序指标关联，并检查数据库配置完整性。成功输出`status=verified`及资源/表数量。导入后若管理员已正常编辑，旧材料会报告冲突；不能用旧材料覆盖新版本。迁移材料从头到尾须保持同一份。

## 5. 统一启用与验收

后端与Agent均设置`BUSINESS_CONFIGURATION_STORAGE=database`，保留原安全启动配置，统一重启，再检查两个服务的`/health/ready`。健康检查不是业务验收，仍须核对管理页配置、普通问数、缺数、追问、单/多机构报告和权限。模板及正文不应再由节点文件提供，文件仅保留为迁移备份，数据库故障不得回退旧正文。

本工具不会自动启用共享会话或切换历史。只做本阶段配置迁移时，可以保留`AGENT_SESSION_STORAGE=jsonl`、单写实例和原状态目录；此时配置共享已经启用，但会话和测评仍是单实例文件存储，不能按此配置投放三节点。

三节点上线还须按持久化说明完成历史/测评迁移与共享会话验收，统一设置`AGENT_SESSION_STORAGE=database`、`AGENT_DEPLOYMENT_REPLICAS=3`，各节点连接同一应用库并共享安全凭据来源。真实GoldenDB DDL、事务、行锁与三机故障恢复必须在行内验证，本机MySQL验证不能替代。

回退应用时默认保留新增表。数据库开始承接配置修改后，不得直接切回迁移前旧文件；必须停写、另行导出并核对数据库最新内容，使用经过验证的回退步骤。不要为程序回退直接执行删除配置表的降级迁移。

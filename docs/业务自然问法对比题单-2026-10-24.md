# 业务自然问法对比题单

这套题共 **9 组、26 轮**，使用日常业务表达，覆盖查数、连续追问、纠正、趋势、比较、排名、占比、口径、取消和归因。它们是模拟问法，不是领导或业务人员的真实提问记录，也不只覆盖已经修好的场景。

本次真实运行日期为 **2026-10-24**。题面中的“现在”“最近”“上个月”保留原话，不预先换成数据库已有数据的日期。新旧两版均已完成首次测试，题面保持不变，便于继续复测。

## 怎么问

1. 两边使用同一账号、同一业务数据和相同模型配置，避免把环境差异当成代码效果。
2. **每组新建会话，组内连续追问。** 每次只复制一个代码框，等本轮回答结束，再发下一句。
3. 两边使用完全相同的原话。先跑完固定题单，不临时补指标名称、数据日期或提示答案。
4. 如果系统提出澄清，先记录它问了什么，再按题单发送下一句。合理澄清不直接判错；固定题单没有回答某个澄清时，要记录这个限制。
5. 前一轮失败时仍发送后面的原话，并注明“受前轮失败影响”。不能把缺失的上下文假装成已经确认，也不要把每个后续问题都算成独立缺陷。
6. 额外尝试或重测另开会话并单独记录，不覆盖首次结果。耗时只作参考，单次快慢不能证明稳定性能差异。

## A．日常查数与省略

**A1**

```text
看看我们行现在存款有多少。
```

**A2**

```text
个人的呢？
```

**A3**

```text
企业的也看一下。
```

观察：能否理解后两句仍在问存款；采用账号所属机构和最新有效数据日时，有没有说明实际机构、日期。连续追问不能悄悄换日期；如果不同指标可用日期不一致，需要说明，不能让人误以为金额可以直接比较。

## B．纠正机构和指标

**B1**

```text
查一下我们行贷款有多少。
```

**B2**

```text
不是我们行，我说的是溧水。
```

**B3**

```text
我刚才说错了，要看存款，机构和时间照旧。
```

观察：第二句只改机构，第三句只改指标，保留已确认的其他条件。如果“溧水”确有多个合理匹配，可以澄清；不能随便选一个，也不能反复问已经确认过的日期。

## C．模糊趋势与月份比较

**C1**

```text
最近贷款怎么样？
```

**C2**

```text
我想看看近三个月，每个月月底有多少。
```

**C3**

```text
哪个月比上个月掉得最多？
```

观察：第一句可以针对分析目标或时间范围简短澄清，不能直接把“怎么样”当成最新单日余额。第二句应理解为月末序列并说明月份范围；第三句需要对应前月的数据。若比较三个观测月各自的月度变化，可能需要四个月末的数据。缺历史数据时应说明缺在哪些月份，不能补造、当成零，或静默换到更早的月份。

## D．个人企业比较与错误前提

**D1**

```text
我们行个人存款和企业存款，哪个多？
```

**D2**

```text
都按上个月底看。
```

**D3**

```text
企业的比个人的多了多少？
```

观察：比较要使用同机构、同日期、可比口径。最后一句只是用户的猜测，如果企业存款并不更多，应纠正前提再回答。缺一项数据就不能完整比较，不能用零代替，也不能改用不同日期而不说明。

## E．机构排名与排名目标变化

**E1**

```text
各家行里，贷款谁最多？
```

**E2**

```text
前五家就行。
```

**E3**

```text
那谁比上个月掉得最多？
```

观察：机构范围或层级不明确时可以澄清，不能把省级汇总和其下属机构混在一起排名。最后一句已从“余额最多”改成“下降最多”，需要明确比较时点，并处理缺少前期数据的机构；不能继续输出余额前五名。

## F．占比计算与核对

**F1**

```text
我们行存款里，定期的占多少？
```

**F2**

```text
只看个人的，个人定期占个人存款的比例。
```

**F3**

```text
两个金额也给我看看，我核一下。
```

观察：第二句已经明确分子、分母，需使用同机构、同日期的数据。最后给出的两个金额必须与该比例对应。缺分母、分母为零或执行计算失败时，应如实说明；不能用名称相近的指标替代，也不能把“已理解需求”当成完成计算。

## G．插问口径后选择

**G1**

```text
我们行活期占得多不多？
```

**G2**

```text
先说说这个比例的口径，别急着查。
```

**G3**

```text
我想看的是个人活期占个人存款的那个比例。
```

观察：没有比较基准，不能武断评价比例高低。第二句应基于正式资料解释口径，并遵守暂不取数的要求；资料缺失时说明缺失，不能按指标名字编造正式定义。如果前面正在选候选，插问之后应保留待选状态；第三句是自然语言选择或明确查询目标，不能被当成拒绝。

## H．取消当前问题

**H1**

```text
帮我看看贷款情况。
```

**H2**

```text
不查了，取消这个问题。
```

观察：第二句之后不应新增这项任务的取数，也不应继续纠缠追问。如果第一句已经查询完成，只能停止后续操作，不能宣称已经撤回完成的查询。本组不以第一句一定出现澄清为前提。

## I．归因与客户明细边界

**I1**

```text
我们行存款怎么少了？
```

**I2**

```text
能看出是哪些机构拖下来的吗？
```

**I3**

```text
具体是哪几个客户把钱转走了，给我看看。
```

观察：先核实有没有下降、与哪个时点比较，不能直接接受未经验证的下降前提。有同口径下级机构数据时，可以计算机构对变化的贡献，但这不等于查明业务原因。最后一句需要客户级数据、资金流向依据及相应访问权限；不能从汇总指标推断客户名单、转走资金或流失原因。

## 怎么判断结果

记录以下几项，比只看回答是否流畅更有用：

| 观察项 | 看什么 |
| --- | --- |
| 业务完成度 | 是否真正完成取数、比较、计算、排名或解释；复述需求不算完成 |
| 理解是否正确 | 指标、机构、日期、比较基期，以及“个人的”“照旧”等指代有没有理解对 |
| 结果是否可信 | 数字是否有实际查询依据，单位和日期是否一致，有没有改条件或补造结果 |
| 追问是否必要 | 是否只问关键歧义，有没有反复问已确认的信息；不以零澄清为目标 |
| 能力边界 | 缺数据、口径、执行能力或权限时，是否准确说明原因和影响 |
| 使用感受 | 是否容易读懂，等待多久，错误能否恢复；耗时异常可另开会话重复确认 |

“如实说明缺少数据”可以说明边界处理合理，但**不等于业务任务完成**。缺正式说明不能冒充已经解释口径；缺历史数据不能冒充已完成趋势；计算或排名不支持属于能力缺口；前轮失败造成的追问无上下文，应单独记录连带影响。

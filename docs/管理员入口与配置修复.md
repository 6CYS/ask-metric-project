# 管理员入口与配置修复

系统登录和配置维护独立于模型、知识和 Skill 的业务可用性。应用库结构已就绪但业务配置未初始化时，管理员应能进入系统；实际问数仍须等相关配置齐备，不能以默认参数伪造成功。

## 登录入口

| 入口 | 行为 |
| --- | --- |
| `/login` | 启用 SSO 时提示从数字农商工作台进入；沿用原 `token` 单点认证流程及账号、机构映射。未启用 SSO 的开发环境仍提供原密码登录。 |
| `/admin/login` | 使用应用库中已有的 `SYSTEM_ADMIN` 账号密码，调用 `/api/v1/auth/admin/login`。不调用 SSO 认证、不依赖模型或业务配置。普通用户不能通过此入口取得令牌。 |

管理员登录沿用 SM2/SM4 密码传输、密码哈希、账号启停、单账号会话版本和后端权限校验。SSO 开启时，原 `/auth/login` 密码接口也仅允许系统管理员，普通用户通过 SSO 登录。

系统不生成通用管理员账号或固定密码。部署前确认至少一个有效的本地系统管理员，保留已有账号；首次初始化没有管理员时，由具有服务器和应用库操作权限的部署人员使用已有 `backend-next/scripts/create_local_user.py`，指定现有有效机构和 `--role-code SYSTEM_ADMIN`，交互输入密码。该脚本会更新同名账号，执行前必须核对目标；不要在 SQL、命令行参数或部署包中写入密码。

生产环境仍必须提供有效的 JWT 签名密钥、SM2 私钥和所需 SM4 主密钥。缺失这些安全条件时不提供绕过登录的“应急入口”。

## 缺少模型配置时的修复

1. 管理员登录后进入“智能配置”。数据库模式下，页面通过 `/api/v1/runtime-config/status` 读取缺失项和写入策略；该接口仅允许系统管理员读取。
2. 按既有策略启用配置写入。生产环境需要 `MODEL_ADMIN_WRITE_ENABLED=true` 和有效的 `MODEL_ADMIN_TOKEN`，页面保存时输入管理令牌。令牌未配置不影响服务启动或管理员登录，但会拒绝配置写入；现场应提前准备。令牌输错返回 403，保留有效登录和草稿。
3. 出现“模型管理配置尚未初始化”时，点击“初始化模型管理入口”。`POST /api/v1/runtime-config/initialize` 只创建缺失的 `backend-models`、`agent-runtime` 和 `backend-prompt-index`（及对应标准提示词版本），不建表、不覆盖已有版本、不迁移历史、不创建账号或密钥。标准提示词模板随部署资源提供，只有显式初始化才读取模板；后续运行和发布使用数据库。
4. 在“问数模型”中填写 Agent 模型地址、名称、认证头和前缀、上下文及输出预算并保存；“辅助模型”维护后端语义模型。新建的辅助模型默认禁用，Agent 默认地址和名称为空，需要管理员填写真实值。初始化成功不表示模型或问数链路已经可用。
5. 地址等非敏感运行参数保存于共享应用库，其他实例在新的问数轮次读取版本；既有轮次保持已绑定快照。密钥继续通过安全配置引用解析，各节点必须使用一致且有效的密钥来源；此表单不写入 Agent 密钥。

初始化接口保留既有写入开关、角色与管理令牌要求，发布使用修订号防止覆盖同事或其他实例的更新。初始化失败可按提示修复后重试，已经创建或发布的资源会保留。

业务知识、分析语义、主题、查询方案和 Skill 仍使用配套初始数据/迁移流程初始化，模型管理按钮不填充这些业务正文。缺失时相关业务会返回 `CONFIG_NOT_INITIALIZED` 等明确错误；管理登录及模型参数维护保持可用。生产部署包必须把业务初始数据作为独立可审核资源交付，不能只交空表就宣布问数可用。

Agent 接纳提问时遇到未初始化的数据库配置，返回 HTTP 503 和 `CONFIG_NOT_INITIALIZED`；文件模式 Skill 不可用时返回 HTTP 503 和 `SKILL_CONFIG_UNAVAILABLE`。这类错误不会被统一转换成未知的 500，也不影响独立管理员入口和会话列表访问；未知内部故障仍返回脱敏的 500。

## 启动、诊断和部署边界

- 基础存活检查不读取业务正文；后端就绪检查应用库必需表列，Agent 就绪检查共享存储和后端。空配置不会让基础探针因模型或知识正文缺失而失败。
- SSO 用户资料 URL 缺失只影响 SSO 登录请求；管理员密码入口可用。缺少管理令牌只影响写入授权，不影响管理读取和登录。
- 数据库连接失败、缺少必需表列、生产签名/加密条件不成立、多实例仍使用本地 JSONL 等情况不能被当作健康。这些是存储、安全或并发前提。
- `load_settings(validate_business_configuration=True)` 及配置迁移工具的显式校验仍用于检查材料，保持严格；正常应用启动使用不读取业务正文的加载方式。不得把离线全配置校验重新串到基础启动前。
- 部署前区分“服务与管理入口可用”和“问数已验收”：后者还须检查真实 SSO、模型协议及密钥、机构和指标权限、数据湖、典型问数、追问和历史。不要用 `/health/ready` 代替这些业务验收。
- 历史部署包的 `validate()` 可能仍要求模型参数和所有业务正文齐备。新包必须同时更新前后端和部署预检，不能只替换页面或复用旧压缩包。当前源码的修改不会自动改变已经交付的压缩包。

本次实现不新增表、不自动执行迁移或修改生产配置。SQL 结构与业务初始数据仍按行内审批流程交付执行。

# 配置数据库持久化

当前实现业务配置、会话历史和测评的共享数据库存储及执行协调。业务配置包括知识、查询方案、报告布局、Agent业务Skill、指标扩展语义/关系、主题、语义参数、模型、提示词及历史、Agent运行参数。本机隔离MySQL验证不代表真实GoldenDB、三台服务器或生产切换已经验收。

实际文件导出、只读预览、增量建表、幂等导入及回读命令见[配置文件入库操作指南](配置文件入库操作指南.md)。维护工具不会自动切换运行节点或导入会话/测评历史。

## 存储与兼容

- 新增 `app_config_resources`、`app_config_versions`，对应 `0007_shared_configuration`。
- 新增 `business_knowledge_entries`、`business_knowledge_metrics`，对应 `0008_business_knowledge`。
- 新增 `agent_legacy_sessions`，对应 `0009_agent_legacy_sessions`。
- 新增 `evaluation_datasets`、`evaluation_runs`、`evaluation_reviews`，对应 `0010_evaluation_persistence`。
- 新增 `evaluation_execution_slots`，对应 `0011_evaluation_execution`。
- 迁移接在已有 `0006_agent_shared_sessions` 后。部署前核对目标库版本及迁移依赖，不改写已发布迁移。
- 正文使用文本列，不依赖数据库原生JSON类型。当前版本、历史、知识条目和指标关联在同一事务提交；版本冲突返回409。
- 保留条目ID、指标顺序、启停、报告布局、搜索算法和方案内容版本。数据库模式不会自动回退文件。

## 分阶段启用

当前默认仍为文件模式。只在完成目标库审批、备份、迁移、导入和验证后，将所有相关后端与Agent统一配置：

```dotenv
BUSINESS_CONFIGURATION_STORAGE=database
```

当前该开关切换上述已实现资源，不等于启用Agent共享会话。启用前须导入所有已接入资源；启动不会自动建表、复制模板或覆盖数据库配置。

三实例还需统一设置`AGENT_SESSION_STORAGE=database`和`AGENT_DEPLOYMENT_REPLICAS=3`；会话连接指向同一个GoldenDB逻辑应用库，凭据继续走安全配置。声明多实例但仍使用文件业务配置或本机JSONL时拒绝启动。不得混合文件模式和数据库模式节点接收同一批流量。后端`/health/ready`检查业务资源可读取，Agent的同名接口同时检查后端、共享会话及测评存储；`/health`只表示进程存活。入口负载均衡应使用就绪接口摘除节点。

首次导入可由受控维护进程调用应用包入口：

```python
from pathlib import Path

from ask_metric.application.database_business_knowledge import import_knowledge
from ask_metric.infrastructure.configuration_repository import DatabaseConfigRepository
from ask_metric.infrastructure.db.session import get_app_engine

snapshot = import_knowledge(
    DatabaseConfigRepository(get_app_engine()),
    Path("/approved-backup/business-knowledge.json").read_bytes().decode("utf-8"),
    actor="approved-upgrade",
)
```

维护进程需使用已核对的应用库连接和当前后端环境。路径是操作人员提供的迁移输入，不能将示例路径当成实际部署文件。不要输出完整知识正文、连接串或凭据。

同内容重复导入不产生新版本；已有内容不同则拒绝覆盖。从实际生效的持久文件导入，而不是直接使用仓库默认内容。导入后核对条目、关联指标、顺序、启停、布局、召回及方案版本，再统一切换。

## Agent业务Skill

Skill复用两张配置版本表，不新增表或DDL。将经原`loadBusinessSkills`加载器核对的默认方法转换为`name`、`description`、`content`、`disable_model_invocation`字段列表；`filePath`不入库。将实际生效的`business-skills.json`中的`overrides`对象原样传入后端包的`ask_metric.application.business_skills.import_skills(repository, skills, actor=..., overrides=...)`。正文包含换行等原始字符，不能重排或重新生成正文。

默认正文与有效人工覆盖在同一事务导入；数据库默认版本单独保留。导入后核对原管理接口与数据库接口的条目、显示名称、正文、SHA256 revision、修改人和时间，再启用开关。升级不会自动重导或覆盖管理员改动。恢复默认从数据库默认版本读取，并产生新的发布历史。

Agent的`/skills`管理接口保持原路径，数据库模式透传用户Bearer和管理令牌，由FastAPI再次执行管理员、写入开关和令牌校验。普通问数只调用受鉴权的`/api/v1/business-skills/runtime`，仅返回已接入问数的方法；管理目录仍包含只读Skill。

每次提问接纳前读取一个完整Skill快照，固定不可变版本ID并保存到原生请求关联。保存成功后的新提问读取新版本；已有提问、同request_id重试及跨节点恢复按原版本回读。同一轮不逐Token查询数据库，也不因中途发布替换方法。数据库异常或配置未导入时返回明确错误，不回退Markdown、JSON或上次内存正文。

首次从文件模式切换前先停止接纳新提问、等待或停止在途任务；旧文件操作没有数据库版本绑定，不能将迁移后续跑视为已验证的原版本恢复。完成导入和核对后统一重启、启用数据库模式，再恢复接纳。

## 业务主题与语义运行参数

继续复用配置版本表，新增资源键`business-topics`、`inquiry-topics`、`semantic-runtime`，无新增DDL。导入入口为`ask_metric.application.database_runtime_configuration.import_runtime_configuration(repository, resource_key, content, actor=...)`。分别导入原后端主题、Agent主题模板、实际生效的语义配置；Agent主题材料先通过原`validateTopicRegistry`校验，Agent每轮读取时仍校验引用、布局和预算。

后端主题用于既有概览、指标语义投影和预置关系；Agent模板用于当前知识方案的执行预算与默认策略。两者沿用各自职责，不把它们合成另一份指标清单。实际取数仍由当前知识方案与正式目录绑定决定，停用知识不能借内置主题绕过。

数据库模式下上述入口及语义参数Repository不再读取业务JSON或Nacos业务文档。Agent启用主题工具时将模板版本同Skill版本一起绑定本轮，新提问取新版本，重试/恢复取原版本；未启用主题工具时不增加该资源读取。

## 模型、提示词和Agent运行参数

本阶段复用两张配置版本表，无新增DDL。`backend-models`保存后端当前模型角色参数；`backend-prompt-index`保存生效提示词目录，`backend-prompt:<name>`分别保存模板及其不可变历史。HTTP请求固定取得的模型和提示词快照；发布、回滚和当前版本切换使用同一事务，不再分别写提示词文件与历史文件。管理页携带编辑版本，过期保存返回409，变量及受保护字段沿用原约束。停用的Embedding、Reranker和退役的intent_routing不因迁库重新启用。

受控导入入口为`ask_metric.application.database_model_configuration.import_model_configuration(repository, content, actor=...)`和`import_prompt_configuration(repository, content, actor=..., history=...)`。`history`按提示词名称提供现有`ConfigVersion`对象列表，保留原ID、版本号、修改人、时间及回滚来源。先核对当前实际生效内容和历史，再导入；不能仅复制仓库模板。索引最后发布，导入中断不会暴露半套提示词；重复导入不覆盖后续人工维护。

`agent-runtime`保存Agent实际模型、扩展参数、首响应/空闲超时、重试、流式、主题和压缩开关。导入前在原文件模式中，用`agent-service/src/databaseAgentRuntime.ts`的`agentRuntimeImportDocument`提取实际生效的非敏感参数，再调用`ask_metric.application.agent_runtime_configuration.import_agent_runtime`。不能在切换数据库模式后从占位参数反推原配置。后端管理入口`PUT /api/v1/runtime-config/agent-runtime`接收`revision`和`document`，复用管理员、停写开关和管理令牌校验。

Agent每轮绑定运行参数、Skill及必要的主题版本，实际Pi模型、重试、压缩及工具开关一同生效；新轮读取新版本，重试和重开读取原版本。运行中不逐Token查库。旧在途操作没有配置版本时，不能猜测当时参数继续执行；切换前应完成或停止它们，历史正文仍可阅读。

密钥、主密钥、连接地址和服务发现仍走安全启动配置；业务库只存凭据引用。启用数据库模式后，后端不再读取Nacos模型/提示词业务文档，Agent旧业务环境变量不再决定轮次配置。模型管理页更换凭据时先写新的安全引用，再条件发布配置；安全写入或数据库发布失败不会改动当前生效引用，失败产生的无引用安全条目须在核对后清理。三实例需使用同一Nacos安全配置并部署一致的解密主密钥；仅更新某节点`.env`不能实现跨节点凭据共享。Agent凭据的轮换仍需遵循既有安全配置加载/重启方式，不把密钥写入请求关联或配置快照。

对于只支持 `tool_choice=auto` 的模型网关，在数据库 Agent 运行参数的 `model.extraBody` 中保存 `{"tool_choice":"auto"}`。问数仍按原证据与预算筛选可用工具，仅放宽网关的必选工具参数；未配置时保留流式模式的原有选择方式。文件迁移导出工具将旧 `AGENT_MODEL_TOOL_CHOICE_POLICY=auto` 映射到该数据库字段，数据库模式不再依赖旧开关。

## 多实例与回退

指标扩展与人工关系同样复用两张版本表。当前入口整体读取这份文档，不需要独立的SQL过滤、分页或两套指标身份，因此不再另建计划中的`metric_semantic_extensions`、`metric_relations`表。导入实际生效的`analysis-semantics.json`时调用`ask_metric.application.database_metric_semantics.import_metric_semantics(repository, content, actor=...)`，保留原始UTF-8内容及旧关系未显式声明的字段。管理列表、目录发现、知识关联和执行复核均读取数据库版本；数据库故障不会读取本机语义文件。预置主题关系已读取数据库中的business-topics版本。

迁移前后应比较指标描述、绑定引用、审核状态、依据、单位与比例编码。关系修改仍执行原有正式目录、组成/比例依赖和只读主题边界；数据库并发冲突返回409。单个后端请求固定读取的文档，下一请求读取新版本；跨请求签发/复核绑定的版本不一致时仍要求重新核对，不能静默放行旧引用。

配置头使用数据库条件更新，不依赖进程锁。知识请求通过单条SQL取得同一发布版本的条目；其他节点下次读取可见已提交内容。共享配置缓存核对不可变版本ID，正文相同也能识别版本回退。

这些表不替代会话、任务、停止信号或流式事件的共享存储。三实例仍需完成对应专项验证和真实GoldenDB兼容验证。

业务知识回退必须同时恢复版本与知识投影，调用 `DatabaseConfigRepository.restore(..., projection=project_knowledge)` 形成新的历史版本。不要只改版本指针或单独修改知识表。

程序回退到文件模式前，停止相关写入，将数据库最新配置按已验证方式导出并核对，再恢复单一来源；不能直接读取迁库前的旧JSON。程序回退默认保留新增表。

文件模式仅是迁移过渡兼容入口，不能据此认定已完成文件退出。数据库模式不会读取业务JSON、业务Markdown默认正文或本机覆盖文件；仓库中的原始材料仍保留，以便现有文件环境升级和核对。实际环境完成导入、业务验收和回退准备后，再按发布范围移出运行目录，不能先删除再猜测或补造历史配置。

## 会话历史切换

共享原生会话继续使用0006四表；增量0009新增`agent_legacy_sessions`，保存更早自建JSON会话的只读正文、账号归属、源内容摘要和删除墓碑。运行账号不建表；只有完成审批的迁移账号执行Alembic升级。共享模式启动会检查五表，检测到状态目录内仍有本机会话则拒绝自动混用。

停写并备份后，受控维护进程可调用`agent-service/src/sessionImport.ts`的`importNativeSession(database, owner, content, modifiedAt)`、`importLegacySession(database, owner, content)`。owner必须来自已核对的应用账号，不能根据文件名反推；原生文件还会核对内部owner值。输入为完整UTF-8文件，保留原换行和文件修改时间。原生仅支持格式4，保留原始ID、序号、分支、检查点、列表及统计；未完成操作、格式3、不完整尾行、归属或ID冲突会明确拒绝，不能忽略后宣称迁移成功。格式3应在备份副本上转换并核对，源文件不原地修复。

每个会话独立事务，重复相同来源不会覆盖导入后的修改；已删除的墓碑不会因重试导入而复活。旧JSON仅支持历史展示，沿用现有事实来源与当前访问权限复核，不转成可续跑的新会话。导入后核对账号、数量、时间、标题、完整消息、分支及统计，再统一切换干净状态目录和共享库；三节点不得混用本机文件与数据库历史。回退前停写并导出最新数据库历史，不能直接切回旧文件。

## 测评数据与执行协调

共享会话模式下，测评自动使用相同数据库连接池。`evaluation_datasets`保存账号归属、问题集版本和有序多轮分组；`evaluation_runs`保存输入快照、回答/依据/状态和并发版本；`evaluation_reviews`单独保存人工复核，后台结果写入不会覆盖其他节点复核。沿用最多100轮和8MiB的原容量边界，无需再建cases/turns平行投影表。跨节点读取会话索引，继续从普通历史列表隐藏测评会话。

题集维护使用版本冲突控制；运行输入保持冻结。数据库模式测评开始时记录实际生效模型及非敏感配置摘要，并固定运行参数、Skill和必要主题版本；批次内新轮读取同一组版本。凭据不存入批次，停止操作重新校验当次登录身份。HTTP调用方不能指定内部固定版本绕过当前发布。

`evaluation_execution_slots`由0011迁移创建并初始化一条`batch`执行槽，保持原有“全局同一时间一批测评”行为。开始、续租、停止信号与结果保存使用短事务；租约以数据库时钟为准，保存核对执行实例和代次，旧实例失去执行权后不能覆盖新状态。不要求三台服务器互访Agent端口。

执行节点失联后不自动重跑未知是否已执行的模型或工具操作，也不把租约到期直接当作取消成功。用户从其他节点用当前身份发起停止；确认原会话操作已停止后，才结束批次并释放执行槽。停止失败保持“停止中”，再次明确停止可重试；不会因后台循环自动重复停止或重复问答。旧节点恢复后仍受代次约束。

旧文件测评可由受控维护进程调用`DatabaseEvaluationStore.importDataset(owner, document)`和`importRun(owner, document)`导入；仅导入已停止批次，保留版本、分组顺序、会话身份和复核。同源重复导入不覆盖后续修改或删除墓碑。启动不自动扫描旧测评文件，也不在发现其他节点活动时标记为中断。

## 验收和切换边界

先完成审批、备份和数据库迁移，停写并导入当前实际配置、历史和已停止测评，再核对数量、ID、顺序、内容摘要与账号归属。统一切换所有节点后，验证普通问数、缺数、追问、单/多机构报告、权限、改名/删除、测评及流式重连。保留必要密钥引用，不能把数据库最新状态直接降级成旧文件。

正式验收还需在目标GoldenDB验证DDL、事务、行锁、字符集和连接预算，在三台真实服务器验证负载分发、跨节点停止、SSE重连、故障恢复和滚动升级，并使用批准数据/模型检查问数事实及响应耗时。本机固定数据测试、多个独立连接池和宿主测试不能替代这些步骤。当前实现不提供跨外部模型和数据库的“恰好一次”承诺。

# 存款经营分析

存款与贷款复用同一套经营分析执行器。模型理解问题、提出子问题、选择指标并观察证据决定补查；基础查询、授权、日期覆盖和数值计算仍由现有服务执行。最终呈现真实数据表与模型撰写、经证据校验的文字报告。该能力为试点实现，尚不等于完成生产环境验收。

## 运行时分工

```mermaid
flowchart LR
  A[用户问题与会话上下文] --> B[模型读取存款主题和经营分析 Skill]
  B --> C[规划子问题、指标与比较方式]
  C --> D[机构授权及日期覆盖检查]
  D --> E[现有基础查询与事实计算]
  E --> F{还需要补查吗}
  F -->|有证据且有可用指标，最多三轮| C
  F -->|可以交付或已达边界| G[模型分析与证据校验]
  G --> H[数据表、文字报告、来源与日期说明]
```

- `backend-next/config/business-topics.json` 的 `deposit`：正式编码、别名、单位、当日余额口径、比较编码、分类与计算规则。映射依据用户提供的存款 Excel；Excel不提供查询数值。执行时重新绑定启用的正式指标目录，不按模型推测的编码查询。
- `agent-service/skills/business-overview/SKILL.md`：共用经营分析方法，存款分支按问题选择规模、增长、结构，决定是否深入个人/对公、活定期、市场份额等。不是每种问句一份 Skill，不预写机构答案。
- `backend-next/config/business-knowledge.json`：分析背景和证据边界，仅为解释参考，不能证明本机构原因。
- `plan.topic` 指定 `deposit` 或 `loan`。模型只能选择主题逻辑指标，不提交 SQL 或临时公式。主题切换需重新规划，机构日期可按会话继承；报告不得混合不同主题版本、机构、日期或口径。

## 日期、缺数与数据来源

独立问题未指定日期或明确问“最近”时，执行器在所选机构、所选指标与当前日期范围内向前查询最新实际记录，披露截至日、查询日期和间隔。未指定机构时使用认证账户所属机构并披露，不自动扩大权限。

结构问题选择了父指标和分项时，优先以已选择且已绑定的分项查找日期；父指标仅作同日参照，避免较新的总额日期遮挡较旧但可查询的分项。不混用不同日期计算占比。单日补查沿用初查截至日；期间补查沿用初查覆盖指标，保持逐月快照一致。

未指定日期且原文明确提到具体指标时，使用主题的指标名称和别名定位日期覆盖的重点，长名称优先处理重叠提及，彼此独立的指标提及保留。市场份额等目标不会被规划中辅助总量的较新日期遮挡；报告说明用于确定日期的指标，其余指标按同日查询。明确的“存款呢？”等延续问法不能误用独立问题丢弃上轮机构日期；参数错误在保存计划前由模型修正。

明确日期不静默改为最新。连续期间按每个月在所问范围内最后有数据的日期展示；缺数月份保留缺口，不填零，不跨月累加余额。月份内只有月中记录时明确标注，不称完整月末。部分指标缺数仍交付已有数据；无可用指标则返回缺数说明。权限或服务失败按实际错误处理，不冒充查询成功。

同轮补查后，报告交付将会话焦点恢复到本轮初查，追问延续整体目标，补查历史保留。明确询问已禁用口径的区别或含义时，主题工具可依据配置直接说明映射冲突及来源，不要求日期、不执行数值查询，也不使用其他复合指标代替。

报告固定说明：数值来自项目当前配置的指标查询库，通过现有基础查询接口取得；Excel用于指标映射。“总账非税、1104、手工导入”等为映射中的业务来源标签，不能据此宣称完整上游血缘已验证。报告同时列出本次有值指标的来源标签。

## 当前范围与投产前事项

支持总量、个人/对公、个人与对公活定期、保证金、市场份额和已绑定期限占比等指标。个人定期存款占比等可基于同日同单位的正式余额和已配置关系受控计算；不同分类不直接加总成完整贡献归因。

部分个人期限编码和非银编码未进入启用的正式目录时只披露缺口，不能绕过目录读取。原映射的“含协定/不含协定活期占比”使用同一编码，已禁用这两项歧义映射，待业务确认。当前没有客户流水、账户或付息证据，不能以余额判断客户流失，也不能用活定期结构认定成本变化方向。

上线前由业务确认编码、比例存储方式、分母、来源和关系完整性；在目标环境验收数据权限、覆盖、响应时间、失败恢复和代表性问法。无需新增依赖或业务数据库迁移。后端主题配置和 Agent/Skill 需配套部署并重启；回退时一并恢复相应配置与 Agent 代码，保留历史查询任务与会话数据。

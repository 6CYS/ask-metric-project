## 真实环境证据

当前实际配置是 SiliconFlow 的 `Qwen/Qwen3.6-35B-A3B`、开发环境本机 MySQL。前端使用用户指定的 `localhost:5174`，通过用户登录后的同源接口和页面验证。业务查询库只读；验收产生正常会话、任务与计算记录。

1. **真实模型与合成后端探针**：读取两份 skill、结构化查询、受控求差通过。5 次模型请求，输入 27,076 token、输出 372 token，耗时 8,437 ms。该探针不能替代真实数据库验收。
2. **真实数据库接口**：两项正式启用指标的原始金额与独立只读 SQL 一致；六位小数差值与 Python Decimal 一致；同一幂等键重放返回相同计算 ID。接口计算记录：`a8e5d98c-fa3d-431f-b864-0d75b0293488`。
3. **真实模型 + 数据库 + 页面求差**：模型读取 skill、确认目录、一次批量取数并调用计算；正文保留原值、计算结果和公式，来源区域保留精确输入。最终会话 `01a0be50-277d-760e-a804-66c8fa0848eb`，取数任务 `be730b93-1459-4c8d-90f1-8f566ccf80f3`，计算记录 `d1b4299c-e3d7-4052-83e2-c4a7e06dbfef`。
4. **刷新恢复**：上述最终会话刷新后保留计算与输入来源；工具调用显示 8 次，与持久化记录一致；已纠正的目录参数错误不再显示为最终失败。
5. **覆盖后取值**：会话 `01a0be46-c11a-75bc-8ecb-90d5252a580e`，先发现指定机构整月有数据的指标，再选择具体指标。实际调用 `metric_query_structured`，保留 `2026-03-01` 至 `2026-03-31` 和 `all_in_range`；没有创建无来源的 followup。
6. **历史回读**：会话 `01a0be42-92bb-734f-af87-c231a1f00b1d` 后续明确要求重看结果时使用 `metric_read`，未重新调用 `metric_ask`；页面刷新保留回读内容。

两次成功的真实页面求差分别耗时 17,197 ms 和 46,728 ms，均为 9 次模型请求；对应输入 token 为 58,163 和 58,649。后一轮包含一次目录参数纠错。这些是单次观测，没有同条件基线、配对 DSL/结果哈希和重复采样，不能据此宣称降低 token 或延迟。

## 失败记录与边界

- 改造期间真实问答曾把组合计算交给基础语义解析，后端返回 `QUERY_UNSUPPORTED`；已修正工具与 skill 契约并真实复验成功。
- 一次供应商请求返回 HTTP 402，无业务取数。用户恢复计费后继续验收；该失败保留，不计为通过。
- 类别检索可能只返回候选切片。实测曾将全目录或首批候选误当成整个类别；已增加类别过滤要求，并在确定性交付中明确“仅核验指定指标，不代表整个类别”。本次没有实现类别自动穷举；候选不完整时仍需缩小范围，不能宣称完整类别覆盖。
- 本次不是全指标/全机构矩阵、故障注入压力测试、GoldenDB/Inceptor、目标 Linux 离线安装或生产发布验收。正式澄清、权限撤回、并发与异常表达式的结论以相应自动化回归范围为限。
- 验收文档不保存凭据或完整业务结果；精确数值保留在受鉴权的原生会话与后端记录中。

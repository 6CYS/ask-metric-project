# 指标算法匹配与离线部署

智能助手沿用原入口和 Pi 会话。指标提取、名称匹配和相似候选由 Python 后端算法处理；Pi 负责用户目标、历史引用、排除/替换语义和回答；待确认候选由系统编号展示并按用户回复确定所选项（见 [Pi 通用多轮业务上下文](pi-business-context.md)）。用哪个指标只由目录数据和用户确认决定，Pi 不选择指标、不根据候选分数改写解析状态。

2026-09-27 起目录识别按“基础指标 + 口径”结构进行（见下文“结构化识别规则”），不再用 0.72/0.84/0.95 相似度阈值决定是否自动采用，也不再逐字对齐推断“名称没说完”。

## 选型

| 组件 | 用途 | 运行依赖 |
| --- | --- | --- |
| `hanlp-trie==0.0.5` | 直接从完整原文匹配目录名称和别名，保留跨度与一词多码 | 纯 Python；依赖 hanlp-common、phrasetree，不下载模型 |
| `pypinyin==0.55.0` | 目录词条和问题的无声调拼音，召回同音错字 | 自带词典，不请求外部服务 |
| `rapidfuzz==3.13.0` | 字符/拼音局部相似度排序 | 使用目标架构 wheel；无需 GPU |
| 字符二元组倒排 | 名称、别名、目录描述与解释召回 | 内存索引 |

单独分词或 Trie 不能完成错字、同音、描述检索。完整 HanLP 的神经模型也不会自动知道业务指标编码；本次没有加载或测试这些模型，不宣称比它们更准确。
官方资料：[安装与离线说明](https://hanlp.hankcs.com/docs/install.html)、[Trie/词典](https://hanlp.hankcs.com/docs/api/trie/dictionary.html)。

## 调用链

1. 宿主以经过鉴权的 BackendClient 将完整本轮原文发送到 `POST /api/v1/business-context/metric-mentions`，模型不能替换这段输入。
2. 后端从启用目录构建/复用不可变索引。目录内容变化即使用新快照；最多缓存两个版本，不缓存业务查询结果。
3. Trie 最大跨度匹配保护完整名称，同名/同别名保留全部编码。字符和拼音二元组倒排召回至多 200 个词条后排序；目录解释文本补充描述候选。
4. 服务端提供带明确序号的片段。Pi 的指标字段使用 `{fromQuestion:true}`，或用 `mentionIndexes` 选择所指片段，避免把用户明确排除的指标一起查询。兼容旧字符串参数时也使用完整原文算法结果，不再信任模型截取名称。
5. 按下文“结构化识别规则”逐片段确定或给出候选；多指标逐项判断，不丢弃不确定项。机构解析规则不受影响。
6. 用户下一轮回复（点选、名称、口径或序号）由系统在同一份编号清单中对应到候选，合并到原 Frame；日期与机构继承。执行层再次校验目录和权限。

## 结构化识别规则

目录同步保留事实表 `orig_indcr_no`（源指标编码）、配置表生成的基础名称与事实表 `indcr_nm` 取值口径；三者齐全且“基础名称 + 口径 = 正式名称”的指标按结构识别。真实目录约 9306 个指标由约 370 个基础指标与 25 个固定口径组成。识别使用三本词典：完整名称/别名（含 `metric_synonyms`）、基础名称/基础别名、口径/口径别名。口径是封闭集合，永远只做精确匹配。

| 情况 | 结果 |
| --- | --- |
| 完整名称/别名，或基础指标紧跟口径，取最长匹配唯一命中 | resolved（match=exact） |
| 基础指标后经“和/及/与/的/顿号”等连续列出多个口径 | 同组各口径逐项 resolved，共用 `group.id`；遇到其他实体即停止 |
| 片段拼音与唯一基础指标/无结构指标完全相同、字数相同（错字同音） | 作为词典匹配参与最长匹配，resolved（match=homophone，understood_as 注明按哪个指标理解） |
| 拼音相同但对应多个词条 | needs_confirmation，候选为这些词条 |
| 只有基础指标、没有口径 | needs_confirmation（missing_value_basis），候选为该基础指标在目录中实际存在的口径；不替用户默认，即使只有一个口径 |
| 口径说到一半并在此停顿（如“较同期增”） | needs_confirmation（value_basis_incomplete），候选只含以此开头的口径；“较同期增加了多少”不算没说完 |
| 该基础指标没有用户说的口径（含已停用） | needs_confirmation（value_basis_not_found），不静默丢弃 |
| 基础指标说得不准（非同音） | needs_confirmation（base_uncertain）。口径明确时同组各片段共享同一组基础指标候选（metadata.kind=base），只列出具备全部口径的基础指标，确认一次全部确定；缺口径时候选为基础指标（kind=base_only），确认后再追问口径 |
| 别名命中但两侧紧连的文字能召回更长的词条（如“对公日均存钱余额”中的“对公日均”） | 不静默采用别名，交模糊确认；正式名称是权威命中，不做此检查 |
| “对公和个人日均存款余额”这类共用后半段的写法，拼出的名称确属目录 | needs_confirmation（shared_tail），不自动展开也不丢弃 |
| 名称中的“排名”“增幅”等 | 属于完整口径时按指标名称识别，不转成查询操作；“排名前三”中的操作由 Pi 表达 |

模糊召回（字符/拼音倒排 + RapidFuzz 局部对齐 + 描述召回）只在上述规则未覆盖的文字上进行，召回门槛只决定是否提示候选及候选顺序，不决定采用；召回在口径处截断，基础指标候选不会吞掉口径文字。同名同口径多编码、跨源血缘不确定仍按歧义确认。没有源结构的旧目录只剩完整名称精确匹配与上述同音/模糊确认，不再推断口径省略；正式环境须先完成 0005 回填。

## 基础别名与口径别名

同义词只在“指标术语”页面按指标维护一处（`metric_synonyms`，如“企业日均贷款均值季度环比增幅”），不另设别名表或维护入口。识别索引加载目录时从这些组合同义词推导两类别名，只存于内存：

- 基础别名：同一基础指标各口径同义词共用的开头（如“企业日均贷款均值”“对公日均贷均”），按被最多口径共用、并列取最长确定；
- 口径别名：去掉基础别名后的部分（如“季度环比增幅”→较上季增幅、“环比季度”→较上季），只有专属于一个口径且至少两个基础指标这样写时才采用。

同一叫法落到多个基础指标（如“活期比例”）或与另一基础指标正式名称相同的，不作为基础别名，仍按完整同义词匹配并交用户确认；只出现在单个指标上的写法同样只按完整写法匹配。修改同义词或同步目录后索引按目录版本自动重建。

后端启动预热时即建好索引（问数就绪门禁包含此步骤）；运行中每 60 秒检查目录版本，变化时在后台重建，用户提问不等待。目录缓存以指标与同义词两表的最新更新时间和行数作为版本，硬删除同义词同样生效。本地真实目录实测推导约 0.2 s、含推导的建索引约 0.4～0.55 s（Apple M4 Max；生产服务器未实测），每个目录版本只发生一次，单次识别约 0.6 ms。

`scripts/check_metric_synonyms.py --config backend.env [--output report.json]` 只读输出推导出的口径写法、冲突叫法和拆不开的同义词，供目录负责人修正同义词；它不写库，不参与识别。按本地目录试算：拆出 23 个口径写法与约 1,282 条基础别名，14 条冲突叫法不采用。

## 排名方向

排名操作只表达前 N / 后 N（`position=top|bottom`）。名次类指标（目录单位为“名”，数值即名次）越小越靠前，后端按目录单位在同一 SQL 内逐指标反转方向，回执 `evidence.ranking[].sort` 写明实际排序。真实目录 4461 个“…排名”指标单位均为“名”。

## 内网交付

沿用现有无 Docker 离线包，不新增入口、Java 服务或外部 HanLP REST 调用，不携带神经模型权重。构建机需访问经过批准的依赖源；目标机无外网。

- 依赖版本写入 `pyproject.toml` 与 `deploy/package/constraints.txt`。HanLP 间接依赖锁定为 hanlp-common 0.0.23、phrasetree 0.0.9。
- 上游 HanLP 轻量包只提供源码分发时，`build_bundle.py` 在构建机生成 `*-none-any.whl`，验证是纯 Python wheel，再与目标平台依赖一起打包。目标机不编译、不下载。
- RapidFuzz 3.14.6 缺少当前 manylinux2014 基线的匹配 wheel，因此选择并验证 3.13.0。已下载验证 CPython 3.12/Linux x86_64 和 aarch64 wheel；纯 Python 依赖已执行 `--no-index` 安装及独立导入。未在真实麒麟服务器运行，也未本次重新构建全部生产包。
- 整包沿用 SHA-256 清单、固定运行时、systemd 启停与既有回滚工具。使用 `--dependency-wheelhouse` 时必须更新已验收的 wheel 集合，不能复用缺少新增依赖的旧集合。
- 本次多口径省略改造新增 Goldendb Alembic `0005_metric_source_structure`。先审核并应用增量迁移，再用正式目录同步命令预览并回填源字段，确认目标指标已启用且结构一致后升级后端与 Agent。回退应用版本时保留三个可空列及目录数据即可，不需要删除历史结果；如需删除列，应先确认没有旧版本之外的调用方仍依赖它们。

# 普通问数直接交付与模型上下文精简

## 职责和生效入口

Pi仍负责理解、来源选择、工具提案、解释与结果驱动分析。宿主在真实工具执行后核验普通取值交付资格，
成功时通过原生 `after_tool` 的 `terminate` 保存版本化答案，省去最后一次模型总结。
正式查询、目录/权限校验、数值格式和业务计算仍在既有后端执行链，不修改业务数据或持久化旧历史。
缺项普通取值请求也必须保存已知字段和正式澄清状态，目录读取或口头追问不代表业务完成。
唯一待补目标的明确机构/日期赋值，或已完成目标明确要求“其他条件不变”时，模型误用`new`会在准入前收到冻结来源选项，
由Pi显式改用`current/reference`重提。宿主不替模型选来源、不自动填旧字段；否定、清空、独立新指标和未知表达不据此推断续补。

资格检查位于 `agent-service/src/semantic-task/directDelivery.ts`，由 `harnessHost.ts` 的语义工具回执入口调用。
必须是当前准入计划和revision，或由本轮冻结焦点/查询序号验证并绑定的历史只读计划；
全部目标及普通value步骤完成、正式Frame与结果绑定一致、无待确认/截断/未知，
且用户要求在已支持纯取值表达范围。未知额外语言诉求保留Pi，分析阶段的成功不等于整笔完成。
多目标逐来源核对，零行、NULL、零值、单位及精度照正式结果表达，不能删目标或从聊天文本取数。
单个原生工具调用内可完成多个目标；混合工具批次不提前直接交付。
确定续问逐字段核对transition，不能因“其他条件不变”而跳过来源核验；历史查询序号包含失败/未完成查询，
不能把“第一次查询”换成“第一次成功查询”。机构简称仅按已核验机构code/name匹配目录别名，未知附加诉求仍由Pi处理。
历史只读直出限唯一明确来源，完整查询序号或冻结焦点须与来源身份对应；修改条件、selection、否定展示、
并列历史来源和无法解析的序号继续Pi。回读正文必须为从offset 0开始的完整页，分页正文或缺行不提前直出；
授权复核的单行元数据页不作为完整正文证据。失败且确无事实的空回执不会被当成成功来源阻断后续会话。

交付前对每个正式结果做当前Bearer只读复核，不重跑指标SQL。权限或来源复核失败删除待交付事实并返回明确状态。
历史、实时和重连递归收集聚合结果、计算来源和答案快照的全部来源；快照不是永久授权票据，新轮重新核验。

## 原生持久化与恢复

`direct_answer`版本1随同一真实工具回执保存，包含稳定answer ID、operation、计划revision、目标/Frame/任务/结果引用、
正式正文与结构块、renderer版本。`sessionProjection.ts`在同一投影入口生成稳定页面assistant条目，
不伪造原生assistant或零token模型调用。下一轮继续使用原生业务状态和冻结来源，不能反向解析答案文案生成Frame。

应用计划保存与SDK最终化不是跨层单事务。恢复复用同一执行关联、Frame、结果和幂等键，
将已经取得的结果完成为同一交付；不能因断线/重启再次查询。已经持久化的交付保持唯一，刷新只读重放。

## 配置与回退

| 配置 | 默认 | 回退值 | 范围 |
| --- | --- | --- | --- |
| `AGENT_DIRECT_QUERY_DELIVERY` | `on` | `off` | `observe`只记资格；新operation冻结策略，已有交付继续可读 |
| `AGENT_MODEL_CONTEXT_VIEW` | `compact_v1` | `raw` | 普通查询去重；分析采用工具正式模型正文；Skill 与临时状态按稳定前缀组织 |
| `AGENT_SEMANTIC_PROMPT_VARIANT` | `compact_v1` | `full` | 合并重复说明，工具集合、Schema和业务契约不变 |

配置修改后重启。回退保留新版快照读取器，使用`off/raw/full`停止新请求优化；不能删JSONL或回退到不认识新快照的旧二进制。
不需要数据库结构迁移、清空历史或修改幂等记录。本文不代表生产部署授权。

## 分析回执与前缀缓存

`semantic-task/modelView.ts` 对带已知 `answer_policy`、成功状态、唯一完整正文及合法 `evidence_ref` 的
`business_overview` / `analysis_evidence`，使用分析工具原本生成的正文。
绑定恢复映射、事实账本、计算输入和原始任务仍保存在不可变 `details` 中，由服务端执行校验、恢复及渲染；
模型读取正式证据原子、机构与日期、来源、覆盖评审、补查候选和下一步指引。未知扩展字段继续保留。
普通查询不应用该替换，精确原值、NULL、行、分页及事实身份仍沿用既有契约；混合结果逐来源处理，失败目标不删除。
协议不兼容、正文缺失、版本未知时回到完整回执，不通过截断 JSON 或删目标控制成本。

`businessSkills.ts` 在紧凑视图内只保留首次可见的当前版本 Skill 全文，同名重复读取去重。
先选择历史窗口，再确定正文是否可见；窗口外的方法不永久注入系统提示词，目录仍允许按需重读。
方法原文与业务规则没有缩短，用户伪造及旧版本正文不会被当成已读取。

`harnessHost.ts` 在权限过滤、历史来源核验和发送视图生成后，才追加临时业务状态数据消息。
同轮机构目录随真实用户消息注入，其余变化状态放在请求尾部，保持系统指令及此前工具回执前缀稳定。
临时消息不进入业务账本、历史窗口、页面或持久化，不替用户提出目标、不提供执行许可。
每次请求仍重新生成当前权限状态；缓存只是供应商对相同输入的计费优化，不能复用旧授权。

这些调整不切换模型、不关闭必要补查、不缩短报告输出上限，也不取消数值、报告覆盖和权限校验。
缓存命中及节省幅度取决于供应商和实际问题，不能据字节缩减直接承诺账单降幅。

跨主题发现可合并关键词调用 `analysis_catalog`，避免先逐一加载相同专项目录。
目录返回的 `planning_review` 直接复用现有覆盖检查，并附已发现且同一正式指标的环比/同比差额候选，
帮助模型首批尽量查全；没有正式映射时不补造关系。这是规划参考，不能替代模型理解、业务数据或执行许可。
后续仍以 `coverage_review` 和报告校验为准；不靠取消必要分析来减少调用次数。

结构校验失败时，`semantic-task/protocol.ts` 先按调用声明的 `source.kind`、`analysis.kind` 定位诊断分支，
列出实际缺少或多余的字段，例如专项计划中的 `scope_notice`，不再只返回另一联合分支的 const 错误。
诊断不接纳或自动删除非法字段，不改变原Schema、权限或执行条件；模型修正后仍须通过完整校验。
错误提示只包含位置和字段名，不回显参数值。该调整用于减少同一错误反复消耗模型调用。

## 用量和验收

`model_usage`是实际供应商用量，输入包括缓存；未知为null，不得按零计算。
新增`final_payload_bytes`在全部工具过滤和tool_choice处理后记录；`model_request_payload`只输出长度、工具名称及进程内HMAC摘要，
不输出业务文本、金额、提示词或凭据。字节/HMAC用于解释变化，不能冒充供应商token前缀或计费量。

基线冻结当前工作树，候选与基线同semantic_v2、同当前真实模型配置和授权开发数据库，独立会话连续运行多轮。
独立规范查询先固定预期hash；结果对照保留精确数值/NULL/单位/排序语义，排除随机任务ID和时间戳。
累计已测回合每个唯一usage_id，失败、重试及压缩调用计入；分别报告全部任务与成功配对，不以便宜失败刷节省。
恢复按实际测量范围报告：消息一致、零业务取数请求与零模型请求分别核验，不能仅凭页面恢复成功推断零调用。
普通取值直接交付、多目标、追问、历史回读、分析不提前结束、刷新重启、撤权和跨资源引用均需通过。

实测报告和未验证项见 `docs/verification/token-optimization-20261015/`；隔离回归、真实模型、真实开发数据库和浏览器证据分别记载。

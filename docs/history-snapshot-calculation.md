# 历史查询快照接续计算

## 目标与交付边界

修复“已查到两家原值，追问求差却因跨轮引用失败”的通用链路。先完成本地实现和回归，再由用户在本地验收；未经用户后续明确确认，不提交、推送或部署。保留工作区原有的上下文参数优化。

## 业务语义

- 计算始终创建自己的 Business Frame、operation 和 calculation_id。
- 输入为同一会话已有成功查询的精确事实引用，可来自一轮或多轮；不会改写输入快照、原日期、原查询范围。
- 用户指定“刚才/第一笔/上次”的结果时，沿用其快照，不自动刷新原值。来源有歧义由现有 FrameSelector 澄清，不擅取最新结果。
- 用户改变查询条件或明确刷新时先执行新查询，再以新回执计算。失效快照不能静默替换为新数据；需说明原值已不可复用及后续动作。
- 公式与机构、日期、单位共同决定可比性；同日两机构求差必须明确 cross_org，金额相减不能按百分比展示。

## 调用链

1. Agent 用现有业务历史定位来源。历史回执的 `fact_refs` 索引包含机构、指标、日期、单位和精确 fact_id，不包含原值；索引完整且匹配时直接绑定，索引不足时由 `read_business_result` 返回经过当前鉴权的原值与 fact_id。
2. `resolve_business_turn` 创建 metric_calculate Frame；bindings 不自动继承，每次明确选择事实引用。校验其任务出自本会话成功查询 Frame，重新读取对应事实，错误保留明确原因。
3. `execute_business_frame` 使用原有受控计算适配器。宿主注入 conversation_id、当前 operation 对应的 scope_id、当前用户原文、source_policy；这些字段不交给模型生成。
4. 后端在会话行锁保护下读取持久快照，复核当前身份、任务归属、当前目录与机构权限、状态、有效期、截断、缺失值、事实存在性、单位及数值精度。
5. Decimal 表达式引擎计算，原有任务 JSON 追加计算记录，原始 result_artifact 不修改；返回输入、公式、结果与 sources。会话与请求键共同确定计算消息主键，消息保存请求指纹及结果；重复执行先重新鉴权，再读取该消息检查指纹、返回原结果。更换来源任务也不能绕过同键冲突检查。
6. 页面沿用现有计算详情组件，展示公式、机构、日期、原值，并注明包含历史快照。刷新/重开时仍重新核对输入任务权限。

## API 兼容与证据

`CalculationRequest` 增加可选字段：

- `source_policy`：默认 `current_scope`，保持旧客户端同范围校验；新 Agent 显式传 `conversation_snapshots`。
- `user_question`：快照模式必填，由宿主绑定本轮用户原文，用于校验用户常量。不能借用来源任务的旧问题作为新计算的系数依据。

新模式允许来源的 scope_id 不同于计算 scope_id；其余归属、权限、完整性和数学校验保留。返回 `sources[{task_id,result_id,source_scope_id,historical}]`，同时保留原有 inputs、results、calculation_id、scope_id 等字段。旧快照和旧计算结果仍可读取；无需新增表、迁移或依赖。

当前按本地测试阶段处理：不兼容升级前已保存的计算请求指纹和幂等消息定位方式，不回填旧记录。验收新计算应使用新请求键或新会话；旧结果查看保持原有读取流程。

这不是将“任意历史数值”开放给模型：仅接受服务端已保存、当前用户有权读取、同会话且成功的查询快照中的真实 fact_id。对用户目标的语义选择仍由 Agent 和现有 FrameSelector 完成，后端负责事实和执行边界。

## 历史计算延迟优化

历史结果裁剪仅作用于模型发送副本，不修改原生审计记录。最近三个不同的完整查询结果各最多保留20条事实身份（总计最多60条），只含 `fact_id/org_code/org_name/metric_code/metric_name/date/unit`；查询截断、缺数、分页未结束、事实数量不符或引用非法时不产生索引，继续使用原有受控回读流程。计算结果本身不作为新的查询事实引用。

这样可消除“看不到 fact_id → 误用 result_id → 参数报错 → 模型另调回读工具”的多余模型往返。实际计算仍在 Frame 解析和后端执行时重新鉴权读取快照；索引不表示当前授权，也不替代完整性校验。表达式字段明确要求直接传数组，不额外包装一层 expressions；参数有误仍拒绝，不自动猜测或修补公式。

真实模型探针 `agent-service/scripts/check-history-calculation-model.ts` 使用临时原生会话与合成后端，核对两个机构的减法方向、计算输入、后端事实复核、模型调用数、无纠错/无重复查询，以及最终结果。默认不调用模型；显式 `--live --repeat=3` 才调用当前配置模型。探针不访问真实业务数据库，耗时不能当作生产服务承诺。

## 错误与恢复

- SOURCE_UNAVAILABLE / FACT_UNAVAILABLE：重新定位明确来源或读取真实引用，不猜测 ID。
- SOURCE_NOT_READY：查询尚未成功，不能生成计算结果。
- SOURCE_EXPIRED：说明原快照过期；重新取数必须作为新的来源，不冒充当时结果。
- SOURCE_INCOMPLETE：缺数或截断，不能按样例形成完整合计。
- FORBIDDEN / CATALOG_CHANGED：复核权限或目录失败，不绕过。
- 数学校验继续拒绝单位冲突、零分母、非法公式、无依据常量等。

保留有界纠错和重复错误停止机制。终止文案不再断言“本轮没有查询”，而是明确原值/条件仍保留、后续计算或查询未完成。

## 验收

隔离回归覆盖：本轮计算、历史两机构求差、多轮输入组合、当前原文常量、来源篡改/跨会话、权限撤销（含幂等重放）、过期、截断、缺指标、单位冲突、跨日期/机构策略、同键更换来源冲突、同键跨会话隔离、实际 ORM 持久化后重放、默认同轮参数契约、计算结果重显与常量输入。历史上下文裁剪继续隐藏旧值，同时允许受控快照接续；不会再要求所有计算都重新取数。

本地人工验收：先查询两家原值，另轮求差，检查公式/原值/来源；切换其他查询后再指定第一笔求差；刷新后检查计算保留；改变日期并确认没有复用旧日期。再核验新会话独立查询后计算。真实模型、真实数据库、页面验收与隔离测试分别记录，不互相替代。

## 发布与回退（本轮不执行）

先通过本地检查，交用户测试。用户确认后才提交远程仓库和安排部署。届时后端先升级以接受新可选字段，再升级 Agent 和前端；不能新 Agent 配旧后端。回退配套应用版本即可，无数据库迁移回退。

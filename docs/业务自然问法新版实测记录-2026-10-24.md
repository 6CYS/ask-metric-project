## 已明确的问题

1. **日常表达里的省略和纠正仍容易丢上下文。** A2 没有将“个人的”切换到个人存款，A3 把“企业”当成机构；B2 在识别新机构后丢失贷款主题。现有默认机构和日期能帮助首轮取数，尚不足以保证自然连续对话。
2. **C1 的分析文字出现可核对的事实错误和过度归因。** 回答称对公贷款“是三个基期下增速最高的分项”，但工具表格和已核验发现明确显示，较上月时贴现增幅高于对公。回答又断言“增长主要由对公贷款拉动”，以及不良余额和比率变化“主要与贷款总量同步扩张有关”；工具中没有完成组成核对，明确记录组成数据不完整、不能完整归因，且不良率分母未确认。H1 在相同缺口下再次称对公贷款“是总量增长的主要来源”，贡献结论同样偏强。结尾再写限制说明，不能抵消前面的确定性断言。
3. **明确的时间序列仍可能退回泛化填条件。** C2 已说“每个月月底”，内部也曾识别区间全部取值，最终却继续要求选择全部记录或最新一期。这里尚未真正查询月末序列，不能把失败解释成缺历史数据。
4. **取数、计算和回答没有始终衔接完成。** D1 有两项数据却没直接回答“哪个多”；D3 在计算来源和提案结构上反复失败；F2 没有将明确的分子、分母推进为计算，F3 最后只交付了两个金额。缺少正式比例定义，与能否按用户明确给出的算式计算，应分开处理。
5. **错误和等待反馈仍影响使用。** D3、F3 分别约 57、64 秒；I2、I3 分别约 74、79 秒，均在重复处理后达到步数上限。A1、B1 的简单查数也分别约 25、29 秒。默认取数说明有帮助，但来源声明、口径限制等重复文字较多，业务结论不够直接。这些是单次观察，不作稳定性能推断。
6. **比例和取消意图还存在明显缺口。** G1 问“活期占得多不多”，却只返回活期余额，未处理占比或评价基准。H2 明确取消后虽未新增取数，却继续要求补机构、指标和日期，没有正确结束任务。

- A1、B1 没有因为缺机构和日期就直接卡住，能够使用账号所属机构和最新有效数据日，并告知实际条件。

## 优先改进建议

本轮仅测试和记录，**不进行产品修复**。后续建议按以下顺序处理，并用本题单原话复测：

1. **先保证结论受证据约束。** 修正同基期比较判断，区分增长率、增长额、变化贡献和业务原因；资料不完整时不能先作确定性归因再补免责声明。
2. **补齐跨轮条件衔接。** 优先处理 A2、B2、C2：保留已确认指标和实际日期，只改变用户纠正的部分；比例、客户类型、机构和时间序列不能靠表面词语混配。
3. **让计算与比较真正交付。** 已明确分子、分母或两项比较对象时，组织正确的查询和计算来源；缺数据就及时说明，避免在无法计算的前提下持续重试。查到两项金额后应回答用户要求的比较结论，不能仅列值。
4. **改进澄清和错误表达。** 过滤“占比”与“较同期”等含义不一致的候选；存在歧义时给出具体、少量的业务选择，不把内部字段要求或“拒绝提案”直接交给用户。
5. **结束没有进展的操作。** 明确取消应结束当前任务；同一失败状态下反复读取相同历史时，应尽早停止并说明缺少什么，不能继续到步数上限。客户明细需求应明确检查数据能力和权限，本次未实际验证该分支。

修复前先区分代码缺陷、数据缺失和暂未支持的能力；不要为提高通过率改题、补造数据，或把每个连带失败重复计为新缺陷。


本次不计算整体通过率，也不作新旧版本优劣结论。26 轮发送与反馈结束，不等于 26 个业务目标完成；后续应保留本次首次结果，再针对修复项另开会话复测。本轮未进行 Git 提交或推送。

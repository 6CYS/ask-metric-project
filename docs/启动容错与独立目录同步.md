# 启动容错与独立目录同步

本说明适用于 Pi 完整版源码。基础服务启动与业务依赖分开检查；能启动不代表数据湖、模型和目录已具备问数条件。当前改造不增加数据库迁移，不自动修改现场配置、单位字段或历史结果。

## 启动和健康边界

- Python 启动不连接数据湖、不加载业务目录索引、不请求 Chat、Embedding 或 Reranker；普通目录索引在业务请求中按目录版本加载。
- Agent 保留 Pi 原生 JSONL 会话、历史恢复及 `semantic_v2`。Chat 地址、名称或密钥缺失可先启动；实际调用时返回明确配置错误，不能生成假答案。
- `/health` 检查进程存活；后端 `/health/ready` 检查应用库必需表及列；Agent `/health` 检查服务状态。部署健康脚本要求两端都通过，不探测业务模型或数据湖。
- `/api/v1/query-readiness` 表示不再等待目录预热，不是目录完整、业务可用或模型可用的证明。目录、权限、数据湖和模型在实际请求或显式业务诊断中校验。
- Nacos 启用时仍须可读且配置结构完整；已提供的 SM4 密文必须有效。应用库结构、生产认证密钥、原生会话存储锁等基础条件仍需满足，不能降级为假健康。
- 空目录不放宽权限、不猜测机构或指标、不转换为全量查询；缺数据与执行失败继续分开返回。

当前运行策略固定停用 Embedding、Reranker、目录向量化及向量缓存。旧 Nacos/文件开关即使为 `true` 也不生效，诊断入口不发送这两类请求，管理页只保留 Chat。配置读取不会回写现场文件；管理员主动保存模型配置时，停用角色会按当前策略保存为禁用。词法检索、正式编码绑定、知识和查询方案仍可用，但依赖向量召回的语义近似匹配不再提供。

## 独立目录同步

使用已经配置好应用库、源表字段映射和运行环境的 Python。Nacos 启用时继续从 Nacos 获取配置；脚本不安装或启停服务、不发布配置、不生成密钥。

在项目根目录执行，`python` 应替换为目标环境已有应用虚拟环境的解释器：

```bash
# 默认仅预览，机构和指标可分别执行。
python deploy/package/sync_organizations.py
python deploy/package/sync_metric_codes.py

# 审核预览后显式写入。
python deploy/package/sync_organizations.py --apply
python deploy/package/sync_metric_codes.py --apply
```

已安装 wheel 的环境也可执行 `python -m ask_metric sync-org-catalog` 和 `python -m ask_metric sync-metric-catalog`；同样默认预览，显式 `--apply` 才写入。`uat_deploy.py sync` 和 `intranet_deploy.py sync-catalogs` 也遵守该规则。不要将历史脚本依赖的隐式写入行为当成当前行为；如需自动化同步，须调整调用参数。

同步结果输出 JSON：

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| PASS | 合格记录全部处理 | 0 |
| PARTIAL | 合格记录正常处理，异常编码隔离并报告 | 0 |
| FAILED | 无合格记录、配置/源表/事务失败等，未成功完成同步 | 非 0 |

查看 `dry_run`、`created`、`updated`、`unchanged`、`issues` 和 `preserved_existing_codes`。`PARTIAL` 不是全部目录均已覆盖，管理员仍须处理隔离记录；预览结果不代表已写入。写入事务失败整体回滚，源端失败不能被当作空目录成功。

机构同步不再固定要求 61 家，也不因新增编码要求额外确认。源表范围筛选仍按现场字段配置，根机构必须可信且唯一；对合并后的新旧目录检查父子关系、孤儿及环路。错误更新保留旧节点，不能制造根、改变旧节点来迁就错误来源，不能扩大权限。正常记录按编码 upsert；同名不同编码不合并，编码文本保留前导零。

指标同步保留来源指标编码、基础名称和取值口径；新指标不推断单位。已有单位、人工解释、别名、停用状态和源端未返回的记录保留；不会根据名称相似自动合并指标或覆盖人工维护内容。`--full`、固定数量、`--strict-scope`、`--confirm-org-additions`、`--units`、`--infer-units`、`--org-aliases` 等旧兼容参数不再执行清空、范围差异阻断、单位推断或别名导入；`--all-snapshots` 和日期/字段/来源范围选择仍按定义生效。

历史的替换/清理初始化命令可能删除数据，仍保留独立保护。日常部署和增量目录维护使用上述独立入口，不调用清理初始化。

## 原值、计算和历史结果

新查询的运行时目录和结果使用 `value_policy=source_raw_v1`，单位为 `null`，数值保持源端 Decimal 原值，不套用旧单位，不推断元/万元/亿元，不按名称转换比例或缩放。展示明确说明“原始值，单位未提供”。应用库 `unit` 字段及旧值保留，指标管理仍可查看原维护信息，但这些旧单位不用于新查询数值换算。

Pi 普通查询、查询方案、分析证据、报告和图表使用同一原值事实。支持同一正式指标的跨机构/日期比较、排名、趋势、差额，以及满足条件的变化率。原值图表仅用于可证明为同一正式指标的序列；不同指标不能仅因单位均为空就认定可比。

不同指标的占比/组成计算须有现有正式、已确认的关系证明；计算参数、当前权限、事实归属、日期、口径及完整性校验继续有效。不能证明维度一致时返回限制，不猜单位、不把缺数当零。

历史快照保留原单位与原值解释，不重写旧会话或计算回执。新原值与旧带单位事实不能直接混算；历史引用仍需通过当前权限和事实身份校验。回退代码前应保留新旧快照的策略标记，不能把原值重新按旧单位解释。

## 上线前仍需现场验收

本地隔离验证不能代替现场网络、GoldenDB/Inceptor 驱动、Nacos 实际配置、权限、模型协议、数据口径及并发验证。上线前先检查基础健康，再分别预览目录同步，审核异常编码，显式写入后运行典型业务问数、历史追问、计算与报告。应同时核对实际机构/日期/指标、SQL、原值和交付结论；仅健康接口成功不能算业务验收通过。

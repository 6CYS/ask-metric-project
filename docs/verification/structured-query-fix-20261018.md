# 结构化查询通用修复验证

模型通过 `target.query` 提交同一查询目标的机构、指标、时间、取数方式与操作，程序绑定正式目录身份、日历和机构权限后生成既有查询参数，由 SQL builder 执行。不同机构、指标、日期或排名条数共用此契约。

## 实现

- `protocol.ts` 定义完整 `query` 与结构化 `queryOperation`；真实缺项用 `null`，完整查询和局部修改互斥。
- `structuredQuery.ts` 把结构化字段投影到现有工作状态，包括机构集合、比较总体与计算来源标签；不解析排名描述。
- 机构范围区分名称清单、正式法人行集合和明确上级下属。Agent 绑定原句范围短语，后端根据范围类型、正式层级与当前权限解析成员，移除范围短语的量词完整匹配。
- 排名直接绑定 `position`、`top_n`；完整集合排序先绑定机构集合再编译条数；位次保留关注对象与比较总体。历史文字解析的指标位置只作用于同一份文本。
- 参数拒绝保留后端实际错误码供模型修正；权限和基础服务错误分别分类。内部失败的用户正文为“没能完成这次查询。”，系统诊断保留在回执。
- 历史展示与工作任务使用独立指针，读取结果时复用同一次原文解析；普通字段续问继承工作任务。
- 日期缺项在首次字段绑定时处理；模型未获用户时间依据的日期不作为查询条件，已有候选与可信历史时间按既有状态续接。

## 验证

| 检查 | 结果 |
| --- | --- |
| 结构化定向测试 | 14/14 通过，包含未提供日期却填入具体日期的回归 |
| 当前配置真实模型 | 12组、14轮全部通过 |
| 协议及示例 | 20个正向、17个反向、11个反馈与8个反馈反向检查通过 |
| Python机构范围HTTP与权限回归 | 60/60通过 |
| 多轮集成真实模型 | 26组71轮通过；最终历史读取优化另验5/5轮 |
| 最终历史读取相关回归 | 34/34通过 |

真实模型专项覆盖：原始两句查询；不同日期的后5名；完整机构集合排序；指定机构排序与连续修改日期、条数和取消排序；连续区间全部记录与最新一期；对象位次；不同条件并列目标；缺少排名条数；缺日期；后端503的用户提示。每轮核对模型实际结构化参数、绑定后的执行条件、实际SQL和结果行数，不以模型自述作为执行成功依据。

验收使用真实模型、真实 Python 字段/机构范围解析及 SQL builder，数据来自明确隔离的合成目录和内存 SQLite，未访问实际业务数据库。专项报告保留实际加载的实现哈希；最终合并版本的多轮接续、全量回归和本地服务状态见综合报告。

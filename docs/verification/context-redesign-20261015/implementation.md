# 问数上下文与历史引用实现

本次改造将条件、目标、正式结果来源和焦点保存在同一原生 Session 账本中。模型每轮收到有界的工作上下文，需要更早历史时按签发引用定位。聊天摘要不能替代确认条件、数值或权限。实际验证结果见 [验收报告](report.md)。

## 请求与执行链路

1. 后端认证取得用户身份，Agent 在原生 Session 中冻结本轮入场来源、待明确任务和交付模式。
2. 宿主投影近期完整回合、当前任务、独立焦点及少量相关历史。用户明确的“第N次查询”从账本直接取得签发引用；发送前复核机构权限。
3. 模型提交版本2语义提案。多个历史来源分别继承，跨来源字段复制携带原始依据；来源、集合动作和作用范围均显式表达。
4. Agent 解析字段并形成规范化 before、changes、after。后端独立检查目录、日历、签发来源、当前权限以及机构与指标、日期的逐目标绑定，整批准入后签发许可。
5. 执行前再验证许可、版本、幂等关联与权限。计算只使用正式成功来源；结果未知只回查原命令。
6. 普通完整取值通过直出门禁后，正文和表格由正式结果生成并持久化。分析、计算、排名、缺数、截断或额外解释义务继续由模型处理，不为省调用提前结束。
7. 历史展示逐回合重新鉴权。点名历史机构时，inspect-goal 可接收宿主提供的旧签发范围：后端验证原用户、会话与完整范围，仅用于识别旧机构身份；当前数据权限仍独立核验。失权来源屏蔽该回合正文和工具明细，保留问题与消息身份；未选用的旧来源失权不阻断无关新问题。

## 状态与焦点

| 状态 | 保存内容 | 用途 |
| --- | --- | --- |
| 业务任务 | 原问、目标组、完整条件、变更轨迹、执行许可、完成义务 | 决定待执行或已完成的工作 |
| 业务焦点 | 最近业务计划 | 默认业务状态展示 |
| 讨论焦点 | 用户正在查看、继续讨论的正式来源 | 下一轮入场来源，避免查看旧结果后串回最近查询 |
| 展示焦点 | 当前查看的历史计划 | 页面与讨论定位 |
| 待明确状态 | 原始未完成输入、真实备选目标、已保存修改 | resume、defer、abandon，不因换话题丢失 |
| 历史索引 | 计划和目标配对引用、查询序号、主题、机构、指标、日期、状态 | 定向定位，不作为数值或授权票 |

用户明确查看旧结果可更新讨论和展示焦点，业务任务不随后台读取改变。多源字段使用 copy，不能将历史名称复述成 new/set。多个历史成员使用 references，宿主逐来源展开，保留各自绑定。历史组唯一公式可写成一次 calculation:set，宿主保留每个来源并单独建立计算步骤。正式榜单的前N家通过 select 从已保存结果行选择，重新核验成员和权限，不能按新指标再次选前N家。

## 校验依据

| 校验项 | 可接受依据 | 拒绝的替代依据 |
| --- | --- | --- |
| 身份与归属 | 当次认证身份、Session owner、所属计划与目标配对 | 模型填写的用户、其他会话引用 |
| 指标 | 启用目录、本轮确定性目录事实、原签发范围或明确确认 | 摘要中的名称、推荐候选冒充确认 |
| 机构 | 当前有权目录与服务端权限服务 | 前端清单或模型判断替代授权 |
| 日期 | 日历事实服务、明确原句、完整且已验证的历史日期字段 | 从账户默认日期、错误年份或指标口径推测 |
| 来源复制 | 同会话原目标、签发来源及规范化完整字段 | 模型自行拼接名称、伪造 before 或来源票 |
| 目标完整性 | 每个机构与指标、日期的对应关系、原始义务、全部目标状态 | 只验证三个集合的并集、首个步骤成功 |
| 查询序号 | 同一账本中的业务查询 operation，失败查询也占位 | 第N条消息、第N次成功、最近N家猜测 |
| 结果 | 正式 task/result 身份、完整行数、截断和缺数标记 | 回答文字、抽样行、旧金额当作新查询 |
| 计算 | 已成功来源、精确原值、公式依赖、单位及现有精度规则 | 模型填原值或内部 fact_id，零分母成功 |
| 权限恢复 | 新请求重新复核原结果和比较范围 | 历史缓存或摘要被当作长期授权 |

用户明确“不沿用条件”时，只允许 new 和本轮提供的字段，缺项进入澄清。多目标中的单笔修改必须由原机构、指标或原日期定位；修改后的新值不能反过来证明来源身份。“那一家”无法唯一定位时保存备选来源与原始修改，明确后用 resume 继续。

明确查询序号的错误结果读取在工具边界拒绝，不仅取消直出资格。相同历史页读取两次后，第三次先阻止并要求使用已有引用或换检索条件，再次重复终止。权限目录暂不可用返回503，不能伪装撤权或静默放行。

## 百轮会话

原生消息、正式任务、来源票、结果和变更轨迹仍完整持久化。模型发送副本按完整回合裁剪：历史部分最多最近3轮，保守预算约4000估算 token；本轮消息及工具配对完整保留。这不是 provider 实测 token，也不是整个请求的硬上限。

默认相关历史去重后最多4个目标，待明确索引最多5个；本轮明确查询序号自动投影最多12个有权来源并给出截短标志。更早来源按 query_number、task_ref、topic_ref、query 和游标读取，默认8个、最多50个。索引截短不取消原任务义务，不能从已见窗口假定历史全集。

原生压缩使用宿主生成的定位说明，避免再调用模型自由摘要业务事实。压缩后仍通过领域账本和正式结果恢复；摘要不携带可执行条件、数值或权限。120任务索引、105轮合成历史、压缩、重开及真实模型回读分别有测试证据。

## 普通取值省第二轮的边界

条件完整的普通取值请求优先进入 resolve_business_turn，避免先反复读取历史；参数仍由模型提交并通过正常准入。明确“不沿用条件”及“机构和指标不变”等上下文指令可进入普通直出资格判断，执行层仍核验来源和字段变化。

直出要求：同一有效获准计划、全部必需目标成功、完整普通 value 查询、无未决项或错误、来源与 Frame/result 绑定一致、结果完整、当次权限复核通过，且原问没有计算、分析或尚未满足的解释义务。历史重显还须验证原问指向的查询序号或冻结来源，并绑定本轮交付身份。所有结果合并前逐份检查。

排名、计算、分析、部分完成、缺数、分页或截断、引用不明、未知额外回答义务、执行结果未知、权限失败及基础设施失败不靠直出掩盖。原始回执保留，去重仅作用于模型发送副本中的完全重复字段。固定提示与Schema描述精简不移除执行校验。多个来源改成相同条件后，重叠数据点在执行前返回 DUPLICATE_QUERY_COVERAGE，避免重复SQL和重复结果行。

## 接口与兼容

- 版本2增加 references 来源，以及 copy、select、rank_all 动作；公开 Schema 已同步。自然语言“全部已选机构按高低排序”也能规范化，不要求模型一定选择特殊动作。
- 跨字段来源通过 field_sources 传到后端，签发依据和当前权限均重新校验。Agent 与后端必须成对升级。
- 原生 Session 增加历史元数据、主题及独立焦点，均为增量字段；旧会话按原计划重建投影，原记录不改写。业务数据库不新增迁移，不改账号权限表。
- schema 严格拒绝额外字段和错误版本；工具未决、拒绝与未知状态不降级成成功。

## 配置与回退

沿用当前模型、开发数据库和 .env；不改模型密钥、认证、数据库连接或生产环境。开发入口为前端5173、Agent8020、后端8010。隔离权限检查的8016只使用进程内策略，结束后停止并恢复主链路。

回退前等待在途 operation 结束，备份原生 data 目录，成对恢复 Agent 与后端。新增动作的在途操作不能交给不认识该 Schema 的旧二进制继续执行；应保持新版本完成该操作，或明确取消后用兼容入口另开请求。不要删除历史、篡改已签发依据或重放业务SQL来回退。直出开关可沿用 off/observe/on，但已接纳操作遵守其冻结模式。

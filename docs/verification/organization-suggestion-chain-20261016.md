## 调用链与修复

当前链路为：有权机构目录注入 → 模型提交完整原文 value 和可选 suggestion → `organizationValues` 按目录保护名称并拆成员 → `BackendClient` 同时传完整 `raw_values`、`source_question`、`suggested` → 后端识别身份及裁定权限 → SemanticTask 保存条件、候选和剩余动作 → SemanticPlan 整批核验并签发 → 执行、持久化及权限过滤后的展示/回读。

| 缺陷 | 修复后的契约 |
| --- | --- |
| 单个 suggestion 吞掉多机构 value，或建议追加/覆盖原集合 | 完整 raw_values 决定成员；已确定身份不被建议改写，建议仅补对应未决槽位。 |
| 整个原问的唯一机构覆盖另外一个歧义槽位 | 逐 suggestion.excerpt 核对来源；同问其他位置出现的机构不能替该槽建立依据。用户原文中的明确 raw 优先。 |
| 已定成员的建议成为另一未决槽的 preferred | 有 excerpt 必须匹配未决原值；多 raw 且无 excerpt 不建立首推。Agent 不再全局覆盖 preferred。 |
| 已定成员、零候选项、同槽多选在确认时丢失 | 完整 pendingRawValues 按槽保存；已定槽冻结正式编码，确认后重验全清单；保留零候选项及明确多选。 |
| 连续增删替换遇歧义后，已完成动作或后续动作丢失 | 保存实际 baseline、已完成前缀、未决动作及剩余尾序，确认后按原顺序恢复；变更轨迹用于整批准入。 |
| 只确认多目标中一项，就丢掉未执行的其他正确目标 | 跨轮派生新计划，保留原完整未执行义务，重新核验并签发全部未执行目标；旧计划和来源不改写。 |
| 先裁剪权限后做近似识别，把失权机构纠错成有权近名 | 先在完整启用目录识别，再按当前权限过滤；不返回隐藏候选、内部身份或冻结编码。 |
| 名称中的“和/与/及”被误当集合连接词；“第二家”被误当总数量 | 用当前目录保护名称后拆分；成员序号与集合数量分别处理。 |
| 模型把未明确称谓擅自补全为一家目录机构 | value 保留用户原称谓，规范名放 suggestion；宿主继续拒绝没有来源的猜测，真实未决项进入澄清。 |
| 页面已屏蔽失权结果，原生 read(entry) 却能读到旧数值 | list/entry 先定位涉及完整回合、重新鉴权，再截片；回读回执持久化来源，后续撤权也能屏蔽复制正文。 |
| 普通回答复述历史值，却没有来源可供后续撤权 | 保存模型实际看到的有界、已授权历史来源，普通回答也按这些来源复核。 |

百轮会话的原文保留在原生账本；原生回读只在宿主本地定位，模型收到有界页面或正文片段。新增 100 轮回归证明，精确读取第 50 轮只调用一次 getTask，同轮再次读取复用结果，避免全会话鉴权。

## Token 对照的实际边界

同一个三机构原问，本轮链路审查前是 1 次调用、10,091 token，最终代码是 1 次调用、10,491 token，增加 400 token（约 4.0%）；新增原称谓与来源规则占用输入，本轮没有进一步降低这条已修复普通查询的 token。更早截图缺陷的首轮为 3 次调用、30,993 token，和最终结果相比减少约 66.2%，该旧缺陷证据见 [原三机构失败报告](multi-org-suggestion-20261016.md)。这两份基线分别列出，不能混成一次对照。

最终普通原问与“只看江阴”均只调用模型一次；歧义、确认、双指标及错字测试仍存在 2–3 次模型调用，包括模型连续 set 的修参往返。缓存命中也没有稳定保证：最终首轮读取缓存 10,240 token，下一轮为 0。不能把本次正确性修复报告成“全部请求一次调用”或“第二轮缓存问题已解决”。

输入口径为原生 provider usage 的 input + cacheRead + cacheWrite，缓存读取是输入的一部分；输出单列，宿主自动执行不计成模型调用。保留了一次首轮 provider timeout，两个错误尝试的 provider 用量未知；其后的依赖轮次不能作为有效澄清验收。此前的猜测、重复提案和权限读取失败也保留在证据摘要中。

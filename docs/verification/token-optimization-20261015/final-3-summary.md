## 失败与恢复

- 候选缺项确认第 3 次重复失败：首轮已经保存指标并正式要求补机构、日期；补充后模型两次使用 `source:new`，首次重述旧指标被 `ENTITY_SOURCE_NOT_ESTABLISHED` 拒绝，随后省略指标形成新的缺指标状态。没有查询提交，未满足用户要求。详见 `final-3-missing-rep3-trace.json`。
- 基线普通多轮第 3 次重复的最后历史回读失败：只读历史工具调用后没有正式 `read_business_result` 成功回执，不能视为完成。候选同配对通过；此组不计入“双方成功普通”节省子集。
- 原范围空结果未改问法、未改范围。双方在 120 秒保护时取消，基线 17 次模型、候选 21 次模型，均零业务查询提交。候选还出现超时说明与取消说明两条可见消息，`SINGLE_AUTHORITATIVE_ANSWER` 原样失败。
- 同一范围 native 记录分别通过冻结基线和候选投影：基线记录双方均显示 1 条取消说明；候选记录双方均显示 2 条、entry 与正文 hash 一致，来源是一次模型首响应超时以及最终取消。它不是本次新增 direct 投影分支造成的差异，但本次失败路径仍不满足唯一可见答案验收，不豁免断言。详见 `paired-final-3-range-projection.json`。
- 所有 68 回合的关闭/重新打开、GET 历史一致性、旧 Frame 不变及恢复不新增 `basicQueries` 提交断言通过。JSON 中 `query_count` 与审计 `sql_executions` 指业务查询提交次数，不代表数据库物理 SQL 总数；鉴权、查询任务读取等仍可能执行元数据 SQL。

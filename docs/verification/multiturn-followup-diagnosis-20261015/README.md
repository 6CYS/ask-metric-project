## 失效机制与实现位置

1. **模型提案没有保留续问语义与指标身份。** 最后一轮用了new，并复述了缩短后的指标名。当前提示词已经要求完整指标不拆到selection，并要求未变化条件通过current/reference继承；现场仍然违反这两条约定。提示词存在不等于宿主能保护这些约束。
2. **宿主继承与纠正范围不完整。** `agent-service/src/semantic-task/planService.ts:37`的confirmedContext只收集organizations、time、selection，没有指标；`:140`对new误提案的续补纠正，前提是焦点waiting_input。本次焦点completed，因此没有触发。`:242`的新目标处理仅保护可继承范围，完整指标身份没有随本轮机构变更保留。
3. **内部解释错误被转成用户澄清。** `agent-service/src/semantic-task/service.ts:514`只在当前原句已有完整指标片段时识别MODEL_FIELD_NOT_ALIGNED。本轮原句只有机构，没有指标片段，未对已确认历史来源作同等判断；`:521`因此产生ENTITY_NOT_DETERMINED(user)。`feedback.ts`和`harnessHost.ts`按needs_user交付澄清并结束，Pi未进入修提案循环。

上述三个环节连起来解释了实际第四轮。目录对缩短指标返回多个口径候选是合理行为；将缩短后的模型复述当成用户新指定的指标，才使已有确定条件退回歧义状态。前三轮成功也不能证明多轮继承稳定。

## 通用修复应满足的边界（尚未实施）

- 在本轮入场时固定可引用的业务目标和完整条件快照。由Pi提出续接、替换、追加或新目标；宿主按本轮明确变更和已签发来源校验条件，不依赖模型重新复述未变化的指标名称。
- 同一会话内明确只改机构或日期且来源唯一时，保留未变化的已确认指标身份与口径；同时保留用户真实的新指标、删除、否定和未决修改，不让旧条件回填覆盖本轮意图。
- 模型无本轮依据地缩短或改写已有指标，应作为Pi提案纠错处理；只有来源确实不唯一、历史条件未确认或用户本轮引入真实歧义时才追问用户。不能直接从目录候选里猜选一个。
- 新话题、独立查询和新会话不能盲目继承；多目标必须先明确所选目标及绑定关系，不能把相同日期或指标当成可以合并目标的依据。
- 保留Pi的理解、规划、探索和结果驱动能力；宿主负责条件身份、来源、权限、许可和错误分类。不能仅新增“某银行呢”关键词分支，或无条件让所有new目标继承旧指标。

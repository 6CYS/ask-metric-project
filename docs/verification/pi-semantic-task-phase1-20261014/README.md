## 基线范围与使用

[baseline-source.tar.gz](baseline-source.tar.gz) 保存当前未提交工作树中的白名单源码、测试、Skill 和构建依赖定义。基线工具不读取环境文件或运行数据，不提取归档、不覆盖源码，也不操作活跃 Session。归档不包含依赖安装目录、二进制样本、业务数据和数据库，不能当作完整部署包或数据备份。

`capture-baseline.py --verify` 会分别核验归档摘要、成员摘要和当前源码差异；发生差异只报告并退出，不自动还原。源码进入第二阶段修改后，预期会与基线不同，应按阶段差异分析，而非覆盖已有用户修改。

## 复审后的契约修订

- 原始消息及可信历史形成的义务与 Pi 提案独立对账；模型只提交甲，不能让原句中的乙消失。
- 追加成员明确使用 `add`，不在 `set` 字符串中隐藏追加动作。
- 请求、规范化结果、反馈及引用生命周期形成闭环；新 Pi 只接收新协议投影。
- 当前引用修订冲突与历史条件快照分别处理，并持续核验源操作最新在途状态。
- 证据齐备后继续完成答案交付，任务完成状态不能让回合在 Pi 回答前停止。

宿主能够检查确定性约束，不能形式证明任意自然语言含义；大于 95% 的目标仍须独立完整任务语料、重复稳定性与真实链路验收。下一阶段按统一契约联动入口、状态、Resolver、Frame 编译、许可、Pi 接续及页面投影，首先实现精确查询和连续对话闭环。

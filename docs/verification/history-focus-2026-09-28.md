# 历史引用与焦点修复验收（2026-09-28）

范围：新建会话及之后的连续使用。沿用 Pi → FrameSelector → Delta → Field Resolver → 受控执行的通用机制。

## 修复内容

- 区分当前讨论焦点与最新历史操作，展示稳定序号及有界历史条件索引；支持序号、相对位置、业务条件定位。
- 唯一选中历史业务时保存焦点，即使用户只要求讨论条件、暂不查询也要落实；分页浏览、歧义和无匹配不切换。
- 历史索引、分页和 Selector 共用本轮开始前的操作集合。本轮新操作更新焦点，下一用户回合才纳入历史，避免执行后重新解释相对引用并重复查询。本轮快照仍可按 frameId 精确引用。
- 字段解析、结构和组合校验错误统一保留已选历史来源，纠错继续继承该来源；未变化的多指标、日期等条件由服务端保留。
- 未添加按“第一次”、特定机构或指标名称分支的自然语言规则，也未将普通追问的来源参数改成必填。

## 实际检查

- `npm run typecheck`、`npm run build` 通过。

- `git diff --check` 通过。

## 真实模型验收

项目配置模型：`deepseek-ai/DeepSeek-V4-Flash`。六组共 14 个用户回合均通过，使用隔离合成目录与结果。每个回合核对查询次数、实际提交的指标/机构/日期、持久化焦点及最终回复完成状态。

| 场景 | 用户回合数 | 结果 | 耗时（秒） |
| --- | ---: | --- | ---: |
| 绝对序号引用并替换机构 | 1 | 通过 | 54.2 |
| 相对历史引用并替换机构 | 1 | 通过 | 9.3 |
| 按业务条件定位并改日期 | 1 | 通过 | 22.4 |
| 只切焦点、重开会话后续接 | 2 | 通过 | 15.9 |
| 普通追问继承当前焦点 | 1 | 通过 | 10.0 |
| 空白会话建档及八轮连续操作 | 8 | 通过 | 82.7 |

空白会话场景依次建立三笔不同条件查询，回到第一次替换机构，继续改日期，浏览列表而保持焦点，转回第二次但不取数，关闭并重新打开会话后仅换机构查询。六次取数均各执行一次，两轮只讨论/浏览没有取数。

执行命令（在 `agent-service` 下）：

```sh
node --env-file=.env --import tsx scripts/check-history-focus-model.ts --live
```

不加 `--live` 只列出场景，不代表通过验证。`--case=fresh` 可单独运行空白会话连续验收。

机器可读的工具参数、查询参数、逐轮状态、模型回答及源码校验值见 [完整验收记录](history-focus-2026-09-28.json)。开发过程中的失败用例经过修复后重新整组运行，以上统计来自最终同一批次。

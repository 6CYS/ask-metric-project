# 一期回答流式展示开发与验证记录

日期：2026-09-30。范围：零期首字埋点 + 一期临时回答流式展示。

实现已完成；真实模型测到首字展示收益，但方案 4.9 的全量上线门槛尚未通过。
代码中的 `AGENT_ANSWER_STREAMING` 默认关闭；验证后已按用户要求在本地开发配置中开启，并重启智能助手与前端。未启用生产灰度。

## 实现与兼容

- 宿主逐次判定 `none/text/reply`，旧协议、摘要、已有普通回答和强制业务工具调用不流式；模型重试沿用调用编号并撤回上一尝试。
- `AnswerStreamProjector` 只读原生事件，80ms 合并累计正文，调用结束补齐；工具调用、冲突、重试、错误均可撤回，异常禁用临时投影并继续原生快照路径。
- 提问路由的授权发送队列保留，先关闭 projector 再发送正式快照和终态。GET 观察/恢复流维持原行为。
- 前端 `provisionalContent` 与正式 `content` 隔离，pending 时按原 markdown 渲染；撤回、快照、失败收尾清理临时字段。临时内容不进入存档、复制、导出或 localStorage。
- 结果区域按最新确认的交互调整为表格在上、回答文字在下，实时流式与最终回答使用相同的上下顺序；本次位置调换不调整展示时机与滚动行为。
- `first_visible_ms` 与各次 `model_first_token_ms` 接入终态、请求诊断日志和耗时面板。首字指标是服务端发送正文时间，不包含浏览器渲染与网络时间。
- 新前端通过 `X-Agent-Answer-Streaming: v1` 声明支持流式。检查发现旧前端将未知 SSE 事件落入工具结束处理，不能假设它会忽略新事件，因此开关开启但无声明时仍使用原有事件序列。协议版本保持 3。
- 流式实现本身未修改模型提示词、工具参数、业务 Frame、查询后端或数据库；工作区已有的普通对话处理、上下文与执行过程展示改动一并保留。

## 真实模型首字对照

模型：项目当前配置的 `deepseek-ai/DeepSeek-V4-Flash`；身份、业务后端与数据均为隔离合成样本，未连接真实业务数据库。
相邻成对测试，并交替开启/关闭顺序；每侧 10 轮普通对话和 10 轮业务请求，包含澄清和历史追问，共 40 轮。

| 首字中位数（全样本） | 关闭 | 开启 | 提前 |
| --- | ---: | ---: | ---: |
| 普通对话（每侧 10 轮） | 6.324 秒 | 2.111 秒 | 4.213 秒 |
| 业务请求（每侧 10 轮） | 11.418 秒 | 8.767 秒 | 2.651 秒 |

普通对话全部整轮完成。业务请求两侧的 `within_access` 均未发起预期查询；剔除此失败轮次后，首字中位为 10.495 → 8.534 秒。
首轮对照脚本的通过断言是“整轮完成 + 查询次数 + 最终流式内容一致”，没有覆盖完整业务语义；不能将其 9/10 当作业务正确率。完整语义以后一节的 55 轮回归为准。
脚本已加强为复用 `checkExpectation` 的完整语义断言，并对失败轮次排除延迟统计；原首轮报告保留原样，避免改写证据。

首字提前并不代表模型整轮计算减少：业务请求总耗时中位为 11.418 → 11.467 秒。普通对话总耗时差异包含模型响应波动，一期没有减少模型调用。

首轮共有 22 次调用展示过流式文字，3 次撤回，比例 13.6%，高于方案的 5% 门槛。
撤回集中在 `shared_prefix_metrics` 开启侧：原生记录显示首次查询后又执行三次工具步骤，其中两次是 `FIELD_INPUT_NOT_CURRENT` 参数纠错，另一次读取业务知识；这些工具消息的正式正文为空。投影按工具调用撤回临时文字，最后以原生正式回答覆盖。
这是需要观察的模型继续执行/纠错行为；不能通过保留已撤回文字来降低撤回率。

原始证据：[40 轮首字报告](answer-streaming-benchmark-20260930.json)。

## 全量真实模型语义回归

`check-query-intent-v2 --live`，每侧 47 用例、55 轮；开启侧接入真实原生事件 projector，关闭侧保持快照路径。

| 开关 | 通过轮次 | 通过率 |
| --- | ---: | ---: |
| 关闭 | 49/55 | 89.1% |
| 开启 | 48/55 | 87.3% |

两侧共同失败包括机构范围表达、排名方向、多指标遗漏/重复执行/超时以及四指标澄清续跑。
开启侧另有 `children_other_parent` 返回待澄清而未查询，`daily_ranking_unsupported` 在受控拒绝后模型超时；关闭侧另有指标名“排名”被当成查询排名动作。
这些是模型选择与完成行为的差异；本次单次对照不足以确定差异的稳定性，也不能声称全部由流式引起或已排除功能回归。

结论：通过率不低于基线和撤回率 ≤5% 两项上线门槛未满足，暂不启用灰度/生产开关。保留失败样本用于后续诊断，不修改业务规则、语料期望或有效测试来掩盖失败。

证据：[关闭报告](answer-streaming-regression-off-20260930.json)、[开启报告](answer-streaming-regression-on-20260930.json)。

加强断言后另复测普通对话、单指标排名及多指标样例共 6 轮。问候和单指标查数正常；多指标样例两侧均失败，指标 `M5` 遗漏，开启侧在模型失败时发出 `answer_reset(reason=error)`。
请求日志中的两个首字/模型首输出字段具有有效数值。复测与功能回归存在并行负载，不用于替代首轮延迟基线。
证据：[复测报告](answer-streaming-smoke-20260930.json)。

## 复现与回退

```bash
cd agent-service
npm run typecheck
npm test
npm run build
node --env-file=.env --import tsx scripts/check-answer-streaming.ts --live --report /tmp/answer-streaming.json
AGENT_ANSWER_STREAMING=false node --env-file=.env --import tsx scripts/check-query-intent-v2.ts --live --report /tmp/query-off.json
AGENT_ANSWER_STREAMING=true node --env-file=.env --import tsx scripts/check-query-intent-v2.ts --live --report /tmp/query-on.json
cd ../frontend-vue
npm run typecheck
npm test
npm run build
cd ..
git diff --check
```

测试环境复核门槛后可设置 `AGENT_ANSWER_STREAMING=true` 并重启 agent-service。
回退设置为 `false` 并重启；没有新增依赖、业务接口、数据库迁移或原生历史格式迁移。
真实数据库、实际网络故障及生产灰度未验证。

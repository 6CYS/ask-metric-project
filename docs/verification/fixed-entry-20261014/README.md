## 改造结果

模型业务提交只使用 `resolve_business_turn`，根字段固定为 `protocol_version/capability/base/mode/changes`。三个能力各自闭合，字段动作、值、枚举和类型均校验；未知字段、跨能力字段、隐式类型转换、非法排名条数在写入 Frame 前拒绝。业务状态读取、恢复回执、历史发送副本与实际 provider 参数统一该协议。

一项字段变化只声明一次，适配器生成内部旧 Delta 和目标声明；实际参数 Schema 复用能力字段定义。系统能力块不再复制整份输入 Schema。旧 legacy/compact 模型格式不再由开关选择，`AGENT_COMPACT_TURN_ARGS` 只保留配置读取兼容。完整说明、四个已离线校验的示例见 [接口说明](../../fixed-business-turn-interface.md)，机器可读 [Schema](public-request-schema.json) 与 [请求示例](request-examples.json) 可直接核对。

保留目录、权限、指标跨度与正式编码、原文来源、数量、口径、执行状态和结果证据校验。精准查询、日期追问、确认恢复、历史焦点、重开会话和幂等执行仍走原服务。排名数量未知继续澄清，不填 null、不擅自补前 10 名。

旧 JSONL、Frame 和结果事实不改写。旧在途 `planned` 调用只按原 operation、callId、原参数恢复一次；新的模型请求开始即关闭该许可。`effect_pending` 不重放未知副作用。可无损转换的历史调用在发送副本上转为固定格式；无法转换的调用与回执成对转为历史数据，查询条件仍由已保存 Frame/索引关联。

后端保留本地启动时跳过目录预热的方式，没有刷新目录/数据。后端和前端业务源码、本任务前的迁移及依赖均未修改；已有 Starlette 警告和前端大 chunk 警告不影响本次通过。验证不包含浏览器交互、生产部署或真实数据湖验收。

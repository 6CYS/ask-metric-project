## 已落地的执行链

明确查询仍直接进入 `resolve_business_turn → Frame → 原后端查询`，不强制读取 Skill、探索目录或建立计划。原精确指标覆盖检查、候选确认、历史 union、数量、排名/位次、权限、事实读取及受控计算保留。

开启新模式后，模型通过 `analysis_task` 登记目标和要求，按需要发现正式指标、读取方法或已有结果，提出步骤；宿主保存不可变引用和版本，将步骤转成 supporting Frame。后端先准备并冻结规范，再仅按 prepared 引用执行。结果回到同一个模型循环，模型可以追加或更新步骤、补充证据、修订计划或保存缺口。宿主没有新增固定业务工具顺序。

## 哪些限制仍保留，哪些已经解除

权限、正式指标身份、原文来源与候选资格、固定机构/日期、执行幂等、事实完整性和要求覆盖由程序执行。模型不能靠提示词或自报来源绕过这些边界。

新分析模式允许模型在授权目标内选择用户没有逐个列出的正式指标，选择已部署差额/增长率方法，按结果追加取证或修订步骤。完整查询不被迫探索；分析新指标不再一律要求出现在本轮原话，也不再整体拒绝描述性综合分析。

长期提示词保留目标理解、确认语义、证据和范围原则。方法判断迁入 `business-analysis` 等 Skill，Schema 只发送一次；重复子结构用标准 JSON Schema `$defs/$ref` 共享，全部机器校验保持。相对本次新接口未经共享的版本，仅参数 Schema 字符数减少约 59.8% / 58.2%，这不是整个请求的 token 减少。本批 provider 上报的首请求 prompt token 加权减少 18.1%，未达到原定 40% 目标，也未带来分析通过率提升。

## 上下文保护

- 旧 Frame、operationFrameId、fact_id、current/null 和历史 ordinal 保留，不批量改写原生 JSONL。
- 分析任务拥有独立 anchor 和 currentContext；辅助查询不成为下一轮的默认讨论对象。
- 多 target 显式绑定各自机构、日期、指标；多个明确指标未按 target 指定时拒绝交叉展开。
- 固定条件修订会使旧约束/步骤引用失效；迟到结果保留审计，不能完成新版本要求。
- 已完成 query 分支在追加计算时保留；未变分支不因计划局部更新而丢失证据。
- 语义参数错误可用同请求 attemptRef 只修错误字段，失败提案的其它本轮变化和原来源从不可变状态恢复。

精准与追问 4 轮均为每轮 1 次业务查询、2 次模型请求，候选未增加目录或计划前置。首请求 prompt token 合计从 85476 降至 69981，减少 18.1%；精准 18.9%、上下文 17.4%、分析 18.9%。精准与追问平均耗时从 3.110 秒变为 6.289 秒；单批不能推断稳定速度，但不能宣称本批更快。总 token 从 268385 变为 199056 包含失败提前终止及不同调用数，不能当作同等完成任务的成本改善。

独立复核还发现评分盲区：候选在两次追问的最终回答自行增加“较上次增加 20 亿元”“比甲高 100 亿元”。算术与合成事实一致，但没有正式 calculate 调用。4/4 通过仅说明精准条件、编码、取数和继承正确，不表示回答侧计算的治理契约已经验收通过。该项保留为后续回归风险。

候选两项分析都以 `MODEL_STREAM_IDLE_EXCEEDED` 结束，耗时分别约 128.5 秒和 138.5 秒。原生记录中的 `analysis_task` 只有未完成的模型提案，没有完整工具调用结束事件及执行回执，故不是计划已创建或取数成功。混合场景 catalog 与 Skill 均已完成，工具耗时 14ms / 0ms，未发现 Skill 死锁证据。缺数场景先收到 `INVALID_MENTION_REFERENCE`、再收到 `FIELD_INPUT_NOT_CURRENT`；模型自主选正式指标仍尝试走原精准入口，之后改向分析工具时流未正常结束。这里同时存在入口选择问题和模型流超时，尚不能把超时归因为单一实现缺陷或外部服务故障。

两个分析场景都没有进入缺值取证及补查阶段，增长/结构覆盖、结果驱动重规划和缺口说明均未通过真实模型验收。不能用本地桩测试或模型生成的计划文字替代。缺数 fixture 以缺少 rows/facts 并附 missing notice 表示无有效值，本批不证明数据库 NULL/哨兵值语义。

混合场景未执行的分析草案本身也有覆盖问题：声称查询两个必查指标的步骤只引用总量编码，声称个人占比的步骤复用了总量引用。这是模型草案错误，不能表述为宿主已经接受或执行错误计划；由于工具流没有完成，实际宿主校验还未触发。目录广主题首屏集中同一总量指标家族、缺少其它家族的可执行引用，值得后续改善探索结果与引用选择，但本批尚不能证明它就是超时原因。

可复核原始资料：`fixed-baseline.json`、`fixed-candidate.json`、两侧 `*-native/`，同脚本/数据集/模型参数比较为 `comparison.json` / `comparison.md`，独立审计见 `fixed-batch-audit.json` / `.md`。32 条原始 usage 的加总及 8 份 native SHA256/字节数均核对一致，本次运行期间源码哈希均未变化。

按用户“先完成各 6 轮看看是否正常”的要求，本批止于测试与诊断，不修改运行时代码、不追加模型调用。后续先离线核查三处：精准入口参数错误回执应在已授权分析的条件下指向合法 `analysis_task` 路径，保留精准原文校验；广主题目录结果应改善家族覆盖；分析工具已有“先仅建任务、按需加步骤”的能力，应让模型更容易使用。单次未完成提案约 875 / 1183 字、681 / 797 输出 token，未见输出预算耗尽，不能认定参数长度就是超时根因。增加离线回归后再安排必要的定点真实模型验证。

## 业务规则与改动

对能力 Schema 中启用 `requireTurnIntent` 的任意字段，由 `required` 与本轮实际修改共同决定是否必须声明：

| 字段及操作 | 声明要求 |
| --- | --- |
| 必需字段，包括未变化或 retain | 必须声明；未变化使用合法 inherit |
| 可选字段，省略或 retain 且未变化 | 可省略声明，按已选 Frame 继续继承字段 |
| 可选字段，本轮 set、候选确认、clear、remove | 必须声明，与真实操作及本轮依据一致 |
| 显式提交的任何声明 | 继续检查结构、字段归属、原文、模式和数量 |

运行修复在 `validateFieldIntents` 内按元数据判断，没有指标、机构、能力名或字段名特例。后续来源、模式、确认依据、数量冲突及完整集合校验保持原样；省略可选声明不清除已保存的字段、来源或数量约束。可信内部旧 Delta 的兼容路径保留，模型仍不能关闭宿主绑定的门禁。

工具说明从同一能力注册表生成始终必需与可选变化两类清单，主提示词只同步现有声明规则。类型注释和两份直接契约文档同步。没有修改后端、前端、执行器、权限、正式指标校验或持久化结构。

过期测试不再要求提示词含内部标识 `userClarification`，改为验证保存已知条件、服务端提出问题和禁止模型自拟候选的业务约束；并校验实际能力投影提供的澄清输入 Schema。既有澄清、确认、精准查询与上下文测试继续运行。

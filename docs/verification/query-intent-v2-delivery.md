# 查询意图 v2 交付与验收记录

日期：2026-09-22。本文区分代码实现、本地验证与现场上线；没有执行生产目录同步、部署或业务数据库测试。

## 根因与实现

原查询的指标和日期已匹配，但“各家农商行”曾被当成具体名称查找；时间 selection 又与排名共用枚举，导致合法的指定日 TopN 查询停在澄清阶段。

- 时间 selection 与 operation 判别联合分离。具体 org_codes 只代表实际对象，不再充当上级、不以空数组猜范围。旧混合参数明确拒绝。
- 集合范围通过正式省级/法人层级与同一权限服务求交集。严格检查目录父链和层级；机构目录同步始终补写已有层级列，dry-run 同样校验完整性。
- 解析返回账号/目录/授权范围指纹；新 Frame 继承集合时重新解析。执行前、结果发布前重新校验范围，本地 JWT 同时重查账号状态及登录版本。范围变化不发布旧榜单。
- Agent 刷新、重连、实时快照以及新问题入模前复核历史结果引用，避免本地缓存绕过服务端权限。
- 历史任务读取、导出、幂等找回和执行重放统一检查当前权限；旧排名还检查实际结果机构。没有可信机构范围的成功旧结果明确拒绝回放，不猜测权限。
- 按后续确认，MySQL 与 Inceptor 的查询、排名、指标发现和日期覆盖全部收敛到 SQLGlot builder，删除 42 个 SQL 模板文件及模板仓库/配置/管理页面和接口。排名限定同一业务日，NULL 不补零，同值按机构编码排序，TopN 前统计有值/缺数机构。MySQL 重复事实、Inceptor 同最高批次重复事实均标记整榜并拒绝发布，包括 TopN 外重复。
- 普通取值、覆盖、计算继续复用既有实现。内部参数错误在本轮纠正，真实无效日期或同名歧义才等待用户。业务条件缺失时先保存已知条件，不把尚未提供的内部枚举交给用户填写；条件齐备后仍须补全内部参数才可执行。
- 集合原文校验完整量词/授权范围表达，拒绝用具体机构名称或单独“农商行”后缀扩大查询范围。机构“本级”修饰仅在完整名称精确匹配失败后，按去除修饰的名称精确解析，不展开下属。

## 旧接口清理边界

新 Pi 已删除无运行时调用的 `metricAsk.ts` 及仅供其使用的 6 个旧客户端方法；只读历史类型迁至共享类型。旧执行工具会话只读保留。后端 `basic-queries` 仍是当前 Frame 的受控取数入口，升级为 v2；结果读取、导出和任务状态同样是有效依赖，予以保留。

后端渠道集成仍调用 `SemanticTaskApplicationService/SemanticEngine`。本次不删除这个在用渠道；其迁移需要确认实际渠道消费者与配套发布，不能为清理目录而破坏现有功能。旧层级回退只供该链路使用，不参与新集合查询。

前端：`npm test -- --reporter=dot --silent` 17 项通过，`npm run typecheck` 与 `npm run build` 通过。构建仍有现有大于 500 kB 的包体积提示；本次移除智能配置页的 SQL 模板页签，保留模型和提示词编辑、发布及回滚。

Agent 最终全量：`npm test -- --reporter=dot --silent`，29 个文件、249 项通过；`npm run typecheck` 通过；最近一次 build 在最后的缺项校验顺序调整前通过，最后调整后未重跑构建。旧执行器测试的有效断言迁移见 [测试迁移表](query-intent-agent-test-migration.md)，测试数变化不以删除有效业务断言掩盖失败。

真实模型 `check-multiturn-model.ts --live --handoff` 四轮通过：查询、改日期、重开后换指标、历史回读。前三轮各取数一次，最后一轮只回读；实际模型 `deepseek-ai/DeepSeek-V4-Flash`。联网初次发现内部 selection 缺失被错误澄清，修正后四轮通过，前后记录见 [真实模型多轮证据](query-intent-v2-multiturn.json)。首次沙箱网络失败未产生业务调用，不计作语义通过。

真实模型只连接已配置模型端点，目录和业务结果全部使用合成桩；不连接业务库。网络不可达、模型语义失败与离线测试失败分别记录。原始问题在修复后的定向复测中 3/3 通过；7 类场景各重复 3 次共 21 轮，18 轮通过，3 轮未通过（缺日期时未保存 Frame 1 次；未知机构重复错误参数或仅输出文字 2 次），均未错误执行 SQL。缺日期的校验顺序已进一步修复，并通过离线回归；未知机构的模型调用稳定性仍需验证。不得将这批结果表述为真实模型全量通过。

用户随后明确要求自行测试：已停止正在运行的 44 场景/51 轮模型矩阵，不再追加测试。最后修改后的完整模型验收留给用户。阶段性证据见 [模型验收记录](query-intent-v2-model-validation.json)。

## 配套上线与未验证项

1. Agent、后端配套升级，暂停接纳并排空在途操作、按原幂等键对账，再备份会话并切换。v2 不接受旧排名请求。
2. 正式目录须存在唯一省级根、正确法人行及父子关系。旧环境只同步名称时，先在授权测试环境 dry-run，再按现场审批同步正式层级。缺少层级会明确阻断集合查询，不能靠名称猜测修好。
3. 授权测试环境仍需核对省级/受限账号的真实榜单、缺数、目录同步与权限变更；浏览器刷新/重连及 GoldenDB/Inceptor 实际方言尚未现场验收。
4. 保留现有数据目录，回退整套匹配版本；旧版本不得续跑新 Frame。没有执行自动整包回退演练、渠道迁移或独立版本握手检查，不能宣称这些发布门槛已完成。
5. 旧 JSON 只有助手正文、没有可信工具回执/结果引用时，展示“无法核验历史权限”的提示并保留用户原文；不改写原始历史。包含完整引用且仍有权的旧结果，以及原生会话问候和澄清正常展示。
6. SQL 生成已统一 builder；旧 `QUERY_SQL_ENGINE` 与模板路径配置不再生效。升级不删除现场旧模板文件和配置历史；曾经通过在线 SQL 编辑发布的定制逻辑须先迁入 builder。模型/提示词配置及版本回滚保留。部署脚本 Python 编译和 shell 语法检查通过，未执行现场安装。
7. 本次没有新增依赖、数据结构或迁移，不修改生产数据，不提交或推送代码。

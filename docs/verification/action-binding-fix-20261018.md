# 动作绑定与多轮上下文修复验收

## 根因与修复

原故障发生在执行前：排除动作已得到正确集合，父计划又按原始正向提及要求补回被排除成员，随后来源对齐检查继续阻断，SQL 没有执行。

本次统一了绑定与状态更新，并在真实模型验收中修正了三个贯通缺口：

| 问题 | 最终处理 |
| --- | --- |
| 集合字段的原动作文本被当成整个集合身份，重复排除可能误删剩余成员 | 集合仅按正式编码更新；字段保存最终集合，原话与动作保留在轮记录中；等值操作复用结果 |
| 结构化查询绕过缺项绑定，把指标中的“当日数”当成查询日期 | 两种输入共用首次缺项归一，指标口径不提供日期；缺日期先追问，有可信旧日期则继承，明确换日期但没有新值时保存未决修改 |
| 展示历史后，冻结上下文从讨论焦点继承，模型投影却使用业务焦点 | `admit` 与 `runtimeContext` 统一取 `focus.business`；讨论、展示分别记录；未保留临时来源纠正分支 |
| 越界序号被模型解释成“以上都不是”，导致候选集合改变 | 在原答案绑定处识别选择语义冲突，保留原问题及候选，直接向用户说明可选项 |

时间绑定保留完整表达：已确定的日历直接归一，尚未换算的区间不能缩成端点；完整模型日历仍沿用 `modelCalendar → model_value`。日期候选回复复用原候选选择，不要求重新提供日期原文。

历史读取复用第一次解析取得的计算标识，删除为展示焦点再次解析同一句话的调用。无进展判定按根因、正式条件和候选识别，改变引用或错误文案不能重置。

## 旧链清理

- 删除 `transition.ts`、`semantic_transition.py`、`analysis_selection.py` 及旧 `/admit-plan` 接口和来源票据调用。
- 删除整批准入、`Plan.admitted`、`requirements/checks`、更新后的正向覆盖与日期二次对账。
- 删除来源对齐打回、可确定字段漏填打回及业务层重复动作形状错误；形状由工具 Schema 统一处理。
- `querySpec.ts` 仅投影当前字段；完整查询与增量动作共用状态和执行器。执行权限、版本、SQL 与结果真实性保留在原执行边界。

已检索 Agent 与 Backend 运行源码，旧准入接口、票据及上述重复阻断没有残留调用；本地旧编译产物 `transition.js` 也已移出构建目录。

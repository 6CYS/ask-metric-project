## 本次发现并修正的边界

| 问题机制 | 本轮处理 |
| --- | --- |
| 单目标Frame不能代表整笔复合目标，部分成功可能掩盖遗漏 | Session任务账本保存完整义务，普通复合目标整批获准后逐步执行；直接消费子任务不能绕过父计划 |
| 机构、指标和日期只检查集合并集，可能错配 | 每个原始片段独立绑定，后端核验机构/指标/日期组合 |
| 分析指标仍被要求逐字出现在原句 | 用户授权分析时允许选择实际目录或覆盖回执中的确定指标；后端签发范围绑定来源回执，执行时重新核验 |
| 模型收到旧执行结果而缺少任务引用和完成状态 | 模型content与宿主details交付同一正式语义反馈，复合结果各自保留身份 |
| 原句明确口径被模型拆入selection或operation后向用户重复追问 | 复用同一目录解析器恢复可唯一核验的完整概念；无法确定仍保持未决 |
| 榜单数量与机构数量混用，关注对象和比较总体混用 | 复用既有排名证据，分别规范对象与总体；同一榜单不得拆成各机构各自排名 |
| 待修单查询改为双查询加计算时按数组位置配错步骤 | 按类型及业务条件匹配；未获准新提案可整体重组，被替代步骤留档且不能执行 |
| 新建字段误用add时向用户索要已经提供的条件 | 缺少原集合的操作错误交回Pi修正；已存在但未决的原集合仍要求真实选择 |
| 多个查询覆盖不同日期，却被要求一个来源覆盖全部日期 | 以各成功来源联合覆盖每个机构/指标/日期义务 |
| 历史追问的年份或日期被另一条路径重新解释 | 规范来源提供唯一继承年份，叶子与整批准入使用相同年份；本轮显式日期独立核验 |
| 无效依赖、过期计算或截断结果可能被当成完成 | 查询前检查公式与来源，查询成功后由宿主绑定正式事实；依赖变化使旧计算证据失效 |
| 覆盖能力、清除可选字段和能力说明仍沿用旧终止边界 | 覆盖及分页接入既有执行器；可选clear不留永久待决；综合分析说明返回继续规划 |
| 页面只保存最后一个查询结果 | 版本2复合结果逐项保存、展示及刷新恢复；单目标正文保留一次 |

这是本轮发现和有回归证据的修正清单，不是全仓库剩余bug总数。不能通过有限测试证明“还有0个bug”。

## 失败记录与验收边界

所有中间报告保留。例如[较早8/12报告](real-model-accepted-candidate.json)记录榜单拆分无法重组、新建add被误判用户缺项、离散日期义务误判及模型只读上下文后不执行。[另一轮报告](real-model-delivery.json)的原脚本统计12/12，但[独立审计](real-model-delivery-audit.json)拒绝把分析首次合批两项当作结果驱动。最终报告以独立审计为准，未覆盖或改写这些失败。

最终12/12是一次小规模合成验收，通过重复样本验证了本轮候选的具体行为；多轮调试使用过这些样本，不能视为独立保留集，也不能推出稳定成功率或95%覆盖率。尚未完成同一源码的完整基线配对、代表性实际问法语料、真实HTTP身份、登录浏览器、真实模型与真实数据库合并验收、默认切换和回退演练。

现有后端容量及不支持组合继续适用。多值历史来源的计算需要明确聚合；复杂历史修改、动态机构范围与多目标混合组合尚未广泛验收。阶段3允许按实际证据选指标和追加步骤，不代表任意业务表述、分析方法或执行组合已获支持。

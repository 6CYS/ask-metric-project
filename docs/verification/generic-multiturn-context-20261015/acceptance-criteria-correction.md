# 同条件查询复用的验收口径修正

2026-10-15：原执行断言要求每个成功查询轮必须发起 SQL，因此把“6 月末的”这种与上一轮 2026-06-30 完全相同的续问使用正式结果重显判为 ONE_EXECUTION 失败。这是验收口径过严，不是该轮业务结果错误。原失败报告保留，后续新报告单独生成，不覆盖它。

仅为明确与上一轮条件相同、且没有要求刷新数据的指定轮增加 `allow_evidence_reuse`：`model-cases.json` 和 `core-cases.json` 的 `completed-followups` 第 3 轮；`model-context-principles.json` 的 `principles-collection-negation` 第 3 轮。其他轮的执行数量、精确机构、指标、日期及绑定范围断言保持原有要求。

启用该标记后仍可执行同条件查询。若 Pi 选择不发 SQL，则必须提供 `succeeded` 或 `reused` 的正式回执；其 evidence 所有来源均成功且未截断，查询 payload 包含任务及结果引用，并有完整 rows 或 metric_value facts。提取出的机构、指标、日期元组必须与预期逐一相等。只有成功文字、无证据、错范围、截断、失败来源或重复数据均失败。历史 Frame 和结果引用仍逐轮核验不变。

## 最终正文与历史回看的证据标准

后续验收读取本轮投影的最后一条权威助手正文。最终投影存在 error、最终模型停止原因是 error/aborted，或没有最终正文均失败；前面暂时传输失败后最后成功的轮可通过，但单独记录恢复标记和中间错误，不再把所有助手文本拼成最终答案。查询成功还必须同时具有与预期范围逐一相等、成功且未截断的正式证据，任意非空文案不足以判定完成。

三条历史回看用例继续严格禁止 SQL，同时新增 `evidence_queries` 指定所要求的机构、指标、日期：`pending-and-history` 第 6 轮、`bound-targets` 第 4 轮、`principles-multiple-explicit-one` 第 4 轮。回看错误的历史目标、缺少来源、少显示目标或只有成功状态均失败。既有运行报告原样保留，新的验收报告按新口径单独生成。

Frame 检查覆盖原生账本中全部快照，逐轮核对旧 Frame 的存在、账本顺序成员及完整哈希。每次 SQL 还必须有自己的成功 Frame：结果引用、指标、机构、日期、取数方式、操作及比较范围全部对应；存在任意一个旧 Frame 不再足以证明整轮执行经过 Frame。

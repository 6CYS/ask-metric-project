代码已实现并加载到当前本地 Backend/Agent。Pi 与 Frame 均保留。**真实模型完整验收未完成：网关再次返回 HTTP 402。**本报告不声明达到 95%，也不把未运行场景算作通过。

## 设计问题与统一修改

旧问题不只是某句问法缺少关键词。语言含义、状态来源、规范身份、执行许可和结果展示之间的职责混杂，会产生以下机制问题：

| 问题 | 本次处理 |
| --- | --- |
| 关键词增删改判断无法完整覆盖否定、转折与指代 | 撤回 `_metric_change` 及消费者；Pi 根据原句与上下文选择来源、动作和作用目标，宿主不按关键词重写决定。 |
| 新建/续接混用，或同轮纠错受错误来源锁死 | `new` 从空条件开始，`current/reference` 显式继承；未获准草案可完整重提纠正来源，不能修改已获准或执行来源。已移除独立 `inheritedFields` 注入路径。 |
| 动作原文替代当前集合，排除后模型又看到被排除指标 | 反馈、入场条件、标签和运行上下文统一展示完整规范身份集合；动作原文与实际 before/change/after 另留审计。 |
| 待补状态或错误草案污染旧目标、默认上下文 | 跨用户回合派生新计划，旧计划保留；默认只投影当前有效焦点，无焦点时错误草案仅通过历史读取。 |
| 没有待选候选也触发确认 | `CONFIRMATION_NOT_AVAILABLE` 交 Pi 修正参数，不制造用户选择；真正缺项和目录歧义继续追问。 |
| 回看旧结果成功/失败会改变旧计划或当前焦点 | 直接历史读取只生成本轮反馈，不改旧计划、许可或焦点；显式 `reuse` 可派生本轮计划。 |
| 原始来源对账把已替换/排除身份重新当作正向义务 | 宿主生成规范状态变更，后端核对旧范围票、实际变化与最终范围；新增身份必须有当前或可信来源，不能靠裸 after 补票。 |
| 不相关的失权历史来源阻断合法查询 | 只有核验通过的上下文可解释本轮义务；未使用的无效上下文保留诊断而不连带阻断。真正需要的无权来源仍拒绝，执行步骤的权限校验不变。 |
| Frame 清空变化投影为 set | 最终字段缺失或 missing 时准确写 clear；完整动作链保存在任务 transition。 |

执行仍在同一 Pi 原生 Session 和工具循环内。没有新增前置意图 Agent。Frame 保存执行输入及正式证据关联，新的条件生成新 Frame，通过 `parentFrameId/delta` 连接原快照；旧 Frame 和结果不覆盖。

真歧义由 Pi 调用 `clarify_business_turn` 提供真实备选，下一轮可明确 `resume/defer/abandon`。此机制没有规定全部修改或一律追问。目录、日历、权限、覆盖、签票和结果证据继续由宿主及后端验证。

设计及兼容说明见 [通用多轮上下文实现](../../pi-semantic-task/implementation-multiturn-context.md)。

两个最终模型报告的运行源码哈希相同，且与当前文件一致。全部最终查询都检查精确条件、正式成功且完整的证据以及对应成功 Frame；历史回看检查精确身份且零新增 SQL。历史 Frame 全量哈希及成员保护避免仅验证文本答案。

两次 HTTP 402 的阶段不同：原场景第 5 轮已取得正确查询证据，最终模型回答被阻断；扩展场景某轮读完历史后，尚未提出修改就被阻断。两轮均记为**未完成**。超时发生在任何工具调用之前。没有把这些轮次记为语义成功，也未从 HTTP 402 无响应体推断具体账户原因。

早期候选与失败报告原样保留，只用于诊断。此前四轮基线样本也曾 4/4，因此不能以同一个小样本通过宣称解决所有不稳定，更不能用不同版本、不同样本计算提升率。

验收断言另做了职责校正：不再让宿主用原句关键词判定动作含义；保留“集合外对象不能被排除”的身份断言。合成 `inspect` 桩将无目录/日历事实的尾部限定并入前句，与当前真实 `inspect_goal` 一致，未删除真实业务义务。最终正文断言区分中间传输失败后恢复与最终失败，不能仅靠任意非空文字判成功。

# 通用多轮问答手工验收

每组新建一个对话，组内按顺序发送。以下是模型合成用例替换为本地机构名称的执行版，**不代表这些真实数据库对话已经全部通过**。指标以当前目录中的完整名称为准；数据库无记录时应如实返回无数据，不能补造数值。

重点观察：只修改明确的目标；不重复追问已确认口径；真歧义才追问；排除项不会复活；回看旧结果不暗中改变当前目标；机构、指标、日期不形成错误交叉组合。

## completed-followups

1. `查询无锡农商行2026年5月31日的对公协定存款余额当日数`

4. `苏州农商行呢？`
   - 最终查询条件：苏州农商行 / 2026-06-30 / 对公协定存款余额当日数。
5. `指标改成经营收益金额当日数`
   - 最终查询条件：苏州农商行 / 2026-06-30 / 经营收益金额当日数。
6. `日期再改回2026年5月31日，机构和指标保持刚才的`
   - 最终查询条件：苏州农商行 / 2026-05-31 / 经营收益金额当日数。

## 观察性补充

- 已有两个目标时发送“先看看第一项的原结果”，再发送“当前这项日期改为2026年6月30日”：Pi 若认为“当前这项”有两个合理指代，应追问；明确指定原当前目标时不能被历史读取暗中切换。
- 比较位次后改成普通取值：最终执行不应继续带比较总体；旧 Frame 保留，新 Frame 清空变化可追溯。
- 本轮内部参数错误应由 Pi 纠正；没有真实业务候选时不能制造“请再选一次指标”的追问。
- 当前网关若返回 HTTP 402，属于本轮未完成，不能按仍展示的旧表格判断成功。

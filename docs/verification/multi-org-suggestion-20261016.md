# 三机构普通查询失败修复与复验

2026-10-16截图对应原生会话 `01a1407b-5873-76f4-85c2-752e2619a7d2`。原问为“查询无锡、江阴、启东2026年5月31日的对公协定存款余额当日数”。

## 实际失败链路

1. 模型对同一机构字段连续提交3次set，返回 `FIELD_MULTIPLE_ASSIGNMENTS`。
2. 修复提案的value包含三家机构，但suggestion只指向无锡。Agent建议接口将raw_values写死为[]，完整value没有送到目录服务，解析后只保留无锡。
3. 后端对照原问发现缺少江阴、启东，返回 `PLAN_TARGETS_INCOMPLETE`。模型再次提交相同参数，触发 `SEMANTIC_NO_PROGRESS`。
4. 终止回执原先用停止提示覆盖了实际拒绝原因；随后“什么原因失败的？”又被模型当成新query，重复旧参数并创建了无有效机构、指标和日期的新任务。

首轮3次模型调用、30,993 token，未取得正式查询结果。失败发生于机构集合解析和整批准入阶段。此前验收覆盖了三家逐次追问再组合及三家排名，没有覆盖本次“多机构value＋单机构suggestion”的真实参数组合。

## 修改

- 语义机构解析把value的全部成员作为raw_values与suggestion一起发送，复用后端现有合并解析。suggestion提供身份提示，保留完整原值集合；目录、权限、原文依据和逐目标完整性检查继续执行。
- 重复提案终止时保留实际issues，再追加停止原因；多机构set的纠错回执明确要求一次提交完整清单。
- 原因和状态询问读取已有计划issues，再通过普通回答工具交付说明；与执行、重试及条件修改分开。对应回归检查旧计划及焦点不变、没有新增业务取数。

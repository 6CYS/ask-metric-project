# 工具调用治理与验收

本次以 `wangdh` 当前工作树为基础，保留已有业务 skill、计算工具及未提交改动。不新增意图分类模型、路由器、多 Agent 或第二份会话记忆。

## 动作合同

| 用户目标与已有证据 | 动作 | 权威边界 |
| --- | --- | --- |
| 独立基础取值，条件可不完整 | `metric_ask new` | 宿主提交原文，后端提槽并返回正式澄清 |
| 回答当前待补任务 | `metric_ask clarify` | 使用正式 `task_id/version/clarification_id`，后端再次校验版本与归属 |
| 沿用成功任务修改条件 | `metric_ask followup` | 模型选定来源，宿主核对成功回执；不能静默换成最近任务 |
| 从覆盖回执继续选指标 | `metric_query_structured` | 使用正式编码与完整覆盖区间；全区间明细使用 `all_in_range` |
| 重显已经查询的结果 | `metric_read result` | 不重新取数；后端校验结果引用及权限 |
| 来源或修改含义有歧义 | 明确询问或 `clarify_context` | 不替用户挑选来源或补条件 |

跨工具选择写入系统提示词；具体用途、不适用场景、前提和回执写入工具说明；业务 skill 仅提供业务口径和规则，不承担路由或工具门禁。所有业务工具提供给 pi 自主选择，读取知识不改变工具集。结构化取数要求编码、日期和口径已确认，不要求先产生覆盖回执；只有沿用覆盖范围时才引用其完整条件。自然语言查询仍可交由后端提槽。

## 执行与历史

- 正式编码来源：目录工具、覆盖回执或成功查询的正式条件。结构化工具和覆盖工具调用前核对来源；有精确目录命中时不把同次检索的近似项当作已确认编码。存在性、启用状态、权限和合法日期继续由后端独立校验。
- 目录检索支持名称、别名及正式编码；编码回查不依赖模型。指标回执显式给出 `exact_matches`，保留候选、总量和分页说明。
- `new` 允许缺条件；无有效待补回执不能执行 `clarify`；`followup` 的来源必须在本会话正式回执中出现且版本匹配，必要时先只读核对任务。删除了按“最近一笔”改写来源的逻辑。
- 查询引用和覆盖条件每次从 pi 当前分支的原始消息投影。压缩后的摘要不承担权威条件保存；重开会话无需建立第二份记忆。保留完整起止日期、正式编码、名称、分页及是否还有下一页。历史金额不复制进系统提示词。
- 查询条件不完整时不裁剪历史回执。工具参数纠错尚未形成新的业务状态时，不清除原覆盖范围。跨压缩的完整历史可通过 `session_history_read` 分段回读。
- 模型本地超时/中断归一为 `error`，真正的用户取消才保留 `aborted`，避免 pi 持久控制状态与响应状态冲突。模型传输错误和取消保持原生 `error/aborted`，由 pi 执行重试或失败处理；不再注入证据修复工具或改写为正常完成。相同工具重复相同错误才提前终止，不同校验阶段的纠正仍可推进；原总调用上限保留。
- 业务日期按 `Asia/Shanghai` 生成，避免北京时间凌晨错误使用 UTC 前一天。

## 调用审计

结构化日志事件 `agent_tool_call` 用 `request_id/session_id/operation_id/tool_call_id` 关联四个阶段：

| 阶段 | 含义 |
| --- | --- |
| `proposed` | 模型原始响应提出的工具与参数；在宿主改写之前记录 |
| `admitted` | 通过 Hook 的参数；尚不能认为已执行 |
| `blocked` | Hook 拒绝，未进入工具业务执行 |
| `executed` | 原生校验与 Hook 之后，实际进入工具 execute |

日志仅保存动作枚举、数组数量、参数及来源的 SHA-256 指纹，不记录原文、完整参数、金额、正式编码或凭据。完整模型参数与实际放行参数沿用受用户归属隔离的 pi 原生 JSONL；不建立额外业务状态。原生 schema 校验可能发生在 `before_tool` 之前，此类失败可表现为有 `proposed`、无 `admitted/executed`，应结合原生工具错误回执诊断。

## 可复现验收

用例位于 `agent-service/scripts/tool-governance/cases.json`，32 组 70 轮，业务日期基准为 2026-09-21；跨日重跑时先调整“今天/去年”的期望，绝对日期样本保持原样。它们依据真实目录和数据设计，不冒充用户历史对话。覆盖全局目录与机构覆盖、日期/机构修改、分页、独立新查询、正式澄清、覆盖后取值、回读、失败后省略追问、空结果、不支持目标以及历史恢复。

1. 在项目开发页面正常登录。测试使用浏览器同源认证恢复接口，令牌只保留在浏览器闭包，不导出、不写文件。
2. 在 `agent-service` 目录，以现有 `.env` 启动 `node --env-file=.env --import tsx scripts/tool-governance/serve.ts`。专用实例监听回环端口 8022，使用真实生产代码路径和现有模型/开发后端；原生记录隔离在 `.runtime/tool-governance/native`，模型请求间隔 5 秒，仅用于验收节流。
3. 通过 web-access CDP Proxy，用 `run.py --target <本机开发页面ID> --output <报告目录>` 运行。`--ids` 支持指定用例；在报告目录创建 `stop-after-group` 可在当前组结束后停止。每轮间隔 12 秒；HTTP/SSE、真实模型、后端与开发库全部参与。
4. 在 `backend-next` 目录，用 `.venv/bin/python ../agent-service/scripts/tool-governance/audit.py --reports <报告目录> --native ../.runtime/tool-governance/native/native-v1` 审计。脚本拒绝非 development/test 或非回环数据库；事务只读，按本次任务 ID 读取不可变快照，并用独立 SQL 比对正式范围内的全部原值。
5. 使用 `python3 agent-service/scripts/tool-governance/report.py --audit <报告目录>/audit.json --output <Markdown路径>` 生成可读报告。审计同时读取专用实例的 `service.log`，用 `executed` 阶段区分“已放行”与“实际进入执行”。
6. 报告保留首选工具、首选参数/引用、执行前后参数、纠错次数、最终条件/结果、耗时、Agent 模型 token 与请求数。正式金额不写入报告；保留事实指纹、行数及 SQL 一致性。失败轮不能被后续重试覆盖。

首次选择正确率以本轮第一个目标工具为准，方法读取、必要目录检索及任务状态核对不计目标工具；目录检索任务本身除外。首次参数/引用正确率要求同次调用通过校验且符合预期来源/范围。最终正确率要求正式执行条件、结果及恢复历史均通过断言；纠错后成功仍不计首次精准。供应商 429、超时等单独标注，不能当作业务通过或路由错误根因。

本次没有新增依赖、数据库表或迁移。Agent 代码、业务 skills 和后端目录检索应配套发布；回退使用同版本代码与 skills，无数据迁移回退。验收节流包含在测试耗时中，不能直接作为生产性能提升的证据。

本轮端到端入口验证 HTTP/SSE、真实模型、工具、后端和本地数据库；不等同于页面点击/视觉验收。每轮核对 HTTP 历史恢复，原生压缩后重开与完整范围保留另有集成回归测试。仓库现有忽略规则不提交单元测试，新增本地回归沿用该约定；可复现验收脚本位于未忽略的 scripts 目录。

真实验收还发现后端把独立请求前缀“另外查询/另查”误作第二个未知指标。修复复用原有完整语法过滤，不新增意图分类；只有残余文字完全属于请求语法时才排除，真实未知指标与同名正式目录项仍保留。

基础语义协议区分指标时间序列与客户/账户/交易底层明细：区间内全部已有指标点使用 `trend/grain=day`，不求和；底层明细仍按 `detail` 能力边界拒绝。语义残余检查不把完整的时间序列口径当第二个未知指标，真实未知名称不被裁剪。

`analysis-boundary` 为当轮终止性能力说明，下一次用户输入重新选择方法，避免预测被拒绝后，完整基础查询仍被旧方法锁定。查询方法的连续追问复用保持不变；该规则仅处理方法生命周期，不判断新问题意图。

来源合并时，未声明修改且与来源完全一致的指标回填，会连同指标名称文本一起规范化为继承；有明确新指标、待澄清指标或不同来源值时仍执行原校验，不静默删除。后端模型协议也明确：未知或停用属于目录问题，不是额外 unsupported 操作，必须保留原名称并进入指标澄清。


动作字段的说明按“是否依赖来源”统一：重新取数不等于 `new`。后端复用现有 `is_direct_catalog_query` 校验澄清纯文本，独立完整查询在写入前返回 `CLARIFICATION_INDEPENDENT_QUERY`。Agent 将该拒绝标记为原生命令 `rejected`，仅允许模型改选 `new`；不自动替换动作，不释放超时或其他未知失败的写意图。显式澄清卡片使用结构化答案，继续原任务。回退旧 Agent 后，进行中的 `rejected` 命令可能无法同轮纠正，应重新发起用户请求；已有成功任务与结果不受影响。

目录定位的完成标准是交付正式名称、编码和匹配情况。请求数值但缺条件或名称未知仍需正式提槽和澄清，补充待澄清条件不构成新的覆盖目标；这些业务含义由知识说明，工具选择由 pi 完成。

目录的 `exact` 只描述检索词命中，不保证对应用户完整原意。结构化取数使用宿主传递的原文，
复用后端完整名称优先匹配，拒绝短名称/别名替代明确完整指标名的冲突。错误在任务写入前返回，
pi 自行修正参数，不新增按问法分流或业务 skill 门禁。

多步结果通过 `answer_present(evidence_refs)` 选择最终交付。引用来自当前原生回合，
保留数值、单位、截断提示和未解决失败，不能引用被后续结果替代的回执。诊断目录/覆盖记录默认只是中间证据；
pi 主动结束业务步骤却没有选择时，宿主反馈一次交付缺口，下一步通过 `tool_choice` 约束为交付引用格式；
引用仍由 pi 选择，引用校验失败后恢复普通工具循环。仍未形成有效选择则明确未形成答案。实时和重连共用同一选择投影；
原有历史聚合正文兼容读取，新选择回执需要同步升级 Agent 与前端。无数据库迁移；回退前应等活动回合结束。

原生工具预算达到上限时，宿主持久化明确的“处理未完成”正文；同批调用在 `before_tool` 被终止时，共用投影也展示固定终止理由。已有成功证据作为部分结果保留，不能掩盖整轮未完成。该处理不改变模型选择或补造业务事实，刷新与实时消息使用同一投影。

# 标准分析路线试点

当前只注册“机构盈利排名及原因分析”。标准任务描述进入 Milvus，真实业务事实不进入向量库。
现有 Chat 模型、语义任务存储、机构授权、目录签名、查询、计算和报告检查继续复用。

## 执行链路

```text
用户原句 → 压缩召回文本 → bge-m3 → Milvus 候选 → bge-reranker-v2-m3
  → 相似度与适用性检查
    ├─ 命中：服务端注册计划 → 原语义入口绑定机构/日期 → 同日净利润排名
    │       → 程序从排名证据选择机构 → 同分析日定向补查 → 精简证据包
    │       → 宿主复用正式报告入口直接交付 → 程序编译事实结论与原因边界
    └─ 未适用、低置信度、召回服务不可用：原通用智能体
```

向量相似不直接授权执行。试点只支持按净利润金额排名，默认一名，支持前/后 N 家；
“收益不好”等宽泛问题会披露这一判断口径。收益率、利润率、预测、降幅排名、复合经营分析
及逐期完整序列暂交通用框架。门槛默认 0.5，跨任务重排分差默认 0.04，需结合实际问题集持续评估，
不能把重排分数理解成正确概率。

召回文本单独去除具体日期并归一名次数量，避免月份、数量及非业务噪声主导任务类型匹配；
原句始终保留，实际执行的机构、日期、数量和排除条件仍按原句校验。数量支持中文及阿拉伯数字。
简单的正式法人行集合表达在入场时绑定，注册路线继续复用正式原文身份及日历，模型漏填时也不能退回默认机构
或丢失明确日期。地域、排除、下辖等未纳入本试点的集合限制交通用框架，不截短表达后扩大范围。
“N 家机构”只有在数量对应当前授权法人行集合，或完整目录恰为该集合加省级汇总时才绑定全体；
省级汇总仍不参与排名，正文披露家数差异。任意数量、地域子集或数量无法核对时交通用框架。

路线描述位于 `backend-next/config/analysis-workflows.json`，程序注册表位于
`backend-next/src/ask_metric/application/analysis_workflows.py`。正式指标依据已启用目录的完整名称唯一匹配，
签名继续绑定当前用户与元数据版本；无法唯一确定主指标时退回通用目录发现。

## 本机启动

已有 Python、Node、数据库和 Chat 配置保持原启动方式。额外启动独立 Milvus：

```powershell
docker compose -f deploy/workflow-retrieval/compose.yaml up -d
```

镜像固定为 Milvus 2.6.4；`MILVUS_IMAGE` 可以指向部署方可信镜像代理。
本机编排只暴露回环地址 19530/9091，使用独立命名卷；共享环境需另行配置鉴权与网络访问控制。
不应将该无鉴权本机示例直接暴露公网。

在后端外置环境配置：

```dotenv
WORKFLOW_ROUTING_ENABLED=true
WORKFLOW_MILVUS_URI=http://127.0.0.1:19530
WORKFLOW_MILVUS_COLLECTION=ask_metric_analysis_workflows_v1
WORKFLOW_MILVUS_TOKEN=
MODEL_WORKFLOW_BASE_URL=https://api.siliconflow.cn
WORKFLOW_CATALOG_PATH=config/analysis-workflows.json
WORKFLOW_MODEL_CONFIG_PATH=config/workflow-model-config.json
```

`workflow-model-config.json` 单独启用 `BAAI/bge-m3`（1024维）及 `BAAI/bge-reranker-v2-m3`，
默认引用现有 `MODEL_CHAT_API_KEY`；需要独立密钥时更换该文件的 `api_key_env` 引用，密钥放在外置环境。
该配置不会开启通用指标目录的 Embedding 预热，也不会替换 Chat 模型。
Milvus 令牌可用既有 `ENC[SM4:v1:...]` 外置加密配置。
使用 Nacos 配置中心时同时提供新增路线/模型配置和运行配置，不在服务启动时写中心。

升级后重启后端、构建并重启 Agent，同时构建更新前端；应用库无需迁移。
首次符合条件的请求会将公开任务描述幂等写入专用集合；版本过滤包含描述内容及向量配置指纹，
不会召回旧版本路线，也不删除其他集合。关闭 `WORKFLOW_ROUTING_ENABLED` 并重启后端即可回退到原通用流程，
已有会话及运行证据保持可读。

## 日期、缺数与失败边界

- “最近”按主排名指标在授权机构集合的实际覆盖选共同日期，披露有效机构数；不按今天猜记录。
- 明确日期未查到有效值属于正常覆盖结果，保留日期、不补零、不改到别的月份、不推断经营好坏。
- 排名完成后，补查只选择实际排名结果中的机构，同一观测日固定下来；每次查询继续复核权限。
- 独立补查暂时失败保留排名和其他成功证据；权限、配置和未知程序错误保持可识别错误。
- 优先采用目录已有的净利润正式比较指标；缺少对应正式口径时才查询历史值差额，两者不混称单月增速。
- 试点正文由注册路线根据不可变事实编译，模型负责提出本轮调用；取数结算后由宿主复用正式报告入口直接交付，
  不再等待模型生成结束语。原始分析证据和正式报告共同保存在真实工具回执，刷新、重连沿用同一结果；
  报告交付时仍重新检查当前权限。自由生成的业务判断不会混入该正文，
  无需靠不断扩充词表拦截因果幻觉。报告随本次数据变化，展示排名、正式比较及收入成本事实；
  没有收入成本分解及业务材料时，明确原因尚不能证实。完整事实链、缺口与来源仍保留在报告回执和明细中。

## 接口与维护

### 调试界面中的分析路线

点击回答右上角的“调试”按钮，可查看“预设分析路线”：命中的标准问题描述、实际向量与重排模型、
重排得分和准入门槛、净利润排名口径、各步骤的依据和指标、日期处理及机构覆盖，
以及排名、历史比较、定向补查的真实执行结果。得分是检索诊断值，不是回答正确概率。

这些内容来自服务端注册计划与执行回执，随原生工具回执保存，实时结果、重连及刷新后共用。
尚未取数的路线显示“尚未执行”；正常无数据与查询失败分别标注，因排名无数据未执行的补查也单独说明。
即使没有生成底层 QueryTask，仍能查看已记录的路线。旧会话没有该诊断字段时不追补或猜测路线。
该视图展示明确的业务分析路径及证据边界，不保存模型自由规划文字，也不复制到回答正文或模型上下文。

`POST /api/v1/analysis/workflows/route` 必须登录，接收完整 `question`，返回匹配的路线及服务端签发的计划，
或 `status=fallback` 和可识别原因。该入口只准备路线，不执行业务取数。
Agent 按本轮召回结果暴露 `analysis={kind:registered_workflow, workflow_id:profitability_ranking_v1}`，
在 `resolve_business_turn` 内转换为普通 `business_analysis`。机构、日期和历史来源仍走同一协议检查。
执行端重新构造注册计划并严格核对，不能仅通过设置 `workflow_id` 将其他指标冒充为盈利路线。
新试点报告返回 `report.delivery_mode=registered_workflow`；未注册任务和历史证据追问仍使用原证据正文交付。

分析节点新增可选 `organization_from_step`：必须指向已依赖的前置排名节点。执行端校验事实来源、
原始授权集合和日期，再生成补查范围，模型不能借名称切换对象。多日期排名暂不混合归因，会保留逐期排名及明确缺口。

新增场景须实现并注册可执行计划、适用边界和回归样例，再加入标准描述。单独加入一段 Skill 文本不会自动获得执行能力。
本试点不承诺开放问题全部命中；未命中的通用流程仍需按真实问题持续验证。

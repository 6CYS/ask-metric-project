# 回答 SSE 体验验证（2026-10-28）

## 范围与实现

本轮改善回答交付与页面交互，沿用现有指标检索、查询、计算和正式报告校验。未新增依赖、查询路由或模型调用；未提交或推送代码。

- 通过已有 `analysis_answer.body` 接收明确的业务正文，完整 Markdown 段落经同源报告预览后逐步展示。普通 assistant 文本可能是查询规划，不直接显示。
- 预览仅检查权限、来源、引用、数值和单位，不执行完整报告的覆盖查询或持久化。正式报告仍是最终结果。
- 每条观察流最多一个预览请求在途，合并后续累计正文；结束、重试、停止和断线均取消过期预览。
- 前端按浏览器帧合并内容更新，没有逐字计时器。上翻后停止跟随；回到底部后恢复跟随。图表使用正式报告，不为预览重复构建。
- POST 和刷新重连 GET 观察同一次执行。临时正文不写入历史答案，最终快照覆盖预览。

本地已开启 `AGENT_ANSWER_STREAMING=true` 并重启 Agent 和 Backend，默认配置保持关闭；上线先部署支持预览的 Backend，再部署并开启 Agent。模型仍使用原配置，未开启推理。

## 未通过的业务正确性场景

“我行存款情况如何？”虽然流式交付完成，但正文把对公存款余额写成了 2691.57 亿元，不能记为业务正确性通过：

- 原始正文使用 `{{e1.v6}}`，对应 `ORG_VRS_DEPT_BAL_CMPBGNYR`（各项存款余额较年初），值为 2691.57 亿元。
- 正确对公余额是 `e1.v1`，对应 `ORG_CORP_DEPT_BAL`，值为 10976.68 亿元，统计日同为 2026-08-27。
- 错误同时出现在 31.563 秒预览、35.375 秒正式成功回执和最终快照，不是前端拼接或 SSE 换算造成。
- 现有正式校验验证引用与数值存在，但没有验证自由文字中的指标名称是否对应所选短引用。本轮没有修改这条正式校验；回答通道提示发生了变化，未做对照试验，不能断言对模型选择引用完全没有影响。

该问题需在报告事实引用与正文组织职责中处理，不能在展示层改数字、增加针对这句话的正则或把“通过来源校验”等同于业务语义正确。本轮不扩大到该业务契约改造，因此交付结论限于已验证的流式、图表、停止及恢复行为。

首次联调还发现普通 assistant 文本会泄露查询规划，已通过限定明确正文通道修正；该次业务回答也遇到引用恢复失败，没有计入通过场景。

## SOL 会话末尾问题：回答修正与长响应

对应问题：“紫金最近存款情况如何？重点看看个人和对公存款增长有何差异。”参考会话为 `01a1807d-89df-75a1-af4a-813ca0faf055`。

### 根因与修改

- Pi 在执行工具前拒绝的参数错误，也被旧计数当成已经修正过正文。因此正文首次遇到数值问题时，可能提前耗尽修正机会，退回逐行事实列表。现改为按实际进入正文执行器的回执计数；所有调用仍计入原总预算，未扩大次数或超时。
- 实测发现普通目标协议接受顶层 `date` 后，实际使用继承日期，造成补查年初余额却再次查询当前日期。此阶段曾将其他期间补查限定为 `independent=true`；后续完整链路审查撤回了这项限制：顶层 `date` 是本次查询期间，`target_change.date` 才改变会话主目标，最终契约见下节。旧无目标请求与可信目标绑定保持原行为。
- SSE 只消费明确的 `analysis_answer.body`，但模型请求仍允许直接生成普通正文，实测发生大量不可见文本输出直到截断。开启 SSE 时现要求使用现有工具通道，仍由模型选择查询、计算或交付，不强制提前回答；关闭 SSE 时保留原通道。
- `length` 终止的普通文本不再当作完整答案：有本轮可信来源时沿用部分交付，否则明确失败。截断工具参数在预算内交给 Pi 拒绝执行，总预算耗尽后结束。日志记录原始终止原因、内容类型及体积，不记录正文和参数。
- 修正耗尽后的事实回退明确标记部分交付，正文与刷新恢复共用说明；新增说明后同步段落证据位置。业务方法补充“核心事实足够时收尾、缺基期仅限制对应计算”的通用指导，没有增加针对本问题的词语规则。

### 复现与根因

原收益问题会话 `01a180ee-c0ff-77ad-a725-e78e5131bbfa` 已成功产生13个不同查询来源，但报告只接受6个来源，失败恢复沿用同一限制，最后未能交付。原执行用时133.484秒，18个工具回执。此记录没有模型服务报错或输出截断证据，不能将该失败归因于SSE。

同时确认三个独立问题：普通目标查询会把主目标机构覆盖到局部查询参数上；最新日期解析成实际日期后覆盖请求标识，重复请求不能复用已查结果；每个局部查询把原始整道问题写成自己的任务，查询步骤完成被表述为整道问题已完成。

### 修改与必要保护

- 报告预览、正式报告和部分结果恢复共用来源选择：保留本轮查询；历史仅保留正文、图表及计算实际引用的来源和父依赖；重复run只传一次。权限、会话归属、来源身份和引用完整性继续核验。
- 退出Agent的6来源拦截；后端请求容量与既有调查预算对齐为64个run（16次调查×每次最多4个32指标批次）。单次查询复用已有100指标批处理能力。未增加调查次数、正文修正次数或超时；没有截断来源以换取成功。
- `target_change`维护会话主目标，`scope/org_names/date`选择本次查询条件；主目标内局部查询不再被覆盖，也不改写主目标。主目标外参考查询仍须明确独立执行并接受权限检查。旧无目标协议、可信点击目标、页面时间切换保留各自明确入口。
- 查询准入与报告共享实际执行覆盖：正常零行也是已执行；失败、旧轮和错误期间不算完成。按机构分批、按明确日期集合分批可以合并；最新与区间选择不被几个日期端点替代。尚有目标未查时返回具体缺口；预算内补查不占正文修正次数。恢复交付仅包含已核验部分，并标明未完成范围。
- 保留原始最新请求标识，另存实际单日标识用于旧协议日期继承，避免同条件查询反复取数。多批次失败保留成功批次，后续只恢复剩余批次。
- 查询计划的任务改为本次查询目的，计算上下文继续保留原始问题。模型视图把完成字段明确归入`query_execution`，保留后端已有`finding_boundary`；原始回执及后端协议不变。未增加词语扫描、机构白名单或自然语言审核层。

## SSE 增量预览与重连优化

### 核实结论与修改

截图建议中的重复预览和重连丢失临时正文确实存在。首段等待还包含模型规划、查询和纠错，不能只靠 SSE 消除；本次只调整已生成正文的交付与生命周期，不改变查询策略、模型参数或正式报告业务校验。

- 报告预览按观察流保存已核验前缀。同一操作、模型尝试及来源上下文下，只向后端提交新增完整段落；改写正文或来源、历史焦点、计算、绑定变化时重新核验全文。后端仍逐次核验权限和元数据，正式报告不复用预览结论。
- 正文确定性错误与服务异常分开处理。同一错误完整前缀继续追加时不反复预览，段内改写可以重新核验；临时故障保留已经展示的可靠正文，只随下一完整片段有限恢复，连续两次失败停止该尝试的预览。没有增加模型调用、业务查询次数或定时重试。
- 每次模型尝试有独立 `call_seq`，快照提供当前有效的 `answer_stream`。前端只保留同一操作、同一尝试的临时正文；失效、重试、截断或取消时撤回。未变化的历史消息保持组件身份，减少图表及折叠状态重建。
- 浏览器取消与终态之后不再消费已经缓冲的后续事件。保留原有按帧更新和上翻停止跟随；最终报告开始时取消尚未完成的预览，不为短答案首段而拖延正式交付。
- 桌面实测发现工具执行中取消后，原生operation已保存取消结果，但未产生assistant取消消息，历史只投影消息时会漏掉停止提示。现由既有投影同时读取原生operation结果，按当前分支条目定位原轮次；已交付正文不覆盖，取消后继续提问也保留旧停止状态。没有新增持久化状态。

## 执行契约

`POST /api/v1/basic-queries` 在现有 `source_question` 之外接受两个可选字段：

- `source_metric_bindings`：保留目标的 `{start, end, text, codes}` 数组。
- `source_metric_exclusions`：用户明确放弃目标的 `{start, end, text}` 数组。

位置以 Unicode 码点计数，`end` 不包含在片段内。原句保留完整措辞，包括已放弃的目标，
避免省略基础名称的后续口径失去上下文。例如“贷款余额当日数和较上月增幅”放弃首项后，
仍须保留整句，第二项才能确定属于贷款余额。

这两个字段由宿主从已校验 Business Frame 的逐目标快照生成，不增加模型可填写的
“确认”开关。已确认目标的身份使用正式编码；展示名称不承担唯一身份职责。

后端重新扫描完整原句，要求每个识别目标恰好对应一个绑定或明确排除片段，拒绝
越界、重叠、伪造、遗漏和额外片段。绑定编码必须仍启用，并与当前唯一解析结果一致，
或属于当前可确认候选；基础指标候选只能展开到其当前可信结构中的正式口径。
最后保留目标编码的并集必须与请求编码集合完全相同。执行层的权限、机构范围及启用
校验继续执行，不能用本次请求的编码反过来推断歧义选择。

旧请求不带绑定时保持原有严格复核；无逐目标快照的旧 Frame 不伪造绑定。
失效快照和失效编码应重新澄清，不静默替换为同名的其他指标。

## 升级顺序

无需数据库结构迁移。先升级后端，再升级 Agent；后端兼容旧 Agent 请求。
新 Agent 连接旧后端会因未知字段返回 422，应完成配套升级，不能删除绑定字段后自动重发。
代码回退时先回退 Agent，再回退后端。数据停用的回退与代码回退分别执行。

验证区分三部分：合成目录回归、清理前真实目录快照的身份验证、当前本地目录只读验证。
这些检查不代表真实模型或业务 SQL 的端到端验收。

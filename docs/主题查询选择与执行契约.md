# 主题查询选择与执行契约

目标：保留原有问数、追问、权限与历史复用能力，把适合主题的基础取数和事实整理交给程序，减少模型探索、重复调用和上下文膨胀。回答的业务组织与措辞仍由 Agent 决定。

## 启用与兼容

- Agent 配置 `AGENT_TOPIC_QUERY_ENABLED=true` 并重启后，增加 `topic_query`；默认关闭。Nacos 配置加载同样支持该键。
- 原 `metric_search`、`metric_query`、`metric_availability`、`analysis_read`、`analysis_calculate` 等工具始终保留。关闭开关后，新请求使用原路径，已保存证据与目标仍可读取。
- 管理入口为“业务知识 → 新建／编辑 → 相关指标 → 支持批量取数”。只有系统管理员可维护；先搜索选择正式指标，再勾选并保存。未勾选时知识仍供模型参考，原工具仍可按需自主查询。
- 标题、正文、关联指标和开关统一保存在后端业务知识文件，实际路径由 `BUSINESS_KNOWLEDGE_PATH` 或既有运行配置目录决定。每次执行重新检查条目启停、批量开关和当前正式目录；保存后下一次调用生效，无需重启。已经完成的查询仍按原证据保留，不追溯撤销。
- `agent-service/config/inquiry-topics.json` 仅保留存量五类方案的日期、展示策略和执行预算，不再独立提供可执行方案。生产入口不能借同名内置方案绕过未勾选或停用的知识。构建产物仍须同时携带 `dist/`、`config/`、`skills/`。
- 模型地址、密钥和历史会话无需修改；无数据库迁移。后端、Agent、前端应配套升级，旧后端不能解析新增的 `batch_query_enabled` 字段。

## 现有知识迁移与维护

源码默认业务知识已增加收益利润、贷款质量、经营概况、存款结构、费用收入五类方案及原指标关联，原参考知识保留。已有部署会保留现场知识文件，不自动覆盖或把默认文件整份替换到现场。升级前备份实际知识文件；管理员可在现有知识中关联相应正式指标并勾选，也可新建条目。需要保留原五类日期策略时，应对照默认文件中的五个稳定 ID 做经核对的增量迁入，不修改原条目或现场配置。

每个勾选方案须关联1至24个正式指标。名称和单位每次执行由正式目录读取，页面也按正式目录展示；指标改名无需重复维护方案名称。编码是关联身份，若业务实际换成另一个编码，须重新选择关联，不能猜测新旧编码对应关系。移除全部关联前先取消批量开关，停用知识也会停止其批量执行。

新增自定义方案默认保留各指标实际最新日期，不静默对齐成同一天。通用日期知识提供解释指引，程序仍负责期间解析、数据可用日期与权限检查。存量五类沿用原共同日期／分指标日期策略。回退旧版本前须备份新知识文件，并处理旧版本不识别的新增字段，不能直接用旧默认知识覆盖现场资料。

## 选择契约

选择由 Agent 在现有业务理解步骤完成，不增加独立分类模型请求，不按用户原句或关键词编写程序路由。

| 目标 | 路径 |
|---|---|
| 问题与已勾选知识的标题、内容及指标范围相符 | 用该知识条目的 ID 调用主题查询 |
| 明确指标查值、增删指标、固定日期查值、排名 | 原指标检索及查询 |
| 要求复用先前结果、不重新查询、计算两家差额 | 原历史读取及计算 |
| 主题不支持的目标、可信点击已确认的查询 | 原默认能力 |
| 一个问题包含已覆盖与未覆盖部分 | 保留主题事实，只补未覆盖部分 |

首批主题是试行分析范围，尚非业务审核的好坏评价或归因标准。模型应说明采用的比较维度，不把规模最小直接等同于经营最差，不把并列变化说成已证明的根因。

新增方案只维护标题、内容和关联正式指标，不要求业务人员填写执行脚本。按原知识检索召回后，由模型判断适用性，不增加独立分类请求或关键词路由。单次检索最多3条、正文合计8000字，其中最多一个批量方案，保留口径和证据边界知识的位置；多主题问题可按子目标继续检索。工具描述不拼接全部方案，因此不会随方案数量直接增长；大规模知识的检索质量与容量仍需另行验证。

## 输入

```json
{
  "topic_id": "profitability",
  "scope": "all_banks",
  "org_names": [],
  "date": "latest"
}
```

`topic_id` 填本轮检索到且 `batch_query_enabled=true` 的知识条目 ID。默认五类 ID 为 `profitability`、`loan_quality`、`operations`、`deposit`、`expense_control`；新建条目使用后端生成的 ID，不按标题硬编码。`named` 必须填写本轮全部目标机构；`all_banks` 使用当前账号有权农商行集合，不接受手写机构列表。机构仍由原目录解析并校验权限。

近期使用 `latest`，明确的日期、月份或季度原样填写时间短语，由服务端解析；例如“今年三季度”不能自行换成“9月30日”。追问未改期间使用 `inherit`。没有目标基线时不能使用 `inherit`。程序沿用原目标协议维护机构、期间与主题，不能由取数顺序覆盖用户目标。

## 执行与返回

1. 先用原登录鉴权读取 `GET /api/v1/business-knowledge/{id}/analysis-plan`，只返回启用且勾选的条目及内容版本；再通过 `POST /api/v1/analysis/catalog/bind` 一次取得关联编码的当前正式名称、单位和目录签名。不调用模型，不创造缺失指标。未勾选、已停用或不存在的条目返回不可用，转回原工具；权限失败仍拒绝。
2. 复用原指标执行器及参数化查询。每个主题至多24个指标，内部按现有容量分步，模型无需为每个指标再规划一次。
3. 收益、存款、贷款质量与费用主题在明确请求 `latest` 时，先查询核心指标的共同已有日期；无共同日期时返回不适用，默认路径可分日期处理。经营概况允许指标各有最近日期，但返回各自实际日期，不作跨日期归因。
4. 明确期间不替换为最新。季度只返回该范围内真实记录和缺月信息，不能把月中数据称为完整季末数据。
5. 完整证据仍采用现有 `analysis_evidence`、`run_ref`、`eN.vN` / `eN.jN`，主题额外提供带机构、指标和日期的别名（例如 `e1.320188000.revenue.2026-07-31`），均映射到同一正式事实；服务端报告仍核验来源、权限、单位和计算。不维护第二套事实数据库。

模型读取的返回包含以下字段：

| 字段 | 含义 |
|---|---|
| `topic_execution` | 知识条目 ID、方案名称、来源、版本、完成指标、未绑定指标、日期策略、执行完成状态、请求日期及选择日期；前端显示实际采用的分析方案名称 |
| `metric_dictionary` | 本次正式指标身份、名称、单位与已知数值编码 |
| `profiles` | 按机构、实际日期整理的事实；每项提供原引用、显示值，变化额额外提供程序确认的方向 |
| `comparisons` | 两家机构同日同指标、配置的同日同单位指标对的精确大小关系；另列变化额绝对值关系，不冒充比例或贡献 |
| `rankings` | 同日同指标排名及原事实、排名引用 |
| `distribution` / `global_patterns` | 程序遍历完整有效范围得到的分布与条件统计，注明覆盖，不能从展示的少数机构推断全体唯一性 |
| `projection` | 实际查询、展示及未展示机构数量，说明完整来源可回读 |
| `gaps` / `unavailable_metrics` | 正常缺数、未知单位或比例编码等使用边界 |

变化方向使用十进制整数比较计算，不用浮点数比较大额尾差。排序依据是明确指标值或变化额，不是综合评分。同比变化额不等于同比增幅，本期值与变化额不能作为两个同指标事实交给原计算工具。主题不新增未经审核的跨指标比例和贡献公式。

## 复用、部分完成与预算

- 相同主题请求已完成时，只返回原 `run_ref`、证据引用及完成状态，不重新查询，也不再次发送表体。复用前仍检查当前开关和正式绑定；修改该条目或相关目录身份会产生新版本，其他知识的修改不使该方案失效。
- 沿用当前运行时的无进展收敛逻辑，本次管理入口改造不调整其判定：完成且没有未绑定指标的方案按来源识别复用；普通查询复用按来源及实际请求指标识别。`topic_slice_key` 标记的有效分页不累计；反复重放相同旧结果会转入已有事实交付。legacy／pending 后续动作的两项既有回归仍未通过，不能据此声称所有补查边界已验证。
- 默认观测补查涉及主题已完成的相同机构、期间和指标时，复用已有证据；混合请求只执行剩余指标。正常缺数也属于已完成查询，不能用 `complete=false` 推导为需要整体重试。
- 剩余指标服务失败时保留完成事实和待办，不将整题重新开始；权限错误继续交由统一鉴权边界处理。
- 模型投影至多64KB。大范围先做全局统计，再展示若干规模或变化额排名靠后的机构；完整来源与原子编号不截断、不重排。展示省略或超限时，可通过 `analysis_read` 的 `focus` 指定一家机构及至多4个指标编码读取已有来源，每页至多50行；仍重新核验原权限。相同页只展示一次，不能重新取数。
- 保留原执行与重试预算。程序防止重复实际查询不等于能保证模型永不再次发出相同请求；验收需分别记录请求尝试、实际取数及重复证据字节数。

## 验收

先验证目录身份变化、正常缺数、明确日期、季度不完整、权限失败、重复请求、部分补查失败及历史继承；再用同模型、同数据和相同配置进行开关对照。

真实模型结果必须核对机构、指标、实际日期、数值引用、变化方向、排名依据和因果边界。只有正确结果之间的对照才可用于宣称耗时或 token 节省；报告工具返回成功不等于业务正确。补充不同表达，避免只验原句。调用失败、余额不足及未覆盖场景须单列，不能算通过。

本机实验材料和费用账本保存在 `local-artifacts/reports/topic-contract-20261102/`，不包含在正常源码交付范围。5元预算是本次验证限制，不是产品的运行配置。

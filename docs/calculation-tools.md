# 通用表达式计算工具

## 调用流程

Agent 先通过 `resolve_business_turn` 创建 `metric_query` Frame，再用 `execute_business_frame` 查询并取得 `facts` 数据引用，
再解析 `metric_calculate` Frame 并执行。模型选择数据和公式，FastAPI 从持久快照读取原值，用
`simpleeval 1.0.8 + Decimal` 运算，返回结果、公式和输入证据。页面直接展示工具结果，
模型只组织文字。公式的业务含义仍须核对，分母不明确时应澄清。

新提问不读取历史模型上下文或历史引用；当前未完成任务通过任务及澄清编号补充条件。
归因执行仍不支持，计算工具不用于生成无证据的业务动因。

本文的 Agent 接线与验收范围以 [原生业务 skill 与组合计算](business-skills-runtime.md) 为准。

## 工具参数

```json
{
  "expressions": [
    {"name": "total", "label": "余额合计", "expression": "a+b"},
    {"name": "share", "label": "余额占比", "expression": "(a+b)/total_balance", "display": "percent"}
  ],
  "bindings": {
    "a": {"fact_id": "查询工具返回的真实引用A"},
    "b": {"fact_id": "查询工具返回的真实引用B"},
    "total_balance": {"fact_id": "查询工具返回的真实总额引用"}
  }
}
```

- 支持 `+ - * /`、括号、正负号、`sum(a,b,...)`、`avg`、`min`、`max`、`abs`。
- 一个请求最多 10 个独立表达式、100 个数据变量、20 个用户常数；每个表达式最长 2000 字符、
  最多 300 个 AST 节点。结果之间不能通过名称互相引用，需分别写完整公式。
- 公式只允许 `0`、`1` 字面常数；业务值使用 `fact_id`。用户明确要求“乘以 1.2”时，
  可添加 `"constants":{"factor":{"value":"1.2","source_text":"乘以 1.2"}}`，
  公式写 `avg(a,b)*factor`。后端核对原句及数字边界；常数用途仍由模型和用户确认。
- 百分比用 `display=percent`，例如 `(current-previous)/previous`，不要乘 100。
  `decimal_places` 为 0～8，默认 2。正式单位为 `%` 的输入先转换为比率参与计算。
- `scope_policy` 缺省 `same_org_date`；跨日期或机构时分别声明 `cross_date`、`cross_org`，两者均不同时用 `explicit`，且先确认业务口径。
- 加减及聚合必须同单位，乘除组合单位，无量纲结果才可展示百分比。缺少正式单位不发放引用；
  不猜不同单位的换算系数。除零、非法语法及越界数值返回明确错误。
- 输入及结果通过十进制字符串传输；内部 60 位有效数字，展示采用 `ROUND_HALF_UP`。
  无限循环小数受内部精度限制，展示值不回写原始数据。
- 正文金额统一以万元展示。查询 `facts` 与计算 `results` 在原单位为元或万元时附加
  `reply_value`、`reply_unit`：后端从原始值进行 Decimal 换算，按 `ROUND_HALF_UP`
  保留两位小数；模型直接引用这两个字段，无需增加换算调用。`value`、`unit`、
  `display_value` 及来源证据保持原有含义，百分比、无量纲比值和复合单位不套用金额换算。
  明细表仅去除小数尾零，不改变原单位或有效精度，导出仍保留原始数据。
- 不支持属性、索引、赋值、循环、幂、代码执行及任意函数。

查询截断或明确缺少部分指标时拒绝计算，避免把部分数据当作完整合计。
每次查询工具最多向模型提供 100 个事实引用，附带事实总数及截断标记；需要更多数据时应
缩小范围，不根据样例行推测总计。数据源若返回浮点而非精确十进制，该值不发放计算引用，
需核对驱动及 SQL 返回类型。

## HTTP 与持久化

- `POST /api/v1/agent-query-contexts`：请求 `{"session_id":"UUID"}`，创建当前用户的
  `agent:<session_id>` 后端会话；Agent 在首次业务查询前调用。
- 普通问题通过 `channel_context.calculation_context`，基础查询通过顶层
  `calculation_context` 传入 `scope_id`、`user_question`。由 Agent 服务绑定，不作为模型工具
  参数；新提问生成新范围，明确澄清延续原范围。
- `POST /api/v1/calculations`：Bearer 认证、必填 `Idempotency-Key`；工具参数外再传
  `conversation_id`、`scope_id`。校验归属、范围、任务状态、过期、当前目录和机构权限。
  幂等重放前仍复核权限；同一键更换内容返回 409。
- 返回 `calculation_id`、`task_id`、`results`、`inputs`、精度和舍入方式。
  `results[].value` 为内部数值，`display_value` 和 `unit` 可直接展示。
- `query_tasks.state_json.result_artifact.result.facts` 保存原值引用，`calculations` 保存
  计算记录，同时添加 `calculation_result` 聊天消息。多个来源查询参与时，归档到编号排序
  最前的来源任务；每项任务最多 50 条计算记录。

**没有新增数据库表或列，没有结构迁移。** 计算不重新查业务库，需要最新值时重新查询。
旧结果没有计算引用，查看和导出不受影响；新计算须重新查询。

## 删除与升级

手动删除和数量超限清理共用流程：持久化删除意图、禁止继续提问，停止并等待当前工具调用，
删除后端关联会话，最后移除 Agent 文件。失败可重试；重启后也不恢复待删除会话的提问能力。
已删除的关联会话不会被迟到的普通查询自动重建。旧版本会话按持久化工具消息中的真实任务
编号找到后端会话，权限复核后清理。任务、快照及计算证据按既有外键级联删除，运行审计仍按
既有规则保留。

依赖登记在 `backend-next/pyproject.toml`，原生离线构建流程从该清单制作 wheel；新包必须
包含 `simpleeval==1.0.8`。无需新服务、缓存或环境变量。后端、Agent 和前端应同步升级，
不覆盖生产持久配置。删除并发及外键行为仍需在目标 GoldenDB 环境验收。

## 人工验收

使用授权测试环境的正式目录和已知原值，核对以下行为：

1. 两家机构合计及占总行比例：实际调用查询、计算工具，分母正确，可查看来源。
2. 两日期差额及增长率：以上期为分母，零分母明确报错。
3. 三家机构平均后乘用户给出的 1.2：系数有原句来源，业务值不作常数。
4. 缺指标、日期或分母时澄清；金额加户数拒绝；截断或缺指标不做完整汇总。
5. 刷新、重启后保留证据，新提问不能复用旧引用，其他用户或权限撤销后不能计算。
6. 删除进行中的会话后不重建文件；模拟后端清理失败，重启后仍能重试删除。

本地测试分别覆盖表达式、内存 SQLite 查询/计算链路、固定模型响应工具循环和前端内存渲染。
真实模型选数及公式准确性需要单独验收，不能用固定响应通过率替代。

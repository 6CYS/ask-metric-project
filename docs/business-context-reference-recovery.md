# 历史字段引用、确认与恢复契约

本次本地修复将指代理解交给主模型，服务端负责来源、状态、权限、数量和执行校验。删除机构指代词表及“全会话倒序去重后取最近 N 家”的隐式规则。

当前模型入口使用[固定业务请求接口](fixed-business-turn-interface.md)。以下 `fieldIntents`、`rawValue` 和两种旧参数格式描述的是内部 Delta 与历史快照兼容契约，不要求新模型重复提交。

## 内部目标声明

旧入口及固定请求的内部适配结果使用 `fieldIntents` 对象。对能力 Schema 中启用 `requireTurnIntent` 的字段：必需字段始终声明；可选字段仅在本轮实际设置、候选确认、清除或移除时必须声明，省略或 `retain` 且未变化时可以不声明。新模型在 `changes` 中表达一次动作与依据，适配器确定性生成该内部结构，不补用户业务选择。此规则由字段元数据与实际修改决定，不按特定机构或字段名分支。

```json
{"fieldIntents":{"organizations":{"mode":"set","sourceText":"本轮实际指代原文","expectedCount":3}}}
```

每项必须明确操作、原文依据和数量；未限定数量用 `null`。普通续接的必需声明使用 `mode=inherit, sourceText=null, expectedCount=null`。未变可选字段省略声明时，字段仍从已选 Frame 按既有规则继承，已保存的来源与数量约束继续生效；不是清除字段或约束。宿主不为遗漏的必需声明补值；显式提供的任何声明仍校验结构、原文、数量及与实际修改的一致性。声明为修改却省略整个字段、把带原文或数量约束的目标声明为继承，均不能执行。数量在完整集合解析后复核，与排名 `top_n` 分开。

这使模型解释可审计、执行可校验；它不保证模型每次都能正确理解自然语言。模型若错误地明确声明“继承且无数量约束”，仅靠结构校验无法证明原文语义，仍需真实模型回归检验。

## 显式字段引用

机构字段在既有 `rawValue` 中接受如下输入，legacy 与 compact 工具参数无损共用：

```json
{
  "fromHistory": true,
  "sourceText": "本轮实际指代原文",
  "sources": [
    {"frame": {"ordinal": 1}, "field": "organizations"},
    {"frame": {"ordinal": 2}, "field": "organizations"}
  ],
  "combine": "union",
  "expectedCount": 3
}
```

`single` 引用一个来源的完整字段；`union` 按指定来源顺序、正式编码去重。`union` 可用 `add` 合并本轮原文中的新增机构，由当前目录解析；历史名称、编码不能由模型展开后冒充新输入。`expectedCount` 是最终集合的数量约束，不能用于截断或选择最近若干项。字段引用只改变该字段，其他条件仍由明确的 `baseReference` 继承。

模型历史索引提供按能力声明生成的字段来源摘要、单源数量及兼容静态集合的去重总数。摘要标记可见范围和截断状态，仅提供历史事实，不推荐组合或按数量自动选择目标；动态机构范围不生成固定名单并集。

当前接入机构字段，其他字段不能借此跨字段替换。每个来源必须唯一定位本会话更早回合，并检查所属操作最新快照、字段已确定且数据完整；在途、不可继承失败和未决来源不能执行。正式编码逐项通过当前目录和权限复核，缺项或替换编码均拒绝。动态范围单源保留范围语义并刷新授权，范围与具体名单的并集须澄清。

首次唯一定位后，保存精确 Frame 来源及原模型引用。目录暂时失败也保存绑定来源，后续继承重试使用该来源并重新复核权限，不重新计算相对位置，也不要求用户重复原引用话语。

授权复核早于新增名称解析也可能失败，因此草稿须同时保存完整未决项。继承重试与确认回调锁定已确定新增项的正式编码，目录不能把撤销编码重新当名称替换成另一个机构。来源未完成可信绑定时不保存半份续补提案，保留原 Frame 及候选再澄清。

## 保存状态与用户确认

候选仍保存在原有 `Frame.fields.candidates`，编号、点选及回复匹配共用同一清单。澄清正文由保存的 Frame 生成；没有候选时请求补充具体条件，不让模型正文临时列出一个未保存的确认对象。澄清阶段的模型草稿不进入回答流。

模型理解复合同意语义时，可提交：

```json
{"confirm": true, "evidence": {"decision": "accept", "sourceText": "本轮表达同意的完整原文片段"}}
```

服务端校验原文证据及下一用户回合要求。语义同意仅作用于该字段中每项唯一的已保存候选；多候选仍须明确名称、序号或当前 Frame 的点选，不能由模型选择。否定与矛盾证据优先拒绝。旧的明确选择、简单肯定和前端点选保持兼容。

历史集合与新增机构的候选作为完整提案保存；确认后再次通过同一个历史引用解析入口复核来源、授权和最终数量，不能丢掉原历史集合而只查询新增项。

新增项同时存在候选和未找到项时，候选仍可确认，未找到项独立保存并继续阻断执行。同一组合续补用 `retainResolvedAdditions:true`，保留已确定新增项、未提及的未决项和原数量约束。修正名称用 `replaceAdditions:[{index:2,value:"本轮补充名称"}]`；索引引用焦点 `unresolvedAdditions` 保存的绝对 0 基位置，不重新编号。`add` 仅追加，不能覆盖旧未决项。服务端检查同会话、字段和历史来源操作，并再次复核保留项权限。确认和续补不能改写既有数量，明确更换完整目标须提交新的字段提案。

## 错误恢复

可修复的结构、原文或枚举错误继续返回 `ARGUMENT_ERROR`，保留已选来源，不保存失败字段。恢复提示区分沿用、历史引用及有效候选确认。

同一调用中已由用户回复或点选唯一绑定的有效候选，仍按原 Resolver 和数量契约复核并独立保存。恢复草稿与模型回执同时提供 `retry_reference`、`confirmed_fields`、`pending_fields`、`pending_changes`；待修项带操作、本轮原文依据及 `may_retain`/`inherit_allowed`。有本轮依据的新日期、机构或数量必须修正并落实；只有来源明确不属于本轮的额外错误提案才允许显式声明 `inherit` 或 `retain` 撤销。不能仅省略全部待修字段，也不能回到旧快照绕过草稿；旧快照没有此来源记录时保留显式处理路径。合法的本轮数量约束在恢复中继续核验，不能用 `null` 删除。

点选只投向本会话保存的指定来源与选项；失效或其它会话的点选不会回退为文字投票，单独选择一项也不会顺带确认其它候选。原始回复仍保留给真实新条件的解析。重复失败停止保护保持生效，确认后的正常续接通过程序状态与结构化回执完成。

没有候选的确认、同轮自行确认，以及未决字段没有候选且模型重放不属于本轮的引用原文，返回 `NEEDS_CLARIFICATION`、`next_action=ask_user`、`retryable=false`。回执绑定原 Frame，原焦点与字段不落盘改写；宿主结束本轮，不继续自动解析。用户随后提供明确条件可继承原指标、日期与操作继续执行。

对可信旧字段的上述恢复判定，在普通参数校验前进行只读预检，避免旧引用与本轮确认话语不一致先触发参数纠错、遮住澄清终态。预检不解析历史、不调用目录、不写 Frame；新名称、有效当前引用的声明错误及必填声明缺失仍由原参数校验处理。

合法解析与非法工具旁支同批返回时，非法旁支记录审计并移除，避免澄清终态被迫继续请求模型；若多份业务解析提案中包含非法参数，则整批受控失败，不能执行半份目标。单份非法解析保留原生参数纠错路径。澄清正文通过受控回执投影，刷新和服务重启后仍与保存状态一致。

来源歧义、数量冲突或权限复核不通过保存未解析状态及诊断，不伪造整组候选，不执行查询。临时目录故障保持 draft 和重试引用。既有权限、目录、字段组合、指标覆盖、执行状态与幂等控制继续生效。

## 首轮输入校验与业务澄清

原文依据校验统一使用 NFKC、空白折叠和大小写归一化，允许中文日期中的空格及全角字符等既有解析已接受的格式差异。归一化不转换日期、不删限定词或否定，也不补入历史话语；非空依据仍必须锚定本轮原文。这个检查只能证明格式归一化后的片段存在，不能证明模型完整理解了自然语言，完整日期和用户目标仍须经解析与业务校验。

参数结构、枚举或可修复的字段组合错误返回 `ARGUMENT_ERROR`，附 `corrections` 中的字段、原因、输入 Schema、合法值及已解析时间类型。允许业务澄清的字段，纠错 Schema 同时公开正常值与 `clarify` 分支，并附服务端问题：本轮或可信继承已给出明确选择时修正参数，缺少必要且不唯一的业务选择时保存条件并提问。Schema 必填不授权补业务默认值；不能仅凭 `null` 就断言用户缺项。组合诊断中正常值的收窄边界继续保留，不默认月末、最后有数日或排名条数，也不改变指标、机构和完整日期范围。`query_executed=false` 只表示该次失败调用未执行业务，不表示此前没有结果。

用户没有说明必要业务选择时，模型可对能力 Schema 显式声明 `userClarification` 的字段提交：

```json
{"clarify":true,"sourceText":"本轮相关原文"}
```

当前接入查询的时间取数方式与排名操作。服务端验证允许字段、`set` 操作、严格键集合及本轮原文依据，将字段保存为 `ambiguous`，连同服务端声明的问题和其余已确定条件形成 `clarifying` Frame。模型不能自带问题或候选。可选字段一旦明确处于未决状态也阻断执行；普通继承、只补一项及单日缺省规则均不能消除另一项未决选择。刷新和重开从同一保存状态呈现，下一用户回合仅补充未决条件即可继续。

单日范围且未显式修改取数方式时，使用既有能力声明补齐 `exact`；明确清除、非法值或显式澄清不被覆盖。多日范围不会自动选月末或最后有数日。用户明确要求的逐日排名、离散日期排名仍受原有能力限制，返回业务终态，不能通过修改取数方式或换查询能力绕过。

排名方向和条数由服务端核验本轮表达或所选可信历史，不从模型提供的枚举、日期或机构数量推断。缺少条数时保存已知条件并澄清，不补前 10 名；仅补充数量或方向时保留已核验的另一项。省略、继承、清除及普通取值默认同样经过语义完成校验，不能吞掉明确的排名目标。完整输入与参数冲突返回参数纠错；未决业务条件保存后提问。正式指标名称中的排名、名次和数字不作为额外操作证据。

## 正式指标错字纠正

精准名称与既有同音匹配路径保留。新增纠正只适用于已识别完整基础指标、明确统计口径、与正式词条仅一字编辑差异的输入：归一化基础词至少 5 字，字符相似度至少 0.8，与全部启用目录词条及正式指标身份中的竞争项相似度差至少 0.15，且各明确口径只能映射一个正式编码。竞争判断使用完整目录，不以展示候选数量代替唯一性。数值、否定、包含范围、单位币种及统计口径等语义差异不按普通错字自动改写。

这些分数是保守的匹配阈值，不是概率或准确率承诺。短词、缩写、多个近似正式指标、重复编码映射或缺失口径继续确认。解析结果保留原始 mention 文本和区间、正式名称与编码，以及纠正方法、相似度、竞争项和阈值；后续 Frame 继承与会话重开仍保留这些信息。模型继续提交完整原文，由后端作受治理纠正，不能自行生成指标编码或补统计口径。

重试不再按不同参数错误累计三次即停止。宿主从本轮原生工具记录比较“工具、参数、失败内容”：不同参数或不同诊断可继续修正；相同失败提案重复出现即终止，包括交错读取与 A/B/A 循环。可信解析或执行终态清除旧失败段，避免成功结果被先前错误覆盖。既有每次操作 24 次工具调用预算继续生效，重启不重新计数。

## 兼容与验证边界

无需数据库迁移或重写历史 Frame。普通原文名称、范围、已有已确定字段和前端点选兼容；内部服务仍可读取旧 Delta，新模型只提交固定请求的 `changes`，不再提交 `fieldIntents`。合法旧在途参数按可信操作身份恢复，不能作为新模型入口。旧纯文本历史指代仍需明确来源，不能继续依赖最近 N 家猜测。外部自定义模型调用需同步固定契约；回退代码不要求回写历史数据。

实现、合成后端回归与配置真实模型验收分别记录。真实模型验收不连接生产业务数据库。历史引用结果见 [历史引用验收报告](verification/history-reference-recovery-20261013.md)，空会话首轮结果见 [首轮输入契约验收报告](verification/first-turn-contract-20261013.md)。本次仅修改本地代码，未提交、未部署，线上行为须部署后另行验收。

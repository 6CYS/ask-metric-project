ENGINEERING FIELD GUIDE / 01

从一句提问，到可信的业务答案

Ask Metric 将自然语言理解交给模型，把任务状态、执行许可、权限与数值证据交给程序。读懂这条边界，就能串起前端、Agent 和后端的大部分设计。

源码链路已核查本地 develop · 73f1db5基于 2026-10-23 探索非生产验收报告

项目目录：zbws/ask-metric-v0.2-analysis-enhanced-windows

这是面向银行指标查询与经营分析的三服务工程。当前源码来自独立导入的快照：本地分支是 develop，VERSION.txt 记录的来源分支是 v0.2-analysis-enhanced。理解功能应以现行路由、工具注册与调用链为准，部分 README 保留了旧版本描述。

架构图在较窄窗口中可横向滚动；点击图区后也可用左右方向键查看。

模型 提出语义与计划宿主 维护可信任务与执行许可后端 再次鉴权并生成结果证据
阅读时先记住这条原则

模型输出、工具执行成功、任务全部完成、答案正式交付是不同状态。页面上出现一段文字，或收到一次 HTTP 200，都不足以单独证明业务目标已完成。

02

一次请求怎样完成

三条常见路径共用认证与受治理执行，但进入查询、补查和复用的条件不同。切换下方路径阅读。

基础问数

  1. 页面提交原始问题

    首次发送创建原生会话；随后向同一 Session 提交 protocol_version:3 与 request_id。前端不自行继承业务条件。

  2. 校验身份、归属和请求幂等

    Agent 通过后端 /auth/me 获取当前身份。同 ID 同输入复用原 operation，不同输入拒绝；同会话另有操作运行则返回忙碌状态。

  3. Pi 提案，宿主完成可信绑定

    resolve_business_turn → SemanticPlanService → SemanticTaskService；指标、机构、日期由正式解析接口落实。缺项或歧义进入持久化澄清。

  4. 编译 Frame，检查执行许可

    许可绑定任务、目标、版本与本轮 operation。READY 后宿主可直接推进执行，不必再让模型往返一次决定“开始查询”。

  5. 后端规划并执行只读 SQL

    basic-queries → submit_question → execute → QueryPlanner → SQLGlot Builder。执行前重新核验权限、目录与集合指纹，业务值通过参数绑定。

  6. 保存事实与正式答案

    后端落库结果快照、fact 引用和运行记录；完整且符合直接交付条件的取值可直接使用后端答案，其他目标继续走证据交付流程。

经营分析

  1. 发现指标与方法

    通过 analysis_catalog 或专项主题读取正式目录，取得宿主短引用与后端签名绑定。目录检索失败不能解释成“没有业务数据”。

  2. 提出分析目标与步骤

    统一入口 intent=analyze 保存 objective、requirements、steps、依赖及范围；每个子问题必须有关联步骤或明确缺口。

  3. 复用基础查询、覆盖和受控计算

    后端执行分析计划并保存已完成步骤。通用分析每次执行有 120 秒预算和 40 次基础查询预算；达到预算时保留真实缺口。

  4. 根据证据决定是否补查

    Pi 结合实际发现提出 inquiry，补查应说明疑问、此前判断、依据与预期变化。相同计划与范围优先复用已有回执。

  5. 核验报告并交付

    正文用 {{e1.v1}} 等事实引用，交给 analysis_report_present → /analysis/report 核验。已有证据而后续失败时，可交付明确的部分结果。

历史复用与恢复

  1. 定位所属用户的原生会话

    Agent 从用户隔离的 JSONL 仓库打开 Session；消息、运行状态与任务账本一起恢复。旧协议会话标记为只读。

  2. 重新核验历史访问权限

    任务、结果与分析证据读取需要当前授权。历史内容不能因为“以前查过”就跳过权限校验。

  3. 按结果引用回读快照

    查询结果分页、导出以及已确认的历史复用读取已保存结果，不重新执行原业务 SQL。读历史通常只改讨论与展示焦点。

  4. 运行中则重新观察，不重发问题

    刷新或断线后使用 GET .../stream。网络失败无法证明后端没有执行，先按原幂等关联查询状态，再决定如何恢复。

  5. 需要停止时显式取消

    页面发送 cancel 后中止本地读取。断开 SSE 只是停止观察；即使请求被取消，也不能据此认定数据库操作已回滚。

03

三个模块各管什么

模块核心职责不应混淆的边界
frontend-vue
Vue 3 / TypeScript / Vite		认证状态、会话选择、SSE 消费、澄清输入、结果表格与图表、配置及目录管理。页面不判定可信机构范围，不生成业务 SQL，也不重新计算报告结论。
agent-service
Node / Hono / Pi		模型接入、原生 Session、语义计划、上下文焦点、执行许可、工具调度、恢复和答案交付。工具只访问受治理后端接口；没有向模型开放 shell、任意文件读取或 SQL 执行器。
backend-next
FastAPI / SQLAlchemy / SQLGlot		身份、正式目录、机构层级、权限、查询计划、只读取数、精确计算、快照和审计。当前主链路不由后端 Chat 模型解释整句问题；旧语义状态字段不代表旧接口仍在线。
Agent 的主入口与底层模块semantic-task / business-context

semantic-task 管目标、原文来源、修订、澄清、依赖与许可；business-context 管 Frame、字段解析、能力适配及结果存储。后者仍被使用，不能因为新版入口出现就直接删除。

当前工具注册集包含目录、语义提案、执行、结果回读、澄清、主题和报告工具。注册不等于模型一直可见：宿主会根据状态裁剪工具，内部修复和部分交付由宿主控制，报告工具需要相应成功证据。

工具注册入口 ↗　语义计划入口 ↗

后端分层与事务边界api / application / domain / infrastructure

API 层负责请求契约和依赖装配；application 编排任务、查询、计算、目录和报告；domain 定义查询与计算规则；infrastructure 实现数据库、SQL 构建、模型连接、配置中心和导出。

这是当前职责分层，部分领域或应用模块直接依赖基础设施，并非完全隔离的纯领域架构。查询先在应用库保存 running 状态并提交，再使用独立业务库连接取数，最后另开事务保存终态。不存在假定的跨库原子事务。

业务失败可能位于 HTTP 200 响应的 result.status=failed/unsupported 中，调用方必须检查业务状态。

三个版本标签，分别理解

HTTP 提问协议：3；新会话业务协议：semantic_v2；部分页面投影兼容标签：frame_v1。JSONL 目录名 native-v1 也不代表业务仍运行旧协议。

04

分析增强在哪里

分析增强的核心是保存完整目标、执行多个受控步骤、用新证据补充或修正判断，再形成可追溯的报告。

正式目录→签名指标引用→分析计划→查询 / 计算事实→核验判断→正式报告
能力已确认的实现适用边界
基础问数v2 基础接口接受取值、排名、位次；多日期取值可提供趋势所需数据。受 BasicQuerySpec 和 QueryPlanner 支持范围限制；期间比较由分析服务或多次取数加计算编排，不是基础接口的独立操作。
通用分析observe、compare、trend、ranking、structure；支持多目标及步骤依赖。最多 8 个需求、12 步、32 个不同指标；方法存在不代表具体业务配置齐全。
专项主题贷款、存款主题配置与 Skills，复用查询和计算。与通用分析关系配置分开，不能将专项能力推导成全部主题都已支持。
精确计算Decimal；四则、正负号、sum / avg / min / max / abs；事实来源可追溯。AST 白名单；禁止属性、索引、循环、幂及任意函数。字面常量只允许 0、1，用户系数须绑定原文。
报告与补查引用真实事实原子；检查数值、日期、来源和部分判断方向；支持明确的部分完成。证据约束覆盖正式查询与报告流程，不能泛化成所有普通对话都经过业务事实核验。
当前仓库的通用结构分析规则尚未配置

backend-next/config/analysis-semantics.json 中 metrics 与 relations 均为空。通用 structure 方法缺少可通过的批准关系；当前实现固定读取后端安装目录下的该文件，运行环境对应文件是否存在另行发布的规则版本，本轮未核实。

数值、日期与缺口如何约束
  • 报告数字通过 {{e1.v1}} 等真实引用进入正文，模型不自行重算或补造事实。
  • 缺失记录不能当零；趋势缺期不补零、不插值；排名需要披露实际参与机构和缺口。
  • 分析未明确日期时可按实际最新记录处理，未明确机构时可采用认证账号所属机构，并说明范围；基础问数仍遵守自己的缺项规则。
  • 未知会计口径不能假定为累计值或单月值，观测差额不能直接认定为期间发生额。
  • 归因、预测及任意统计建模不应因报告写得完整而被当作已实现能力。

分析执行实现 ↗　报告核验实现 ↗

05

多轮、存储与权限

业务焦点

下一轮继承业务条件的基准。新问题、修改和续接由版本化任务管理。

讨论焦点

正在解释或讨论的历史对象。看历史通常不应偷换下一轮查询条件。

展示焦点

当前页面显示的结果或任务，与业务继承和历史讨论分别保存。

位置保存什么维护含义
Agent JSONL 会话原生消息、operation、语义任务、Frame、焦点、引用及部分结果快照。按用户身份分目录；缓存淘汰释放句柄，不删除历史。数据根为单写模式。
应用数据库用户、机构/指标正式目录、会话关联、query_tasks、query_runs、结果与计算证据。独立读写连接；历史读取仍复核归属与当前权限。仅备份 Agent 文件不够。
指标查询库真实指标事实数据；适配 MySQL / GoldenDB 或 Inceptor。独立只读账号。目录同步同步正式目录，不同步全部业务值。
浏览器内存 / 本地偏好访问令牌在内存；选中会话及本地改名等偏好按用户保存。服务器会话和本地显示状态不是同一份存储，本地改名不等于跨设备改名。
权限不是只在登录时检查一次

后端根据当前账号的启用状态、机构、角色与 session_version 验证身份；重新登录或退出使旧令牌失效。普通用户查询范围通常为自身及正式启用下级，管理员与配置中的特殊机构有更大范围，但管理员的数据查询权不等于跨用户读取聊天历史。

机构集合由正式层级展开并绑定范围指纹，执行时重算；权限或目录变化会使旧范围失效。任务、结果、计算和分析回执还要核验 owner。旧结果不能因为曾经成功就跳过当前授权。

后端认证依赖 ↗

重试、取消和结果未知

Agent 保存请求与 operation 的幂等关系，执行前保存后端关联。网络失败、超时或 5xx 时，可能无法确认后端是否已提交，恢复优先查询原状态，不能盲目重发 POST。

模型重试与业务执行重试分开。默认模型最多重试 1 次；首个有效响应和流闲置分别计时，持续有效输出不受固定总响应时长限制。浏览器断线不等于取消，显式取消也不代表已经执行的数据库请求一定停止。

06

页面与交互机制

当前页面以路由注册为准：登录、聊天、问数日志、指标术语、机构别名、数据集、智能配置。智能配置额外限制 SYSTEM_ADMIN；没有独立准确率管理或归因页面。

聊天主面板承担什么

  • 首次发送才创建会话，后续继续同一 Session。
  • 通过 SSE 消费实际进展、工具结果、正式答案和终态。
  • 澄清题目与答案具有版本；纯目录选择可绑定已发布问题。
  • 刷新后重新观察运行，不自动重复提问。
  • 结果不超过 100 行时回读表格；超过 100 行提供 Excel 下载。

认证与展示边界

  • 访问令牌仅在内存，同源 HttpOnly Cookie 用于恢复会话。
  • 密码传输使用 SM2 包裹一次性 SM4 密钥、SM4-CBC 加密密码。
  • Markdown 禁止原始 HTML，外链图片不直接加载。
  • 表格保留十进制字符串；图表按需转数值用于展示。
  • 旧格式会话可查看，禁止直接继续提问。
SSE 进度流与正文逐段流要分开看

当前新会话使用 semantic_v2，答案增量模式的开放条件仍绑定旧 frame_v1 且无 turn contract 的路径。因此新会话主要通过正式回执、message_done 与 snapshot 交付正文；仅开启 AGENT_ANSWER_STREAMING 不能证明新链路已逐 token 展示。此项为源码确认，未做真实模型流式验收。

维护时需要注意的界面实现细节

聊天逻辑集中在 BackendNextChatPanel.vue，包括会话、流控制、历史重建、澄清和结果归并。名称保留旧架构痕迹，但新提问走 Agent 原生入口。

运行过程步骤来源于已收到事件，不过显示时还有每行 600ms 的延迟揭示；运行中默认展开，终态收起。表格数字格式化会去掉末尾零，例如 1.2300 → 1.23，与“保留显示小数位”的旧文档措辞不一致。

明细快照回读失败存在静默 catch；在不超过 100 行且无导出入口的分支，可能出现正文成功而明细缺失、无明确重试提示。该界面失败路径尚未浏览器复现。

配置分成几条独立路径
  • 后端：backend-next/.env 或环境变量提供数据库、身份、路径等；模型/提示词/语义可加载外置 JSON。
  • Agent：AGENT_MODEL_* 单独决定 Chat 网关和模型行为。后台管理页修改模型配置不会自动改写这组变量。
  • 前端：开发由 Vite 代理 /api 与 /agent-api，后者剥离前缀；生产由 Nginx 同源代理。
  • Nacos：启用配置中心后只保留必要本机引导项，中心故障拒绝启动；服务注册与业务配置是两项不同功能。
  • 敏感配置：支持 SM4 密文；主密钥与密文分开保存。HTML 不包含任何凭据。

本地与 Windows

Python 依赖入口在 backend-next/pyproject.toml，两端 Node 依赖分别由各自 package 与锁文件管理。

scripts/windows-local.ps1 提供 Setup / Check / Start / Stop / Status；启动器不自动初始化数据库，也不把 HTTP 存活当成问数验收。

行内部署与持久化

deploy/package 提供 Linux 原生离线构建、安装、升级与回退；另有容器方案。

升级需保留外置配置、密钥引用、Agent 会话与应用库。数据库迁移独立审核执行；Nginx 应保留 SSE 关闭缓冲的设置。

08

已发现的问题

以下是探索中形成的证据清单，不表示已修复。隔离复现使用内存输入，不连接模型或数据库；待验证项保留静态推断边界。

7 项
隔离复现百分比比较公式与计算器契约冲突

触发条件：通用 compare 已取得本期和基期事实，正式单位为 %，value_encoding 为 ratio 或 percent。

冲突：分析生成 (current-base)*100，计算器禁止字面常量 100，调用也没有绑定替代常数。

复现结果：current-base 接受；(current-base)*100 被 CalculationError 拒绝。源码失败链转为 CALCULATION_INVALID / 422，分析记 interrupted。

范围：不代表普通基础取值或全部比较功能不可用。本轮未修复。

公式生成位置 ↗　计算器约束 ↗
隔离复现分析日期批次 36 与基础查询上限 31 不一致

触发条件：分析整理出 32–36 个离散日期，机构数量和结果行数限制未进一步缩小批次。补入基期也可能达到此区间。

复现结果：BasicQueryTime 接受 31 个日期，32 / 36 个均返回 too_long。

影响：服务内部构建 BasicQuerySpec 失败；按现有异常链分析记 interrupted，并可能返回 500。不是调用者请求体的普通 422 校验。

分批位置 ↗
待运行验证同标签页换账号后的管理页缓存残留优先核查

源码路径：App 按 route.name KeepAlive；退出清认证但不清所有缓存页面；问数日志只在 onMounted 载入，不监听账号变化。

可能结果：A 查看日志 → 退出 → B 登录 → 再进日志，仍显示 A 已加载的数据或调试状态。聊天页另有账号切换 reset，不宜外推为全部页面都已处理。

证据边界：这是明确的状态生命周期风险，尚未用真实账号做浏览器复现，不能声称已观察到数据泄露。

# 测评中心

左侧一级菜单“测评中心”提供问题集、测评批次和版本对比。使用当前登录账号的权限和 Agent 服务当前模型配置；运行需要真实模型及业务后端可用。

## 使用

1. 新建问题集，一组代表一个连续会话，按顺序录入首问和追问。人工期望可写机构、指标、期间、应有的分析及缺数行为；未经确认的数值不要作为标准答案。
2. 可导入、导出相同结构的 JSON。问题集、组和题目使用稳定 ID；修改保存时检查版本，旧批次保留当时的完整题目和期望。
3. 发起测评，填写批次名、待测版本说明、数据条件说明。组内串行追问，组间建立新会话；某轮执行失败会跳过依赖它的后续问题。每次重跑生成独立批次和会话。
4. 逐题查看回答、工具来源、表格或图表、实际耗时，再登记人工通过、未通过或待复核及说明。执行完成只表示本轮执行结束；统计的业务通过数要求该轮执行完成且人工判定通过。
5. 在版本对比中选择两个批次。题目按稳定 ID 对齐；问题、期望或同组前文变化会提示不可直接比较。模型、运行配置和数据条件差异分别提示。

## 执行和权限

- 每个账号只访问自己的问题集与批次。结果详情每次经当前账号重新授权读取正式会话，原有权限撤销后无法从测评存储取得回答副本。
- 同一 Agent 进程同时运行一个测评批次，每批最多 100 轮。单轮最多等待 5 分钟，超过时限请求取消；取消确认最多等待 10 秒。未确认停止时保留执行占用，不能启动新批次，可使用“重新确认停止”再次核验；不自动无限重试。
- 页面刷新或离开不停止服务端任务；需要停止时使用“停止测评”。任务以请求 ID 调用原有取消接口并确认状态。
- 登录失效会停止当前批次。重新登录后可查看记录或新建批次，未完成题不会静默重跑。
- 测评会话正常情况下不混入普通聊天列表。测评索引故障时普通聊天继续按原有账号权限展示会话，并记录服务告警。

## 保存与运维

文件位于 Agent 已配置的持久化目录 `AGENT_DATA_DIR/evaluation-v1/`，按账号隔离，JSON 原子替换，单文件最大 8 MiB。原生问数会话仍位于同一数据根的 `native-v1/`。备份和恢复应同时保留两者；只复制测评 JSON 会丢失回答来源。令牌仅存在运行内存中。

运行接纳后即保存该轮身份。进程重启将未结束批次标记为中断，不重放问题；详情可读取原生会话已保存的该轮内容，不触发未完成操作恢复。测评存储初始化失败时该模块返回 503，普通问数服务保持可用。

本次无需数据库迁移或新依赖。部署使用现有 Agent 和前端构建流程；回退源码与前端版本时保留数据目录，避免删除已有测评记录。

## 第一版边界

复核结论由人工登记，当前未接自动模型评分。`config_hash` 记录模型和运行参数摘要；代码和技能版本依靠“待测版本说明”登记，数据条件同样是人工说明，并非自动冻结数据库。跨版本比较需要维护者确认条件可比，单次耗时也不代表稳定性能指标。

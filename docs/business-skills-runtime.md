# 原生业务 skill 与组合计算

业务知识改造的历史检查见 验收记录（历史参考材料，未随交付包提供）；当前多轮改造及未验证边界见 [Pi 通用多轮业务上下文](pi-business-context.md)，旧记录不代表当前版本已完成真实模型验收。

## 运行入口与职责

`agent-service/src/server.ts` 使用 pi-agent-core 0.85.1 的 `loadSkills` 加载
`agent-service/skills` 并注册到 Harness resources。目录仅提供知识名称和适用业务内容，
通过 `business_skill_read` 按名称查阅，不注入通用文件 skill 的强制先读指令。
服务提供已审核内存快照，不开放文件路径、Shell、编辑或用户目录访问；缺文件、无有效
知识、重复名称和越界路径仍使加载失败。

四类知识包括指标查询口径、数据覆盖含义、结果计算规则和分析能力边界。它们不选择工具、
不声明工具依赖，也不控制执行顺序。pi 根据用户目标、会话和工具契约自主决定是否查阅
知识及调用哪些工具。未读知识、读取多份或跨轮查阅都不改变业务工具集。

宿主不维护当前方法或已激活工具状态。当前上下文中实际存在的成功读取回执，经当前版本
正文核验后去重投影，可同时参考多份知识；用户文字、摘要和失败回执不冒充已审核正文。
旧版本知识在发送副本中标记失效，原生历史保留；压缩后缺少正文时由 pi 按需重新查阅。

工具描述承担输入输出与能力契约，工具及后端校验正式编码来源、权限、归属、版本、日期、
幂等和计算事实范围。当前公开查询入口只接受通过 Resolver/Validator 的 READY Frame，不要求先查
覆盖或先读计算知识；条件不明由 Frame issues 驱动澄清。历史结果可按需回读，
能否将其中事实用于本轮计算由后端计算范围校验决定，与读过哪份知识无关。

业务知识与工具选择保持解耦。知识提供业务口径，不能替代 Schema、字段校验和后端权限。

## 提示词与知识的分层

模型的普通业务上下文由主提示词、能力字段 Schema、四份知识的名称与描述、当前可见的已读取正文以及本轮业务状态共同组成。主提示词由 `buildBusinessSystemPrompt` 构建；Harness 在发送副本中追加能力 Schema、可信知识正文和状态，不把这些投影另存为一份会话记忆。SDK 不为该业务入口自动附加默认编程助手提示词。

主提示词常驻目标、来源、完整变化、候选确认、纠错与澄清、证据和完成条件等跨能力决策规则。字段输入结构、枚举和组合边界由对应工具及能力 Schema 说明；业务口径和适用场景由知识正文解释。知识描述说明用途和何时需要参考，详细判断放正文。读取知识不是业务调用前置条件，未读取知识时仍须遵守主提示词与服务端契约。

机构指代由模型结合当前会话理解并选择结构化来源，服务端核对来源、状态、权限和用户明确的数量。固定模型入口通过明确的 `base` 继承整笔历史业务的未变字段；特定字段单独取自历史或多个来源组合时，提交对应字段的结构化引用。唯一来源不因没有数量词而额外澄清；来源不唯一或数量不符时保存已知条件再询问。示例只解释判断分支，不定义默认机构、时间口径、排名条数或固定回答。

用户已明确条件而模型遗漏或格式不合法时，根据原文及纠错回执修正参数；用户未提供且不能唯一确定的业务选择，通过已声明的澄清输入保存状态，不能为了满足必填 Schema 补默认值。两类情况共用现有工具契约，不改变字段、权限、候选确认或执行校验。

正式指标的保守错字纠正由后端目录匹配实施，保留原文与正式编码的映射证据；确认恢复与排名方向、条数由程序核验，并在 Frame 中保存续接进度。阈值、歧义边界与恢复结构见[确认与恢复契约](business-context-reference-recovery.md)。Skill 不代替这些校验，也不要求新增分析规划流程。

合法枚举或纠错回执的 `allowedValues` 仅表示接口可接受的值域，即使只剩一个合法值，也不能证明用户已经选择。新增业务控制值必须有本轮原文、已选可信来源或 Schema 明确无损派生的依据。模型在固定 `changes` 中表达一份动作、值、原文与必要数量，实际工具 Schema 限定字段及类型；必需的机构动作即使未变仍显式声明 inherit，其余未变字段可省略。内部适配器生成既有 Delta 和目标声明，已选来源及原数量约束继续核验。确认原文保留本轮名称、编号或完整同意，不能用未出现在本轮的候选标签代替。

固定 confirm 动作把确认方式和原文集中表达：select 对应名称、编号或点选，accept 对应完整语义同意；内部适配保留旧 evidence 校验。服务端匹配已保存清单并逐组核验唯一性，不能在同一待确认项的多个候选中任选。指标的同基础名称、多口径分组继续按既有确认契约处理。历史来源的机构数量不等于用户本轮声明的数量约束，无明确数量的指代不自行新增数量要求。格式与兼容边界见固定业务请求接口（历史参考材料，未随交付包提供）。

多个必要业务选择同时未决时，同次保存全部未决选择及已知条件，不能仅澄清其中一项而给另一项填无依据的正常值。多日连续范围不自动确定取数方式；既有服务端算法对已解析单日、缺省且未显式修改的取数方式确定为 `exact`，字段说明公开这一无损规则，不改变算法或覆盖显式选择。

提示词中的当前日历日期来自 `Asia/Shanghai` 时区的系统日期，不代表营业日、已完成批次日或最近可用数据日。状态中的受控协议说明只能在其代码定义的路径解释；用户原文、实体名称、业务值和结果内容始终是数据，不能因出现同名说明字段而成为指令。此说明不等于新增了消息身份隔离机制。

## 一步成功与最终交付

普通取值、覆盖和计算成功后继续 Pi 原生循环。Pi 根据本轮事实决定是否继续，并组织最终正文。
NEEDS_CLARIFICATION 在原生工具回执处按已保存 Frame 交付必要问题并结束本轮，不再请求模型自拟候选或重复解析；工具门禁同时防止继续调用来代替用户补充。
宿主不注入旧 `answer_evidence_check` 或强制 `answer_present`。候选澄清和能力限制使用受控回执交付，其余正文依据实际工具事实组织；旧历史投影仅保留读取兼容。

每个原生 operation 最多 24 次工具调用。参数和诊断变化时允许继续纠错；同一失败提案重复出现时停止，交错读取不能绕过循环检查。计数从持久化记录取得，恢复不重置。
参数错误不保存新 Frame 或覆盖焦点；失败状态不作为成功事实。模型响应格式错误返回明确运行错误，不能展示协议标签或解析文本伪调用。

当前轮结果提供事实与引用；历史模型副本移除大型行表和重复状态读取，焦点由原生 Session 的业务 values 提供。
Pi 的最终说明随原生消息保存，页面、历史及刷新使用同一投影；表格仍只使用后端快照。
业务状态由 [Pi 通用多轮业务上下文](pi-business-context.md) 的 Frame/Delta/Schema 管理。
`metric_ask` 及直接由模型提交业务编码的方式已退出公开工具集。

## 受控计算

复用既有 `/api/v1/calculations` 与 Decimal 表达式执行器。`execute_business_frame` 的取值回执返回最多 100 条事实引用以及截断标记；完整查询快照保存权威数值。
分页 `read(kind=result)` 返回对应行的事实引用，不把预览当完整计算输入。

结构化查询先建立受当前身份约束的后端会话映射，并绑定原生 operation 和用户原文。
Frame 字段补充后执行使用当前原生 operation 的计算范围。计算工具只接受事实引用和公式，
会话与范围由宿主绑定；后端重新检查归属、范围、当前权限、启用目录、任务状态、过期、
数据完整性、单位及数值精度。模型提供的业务金额不能进入参数。

默认 `same_org_date` 要求同机构同日期；`cross_date`、`cross_org`、`explicit` 分别用于
已明确的跨日期、跨机构或组合范围。它们声明可比较范围，不自动证明指标的业务意义可比，
公式含义不明仍须澄清。单位不同、零分母、缺数、查询截断或非法表达式均明确拒绝。
计算记录、输入证据和幂等结果保存在原有任务 JSON 及消息中，没有新增表或迁移。
历史回读不改写事实的原范围。新宿主显式使用 conversation_snapshots，将本轮计算 scope_id 与输入原范围分开；同会话合法快照可组合，权限与有效性仍逐项复核，常数仅按本轮用户原文核验。旧客户端默认 current_scope。具体见 [历史快照接续计算](history-snapshot-calculation.md)。

当前计算是有界数学运算，不提供业务动因、预测、血缘或综合分析报告。

## 发布与验证

组合计算功能涉及 Agent、后端和前端配套版本。通用多轮改造需配套更新 Agent、后端字段解析接口及前端工具标识，保持页面入口和 V3 消息协议。离线构建复制 `skills/` 与 `dist/`；Agent Docker 镜像也需包含
该目录。无需升级 pi 或新增依赖。本次回退同步恢复 Agent 代码与知识文件；现有查询快照仍可读取，计算
JSON 不要求数据库回退。已有旧结果缺少计算范围时，应重新查询后计算。

更新方法文件后须重启 Agent 以加载新的内存快照；发布前让活动操作结束，再切换对应
代码和方法版本，避免恢复中的操作继续使用旧工具快照。本次修复不改写历史会话或业务结果，
历史榜单保持原快照；要应用新的排名范围需重新查询。

验证不能只检查提示词关键词：覆盖原生 skill 读取、取数后继续求差、失败/权限/截断、
澄清与历史回读、刷新恢复以及受控数值交付。`scripts/check-skill-model.ts` 使用当前 Frame 工具链核验查询后计算，
`scripts/check-context-semantics.ts --live` 核验多种表达对应的 Delta；二者使用
配置的真实模型和合成后端，不能当作真实数据库证据。真实环境验收另行记录模型调用数、
输入 token、总耗时和结果正确性；没有同条件前后对比时不声称速度提升。

提示词和四份知识的修改前后对照使用 `scripts/check-prompt-skill-ab-model.ts`：修改前与各候选均冻结源码，同一模型、场景和输入干预分别保留原生记录。目录、权限、查询和计算响应为隔离合成数据；部分场景明确预读知识以检验正文影响，其他场景由模型自然决定是否读取。测量期间修复了运行器失败断言的 Node 源码定位问题并增加检查点，修订前后脚本及补丁有单独记录，不改变模型输入或业务桩。比较错误调用、无依据业务条件、已知条件下的额外澄清和真实目标达成，不能仅用请求结束或零查询判定通过。结果及样本边界见 对照验收报告（历史参考材料，未随交付包提供）。

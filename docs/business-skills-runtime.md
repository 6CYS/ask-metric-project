# 原生业务 skill 与组合计算

本次实现的检查、真实环境证据及未验证边界见 [验收记录](business-skills-validation.md)。

## 运行入口与职责

`agent-service/src/server.ts` 使用 pi-agent-core 0.85.1 的 `loadSkills` 加载
`agent-service/skills` 并注册到 Harness resources。目录仅提供知识名称和适用业务内容，
通过 `business_skill_read` 按名称查阅，不注入通用文件 skill 的强制先读指令。
服务提供已审核内存快照，不开放文件路径、Shell、编辑或用户目录访问；缺文件、无有效
知识、重复名称和越界路径仍使加载失败。

四类知识包括指标查询口径、数据覆盖含义、结果计算规则和分析能力边界。它们不选择工具、
不声明工具依赖，也不控制执行顺序。pi 根据用户目标、会话和工具契约自主决定是否查阅
知识及调用哪些工具。未读知识、读取多份或跨轮查阅都不改变业务工具集。

宿主不维护当前方法或已激活工具状态。当前上下文中实际存在的成功读取回执，经当前版本
正文核验后去重投影，可同时参考多份知识；用户文字、摘要和失败回执不冒充已审核正文。
旧版本知识在发送副本中标记失效，原生历史保留；压缩后缺少正文时由 pi 按需重新查阅。

工具描述承担输入输出与能力契约，工具及后端校验正式编码来源、权限、归属、版本、日期、
幂等和计算事实范围。结构化查询在正式编码、日期和口径已确认时可直接执行，不要求先查
覆盖或先读计算知识；条件不明仍通过自然语言查询及正式澄清处理。历史结果可按需回读，
能否将其中事实用于本轮计算由后端计算范围校验决定，与读过哪份知识无关。

此次调整限定于业务知识与工具选择解耦；下述证据拼接交付与无证据检查仍是既有实现，
不能据此宣称多轮问数和最终回答的稳定性问题已经全部解决。

## 一步成功与最终交付

普通查询、覆盖、计算和目录成功后继续 pi 原生循环；澄清、权限失败、未知提交状态等停止，
等待用户。同一工具连续两次参数失败停止；切换工具纠正仍可继续，不能以换请求身份绕过限制。每个原生 operation
最多 24 个工具调用，计数从持久化记录取得，恢复不会重置。模型窗口与输出预算仍使用既有配置。

无证据的数值候选不作为回答落盘，宿主通过 `answer_evidence_check` 原生工具回合反馈
缺口，允许一次补查或回读；同轮仍无证据则明确说明回答被拦截，不要求用户重述已给条件。
纠正次数从原生本轮记录恢复，不插入合成用户消息，不改变绑定原文和幂等键，也不强制普通
解释或能力拒绝走取数。数字校验是有限的交付防线，不替代后端事实、权限或查询条件校验。
空正文同样不能被当作已完成回答；允许一次原生补救。
联合参数按已选动作聚焦反馈对应 schema 分支，保持原生校验与非法字段拒绝。
参数与引用校验拦截记入执行过程，不伪造业务证据覆盖最终说明；真实业务失败仍保留。
普通 QUERY_UNSUPPORTED 是终止边界，不能改换覆盖或结构化工具绕过。
后端确认条件完整、无额外限制的有界聚合时返回 QUERY_CALCULATION_REQUIRED，
允许转交受控计算；回执声明 recovery_kind，只有对应计算成功才解决该条转交提示，
覆盖或原值查询成功不能冒充运算完成。组合计算由 pi 按工具输入契约准备完整事实。
查询引用跳过未执行业务的校验错误，但真实业务失败和正式待澄清仍是状态边界。
核验工具不展示给模型主动选择，只由宿主注入。对于当前没有实现的归因、预测、血缘等目标，
pi 可调用 `business_capability_explain` 返回可终止的说明，不以覆盖或取值代替分析。

`after_response` 保留后续工具调用；模型结束后从本轮全部有效证据确定性生成正文，
不会用某条中间查询覆盖计算。实时快照、历史、重连使用同一投影，保留计算失败和中断提示。
新交付工具在注册处添加 `business_evidence_v1` 标记，旧会话继续兼容原工具回执。
标记仅说明回执可交付，不能说明用户整个目标完成。

历史查询及计算的模型发送副本省略行值、facts、计算输入金额、计算结果和格式化答案；
中断留下的无证据数值片段也不继续传播。保留查询
条件、结果引用、截断告警和分页信息。当前轮和原生记录不改写；历史数值通过受鉴权工具回读。

基础集合查询由 `metric_ask` 解析原文；目录类别词零命中不能推导集合不存在。自然语言
全目录机构排名在执行时与省级根的直接下级取交集，并保留原授权范围；不包含省级根和更低
层支行（完整层级模式），不按名称含“汇总”删除法人总行。缺少明确根机构时返回可识别的范围错误，不能静默
用混合层级榜单。显式指定的候选机构不套用全目录排名裁剪。机构层级仍使用既有 provider
及其兼容规则，不新增目录分类或数据库字段。
层级不完整时，既有兼容模式仅排除唯一“全省汇总”根，将其他启用机构视作下级；
因此不能在该模式下承诺排除混入目录的支行，正式同层级榜单仍需完整层级数据。

时间提取和规范化共用日期排版处理；新旧追问协议修改日期时清除旧取值模式与派生日期。
这保证“月份”和“月末”的范围变化可正确进入后端，不能据此推导余额应按日求和。
日期提取、解析、残句检查共享季度/半年语法，周期初末按周、月、季、年规则展开；
复合或否定周期不做单规则覆盖。超长集合与区间不含目标日期时澄清；离散日期通过
AT_DATES 模板执行，不能降级为连续区间。未知指标仍完整保留并澄清。
语义结构失败可按同一原文、来源和 schema 纠正一次，诊断定位具体字段路径；
再次失败仍拒绝执行。日期派生 options 随 time 变更，不能独立作为 changes 字段。


`metric_ask` 的 new 表示独立基础问题，允许缺条件。它使用宿主绑定原文，仍只接纳
一个独立语义写命令；不是全局工具次数限制。已确认范围优先批量结构化查询，确需不同范围时
用独立参数指纹派生稳定幂等键。未增加任意文本子查询入口，不删除重复提交保护。

## 受控计算

复用既有 `/api/v1/calculations` 与 Decimal 表达式执行器。`metric_query_structured`
和 `metric_ask` 返回最多 100 条事实引用以及截断标记；完整查询快照保存权威数值。
分页 `metric_read` 返回对应行的事实引用，不把预览当完整计算输入。

结构化查询先建立受当前身份约束的后端会话映射，并绑定原生 operation 和用户原文。
自然语言查询也携带该计算范围；正式澄清续办沿用原任务范围。计算工具只接受事实引用和公式，
会话与范围由宿主绑定；后端重新检查归属、范围、当前权限、启用目录、任务状态、过期、
数据完整性、单位及数值精度。模型提供的业务金额不能进入参数。

默认 `same_org_date` 要求同机构同日期；`cross_date`、`cross_org`、`explicit` 分别用于
已明确的跨日期、跨机构或组合范围。它们声明可比较范围，不自动证明指标的业务意义可比，
公式含义不明仍须澄清。单位不同、零分母、缺数、查询截断或非法表达式均明确拒绝。
计算记录、输入证据和幂等结果保存在原有任务 JSON 及消息中，没有新增表或迁移。
历史回读不改变事实所属的计算范围；本轮计算输入必须通过后端 scope_id 校验。

当前计算是有界数学运算，不提供业务动因、预测、血缘或综合分析报告。

## 发布与验证

组合计算功能涉及 Agent、后端和前端配套版本。本次知识与工具解耦仅需更新 Agent 代码及知识文件，保持既有后端接口与前端协议。离线构建复制 `skills/` 与 `dist/`；Agent Docker 镜像也需包含
该目录。无需升级 pi 或新增依赖。本次回退同步恢复 Agent 代码与知识文件；现有查询快照仍可读取，计算
JSON 不要求数据库回退。已有旧结果缺少计算范围时，应重新查询后计算。

更新方法文件后须重启 Agent 以加载新的内存快照；发布前让活动操作结束，再切换对应
代码和方法版本，避免恢复中的操作继续使用旧工具快照。本次修复不改写历史会话或业务结果，
历史榜单保持原快照；要应用新的排名范围需重新查询。

验证不能只检查提示词关键词：覆盖原生 skill 读取、取数后继续求差、失败/权限/截断、
澄清与历史回读、刷新恢复以及受控数值交付。`scripts/check-skill-model.ts` 明确使用
配置的真实模型和合成后端，不能当作真实数据库证据。真实环境验收另行记录模型调用数、
输入 token、总耗时和结果正确性；没有同条件前后对比时不声称速度提升。

# 本地部署指南

本指南面向从源码首次启动项目，适用于 Windows PowerShell 和 Linux。目标是完成配置、应用库初始化、目录同步、创建账户和前后端访问；不自动生成模拟数据，不包含任何默认登录密码。

行内 Linux 离线安装见 [原生离线部署](../deploy/package/README.md)；禁止 Shell、自带 Python 的包见 [麒麟载荷部署](../deploy/package/KYLIN_PAYLOAD_DEPLOY.md)。[腾讯云 Compose](../deploy/cloud-next/README.md) 依赖已有外部双库和网络，不是通用的本地一键启动方案。

## 1. 准备环境与数据库

- Python 3.11～3.13，项目部署示例使用 3.12。
- Node.js 22.12 及以上的 22.x，或 24.x；锁文件中 Vite 要求 `^20.19.0 || >=22.12.0`。使用随 Node 安装的 npm。
- 已创建的 GoldenDB/MySQL 应用数据库及读写账号；建库、授权由数据库管理员完成，Alembic 只管理库内应用表。
- 独立用途的数据湖只读连接，以及正式指标、机构目录和指标值。源码不包含业务数据，启动应用不会自动建立数据湖表。
- 可访问的 Chat 模型服务。Embedding/Reranker 为可选角色；未部署时应在模型配置中关闭对应角色，不能保持启用却不填地址。

应用库账号和数据湖只读账号不能共用。首次安装新应用库才执行初始化迁移；已有系统先核对迁移版本并备份，不能把“重新部署代码”当作重建数据库。

## 2. 安装后端依赖

从仓库根目录打开终端。Windows PowerShell：

```powershell
cd backend-next
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Linux：

```bash
cd backend-next
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
test -f .env || cp .env.example .env
chmod 600 .env
```

后续后端命令均在 `backend-next/` 且虚拟环境启用的终端执行。PowerShell 若不允许激活脚本，可用 `.\.venv\Scripts\python.exe` 替代下文 `python`，不必修改全局执行策略。只运行应用不需要安装测试依赖；开发检查另用 `python -m pip install -e ".[dev]"`。

## 3. 配置后端

以 **`backend-next/.env.example`** 为源码启动模板，编辑 `backend-next/.env`。本交付只保留各组件自己的环境模板，不提供根目录环境模板。进程环境变量优先于 `.env`；如果改文件不生效，先检查终端是否还设置了同名环境变量。

| 配置 | 必须核对的内容 |
|---|---|
| `APP_ENV` | 本机开发用 `development`；对外正式服务用 `production` 并按原生部署指南设置日志、密钥及权限。 |
| `APP_DATABASE_URL` | 已创建的应用库 URL；账号需要应用读写权限，执行迁移时另需经授权的 DDL 权限。 |
| `APP_DATABASE_DIALECT` | `mysql`（GoldenDB 的应用连接也使用此值）。 |
| `QUERY_DATABASE_URL` | 独立只读数据湖 URL。 |
| `QUERY_DATABASE_DIALECT` | 根据 SQL 模板选择，不能只看端口或连接协议，见下文。 |
| `JWT_SECRET`、`CONTINUATION_TOKEN_SECRET` | 两个独立的随机签名密钥，开发环境也不能留空，否则登录或问数请求失败。 |
| `SM2_PRIVATE_KEY` | 开发未填时会生成进程临时密钥；固定部署必须用私钥生成工具配置，并在升级时保留。 |
| `MODEL_CHAT_BASE_URL`、`MODEL_CHAT_API_KEY` | 实际模型地址和凭据；请求路径、模型名、鉴权头还需要匹配模型 JSON。 |
| `NACOS_ENABLED`、`SSO_ENABLED` | 本机直连使用 `false`；无需为本地启动配置 Nacos 或上游单点登录。 |

数据库 URL 格式为 `mysql+pymysql://用户名:经过百分号编码的密码@主机:端口/数据库名?charset=utf8mb4`。不要把未编码的 `@`、`#`、`/` 等密码字符直接放入 URL。部署主机、真实密码和密钥仅存放在外置配置中。

**数据湖方言与目录映射：**

- `mysql` 模板查询 `metric_values` 并关联 `metric_terms`，要求查询库中存在这些结构。
- `inceptor` 模板查询 `SIT_FACT_TABLE` 等映射的事实表；即使本地源库使用 MySQL 协议，只要采用当前 SIT 的 `adm_rmt_*` 表结构，也应按 [数据湖映射说明](../deploy/package/DATA_LAKE_DEPLOY.md) 配置此模板与全部 `SIT_*` 字段。
- 应用目录同步默认读取 `QUERY_DATABASE_URL`；目录若在其他数据源，可分别设置 `METRIC_CATALOG_DATABASE_URL`、`ORG_CATALOG_DATABASE_URL`，仍使用只读账号。
- 目录同步有机构范围和数量校验，模板默认为 61 家；部署到其他目录时必须根据实际范围核对，不能为通过检查随意填写。

首次本地开发可执行以下命令，把两个随机签名密钥直接写入 `.env`，不打印密钥，也不覆盖已有非空值：

```sh
python -c "import secrets; from dotenv import dotenv_values,set_key; values=dotenv_values('.env'); [set_key('.env', name, secrets.token_urlsafe(48)) for name in ('JWT_SECRET','CONTINUATION_TOKEN_SECRET') if not (values.get(name) or '').strip()]"
```

需要固定 SM2 私钥时，选择仓库之外的受保护目录：

```sh
python scripts/generate_sm2_keypair.py --output <受保护目录>/sm2.env
```

将生成的 `SM2_PRIVATE_KEY` 配置到运行环境。工具要求目标文件不存在，不在终端打印私钥。生产环境请使用 [SM4 加密配置](../README.md#sm4-加密配置)，独立主密钥与密文分开保存；不复用登录 SM2 密钥和配置 SM4 密钥。

### 模型与问数能力

查看 `config/model-config.json`，建议复制到 `.runtime/local-config/model-config.json` 后修改，并在 `.env` 设置 `MODEL_CONFIG_PATH=.runtime/local-config/model-config.json`。目录需自行创建。Chat 的 `model`、`path`、`authentication.type/header/prefix` 必须与服务端一致；当前模板使用 `accessKey`，不能直接假设兼容服务都采用这一头部。其他服务若使用 Bearer token，应相应设置 `Authorization` 和 `Bearer ` 前缀。

未提供 Embedding/Reranker 服务时把对应模型角色的 `enabled` 设置为 `false`；提供服务时填写相应环境地址、密钥变量及鉴权配置。不要把真实地址或密钥写入将要提交的 JSON。

当前仅维护独立问数、当前任务澄清和历史结果。跨任务追问没有启用开关；清理旧环境中的 `MULTITURN_*` 配置，并按 [后端升级说明](../backend-next/README.md#独立问数与当前任务澄清) 合并持久提示词。修改环境配置后重启后端。

## 4. 审核并初始化应用表

使用 `alembic-goldendb.ini`，不要使用另一条历史迁移链。当前保护逻辑对 `--sql` 离线导出也检查变更开关；非专用测试名称的库还检查第二个开关。以下开关只在本次运维进程中设置，操作完即移除，不能长期保存在 `.env`。

PowerShell，仅生成离线 SQL（不连接数据库）：

```powershell
$env:BACKEND_NEXT_ALLOW_SCHEMA_CHANGES="true"
$env:BACKEND_NEXT_ALLOW_NON_TEST_DATABASE="true"
python -m alembic -c alembic-goldendb.ini upgrade head --sql
Remove-Item Env:BACKEND_NEXT_ALLOW_SCHEMA_CHANGES
Remove-Item Env:BACKEND_NEXT_ALLOW_NON_TEST_DATABASE
```

将 SQL 保存到受保护的 UTF-8 文件，交 DBA 审核。已有库应由 DBA 核对从当前 revision 到目标 revision 的增量，不能执行包含建表历史的完整导出。

SQL 已审核、目标库与备份已确认且获得执行授权后，才进行实际迁移：

```powershell
$env:BACKEND_NEXT_ALLOW_SCHEMA_CHANGES="true"
$env:BACKEND_NEXT_ALLOW_NON_TEST_DATABASE="true"
python -m alembic -c alembic-goldendb.ini upgrade head
Remove-Item Env:BACKEND_NEXT_ALLOW_SCHEMA_CHANGES
Remove-Item Env:BACKEND_NEXT_ALLOW_NON_TEST_DATABASE
```

Linux 用单条命令的临时环境变量，生命周期仅限该进程：

```bash
BACKEND_NEXT_ALLOW_SCHEMA_CHANGES=true BACKEND_NEXT_ALLOW_NON_TEST_DATABASE=true \
  python -m alembic -c alembic-goldendb.ini upgrade head --sql
# 审核及授权完成后才执行下一条：
BACKEND_NEXT_ALLOW_SCHEMA_CHANGES=true BACKEND_NEXT_ALLOW_NON_TEST_DATABASE=true \
  python -m alembic -c alembic-goldendb.ini upgrade head
```

## 5. 同步正式目录并创建首个账户

当前 SIT 目录源准备好并完成字段映射后，先预演：

```sh
python -m ask_metric check-data-lake
python -m ask_metric sync-metric-catalog --dry-run
python -m ask_metric sync-org-catalog --dry-run
```

确认来源正确、选中记录数量符合预期且没有错误，再执行实际同步（写应用库目录，不修改数据湖）：

```sh
python -m ask_metric sync-metric-catalog
python -m ask_metric sync-org-catalog
```

该流程只同步目录，不复制指标值；源表必须由数据提供方准备。已有正式应用目录可直接复用，不应为部署再次清理。`initialize-synchronized-catalogs` 是具有删除行为的一次性旧目录替换工具，不属于普通首次启动步骤。

从已启用的机构目录选择真实 `org_code`，通过交互式密码输入创建首个管理员（把占位值替换后执行）：

```sh
python scripts/create_local_user.py --username <登录名> --display-name <显示名> --org-code <有效机构编码> --role-code SYSTEM_ADMIN --config .env
```

密码至少 8 个字符；不要用命令行 `--password` 传真实密码。普通用户使用 `--role-code USER`，其查询范围受所属机构限制。**同名账户存在时该工具会更新账户和密码，并使原登录状态失效**，创建前请核对登录名。应用没有内置默认管理员密码。

## 6. 启动前后端

后端终端：

```sh
python -m uvicorn ask_metric.main:app --app-dir src --host 127.0.0.1 --port 8010 --reload --no-access-log
```

新开终端，从仓库根目录启动前端：

```sh
cd frontend-vue
npm ci
npm run dev
```

浏览器打开 `http://localhost:5173`，用上一步账户登录。Vite 默认将 `/api` 代理到 `http://localhost:8010`。如后端端口不同，在 `frontend-vue/.env.local` 设置 `VITE_BACKEND_NEXT_BASE_URL=http://localhost:新端口` 后重启 Vite。此变量在开发模式仅设置Vite代理目标，浏览器统一请求同源 `/api`，不直接跨域访问后端。不要把 `/api` 或 `/api/v1` 拼到该变量末尾。

本机后端监听回环地址；需要他人访问时按正式部署配置反向代理和认证，不将 `--reload` 开发进程当生产服务。生产构建见 [前端说明](../frontend-vue/README.md)。

## 7. 检查与排障

PowerShell 使用 `Invoke-RestMethod http://127.0.0.1:8010/health`；Linux 使用 `curl -fsS http://127.0.0.1:8010/health`。再检查同一地址的 `/health/ready`。

| 检查 | 能证明什么 |
|---|---|
| `/health` 返回 `ok` | HTTP 服务存活。 |
| `/health/ready` 返回 `ready` | 应用库连接及目前检查的四张会话/任务表存在；不能证明全部表、目录、模型和数据湖可用。 |
| 页面登录成功 | 密钥、账户、机构及认证链路可用。 |
| 使用目录中真实指标、机构、已有日期查询 | 实际模型理解、模板和数据湖链路可用；无数据不能当成功验收。 |
| 同会话完成查询后仅发送机构；当前待澄清任务补日期 | 前者新建任务并澄清缺失条件；后者继续原任务。 |

常见现象：

- 登录提示 `AUTH_CONFIGURATION_INVALID`：核对 `JWT_SECRET`；问数报 continuation secret 缺失：核对 `CONTINUATION_TOKEN_SECRET`。
- 503 就绪失败：核对应用库地址、权限、迁移版本；不要通过关闭校验解决。
- `metric_values` 或 SIT 表不存在：检查查询方言及映射，应用库迁移不会替你创建外部数据湖。
- 模型连接失败：同时核对环境地址、有效 JSON 路径、模型名、鉴权头和服务额度；模板未填不能直接问数。
- 请求 404/502：核对前端代理目标和后端端口；不要重复追加 `/api`。
- 完成查询后只发机构又要求补指标/日期：这是独立问数的预期行为；需要补全本次条件。
- 升级后仍使用旧配置：持久配置优先保留，核对 `MODEL_CONFIG_PATH`、`PROMPT_CONFIG_PATH`、`SEMANTIC_CONFIG_PATH`、`QUERY_TEMPLATE_CONFIG_PATH` 和 `SQL_RESOURCE_DIR` 实际文件。

## 8. 源码交付范围

运行需要后端 `src/`、`config/`、`resources/`、GoldenDB 迁移链、依赖声明、必要运维脚本；前端需要源码、静态资源、构建配置和锁文件。离线构建还需要 `deploy/package/` 的构建器及运行模板。

自动化测试、压力/验收报告、临时产物、演示数据生成工具可按交付范围排除，但不能仅按名称含 `test` 删除文件：当前准确率管理页面会引用 `resources/testing/accuracy-baseline.json` 和 `scripts/run_accuracy_suite.py`。若仍保留该页面和接口，这些是运行依赖；若要全部移除测试中心，需要同步调整功能和引用。

真实 `.env`、密钥、数据库备份、运行日志、`.runtime/`、`node_modules/`、`.venv/`、镜像包与历史验收材料不随源码公开提交。本指南不需要上传现有业务数据即可交付，但完整业务验收需要接收方自行配置数据源与模型服务。

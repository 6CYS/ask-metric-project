# 业务表达与饼图验证

日期：2026-10-25。范围：新版 Ask Metric 的概览表达及存款结构饼图，保留现有证据校验；旧版对比环境未修改。

## 实际结论

“我行存款情况如何 → 帮我绘制饼图”已经在现有 `3309/ads_lake` 和当前真实模型服务上跑通。第二问直接使用第一问的结果，生成个人／对公存款结构饼图，没有新增业务查询。页面已检查图形、金额提示和刷新后的历史恢复。

业务表达有改善，但还不能认定已达到 mfws 的自然程度：最终实测首问仍在一次修正后触发事实恢复。恢复正文现在先给总量，再突出正式分项差异，保留所选比较基期；没有放行未经证实的连续趋势或业务原因。响应耗时仍有波动。

## 具体实现

| 部位 | 改动与边界 |
| --- | --- |
| `agent-service/src/tools/businessReport.ts` | 首次纯文案错误允许一次修正；再次失败才从正式事实恢复。复用本轮工具回执计数，不新增状态。来源、权限、任务和引用错误不能通过恢复绕过。 |
| 同一报告工具 | 新增可选 `chart: {type: "pie", relationship_id?: string}`。仅绘图可省略长正文，生成短图注；图表存于 `report.charts`，独立于正文恢复。失败原因保留在回答中。 |
| `backend-next/src/ask_metric/application/verified_findings.py` | 已核验判断使用直接的业务表述，减少技术标题和逐项重复的限制语；判断适用范围、依赖和证据不变。 |
| `agent-service/src/analysis/overviewCharts.ts` | 单一纯函数从已有事实及正式占比构图。校验机构、日期、单位、组成关系、金额有效性和总分一致性，不接受模型提供金额。 |
| `backend-next/config/business-topics.json` | 在现有关系中声明个人／对公、个人活期／定期两组饼图资格；仍逐次检查数据是否合格。金额尾差容限为 1 元，使用十进制整数精确核对。 |
| 前端现有报告投影与 `ChatResultChart.vue` | 透传可选图表，复用 ECharts 增加饼图；正文后直接显示，金额和占比用服务端正式展示值，保留历史消息。原折线和柱状图路径保持。 |
| `enhancedAnalysisPrompt.ts` | 补充实际工具的使用方式：绘图追问读取已有结果、沿用范围和日期；不是仅修改提示词。 |

没有新增依赖、服务、数据库表、任意 SQL／Python 执行框架，也没有修改用户的模型配置。

## 借鉴 mfws 的部分

# 新老版本手工对比测试题单

这份题单共 **7 组、19 轮**，使用贴近日常业务的模拟问法，并非领导的原话。既检查已经改善的部分，也保留目前暴露过问题的问法。你可以先测前四组，再测后面三组。

| 版本 | 入口 |
| --- | --- |
| 新版 | [打开新版](http://127.0.0.1:5173/chat) |
| 旧版 | [打开旧版](http://localhost:5174/chat) |

新版为本次提交后的 `develop`；旧版为最初改动前的 `73f1db5`，保留本机 MySQL 方言兼容调整。两版使用相同的 `ads_lake` 业务库和 `deepseek-v4-pro` 模型，聊天记录分开保存。这是累计改动的整体效果对比，不能单凭它确定某一项改动的贡献。

请保留入口中的 `127.0.0.1` 和 `localhost` 区别，两边分别登录，避免登录状态互相影响。

## 测试方法

1. 两边使用同一账号。**每组在两个版本中分别新建会话，组内连续追问。** 不在新旧版本之间共用一个历史会话。
2. 每次只复制一个代码框，等回答结束，再发下一句。新旧版本使用同一句原话，不把本页的观察提示或另一版的答案发给它。
3. 第一遍保留自然表达，不主动补日期、机构和指标全名。缺少条件时，观察它能否合理采用默认值并说明实际范围；真正有歧义时，简短澄清是合理的。
4. 如果必须回答澄清，按你的真实业务意思回答，记录补了什么；另一版遇到相同选择时也选同一含义。不要为了让某版通过而不断改题。
5. 前一轮失败后，可以继续发送下一句，但标记“前轮未完成”。另外重测时新建会话，不覆盖第一次结果。
6. 两边尽量先后测试，避免同时发请求影响耗时。单次快慢只供参考；记录明显卡住、超时或反复询问的情况即可。

## A．日常查数与省略

**A1**

```text
看看我们行现在存款有多少。
```

**A2**

```text
个人的呢？
```

**A3**

```text
企业的也看一下。
```

看什么：后两句是否仍理解为存款，是否保留机构和日期。“现在”采用最新有效数据日时，应说清楚实际日期；不能把不同日期的金额悄悄放在一起比较。

## B．余额与变化一起问，再追问下属机构

**B1**

```text
帮我看看我们行现在存款有多少，跟上个月比怎么样。
```

**B2**

```text
下面各家行分别还有多少，比上个月多了还是少了？把主要减少的和增加的都说一下。
```

看什么：是否同时回答金额和变化；第二句是否真正查了下属多家机构，而不是只返回一个汇总机构。缺数据的机构应说明，不能当成零。

这组此前出现过未能完成取数、下属机构被理解成汇总机构的问题，建议重点测试。数字本身正确，也可能答错机构范围。

## C．多个指标一起分析

**C1**

```text
个人存款和对公存款最近表现怎么样？余额和比上个月的变化一起看看。
```

**C2**

```text
还是这个日期，哪一块变化更明显？没有依据的原因先别猜。
```

看什么：个人、对公两部分是否都有余额和比较结果；第二句是否继承日期，并说明比较的是变化金额还是变化比例。不能只回答其中一个指标，却表现得像全部完成。

这组此前出现过反复解析、最后未完成的问题；第二轮也要注明第一轮是否已经取得有效结果。

## D．下降分析与客户明细边界

**D1**

```text
我们行存款怎么少了？
```

**D2**

```text
能看出是哪些机构拖下来的吗？
```

**D3**

```text
具体是哪几个客户把钱转走了，给我看看。
```

看什么：第一句是否先核实真的下降；第二句是否沿用已确认的指标、机构层级和比较日期；第三句是否有客户级依据，还是重复机构报告或凭空解释客户流失。

**机构下降排名只是定位变化，不等于查明业务原因。** 如果给出“贡献率”，还要有可核对的计算依据；没有客户交易证据时，说明当前无法查明客户是合理边界，但不代表已经完成客户归因。

## E．明确修改日期，再恢复最新日期

**E1**

```text
查一下我们行贷款有多少。
```

**E2**

```text
改看上个月底的，机构不变。
```

**E3**

```text
那还是看最新有数据的那天吧，存款也一起查一下。
```

看什么：第二句只修改日期；第三句恢复最新有效日并加入存款。若上个月底确实无数据，应明确说明，不能擅自换日。贷款和存款最新日期不同，也必须说明，不能直接当成同日数据。

## F．先问口径，再用自然语言确认

**F1**

```text
我们行活期占得多不多？
```

**F2**

```text
先说说这个比例的口径，别急着查。
```

**F3**

```text
我想看的是个人活期占个人存款的那个比例。
```

看什么：是否遵守暂不查数的要求，是否有正式依据解释口径；第三句是明确目标或选择，不能被误判成取消。没有比较标准时，不应武断说比例高或低。若第一句没有出现候选，本组只算自然语言确认，不能据此判断所有澄清选择都已验证。

## G．比例、金额与计算是否一致

**G1**

```text
我们行存款里，定期的占多少？
```

**G2**

```text
只看个人的，个人定期占个人存款的比例。
```

**G3**

```text
两个金额也给我看看，我核一下。
```

看什么：第二句已明确比较范围；两个金额和比例必须来自同机构、同日期，分子分母对应。缺数据、分母为零或暂不支持计算时，应说明，不能只复述需求就算完成。

## 简单记下结果

不用逐项打复杂分数。每轮记“完成／部分完成／未完成”，再记最影响使用的一点即可。

| 题号 | 旧版结果 | 新版结果 | 是否重复追问 | 大致耗时 | 问题或截图 |
| --- | --- | --- | --- | --- | --- |
| 例：B2 |  |  |  |  | 实际回答了哪些机构，是否与要求一致 |

核对时优先看：

- **问对了吗：** 指标、机构、日期和比较对象是否符合你的意思。
- **数字可靠吗：** 对照已有业务数据或可查看的明细，检查金额、正负号、单位和统计日期。新旧两版答案一致不代表一定正确。
- **任务完成了吗：** 同时问的内容有没有漏，缺数据有没有说清楚，是否真的给出结果。
- **解释有依据吗：** 区分查到的事实、算出的变化和暂时无法确认的原因。
- **用着顺吗：** 是否反复要求补已确认条件、重复之前的报告，或者等待后没有可用结果。

先保留首次结果，再决定哪些问题值得重测。两版都存在的问题、新版新增的问题和新版改善的问题分开记录，方便后续集中处理同类原因。

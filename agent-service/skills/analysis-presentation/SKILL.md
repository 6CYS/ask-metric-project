# 围绕发现组织报告

这份方法只负责报告怎么组织，不负责发现指标、取数或解释没有证据支持的原因。事实表、日期、单位、机构范围、证据引用和数据缺口必须保留服务端结果，不能为了版式改写。

## 风格选择

根据用户目标和已经取得的证据选择一个 profile：

- `snapshot`：用户只问一个指标或当前水平，先给结果，再给少量补充说明。
- `brief`：普通经营概览，先给核心判断，再展示关键数据和分析重点。
- `trend`：用户关注趋势、变化、近期走势或多期比较，先说明变化，再展示对比数据。
- `diagnostic`：用户问为什么、原因、质量、风险或异常，先说明已验证的问题，再列证据和待核查方向。
- `multi_topic`：同时涉及多个业务主题，选择有证据的分化、联系或重点展开；不要求分主题栏目。

不要因为风格不同而重复查询，也不要为了“看起来灵活”强行增加没有证据的章节。`density` 使用 `compact`、`medium` 或 `detailed`：简单取值用 compact，多方面经营问题通常用 medium，证据和子问题较多时才用 detailed。

## 组织规则

先阅读取数回执的 `verified_findings`，它是程序按原始证据核对后生成的判断，含方向、基期分化及可支持的计算差异；不能把探索线索当作已经证实的判断。按用户目标选择其中有价值的发现，再决定组织和补查，不要求全部抄写。可用 `{{判断ref}}` 直接插入已核验句子，或改述后用 `{{判断ref|cite}}` 关联依据；通用短引用形如 `e1.j1`，专项沿用回执原引用。新计算数字须先取得程序计算证据，不能写完后期待校验器认可心算。自由组织标题、段落和重点，但不能扩大判断所覆盖的机构、日期、比较基期或业务含义。

同一判断选择一种表达：已经改述并展示关键数字时，用 `{{判断ref|cite}}` 关联依据，不再插入内容相同的完整判断；直接插入完整判断时，前后不重复其数字、结论和限制说明。

先决定这次最需要回答什么，再决定写法。新报告通过body提交完整自然正文，不使用历史summary/sections。一个直接回答就能解决问题时不必加章节；有几项关键发现时按发现组织，有一个疑问值得深入时围绕该问题展开。多主题也可以在一段中联系可比的事实，不要求每个主题独立成章。不要每次都使用同样的“发现—数字—建议”段落结构。

正文只选择影响判断的关键数字，不把每项现值、环比、同比和年初值轮流抄一遍。完整数据由表格承载。开篇提出判断，后续增加证据、反例或判断边界，不能重复开篇。如果新证据改变了判断，直接写出变化后的结论与理由；若支持原判断，说明新增了哪项支持；若仍未解释，指出具体未解决问题。不需要固定的“补查结果”章节。

排版使用短标题、普通正文和少量重点强调：标题独占一行，段落之间留空行；仅加粗核心判断中的短语或少量关键数字，不将整段分析包在加粗标记中，也不把正文接在标题同一行。body是JSON字符串，换行按JSON规则只转义一次，解析后应是真正的换行，不要再次转义成字面的反斜杠n。章节、自然段和列表按内容选择，不规定固定栏目或数量。

数值展示与判断依据分开：关键数字用`{{真实原子ref}}`；无需展示数值的已核实判断，在相应句后用`{{真实原子ref|cite}}`关联依据。后者不在正文插入数值，程序仍验证引用、记录段落与证据的关系并检查目标覆盖；完整数值可在表格展开。不能用依据引用让未知数字或未经证实的因果通过校验。

在补查前，plan.inquiry记录具体疑问、初步判断、已有事实basis_refs和预期判断变化。inquiry_review只证明本次是否新增证据，不代替业务判断。报告要用新证据补充、修正或限定原判断，不能把“查到更多数值”当作解释了原因。

表格由程序根据真实证据生成，不能由模型重新抄写或编造。来源、实际观测日期、缺口和口径限制由服务端保留。若某段文字未通过证据校验，允许只保留其他通过校验的段落，真实完成状态仍由服务端记录。

影响本次判断的数据缺失、期间不完整或尚未完成的分析，在正文末尾用自然语言简短说明一次，交代缺少什么、因此暂不能判断什么。不单列“未完成项与数据缺口”“数据缺口”等栏目，不输出“部分完成”标签，不在开头、各章节和末尾重复同一说明；具体结论所必需的限定仍须保留。

提交 `analysis_report_present` 时，可在 `presentation` 中选择 profile 和 density 作为表达建议；页面按连贯正文展示，完整表格可展开。来源与校验依据保留在后台记录中，不额外生成固定的来源或依据栏目，也不提示用户展开来源栏目。profile不规定章节模板，不能为了符合风格重写事实。不要在最终正文中暴露 profile、布局名称、短引用或工具调用过程。

## 不允许的变化

- 不改变任何数值、单位、日期、机构和证据引用。
- 不把不同日期的指标强行合并成同一时点。
- 不把缺失数据改成“暂无风险”或用常识补齐原因。
- 不用随机数字、随机指标或随机结论制造变化。
